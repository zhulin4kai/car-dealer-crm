# 发票管理流程规则与验收规格

## 主流程

### 开票申请

- 开票申请应基于订单创建。
- 申请时应提供客户抬头、税务信息摘要、开票金额和开票内容。
- 开票金额应与订单和收款情况保持业务一致。
- 开票申请提交后进入财务处理。

### 可开票余额

- 订单可开票余额 = 订单可开票基数 - 已开具且未作废的正数发票金额 + 已完成红冲金额。
- 订单可开票基数应来自订单中允许开票的成交金额、服务项目和税费，不包含明确不开发票或不计入开票的押金、保证金和代收代付项目。
- 可开票余额不得为负数；任何新开票申请都不得超过当前可开票余额。
- 红冲申请中、红冲失败或待确认红冲金额不得恢复可开票余额；只有已完成红冲金额才能恢复可开票余额。
- 是否受已确认收款限制由订单票款策略决定：先款后票订单不得超过已确认收款中尚未开票的金额，先票后款和特批并行订单可以不受已确认收款限制，但不得超过订单可开票余额。
- 无需开票订单不得提交普通开票申请，除非订单票款策略已重新确认。

### 部分开票与多张发票

- 订单允许部分开票。
- 订单允许多张发票，但多张发票累计金额不得超过订单可开票余额。
- 订金已确认后，可以按订金对应金额申请发票；如果订金属于可退保证金或不计入开票基数，不得直接开具正式发票。
- 部分开票和多张发票都必须保留对应订单、开票金额、开票内容和业务原因。
- 发票抬头、税务信息或开票内容发生变化时，应形成新的开票申请或重开流程，不得直接覆盖历史发票事实。

### 财务处理

- 财务确认开票信息后完成开票。
- 开票失败应记录原因，并允许销售或客户补充信息后再次申请。
- 已开票记录应保留发票号码或可识别摘要。
- 票据文件或号码展示应受权限控制。

### 作废与红冲

- 发票错误、订单取消或业务纠错时，可以进入作废或红冲流程。
- 作废和红冲必须说明原因。
- 作废和红冲不得删除原开票事实。
- 红冲后如需重新开票，应形成新的开票记录。
- 作废适用于发票尚未交付客户、尚未被客户使用，且财务规则允许作废的场景。
- 已交付客户、已入账、跨期或不满足作废条件的发票，应走红冲流程。
- 已交付发票原则上不得普通作废；确需作废时，必须由财务确认票据可收回且满足作废条件。
- 红字发票应作为新的负数发票记录，不能只把原发票改成负数或覆盖原记录。
- 原发票被红冲后，应标记为部分红冲或已红冲，并保留与红字发票的关联。
- 重开发票必须关联原发票、原红冲或作废事实。

### 票据交付

- 发票开具后应记录是否已交付客户。
- 电子交付和纸质交付可以使用不同方式，但均应保留交付事实。
- 票据交付不等于车辆交付。

## 关键业务规则

- 发票状态与收款状态必须区分。
- 发票状态与车辆交付状态必须区分。
- 发票待开具、已开具、失败、作废和红冲不能与交易待收款状态混用。
- 开票是否必须等待收款，应由订单票款策略决定，不得由发票模块自行改变订单票款策略。
- 未确认订单不应开票。
- 发票金额不得超过订单可开票余额。
- 个人购车或其他业务明确无需开票时，必须由财务确认无需开票依据，不能由销售单独决定。
- 开票申请完成不等于发票完成；发票完成至少应达到正式开具状态。
- 发票是否计入交易完成，还应结合票据交付状态和交易履约完成规则判断。
- 作废或红冲不能物理删除原发票记录。
- 红冲后恢复的可开票余额只能来自已完成红冲金额。
- 重开发票不得覆盖原发票号码、原开票金额和原开票事实。
- 敏感税务信息不得在普通列表完整展示。
- 开票导出必须受权限控制。

## 指标要求

发票管理应支持观察：

- 待开票数量。
- 已开票数量。
- 开票失败数量。
- 作废数量。
- 红冲数量。
- 待交付票据数量。
- 订单开票完成率。

## 验收场景

- 订单成立后，可以提交开票申请。
- 先款后票订单在已确认收款不足时，不能提交超过已确认收款未开票部分的发票申请。
- 先票后款订单可以在收款完成前开票，但不能超过订单可开票余额。
- 同一订单可以部分开票和多次开票，但累计金额不能超过订单可开票余额。
- 订金开票只能开具已确认且允许计入开票基数的金额。
- 开票申请缺少必要抬头信息时，不能进入已开票。
- 财务处理成功后，发票状态变为已开票。
- 开票失败时，销售能看到可理解原因。
- 订单取消后，已开发票可进入作废或红冲流程，而不是被删除。
- 未交付且满足作废条件的发票可以作废；已交付或跨期发票应走红冲。
- 红冲完成后，可开票余额按红冲金额恢复，重开发票必须关联原票。
- 发票已开具但车辆未交付时，交易不会仅因发票完成而结束。
- 无权限用户不能查看完整税务信息或导出票据明细。

## 状态与事件边界

- 拥有发票处理状态：待申请、待开票、开票中、已开具、开票失败、已作废、部分红冲和已红冲。
- 拥有票据交付状态：未交付、待交付、已交付、交付失败和已撤回。
- 消费事件：订单成立、开票资料确认、财务处理、订单取消、作废申请、红冲申请和票据交付。
- 发出事件：开票成功、开票失败、发票作废、发票红冲、重开申请和票据交付。
- 发票处理正常终态包括已开具、已作废和已红冲；开票失败为可处理异常态，部分红冲为可继续处理态。
- 票据交付终态包括已交付和已撤回；待交付和交付失败为可处理态。
- 不允许发票状态覆盖收款、交付和交易完成状态。
