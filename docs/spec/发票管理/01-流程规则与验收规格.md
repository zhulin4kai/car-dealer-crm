# 发票管理流程规则与验收规格

## 主流程

### 开票申请

- 开票申请应基于订单创建。
- 申请时应提供客户抬头、税务信息摘要、开票金额和开票内容。
- 开票金额应与订单和收款情况保持业务一致。
- 开票申请提交后进入财务处理。

### 财务处理

- 财务确认开票信息后完成开票。
- 开票失败应记录原因，并允许销售或客户补充信息后再次申请。
- 已开票记录应保留发票号码或可识别摘要。
- 票据文件或号码展示应受权限控制。

### 作废与红冲

- 发票错误、订单取消或业务纠错时，可以进入作废或红冲流程。
- 作废和红冲必须说明原因。
- 作废和红冲不得删除原开票事实。
- 红冲后如需重新开票，应形成新的开票记录。

### 票据交付

- 发票开具后应记录是否已交付客户。
- 电子交付和纸质交付可以使用不同方式，但均应保留交付事实。
- 票据交付不等于车辆交付。

## 关键业务规则

- 发票状态与收款状态必须区分。
- 发票状态与车辆交付状态必须区分。
- 未确认订单不应开票。
- 发票金额不得随意超过订单可开票金额。
- 作废或红冲不能物理删除原发票记录。
- 敏感税务信息不得在普通列表完整展示。
- 开票导出必须受权限控制。

## 指标要求

发票管理应支持观察：

- 待开票数量。
- 已开票数量。
- 开票失败数量。
- 作废数量。
- 红冲数量。
- 待交付票据数量。
- 订单开票完成率。

## 验收场景

- 订单成立后，可以提交开票申请。
- 开票申请缺少必要抬头信息时，不能进入已开票。
- 财务处理成功后，发票状态变为已开票。
- 开票失败时，销售能看到可理解原因。
- 订单取消后，已开发票可进入作废或红冲流程，而不是被删除。
- 发票已开具但车辆未交付时，交易不会仅因发票完成而结束。
- 无权限用户不能查看完整税务信息或导出票据明细。
