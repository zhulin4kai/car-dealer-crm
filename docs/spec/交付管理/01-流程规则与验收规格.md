# 交付管理流程规则与验收规格

## 主流程

### 交付计划

- 订单进入待交付阶段后，应形成交付计划。
- 交付计划应明确客户、车辆、预计交付时间、负责人和准备事项。
- 预计交付时间变更应保留原因。

### 交付准备

- 交付前应确认车辆状态、库存占用、必要资料、收款条件和开票要求。
- 准备事项未完成时，不应进入已交付。
- 交付准备可以并行处理，但每项条件必须有明确结果。

### 客户交付

- 客户到店或确认交付后，应进行车辆验收和资料移交。
- 客户签收是交付完成的重要依据。
- 实际交付时间应来自真实交付动作。
- 交付完成后应触发库存出库或已交付状态，并推动交易完成判断。

### 交付异常

- 车辆不符、资料缺失、客户延期、付款未完成、票据异常等情况应标记为交付异常。
- 交付异常必须记录原因、责任方和下一步处理。
- 异常解除后才能继续交付。

### 交付后回访

- 交付完成后应生成回访任务。
- 回访可记录客户满意度、问题反馈和后续服务需求。
- 回访不承担售后维修工单职责。

## 关键业务规则

- 交付完成必须基于客户确认或签收事实。
- 交付完成不应仅由销售手工点击而缺少准备条件。
- 交付取消应联动订单、库存和收款处理。
- 交付资料不得在普通列表中暴露敏感信息。
- 已交付车辆不得再次作为可售库存。
- 交付后发现错误应走纠错或售后流程，不应直接删除交付记录。

## 指标要求

交付管理应支持观察：

- 待交付订单数量。
- 交付中订单数量。
- 已交付数量。
- 交付异常数量。
- 平均交付周期。
- 超期交付数量。
- 交付后回访完成率。

## 验收场景

- 订单达到交付条件后，系统形成交付计划。
- 车辆资料未准备完成时，不能标记为已交付。
- 客户签收后，交付状态变为已交付并保留实际交付时间。
- 交付完成后，库存车辆不再可售。
- 收款未达到交付条件时，交付视图提示阻塞原因。
- 交付异常处理完成后，可以继续交付流程。
- 交付完成后生成客户回访任务。

## 状态与事件边界

- 拥有状态：待准备、准备中、待客户确认、待交付、交付中、已签收、已完成、交付异常和已取消。
- 消费事件：订单成立、库存占用、收款满足交付条件、发票满足规则和客户预约。
- 发出事件：交付预约、资料确认、客户签收、交付完成、交付异常和交付回访。
- 终态包括已完成和已取消；交付异常为可处理态。
- 不允许交付状态覆盖资金、票据和订单状态。
