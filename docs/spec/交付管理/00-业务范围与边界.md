# 交付管理业务范围与边界

## 业务目标

交付管理用于管理车辆从订单待交付到客户完成签收的过程，确保车辆、资料、票据、收款条件和客户确认全部清晰可追溯。

交付是成交闭环的最后业务环节，不等同于开票完成，也不等同于收款完成。

## 目标用户

- 销售人员：协调客户交车时间、确认交付事项。
- 交付或库存人员：准备车辆、资料和交付检查。
- 财务人员：确认交付前资金条件。
- 销售主管：处理交付异常和客户争议。
- 管理者：观察待交付、交付周期和交付异常。

## 功能范围

交付管理覆盖：

- 交付计划。
- 交付车辆确认。
- 交付条件检查。
- 资料准备。
- 客户到店确认。
- 车辆验收。
- 客户签收。
- 交付完成。
- 交付异常。
- 交付后回访。
- 与订单、收款、发票和库存的关系。

## 交付信息

交付记录至少应表达：

- 关联订单。
- 客户。
- 交付车辆。
- 预计交付时间。
- 实际交付时间。
- 负责销售。
- 交付准备状态。
- 收款条件状态。
- 票据或资料状态。
- 客户签收状态。
- 异常原因。

交付资料可能包含客户证件、合同、票据和车辆文件，访问必须受权限控制。

## 交付状态

交付状态应至少区分：

- 待准备。
- 准备中。
- 待客户确认。
- 待交付。
- 交付中。
- 已交付。
- 交付异常。
- 已取消。

交付状态应表达车辆和客户签收过程，不应替代订单、收款或发票状态。

## 非目标

交付管理不承担：

- 物流运输全流程。
- 车辆上牌代办完整政务流程。
- 保险出单。
- 金融放款。
- 售后维修工单。
- 客户满意度调研平台。

## 成功标准

- 每笔待交付订单能看到交付准备进度。
- 车辆、资料、收款和客户签收条件清楚。
- 交付异常能被识别并分派责任。
- 交付完成后库存和交易状态能够形成一致结果。
- 管理者能观察待交付积压和交付周期。

## 业务对象关系

- 上游对象：订单、交易履约、库存占用、收款条件、发票条件和资料准备。
- 下游对象：交易完成判定、库存出库、客户回访和经营分析。
- 本模块负责交付计划、准备清单、预约、车辆确认、资料确认、客户签收、异常和回访。
- 本模块不负责收款确认、发票开具和订单价格事实。
- 交付完成是交易完成条件之一，但不能单独完成交易。
