# 操作记录功能规格

## 业务目标

操作记录用于追溯影响客户、交易、资金、库存、权限和基础数据的关键业务动作。记录应描述业务事实，而不是简单罗列所有 HTTP 请求。

## 必须审计的动作

第一阶段至少覆盖：

- 用户：创建、编辑、启用、禁用、锁定、解锁、重置密码、角色或权限调整。
- 线索：创建、编辑、导入、删除、转化客户。
- 客户：归属变更、关键资料变更、敏感数据导出。
- 交易：创建、编辑、提交审批、审批通过、审批驳回、重提、结算、关闭、删除。
- 收款与退款：创建收款、确认收款、退款及退款结果。
- 发票：创建、开具、作废和状态变化。
- 商品与库存：商品状态变化、入库、库存调整和库存锁定或释放。
- 字典：字典类型和值的新增、编辑、启停和删除。
- 导入导出：涉及客户、交易、资金或批量业务数据的导入导出。

普通详情查询、下拉选项查询、统计读取和界面刷新默认不记录操作审计。

## 记录时机

- 成功记录必须以业务事务最终成功提交为准。
- 业务回滚时禁止留下成功记录。
- 失败记录只用于明确要求保留的高风险动作，且必须标记为失败，不能与成功记录混淆。
- 批量操作应记录批次结果和数量摘要，不为每条数据制造无法控制的日志风暴。

## 记录内容

每条操作记录必须能够表达：

- 唯一记录标识。
- 操作者标识和姓名。
- 稳定的动作编码与可理解的动作名称。
- 所属业务模块。
- 业务对象类型和对象标识。
- 操作结果。
- 受控、脱敏的业务摘要。
- 客户端 IP。
- 操作发生时间。
- 可用于跨日志关联的请求标识。

根据业务需要，摘要可以包含：

- 变更前后状态。
- 变更前后负责人。
- 金额、数量等关键值的受控摘要。
- 批量操作的总数、成功数和失败数。
- 关联交易号、支付流水号或其他稳定业务编号。

## 摘要边界

摘要必须使用受控结构，不得直接序列化完整请求、响应、持久化对象或异常对象。

摘要禁止包含：

- 密码、密码摘要和验证码。
- Token、Authorization、Cookie、Session 和密钥。
- 手机号、身份证号、邮箱、地址的未脱敏完整值。
- 客户备注、沟通内容或其他自由文本全文。
- 银行账号、支付凭证和第三方敏感返回全文。
- Java 堆栈、SQL 和内部类名。

## 删除和清理边界

- 业务功能不得提供删除、批量删除或清空操作记录的入口。
- 后端不得向普通管理功能暴露删除或清空能力。
- 审计记录禁止通过业务接口物理删除。
- 数据规模治理采用保留期限、归档和受控运维流程，且归档或清理行为必须留下独立审计事实。

## 业务边界

- 操作记录描述关键业务命令，不记录所有读取请求。
- 操作记录不能成为绕过原业务权限读取敏感数据的通道。
- 操作记录不能覆盖原业务对象的生命周期状态。
- 导出行为本身属于高风险操作，必须留下操作记录。

## 状态与事件边界

- 拥有状态：记录成功、记录失败、待归档、已归档和保留期内。
- 消费事件：登录成功/失败、业务新增、编辑、审批、取消、作废、红冲、导出、删除和权限变更。
- 发出事件：审计记录写入、审计查询、审计导出和安全异常提示。
- 终态包括已归档；保留期内记录不可被业务接口物理删除。
- 不允许审计状态覆盖业务状态，也不允许业务删除动作删除审计事实。
