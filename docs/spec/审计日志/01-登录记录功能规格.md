# 登录记录功能规格

## 业务目标

登录记录用于识别账号访问情况、排查登录失败、发现异常访问迹象，并为账号安全争议提供可验证事实。

登录记录表达的是认证结果事实，不承担在线会话管理、强制下线、账号自动封禁或服务器安全监控职责。

## 记录触发

系统必须记录：

- 账号和凭证校验成功的登录。
- 账号不存在、密码错误、账号禁用、账号锁定、账号过期或凭证过期导致的登录失败。
- 认证流程发生未预期异常而未完成登录的失败结果。

普通接口的 Token 过期、权限不足和业务请求失败不属于登录记录。

登出记录不属于第一阶段必需项；如后续加入，必须与登录记录使用不同事件类型，不能伪装成登录失败。

## 记录内容

每条登录记录必须能够表达：

- 唯一记录标识。
- 用户提交的登录账号。
- 能够识别时的用户标识和用户姓名。
- 登录结果：成功或失败。
- 稳定的结果原因类别。
- 面向管理员的简短结果说明。
- 客户端 IP。
- 浏览器名称及主要版本。
- 操作系统名称。
- 登录发生时间。
- 可用于跨日志关联的请求标识。

登录失败且无法识别用户时，用户标识可以为空，但登录账号、结果、原因、IP 和时间不得缺失。

## 失败原因

失败原因必须使用稳定类别，至少区分：

- 账号不存在或凭证不正确。
- 账号被禁用。
- 账号被锁定。
- 账号已过期。
- 凭证已过期。
- 请求参数不合法。
- 认证服务异常。

对前台登录用户可以合并提示以避免账号枚举；管理员审计记录仍应保留受控的真实类别。

## 客户端信息边界

- 第一阶段只保存和展示 IP，不解析 IP 归属地。
- IP 不作为用户身份的唯一证明。
- 反向代理场景下只能接受受信任代理提供的客户端地址信息。
- 浏览器和操作系统根据客户端声明解析，只用于辅助排查。

## 敏感信息边界

登录记录禁止保存或展示：

- 密码、密码摘要和验证码。
- Token、Authorization、Cookie、Session 和刷新凭证。
- 完整请求体。
- 内部异常堆栈。
- 可被普通用户用于账号枚举的未授权信息。

## 业务边界

- 登录成功记录必须来源于服务端实际认证成功结果。
- 登录失败记录必须来源于服务端实际认证失败结果。
- 登录记录不能由客户端声明登录结果。
- 登录记录不能替代用户账号状态、角色权限或登录会话本身。
