# AI 业务助手业务范围与边界

## 项目定位

AI 业务助手用于帮助汽车经销商 CRM 用户理解业务上下文、发现风险、生成低风险提议、执行受控工作流和接收主动提醒。

AI 业务助手不是新的业务真源，也不是普通业务页面的替代入口。它围绕现有 CRM 业务对象提供辅助能力，所有业务事实仍以 CRM 已确认数据、业务规则、权限、数据范围、状态机和审计为准。

## 目标用户

- 销售人员：快速了解客户背景、最近跟进、商机进展、试驾、报价和下一步行动。
- 销售主管：识别长期未跟进客户、异常商机、异常交易、库存风险和团队待办堆积。
- 财务人员：理解交易的收款、退款、发票和履约缺口，但不通过 AI 直接执行资金或票据动作。
- 库存与交付人员：了解车辆商品、库存预警、交付准备和交付异常摘要。
- 管理员：配置 AI 模型供应商、模型、密钥、权限边界、审计追踪和数据保留要求。

## 核心业务问题

- 客户、商机、交易、跟进、库存和交付信息分散，业务人员需要频繁跳转才能理解上下文。
- 跟进任务、客户回访和异常提醒容易遗漏，影响销售转化和客户体验。
- 销售人员难以快速判断客户下一步应做什么、交易还有哪些履约缺口。
- 销售主管难以及时识别异常跟进、异常交易、库存风险和团队工作堆积。
- 沟通记录、跟进任务等低风险记录类工作耗时，但又需要保留清晰责任链。
- 管理员需要在系统内切换模型供应商、模型和 API Key，并保证普通用户看不到密钥。
- 业务人员希望使用自然语言询问 CRM 数据，但系统必须继续保护权限、数据范围和业务边界。

## 业务范围

- 查询当前用户有权访问的客户、线索、商机、跟进、试驾、报价、交易、收款、退款、发票、库存、交付和经营摘要。
- 总结客户画像、最近沟通、跟进状态、商机进展、交易履约缺口和库存风险。
- 生成待办提醒、异常提醒、跟进建议和可解释的业务状态说明。
- 基于当前页面或当前业务对象引用，辅助用户理解该对象的上下文。
- 对低风险记录类动作生成需用户确认的提议，用户确认前不产生业务写入。
- 支持受控多步骤工作流，展示计划、工具调用、等待确认、失败原因、恢复结果和最终总结。
- 支持主动提醒、每日摘要和周期性销售分析。
- 记录 AI 辅助过程，保证用户、问题、结果、工具调用、提议、确认、工作流和执行结果可追溯。
- 管理员可以维护多个全局 AI 模型配置，并选择当前系统启用配置。
- 管理员可以维护独立于模型供应商的 AI 运行策略，包括工具启停、低风险提议、安全等级、联网边界、上下文窗口和运行时限。

## 模型配置业务边界

- 系统支持多个全局模型供应商配置，同一时间只有一个启用配置。
- 模型配置必须包含供应商、协议格式、模型名称、模型显示名、连接地址、启用状态和测试状态。
- 协议格式必须覆盖 OpenAI-compatible 和 Anthropic。
- API Key 只允许写入、轮换和掩码展示，不允许明文查看。
- 普通用户只能使用 AI 助手，不能查看或修改模型供应商配置。
- 管理员测试连接必须受次数、超时和输出长度限制，不能触发业务工具和业务写入。

## AI 运行策略业务边界

- AI 运行策略是全局安全控制面，不随 Provider 切换而改变。
- 管理员可以在 ToolRegistry 白名单内启用或停用工具，并设置单次 Run 的最大工具调用次数。
- 模型可见工具必须同时满足管理员启用、ToolRegistry 注册和当前用户拥有对应业务权限；工具执行时仍必须重新校验权限和数据范围。
- 安全等级只能在系统允许的范围内收紧或选择标准低风险能力，不能关闭危险工具禁令、权限校验、数据范围、脱敏、审计或 Proposal 人工确认。
- 联网模式只允许关闭外部访问或访问管理员配置的模型供应商，不提供通用网页抓取、任意 URL、任意 HTTP 请求或用户自定义网络工具。
- 上下文消息数量可以由管理员在 1 到 8 条范围内设置，不能突破系统最大安全窗口。

## 会话、上下文与记忆边界

- AI 助手必须支持多轮 Conversation，会话用于承载同一用户围绕一个业务问题或业务对象的连续提问。
- Run 只表达 Conversation 中的一次模型执行、工具调用和结果生成，不能把单次 Run 当作会话。
- Conversation 必须绑定用户，可选绑定业务对象类型和业务对象标识。
- 同一用户在同一业务对象上下文中默认复用一个活跃 Conversation；没有业务对象上下文时使用通用 Conversation。
- 用户可以新建、重命名和归档 Conversation；归档只隐藏用户侧列表，不物理删除 Run、Message、ToolCall、Proposal、Workflow、Approval 和 ExecutionEvent。
- 用户可以编辑或撤回自己发送的消息；消息、Run 和业务执行记录保持不可变审计链，不通过覆盖或物理删除实现。
- 编辑历史用户消息时创建新的 Run，原轮次及其后续轮次退出当前活动上下文；撤回消息时同样从活动上下文排除相关轮次。
- 编辑或撤回不会回滚已经执行的 Proposal、业务写入和操作审计；界面必须明确提示这一边界。
- 运行中的轮次禁止并发编辑或撤回，消息修改必须使用版本号防止覆盖。
- 模型上下文只能使用脱敏会话摘要、最近用户可见消息、当前问题和当前业务对象引用。
- 模型上下文不得包含用户权限、角色、数据范围、审计操作者、API Key、Provider runtime config、服务间 token、原始 JSON 或供应商原始响应。
- Conversation 恢复必须恢复会话消息、最近 Run、业务结果、Proposal、Workflow 和可追溯状态；Run trace 恢复不等于 Conversation 恢复。
- Conversation 恢复必须按每一轮 Run 绑定用户问题、AI 回答、业务结果卡片、Proposal、Workflow、Approval 和 ExecutionEvent，不能只恢复最后一次 Run 的可追溯状态。
- 工具调用结果必须保存脱敏后的展示 payload，刷新、切换会话和展开独立页面后仍能恢复业务卡片；只保存工具摘要不满足会话恢复要求。
- 多轮回答必须能理解“刚才”“继续”“上一笔交易”等当前会话内引用，但仍不得越过用户权限和数据范围。

## 前端业务结果展示边界

- AI 对话默认展示业务结论、关键业务对象、风险或建议、下一步动作。
- 工具调用、工作流步骤和运行追踪只作为可选追溯信息，不能作为普通用户默认看到的回答主体。
- 工具结果必须按 CRM 业务对象展示，例如交易、客户、库存、跟进任务和交付记录；字段名称必须使用中文业务名称。
- 金额、时间、状态和数量必须按业务用户可读格式展示，不能直接输出数据库字段值或接口字段名。
- 交易结果至少展示交易编号、客户、金额、状态、创建时间和建议动作。
- 对话主视图不得展示 `id`、`tranNo`、`stageLabel`、`workflowNo`、`stepType`、工具 code、内部事件名、内部 JSON 或 Provider 原始响应。
- “查看处理过程”只能作为默认折叠的追溯入口，展开后也必须使用中文业务文案说明处理过程。
- 操作按钮必须来自当前问题和当前结果，不能在每次回答中固定展示与本次问题无关的工作流或能力菜单。
- 模型 Markdown 可以渲染为段落、列表、表格和代码块，但模型返回的 HTML 必须被禁用和清理，不能作为 HTML 直接插入页面。

## 业务事实来源

- AI 不能发明 CRM 业务枚举、状态、类型和值。
- 业务枚举、状态、类型和值的最终事实来源是 CRM 已确认的业务规则、业务对象边界和稳定业务口径。
- AI 只能使用当前 CRM 已支持的业务值生成查询、工具参数、提议参数和工作流动作。
- 如果 AI 能力需要新增沟通方式、跟进任务类型、业务对象类型、交易状态或其他业务值，必须先纳入对应业务规则并形成稳定业务口径，不能由 AI 编排临时创造。

## 主要能力

- 自然语言业务查询。
- 客户、线索、商机和交易摘要。
- 交易履约缺口解释。
- 库存、车辆商品和交付辅助。
- 待办、异常和周期性提醒。
- 低风险提议与人工确认。
- 受控多步骤工作流。
- 管理员模型供应商配置。
- 结构化结果展示。
- 可追溯运行记录和审计衔接。

## 非目标范围

- 不替代普通业务页面，也不要求用户通过 AI 完成所有业务操作。
- 不替代权限、数据范围、事务、状态流转和审计。
- 不直接审批交易、确认收款、执行退款、开票、作废发票、红冲发票、占用库存、释放库存、库存出库、删除客户、合并客户、删除交易或批量删除。
- 不直接创建交易，也不直接创建交易草稿。
- 不开放由用户输入、模型输出或提议参数驱动 AI 任意访问外部资源的能力。
- 不提供通用外部请求、文件处理或系统执行类能力。
- 不把模型输出作为可信业务参数直接落库。
- 不展示当前用户无权查看的敏感字段或跨范围业务数据。
- 不允许普通用户查看 API Key、模型密钥、服务间令牌或供应商原始响应。

## 成功标准

- 业务人员能通过 AI 更快理解客户、商机、交易、跟进、库存和履约上下文。
- 销售主管能及时发现逾期跟进、异常交易、库存风险和团队待处理事项。
- 财务、库存和交付人员能通过摘要理解交易履约缺口，但高风险动作仍在原业务流程中完成。
- 沟通记录和跟进任务等低风险提议必须经过用户确认，确认前不产生业务写入。
- AI 查询结果不越权、不泄露无权限字段、不绕过现有业务边界。
- AI 给出的交易、库存、收款、发票和交付说明能被业务明细追溯验证。
- 管理员能在系统内配置、测试、启用、停用和轮换模型配置。
- 管理员能在系统内管理 AI 工具、安全、联网、上下文和运行时限，配置会真实约束模型可见能力和后端执行。
- 用户编辑或撤回消息后，旧分支仍可审计但不再进入当前模型上下文，会话摘要不保留已失效内容。
- API Key 不出现在前端、响应、日志、SSE、trace、测试快照或 Git diff 中。
- AI 辅助过程可追溯，用户能够知道结果来自哪些业务对象和哪些已确认动作。
