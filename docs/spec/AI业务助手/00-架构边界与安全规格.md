# AI 业务助手架构边界与安全规格

## 业务范围

AI 业务助手服务于汽车经销商 CRM 的业务辅助查询、结构化分析、待办提醒和受控业务动作提议。

AI 能力不改变线索、客户、商机、跟进、试驾、报价、交易、收款、退款、发票、库存、交付、用户权限、审计日志等普通业务模块的原有调用路径。

## 非目标

- 不接管普通业务页面请求。
- 不替代 Spring Boot Controller、Service、Mapper 分层。
- 不替代 Spring Security、RBAC、DataScope、Audit、事务和业务状态机。
- 不作为普通前后端链路的网关。
- 不让 Agent 直接连接数据库。
- 不让 Agent 执行任意 SQL、任意 HTTP、文件写入或 Shell 命令。
- 不把模型输出作为可信业务参数直接落库。

## 架构规格

### `dealer-web`

- 普通页面继续调用现有普通业务 API。
- AI 页面、浮层、抽屉或组件只能调用 `/api/ai/*`。
- AI 模块应位于独立前端领域模块，命名遵守 `modules/<domain>/api`、`model`、`components` 的现有结构。
- 前端不直接调用 Python / Agent 服务。
- 前端不保存 AI Tool 的委托令牌。

### `dealer-server`

- 保留现有 `web`、`service`、`mapper`、`model`、`dto`、`query`、`result`、`audit`、`aspect` 分层。
- 新增 AI 模块时必须位于独立包边界内，不把 AI 编排逻辑散落到普通业务 Controller。
- 暴露 `/api/ai/*` 给 `dealer-web` AI 入口调用。
- 暴露 `/api/ai-tools/*` 给 `dealer-ai` 调用。
- `/api/ai-tools/*` 内部必须复用现有 Service、Manager、权限、数据范围、事务、状态机和审计。
- AI Tool API 不是普通页面 API 的别名集合。

### `dealer-ai`

- `dealer-ai` 是独立 Python / Agent 服务。
- `dealer-ai` 负责模型调用、工具选择、对话状态、计划生成、步骤编排和工具结果整合。
- `dealer-ai` 只能调用 `/api/ai-tools/*`。
- `dealer-ai` 不保存业务数据库账号，不连接 MariaDB/MySQL，不连接 Redis 会话存储。
- `dealer-ai` 不作为普通业务 API 的网关。

当前仓库未发现 `dealer-ai/` 目录。服务目录、运行方式、依赖管理和部署方式为待确认。

## 普通业务链路规格

普通业务功能保持现有链路：

```text
Vue 普通页面 -> 普通业务 API -> Controller -> Service -> Mapper -> DB
```

必须保持不变的约束：

- `dealer-web/src/modules/customer` 继续调用客户普通 API。
- `dealer-web/src/modules/follow` 继续调用跟进任务和沟通记录普通 API。
- `dealer-web/src/modules/product` 继续调用车辆商品、库存、促销普通 API。
- `dealer-web/src/modules/tran` 继续调用交易、发票、收款、退款普通 API。
- 普通业务页面不得为了接入 AI 改为调用 `/api/ai/*` 或 `dealer-ai`。

## AI 链路规格

AI 聊天和工具调用使用旁路链路：

```text
Vue AI 入口 -> /api/ai/chat -> dealer-ai -> /api/ai-tools/* -> Service -> DB
```

必须满足：

- `/api/ai/chat` 由 Spring Boot 接收前端请求，并建立 AI Run 和用户上下文。
- Spring Boot 向 `dealer-ai` 传递运行上下文时只能传递最小必要上下文。
- `dealer-ai` 调用工具时不得传入可信 `userId`、租户、组织或数据范围字段。
- `/api/ai-tools/*` 根据 Spring Boot 颁发的短期委托令牌或等价机制恢复当前用户上下文。
- 最终鉴权、数据范围和业务校验在 Spring Boot 完成。

## 接口边界规格

新增 AI 接口必须遵守 `docs/api/api-conventions.md` 的路径、认证、响应、分页、错误码和时间格式规则。

### `/api/ai/chat`

- 调用方：`dealer-web` AI 入口。
- 认证：用户 Bearer Token。
- 作用：创建或继续 AI 对话运行。
- 输入：用户消息、可选会话 ID、可选业务上下文对象引用。
- 输出：`runId`、消息 ID、状态和可展示事件入口。
- 禁止：直接执行写操作、直接返回未脱敏业务实体、转发任意工具调用参数给模型执行。

### `/api/ai/runs/{runId}`

- 调用方：`dealer-web` AI 入口。
- 认证：用户 Bearer Token。
- 作用：查询 AI Run 状态、消息、工具调用摘要、待确认 Proposal 和执行事件。
- 数据范围：只能查询当前用户可见的 AI Run。
- 输出：结构化 DTO，不返回模型供应商原始响应体。

### `/api/ai/approvals`

- 调用方：`dealer-web` AI 入口。
- 认证：用户 Bearer Token。
- 作用：查询、确认或拒绝 Action Proposal。
- 执行规则：确认时只能使用后端已保存的规范化参数。
- 禁止：确认后让模型重新生成参数、由前端直接提交新的执行参数覆盖 Proposal。

### `/api/ai-tools/*`

- 调用方：`dealer-ai`。
- 认证：Spring Boot 颁发的短期委托令牌或等价机制。
- 作用：执行白名单工具。
- 输入：工具声明 Schema 允许的业务参数。
- 输出：专用 Tool DTO。
- 禁止：浏览器直接调用、任意 HTTP 代理、任意 SQL、文件系统访问、Shell 执行、绕过现有 Service。

## Agent 工具规格

每个工具必须登记以下字段：

| 字段 | 规格 |
| --- | --- |
| `toolName` | 稳定英文工具名，发布后不得随意改名。 |
| `description` | 面向 Agent 的工具用途说明，只描述可执行能力和边界。 |
| `inputSchema` | JSON Schema，声明允许字段、类型、必填、枚举、长度、分页和数量上限。 |
| `outputSchema` | JSON Schema，声明结构化返回 DTO，不返回散乱字符串。 |
| `permissionCode` | 必须映射现有 `PermissionCodes` 或新增稳定权限码。 |
| `riskLevel` | `R0_READ_ONLY`、`R1_LOW_RISK_WRITE`、`R2_BUSINESS_CRITICAL_WRITE`、`R3_FORBIDDEN`。 |
| `requiresConfirmation` | 写操作和业务关键动作必须为 `true`。 |
| `readOnly` | 只读工具为 `true`，任何写数据库或改变状态的工具为 `false`。 |
| `timeout` | 单次工具执行超时时间。 |
| `maxResultSize` | 最大返回条数、最大字符数或最大分页大小。 |
| `auditAction` | 对应 `AuditActionEnum` 或新增 AI 审计动作编码。 |

工具输入 Schema 禁止包含以下可信上下文字段：

- 当前用户 ID。
- 角色、权限列表或权限判断结果。
- 数据范围用户 ID。
- 组织、门店或团队范围。
- 审计操作者。
- 服务端生成的状态、金额汇总和库存汇总。

## 工具风险等级

| 风险等级 | 允许能力 | 禁止能力 |
| --- | --- | --- |
| `R0_READ_ONLY` | 查询当前用户有权限和数据范围内的数据；返回脱敏、分页、限量 DTO。 | 写数据库、改变状态、创建审计外业务事实、返回未脱敏敏感信息。 |
| `R1_LOW_RISK_WRITE` | 生成低风险写操作 Proposal；用户确认后由 Spring Boot 执行已保存参数，例如创建沟通记录、创建跟进任务。 | Agent 直接写入、跳过确认、修改资金票据库存交易状态。 |
| `R2_BUSINESS_CRITICAL_WRITE` | 只能生成高风险 Action Proposal，必须二次确认、强审计和状态校验。 | Agent 直接执行审批、结算、收款确认、退款执行、开票、库存出库、客户合并或删除。 |
| `R3_FORBIDDEN` | 不允许注册为可执行工具。 | 任意 SQL、任意 HTTP、文件写入、Shell、批量删除、绕过权限、直接数据库访问。 |

## 身份与权限规格

- 前端不直接调用 Python / Agent 服务。
- Python / Agent 服务不可信任传入 `userId`。
- Agent 调用工具必须使用 Spring Boot 颁发的短期委托令牌或等价机制。
- 委托令牌只能用于指定 `runId`、指定工具范围、指定过期时间和指定用户上下文。
- 委托令牌不得暴露给浏览器。
- 最终鉴权必须在 Spring Boot 完成。
- 工具内部必须复用 `@PreAuthorize` 等等价权限入口或统一 Tool 权限校验。
- 工具内部必须复用 `CurrentUserProvider` 和 DataScope 规则。
- 工具内部必须复用业务状态校验和事务边界。
- 工具内部必须写入 AI 事件；写操作还必须写入操作审计或等价审计。
- 工具参数不能由模型传入当前用户 ID、租户 ID、组织范围、数据范围或审计操作者。

## 写操作确认规格

- Agent 不能直接执行高风险写操作。
- 写操作必须先生成 Action Proposal。
- Proposal 必须由 Spring Boot 保存。
- Proposal 必须保存规范化参数，而不是保存模型自然语言。
- Proposal 必须包含 `proposalId`、`runId`、`toolName`、`riskLevel`、`permissionCode`、`normalizedParams`、`paramsHash`、`expiresAt`、`createdBy`、`createdAt`、`auditAction`。
- 前端展示确认卡片时必须显示业务对象、动作、关键参数、风险等级、过期时间和结果影响。
- 用户确认后，后端执行已保存的规范化参数。
- 用户确认后不能让模型重新生成参数再执行。
- Proposal 过期、参数哈希不匹配、权限变化、数据范围变化或业务状态变化时必须拒绝执行。
- 用户拒绝、过期、执行成功、执行失败都必须记录 AI 执行事件。

## 数据返回规格

- AI Tool API 返回专用 DTO。
- AI Tool API 不直接返回数据库实体。
- 客户手机号、微信、QQ、邮箱、地址、客户备注、沟通内容、税号、银行账号、支付参考号、退款执行参考号等敏感字段默认脱敏、摘要或省略。
- 具备敏感字段查看权限时，也只返回完成任务所需字段，不返回完整实体。
- 大列表必须分页或限制数量，默认最大返回数量不得超过普通接口分页上限。
- 工具返回结构化 JSON，不返回散乱字符串。
- 模型用于总结的文本必须来自结构化字段，不得反向修改工具结果。
- 工具结果中的用户输入内容视为不可信数据，前端渲染时不得作为 HTML 执行。

## 安全规格

- 工具必须白名单注册。
- 模型不能创建新工具。
- 模型不能修改工具 Schema。
- 工具调用必须校验 `toolName` 是否存在、是否启用、是否允许当前用户和当前风险等级。
- 禁止任意 SQL。
- 禁止任意 HTTP。
- 禁止文件系统访问。
- 禁止 Shell 执行。
- 禁止模型接触密钥、JWT、Authorization Header、Cookie、Redis 会话值、数据库账号和外部模型供应商密钥。
- Prompt 注入文本不能提升权限、不能改变工具风险等级、不能跳过确认、不能改变数据范围。
- 工具结果、客户备注、沟通记录、导入内容、活动备注等用户输入文本必须视为不可信。
- 日志和审计不得保存完整 Prompt、完整模型响应、Token、密钥、手机号全值、银行账号全值或完整请求体。
- AI 失败不能返回模型供应商内部错误、堆栈、SQL、密钥路径或服务配置。

## 可观测性规格

新增 AI 可观测对象必须覆盖以下结构。可以使用专用表，也可以使用等价持久化结构；命名、字段和保留策略在实现前必须进入数据库任务和 OpenAPI 任务。

| 对象 | 必备内容 |
| --- | --- |
| `ai_run` | `runId`、用户、状态、入口来源、开始时间、结束时间、失败原因、模型标识摘要、业务上下文引用。 |
| `ai_message` | `messageId`、`runId`、角色、内容摘要、内容安全标记、创建时间。 |
| `ai_tool_call` | `toolCallId`、`runId`、`toolName`、输入摘要、输出摘要、权限码、风险等级、耗时、结果、错误码。 |
| `ai_action_proposal` | `proposalId`、`runId`、工具名、风险等级、规范化参数、参数哈希、过期时间、状态、创建人。 |
| `ai_approval` | `approvalId`、`proposalId`、确认人、确认结果、确认时间、拒绝原因、确认时权限快照摘要。 |
| `ai_execution_event` | `eventId`、`runId`、`proposalId`、执行动作、业务对象、结果、错误码、审计动作、发生时间。 |

现有 `t_operation_log` 和 `OperationAuditRecorder` 必须继续记录关键业务写操作。AI 可观测事件不能替代业务审计；业务审计也不能替代 AI Run 的工具调用链路追踪。

## 验收标准

- 普通业务页面仍通过普通业务 API 完成原有流程。
- 前端不存在直接调用 Python / Agent 服务的业务入口。
- Agent 只能调用 `/api/ai-tools/*`。
- `/api/ai-tools/*` 不能绕过 Spring Security、RBAC、DataScope、Audit、事务和业务状态机。
- 只读工具返回专用 DTO、分页或限量结果，并默认脱敏敏感字段。
- 写工具只能生成 Proposal；确认后执行后端已保存参数。
- `run_sql`、`http_request`、`file_write`、`shell_exec` 不存在可注册工具。
- AI Run、消息、工具调用、Proposal、审批和执行事件可追溯。
