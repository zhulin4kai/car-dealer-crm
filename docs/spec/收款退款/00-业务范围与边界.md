# 收款退款业务范围与边界

## 业务目标

收款退款用于管理订单相关资金事实，包括订金、尾款、退款、应收、实收和确认状态，帮助销售、财务和管理者掌握资金风险。

收款退款记录业务资金确认，不承担第三方支付清算或财务总账职责。

## 目标用户

- 财务人员：确认收款、处理退款、核对应收。
- 销售人员：查看客户付款进度和催收提醒。
- 销售主管：处理异常付款和退款申请。
- 管理者：观察应收、实收、退款和资金风险。

## 功能范围

收款退款覆盖：

- 收款计划。
- 订金记录。
- 尾款记录。
- 其他费用收款。
- 收款确认。
- 应收金额。
- 实收金额。
- 欠款和逾期。
- 退款申请。
- 退款审批。
- 退款结果。
- 收款退款历史。
- 与订单、发票和交付的关系。

## 收款类型

收款类型至少包括：

- 订金。
- 尾款。
- 全款。
- 补款。
- 服务或附加费用。
- 退款冲抵。

不同收款类型影响订单履约，但不直接改变客户或商机状态。

## 退款类型

退款类型至少包括：

- 订单取消退款。
- 多收退款。
- 价格调整退款。
- 客户违约处理后的部分退款。
- 内部纠错退款。

退款必须关联原订单和原因，不应成为孤立资金记录。

## 非目标

收款退款不承担：

- 银行清结算。
- 第三方支付网关。
- 企业总账。
- 税务申报。
- 贷款放款。
- 保险缴费。
- 自动对账平台。

## 成功标准

- 每笔订单能看到应收、实收、欠款和退款情况。
- 订金、尾款和退款有明确状态和确认责任。
- 财务确认前，销售不能把未确认资金当作已到账。
- 退款不会破坏原收款事实。
- 管理者能看到逾期应收和异常退款。

## 业务对象关系

- 上游对象：订单、交易履约、客户付款责任和财务确认。
- 下游对象：交易履约、退款处理、经营分析、审计日志和客户资金视图。
- 本模块负责订金、尾款、收款确认、退款、退回、冲正、幂等和可退金额。
- 本模块不负责发票开具、交付完成和交易完成单独判定。
- 收款满额只是交易完成必要条件之一，不能绕过票据、库存和交付条件。
