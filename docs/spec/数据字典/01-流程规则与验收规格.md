# 数据字典流程规则与验收规格

## 主流程

### 字典类型管理

- 字典类型表示一组稳定业务口径，例如线索来源、商机阶段或退款原因。
- 字典类型应有稳定编码、中文名称、适用范围和启用状态。
- 系统核心字典类型应受保护，不能被普通管理员随意删除。

### 字典项管理

- 字典项应有稳定编码、中文名称、排序和启用状态。
- 字典项展示名称可以调整，但稳定编码不应随意改变。
- 新增字典项应明确适用业务场景。
- 停用字典项后，不再用于新业务选择，但历史数据仍能展示原含义。

### 删除和变更

- 已被历史业务引用的字典项不得直接删除。
- 字典项含义发生实质变化时，应新增字典项而不是修改旧含义。
- 排序和展示名称调整不应改变业务判断。
- 核心状态字典变更应经过业务确认。

### 字典使用

- 业务模块应使用字典表达可变业务口径。
- 状态机核心含义不能完全交给普通字典随意修改。
- 字典展示值和业务判断值必须区分，避免改中文名称导致业务逻辑变化。

## 关键业务规则

- 字典稳定编码用于业务判断，展示名称用于用户理解。
- 字典停用不等于历史数据失效。
- 字典删除必须检查引用关系。
- 被任何业务记录引用的字典值不得物理删除，也不得为了删除字典而删除业务备注或历史记录。
- 系统内置字典类型编码和业务判断编码不得普通修改。
- 不同模块不能为同一含义创建多套相似字典。
- 字典导入和批量修改应受权限控制。
- 字典变更应被审计记录。

## 治理要求

字典治理应定期检查：

- 是否存在重复含义。
- 是否存在长期未使用项。
- 是否存在名称相近但业务含义不同的项。
- 是否存在被停用后仍用于新业务的项。
- 是否存在影响统计口径的随意修改。

## 验收场景

- 新增线索来源后，线索登记可以选择该来源。
- 停用线索来源后，新线索不能再选择，但历史线索仍显示原来源。
- 已被订单引用的订单状态字典项不能直接删除。
- 修改字典展示名称后，历史数据展示更新但业务判断不变。
- 普通销售不能维护全局字典。
- 字典项变更后，经营分析口径不产生无法解释的断裂。
- 字典变更可以在审计日志中追溯。

## 状态与事件边界

- 拥有状态：启用、停用、内置、删除受限和草稿。
- 消费事件：业务模块新增口径、展示名称调整、字典引用和字典停用。
- 发出事件：字典新增、字典启停、字典改名、字典删除拒绝和缓存失效。
- 终态包括停用和归档；被引用字典值为删除受限态。
- 不允许字典删除级联删除业务历史，不允许修改核心编码造成状态机语义漂移。
