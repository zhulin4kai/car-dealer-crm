# 数据字典业务范围与边界

## 业务目标

数据字典用于统一项目中的来源、状态、类型、原因、分类和展示选项，确保不同模块使用同一套业务口径，避免统计、权限、筛选和状态判断混乱。

数据字典是业务基础数据治理能力，不是临时下拉框管理器。

## 目标用户

- 系统管理员：维护全局字典和启停状态。
- 业务管理员：提出来源、原因和类型口径调整。
- 销售主管：关注销售状态和原因是否符合管理要求。
- 管理者：依赖统一口径进行经营分析。

## 功能范围

数据字典覆盖：

- 字典类型维护。
- 字典项维护。
- 启用和停用。
- 排序。
- 展示名称。
- 稳定业务编码。
- 适用模块。
- 默认值。
- 删除限制。
- 字典变更审计。

## 字典范围

数据字典至少应治理：

- 线索来源。
- 线索状态。
- 客户类型。
- 客户状态。
- 商机阶段。
- 跟进方式。
- 战败原因。
- 试驾状态。
- 活动类型。
- 商品分类。
- 库存状态。
- 促销类型。
- 订单状态。
- 收款类型。
- 退款原因。
- 发票状态。
- 交付状态。

不同模块如需使用同一含义，应引用同一业务口径。

## 非目标

数据字典不承担：

- 业务规则引擎。
- 流程编排系统。
- 多语言翻译平台。
- 数据仓库维表管理。
- 用户自定义资料项平台。
- 权限系统替代品。

## 成功标准

- 核心状态和原因不在各模块重复硬编码为不同含义。
- 字典项启停不会破坏历史数据展示。
- 经营分析使用统一字典口径。
- 删除或修改字典受到业务关系约束。
- 管理员能够理解每个字典项的适用范围和影响。
