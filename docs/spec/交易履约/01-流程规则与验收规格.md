# 交易履约流程规则与验收规格

## 主流程

### 订单成立

- 订单成立后进入交易履约。
- 履约应关联客户、商机、报价、车辆、销售负责人和订单事实。
- 订单成立不代表交易完成。
- 成立后可以触发订金、锁车、开票准备和交付准备。

### 履约推进

- 订金确认后，可以推进车辆锁定或订单有效性确认。
- 尾款确认、发票完成、车辆准备完成和客户签收共同支撑交易完成。
- 某一子状态完成不代表整笔交易完成。
- 履约视图应能提示当前阻塞点。

### 交易完成

交易完成应至少满足：

- 订单未取消。
- 车辆已交付或客户确认交付完成。
- 应收款达到业务完成条件。
- 必要发票或票据流程已完成或明确不需要。
- 关键资料已移交。

完成条件应由业务定义，不得只依赖单个状态值或页面按钮。

### 取消与关闭

- 客户取消、库存无法交付、审批失败、长期未付款等场景可以取消或关闭交易。
- 取消或关闭必须说明原因。
- 取消应联动库存释放、退款处理和商机结果。
- 已完成交易原则上不得普通取消，应走冲正或售后纠错流程。

## 关键业务规则

- 交易履约不能替代客户生命周期。
- 交易履约不能替代资金流水、发票记录和交付记录。
- 履约状态推进必须由真实业务动作触发。
- 订单历史必须保留关键状态变化、责任人和时间。
- 履约异常应暴露给相关责任角色。
- 已取消交易不应计入成交完成指标。

## 指标要求

交易履约应支持观察：

- 已下单交易数量。
- 待订金数量。
- 待尾款数量。
- 待开票数量。
- 待交付数量。
- 已完成交易数量。
- 取消和关闭数量。
- 履约周期。
- 异常交易数量。
- 成交金额口径。

## 验收场景

- 订单成立后，交易履约视图显示订单、客户、车辆和当前阻塞点。
- 只完成订金收款时，交易不会被标记为已完成。
- 发票完成但车辆未交付时，交易仍处于待交付或交付中。
- 交付完成且应收满足完成条件后，交易可进入已完成。
- 订单取消后，库存释放和退款待处理状态可见。
- 已取消交易不计入完成成交数。
- 交易历史能看到状态变化、时间和责任人。
