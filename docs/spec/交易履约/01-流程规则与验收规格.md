# 交易履约流程规则与验收规格

## 主流程

### 订单成立

- 订单成立后进入交易履约。
- 履约应关联客户、商机、报价、车辆、销售负责人和订单事实。
- 订单成立不代表交易完成。
- 成立后可以触发订金、锁车、开票准备和交付准备。
- 每笔订单应明确票款策略，用于决定收款、开票和交付准备之间的业务顺序。

### 票款策略

- 先款后票：订单应先完成约定收款条件，再进入正式开票流程。
- 先票后款：订单可以在收款完成前进入开票流程，但必须有业务授权，未到账应收款仍是完成阻塞点。
- 无需开票：订单应由财务确认无需开票依据，销售不得单独确认。
- 特批并行：订单可以并行推进收款、开票和交付准备，但必须有主管或财务授权，且不得绕过最终完成条件。
- 票款策略应在订单成立前或成立时确定；策略变更应保留原因、责任人和时间。

### 履约推进

- 订金确认后，可以推进车辆锁定或订单有效性确认。
- 尾款确认、发票完成、车辆准备完成和客户签收共同支撑交易完成。
- 某一子状态完成不代表整笔交易完成。
- 履约视图应能提示当前阻塞点。

### 交易完成

交易完成应至少满足：

- 订单未取消。
- 车辆已交付或客户确认交付完成。
- 应收款达到业务完成条件。
- 必要发票或票据流程已完成或明确不需要。
- 关键资料已移交。

完成条件应由业务定义，不得只依赖单个状态值或页面按钮。

### 业务完成矩阵

| 完成维度 | 完成口径 | 不满足时的处理 |
| --- | --- | --- |
| 订单事实 | 订单已成立，且未取消、未关闭、未处于变更确认中 | 禁止完成，继续停留在履约或变更处理流程 |
| 应收款 | 全部应收款已确认到账；金融贷款、厂家金融或第三方放款已由财务确认可视为到账 | 禁止完成，保留待收款或待金融确认阻塞点 |
| 票据 | 需要开票的订单，应以正式开具且已交付客户或电子送达为完成；仅提交申请、待审核或待开具不算完成 | 禁止完成，保留待开票、待交付票据或票据异常阻塞点 |
| 无需开票 | 客户或业务类型明确无需开票，并由财务确认依据 | 未经财务确认时禁止按无需开票完成 |
| 交付 | 车辆已出库，交车确认已完成，客户或授权代理人已签收 | 禁止完成，保留待出库、待交车或待签收阻塞点 |
| 资料移交 | 合同、票据、车辆资料、交付清单等关键资料已完成移交或明确不适用 | 禁止完成，保留待资料移交阻塞点 |
| 异常状态 | 不存在退款中、发票异常、库存异常、交付争议、收款异常或订单变更确认中事项 | 禁止完成，先处理对应异常 |
| 完成方式 | 交易完成应由完成条件聚合后产生；主管可以处理异常、补充凭证或批准策略变更，但不得绕过未满足的完成条件直接完成 | 未满足条件时不得人工强制完成 |

### 取消与关闭

- 客户取消、库存无法交付、审批失败、长期未付款等场景可以取消或关闭交易。
- 取消或关闭必须说明原因。
- 取消应联动库存释放、退款处理和商机结果。
- 已完成交易原则上不得普通取消，应走冲正或售后纠错流程。

## 关键业务规则

- 交易履约不能替代客户生命周期。
- 交易履约不能替代资金流水、发票记录和交付记录。
- 履约状态推进必须由真实业务动作触发。
- 交易完成必须同时满足既定的收款、发票和交付条件，不能只由单一收款动作直接完成。
- 每笔订单必须有明确票款策略，不能用系统全局默认流程替代订单自己的业务约定。
- 待收款、待开票和待交付应作为可同时存在的阻塞点，而不能混成一条固定串行状态。
- 票据完成以正式开具并交付客户或电子送达为准；开票申请完成不等于票据完成。
- 明确不需要发票必须由财务确认，不能由销售或客户口头选择直接决定。
- 存在退款中、发票异常、库存异常、交付争议、收款异常或订单变更确认中事项时，交易不得完成。
- 订单历史必须保留关键状态变化、责任人和时间。
- 履约异常应暴露给相关责任角色。
- 已取消交易不应计入成交完成指标。

## 指标要求

交易履约应支持观察：

- 已下单交易数量。
- 待订金数量。
- 待尾款数量。
- 待开票数量。
- 待交付数量。
- 已完成交易数量。
- 取消和关闭数量。
- 履约周期。
- 异常交易数量。
- 成交金额口径。

## 验收场景

- 订单成立后，交易履约视图显示订单、客户、车辆和当前阻塞点。
- 只完成订金收款时，交易不会被标记为已完成。
- 先款后票订单在约定收款条件未满足前，不得进入正式开票流程或交易完成。
- 先票后款订单即使发票已完成，只要应收款未满足完成条件，交易仍不得完成。
- 无需开票订单必须经过财务确认后，才能跳过票据完成条件。
- 特批并行订单可以并行推进收款、开票和交付准备，但最终完成仍必须满足业务完成矩阵。
- 发票完成但车辆未交付时，交易仍处于待交付或交付中。
- 交付完成且应收满足完成条件后，交易可进入已完成。
- 存在退款中、发票异常、库存异常或交付争议时，交易不能进入已完成。
- 订单取消后，库存释放和退款待处理状态可见。
- 已取消交易不计入完成成交数。
- 交易历史能看到状态变化、时间和责任人。

## 状态与事件边界

- 拥有履约主状态：已下单、履约准备中、履约中、异常、已完成、已取消和已关闭。
- 拥有阻塞点：待订金、待锁车、待收款、待金融确认、待开票、待票据交付、待交车、待签收、待资料移交和待异常处理。
- 票款策略决定收款、开票和交付准备的允许推进顺序；履约主状态不得替代票款策略。
- 消费事件：订单成立、库存占用、收款确认、退款完成、发票开具、发票作废、交付完成和订单取消。
- 发出事件：履约阻塞提醒、完成判定、取消关闭、退款处理请求和库存释放请求。
- 终态包括已完成、已取消和已关闭；异常为可处理态。
- 不允许单一收款、发票或交付事件直接覆盖交易完成状态。
