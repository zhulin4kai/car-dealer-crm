# 交易履约业务范围与边界

## 业务目标

交易履约用于管理订单成立后的业务推进，协调订单状态、库存、收款、发票、交付和关闭结果，确保一笔成交从确认到完成有清晰责任和状态。

交易履约关注订单生命周期，不应把线索、客户、商机、收款、发票和交付压缩成一个无法解释的单一状态。

## 目标用户

- 销售人员：推进订单履约、协调客户确认和交付。
- 销售主管：处理订单变更、取消和异常审批。
- 财务人员：查看收款和退款状态。
- 库存人员：查看占用和交付准备状态。
- 管理者：观察成交完成、异常订单和履约效率。

## 功能范围

交易履约覆盖：

- 订单履约状态。
- 订单历史。
- 订单变更。
- 订单取消。
- 订单关闭。
- 交易完成。
- 库存占用结果观察。
- 收款状态观察。
- 发票状态观察。
- 交付状态观察。
- 异常订单处理。
- 成交结果统计口径。

## 履约状态

交易履约状态应至少区分：

- 已下单。
- 待订金。
- 已锁车。
- 待尾款。
- 待开票。
- 待交付。
- 交付中。
- 已完成。
- 已取消。
- 已关闭。
- 异常处理中。

这些状态可以作为订单履约视图，但资金、票据和交付仍应保留各自独立状态。

## 异常类型

交易履约应能识别：

- 库存无法交付。
- 客户取消。
- 价格或合同变更。
- 付款逾期。
- 发票信息异常。
- 交付资料不完整。
- 退款处理中。
- 内部审批未完成。

异常不应被简单隐藏在备注中。

## 非目标

交易履约不承担：

- 支付清算。
- 税控开票。
- 物流运输全流程。
- 金融贷款审批。
- 保险承保。
- 法律纠纷处理。
- 售后维修服务。

## 成功标准

- 一笔订单从成立到完成的状态清晰可见。
- 收款、发票、库存和交付的进度能在交易视图中被观察，但不被混淆。
- 订单取消、关闭和异常处理都有原因和责任人。
- 管理者能看到未完成、逾期和异常交易。
- 成交统计只统计符合业务完成或确认条件的交易。

## 业务对象关系

- 上游对象：订单、库存占用、收款计划、发票申请和交付计划。
- 下游对象：经营分析、审计日志、异常提醒和客户历史。
- 本模块负责订单成立后的履约视图、阻塞点、取消关闭、变更历史和完成判定。
- 本模块不负责替代收款、退款、发票、库存和交付的独立状态。
- 交易履约可以聚合观察并协调状态，但不能把资金、票据、库存和交付压成单一字段。
