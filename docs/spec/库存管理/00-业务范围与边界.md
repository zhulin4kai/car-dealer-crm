# 库存管理业务范围与边界

## 业务目标

库存管理用于维护门店可销售车辆的真实可用情况，支持入库、占用、释放、出库、盘点、预警和库存周转分析。

库存管理描述“具体还有什么车可以卖、是否被占用、能否交付”，不应被商品目录或交易状态替代。

## 目标用户

- 库存人员：维护车辆入库、出库、调整和盘点。
- 销售人员：查询可售车辆并申请占用。
- 销售主管：审批关键占用或异常调整。
- 管理者：观察库存结构、库存周转和积压风险。

## 功能范围

库存管理覆盖：

- 库存车辆登记。
- 入库。
- 在库状态维护。
- 销售锁定。
- 试驾占用。
- 订单占用。
- 占用释放。
- 出库。
- 退回或取消占用。
- 库存调整。
- 盘点差异。
- 库存预警。
- 库存变动记录。

## 库存信息

库存车辆至少应表达：

- 所属商品。
- 车辆唯一识别信息。
- 颜色和配置。
- 入库时间。
- 所在门店或库位。
- 当前库存状态。
- 是否可售。
- 是否被试驾、报价或订单占用。
- 当前占用对象。
- 预计释放或交付时间。

车辆唯一识别信息属于重要业务事实，展示和导出应受权限控制。

## 库存状态

库存状态应至少区分：

- 待入库。
- 在库可售。
- 试驾占用。
- 销售锁定。
- 已订占用。
- 待交付。
- 已出库。
- 盘点异常。
- 不可售。

状态必须表达车辆真实可用性，不能只依赖商品数量推断。

## 非目标

库存管理不承担：

- 厂商生产排产。
- 物流运输全流程。
- 车辆维修保养工单。
- 配件仓库管理。
- 财务固定资产系统。
- 二手车整备和评估系统。

## 成功标准

- 销售能判断某车型是否有可用现车。
- 库存人员能追溯每次入库、占用、释放和出库。
- 同一车辆不会被多个订单重复占用。
- 管理者能看到库存周转、积压和异常状态。
- 订单交付前的库存占用和交付后的库存扣减边界清楚。

## 业务对象关系

- 上游对象：车辆商品、订单、试驾预约、锁车动作、盘点和库存调整。
- 下游对象：报价候选、订单占用、交付出库、库存预警和经营分析。
- 本模块负责可售、占用、锁定、释放、调整、出库、盘点异常和库存流水。
- 本模块不负责客户成交、收款、发票和交付签收事实。
- 库存占用应由订单成立或明确锁车条件触发，报价创建不应永久扣减库存。
