# 跟进任务业务范围与边界

## 业务目标

跟进任务用于把销售过程中的下一步动作明确化，避免线索、客户和商机停滞在静态资料中。它回答“谁在什么时间要对哪个客户做什么”的问题。

跟进任务可以关联线索、客户、商机、试驾、报价或交付，但不替代这些业务对象本身。

## 目标用户

- 销售人员：查看待办、记录沟通、完成跟进。
- 销售主管：查看逾期、督办和团队跟进质量。
- 客服或市场人员：执行回访、活动邀约和满意度沟通。
- 管理者：观察跟进及时率和客户经营质量。

## 功能范围

跟进任务覆盖：

- 手工创建待办。
- 由业务动作生成待办。
- 电话、到店、微信、短信、邮件等跟进方式记录。
- 下一步时间维护。
- 任务提醒。
- 任务完成。
- 任务延期。
- 任务取消。
- 逾期识别。
- 跟进结果沉淀。
- 团队督办。

## 任务类型

任务类型至少包括：

- 首次联系。
- 电话回访。
- 到店邀约。
- 试驾确认。
- 报价沟通。
- 价格协商。
- 合同签署提醒。
- 收款提醒。
- 交付确认。
- 交付后回访。
- 长期客户维护。

任务类型应使用统一口径，不得在不同模块各自定义互不兼容的名称。

## 非目标

跟进任务不承担：

- 即时通讯系统。
- 自动外呼平台。
- 短信营销平台。
- 企业日程系统的完整替代。
- 客服工单系统。
- 售后维修派工系统。

## 成功标准

- 销售能看到按时间排序的个人待办。
- 每个关键线索、客户或商机都有可理解的下一步动作。
- 逾期未跟进能够被销售和主管发现。
- 跟进完成后业务对象的最近跟进事实同步可见。
- 管理者能评估跟进及时率和客户经营连续性。

## 业务对象关系

- 上游对象：线索、客户、商机、试驾、订单、交付和管理指派。
- 下游对象：线索状态、客户时间线、商机推进、交付回访和经营分析。
- 本模块负责待办、沟通记录、回访、预约、延期、逾期和完成结果。
- 本模块不负责主业务对象的终态判定。
- 跟进任务可以推动业务对象产生新事件，但任务完成本身不代表线索转化、商机赢单、订单成立或交付完成。
