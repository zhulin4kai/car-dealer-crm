# 经营分析业务范围与边界

## 业务目标

经营分析用于把线索、客户、商机、报价、订单、收款、库存、交付和活动结果转化为管理者可理解的业务指标，帮助门店判断销售效率、来源质量、库存压力和资金风险。

经营分析只展示经过统一口径定义的业务结果，不应把原始数据随意拼成看似精确但不可解释的数字。

## 目标用户

- 门店管理者：查看经营概览和异常。
- 销售主管：查看团队漏斗、跟进、成交和停滞情况。
- 市场人员：查看来源和活动效果。
- 库存人员：查看库存周转和积压。
- 财务人员：查看应收、实收和退款风险。

## 功能范围

经营分析覆盖：

- 首页经营概览。
- 销售漏斗。
- 线索来源分析。
- 商机阶段分析。
- 报价和订单分析。
- 成交金额和成交台数。
- 收款和应收分析。
- 库存周转和积压分析。
- 试驾转化分析。
- 活动 ROI 分析。
- 销售人员表现。
- 异常事项和待处理提醒。

## 指标口径

经营分析必须定义清楚：

- 统计时间范围。
- 业务发生时间。
- 组织或人员归属。
- 成交口径。
- 金额口径。
- 来源归因。
- 取消和退款处理方式。
- 重复客户处理方式。

没有口径定义的指标不应作为管理决策依据。

## 非目标

经营分析不承担：

- 企业级 BI 平台。
- 财务报表系统。
- 税务报表。
- 人力绩效薪酬系统。
- 预测算法平台。
- 实时大屏监控系统。

## 成功标准

- 管理者能看到从线索到成交的核心漏斗。
- 指标口径可解释，不因模块不同产生冲突。
- 管理者能识别逾期跟进、停滞商机、库存积压和应收风险。
- 市场人员能判断活动和来源质量。
- 销售主管能观察团队推进效率。

## 业务对象关系

- 上游对象：线索、客户、商机、跟进、试驾、报价、订单、收款、发票、库存、交付、活动和审计事实。
- 下游对象：管理首页、销售漏斗、来源分析、库存资金分析和异常提醒。
- 本模块负责指标口径、数据范围、时间范围、明细下钻和异常识别。
- 本模块不负责修改任何业务对象状态。
- 指标必须基于业务事件和状态终点反算，不能使用无法解释的混合口径。
