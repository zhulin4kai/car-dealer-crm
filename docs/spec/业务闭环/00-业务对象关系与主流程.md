# 业务对象关系与主流程

## 主业务链路

汽车经销商 CRM 的主业务链路为：

线索 -> 客户 -> 商机 -> 跟进/试驾 -> 报价 -> 订单 -> 收款/发票/库存/交付 -> 完成 -> 经营分析。

这条链路表达业务事实的产生顺序，不代表所有模块只能串行处理。订单成立后，收款、发票、库存和交付可以并行推进，但必须围绕同一订单事实保持一致。

## 业务对象职责

### 线索

- 记录潜在购车意向的进入事实。
- 承载来源、联系方式、初始意向、负责人和跟进记录。
- 可以转为客户或商机。
- 不代表客户已经长期沉淀，也不代表已经产生订单。

### 客户

- 记录可持续经营的自然人或组织。
- 承载基础资料、联系方式、归属、意向、历史沟通和关联业务。
- 可以拥有多个商机、报价、订单和交付历史。
- 不代表一定存在进行中商机或成交机会。

### 商机

- 记录客户针对车辆或购车需求形成的可推进销售机会。
- 承载意向车型、预计金额、阶段、负责人、下一步动作、赢单或输单结果。
- 可以产生跟进任务、试驾、报价和审批。
- 不承载收款、发票、交付和库存最终状态。

### 跟进任务

- 记录销售、客服或交付人员的下一步动作和沟通计划。
- 可以服务线索、客户、商机、试驾、订单和交付回访。
- 任务完成说明某个待办已处理，不代表主业务对象进入终态。

### 试驾

- 记录客户体验车辆的预约、到店、安全确认、执行结果和反馈。
- 可以影响商机阶段、客户意向和后续报价。
- 试驾完成不自动生成报价、订单或成交。

### 报价

- 记录面向客户的价格方案和版本。
- 承载车辆、配置、指导价、优惠、促销、审批结果、有效期和客户确认结果。
- 报价被客户接受并满足审批要求后，才能形成订单。
- 报价不等于订单，也不应触发永久库存扣减。

### 订单

- 记录客户确认成交后的基础事实。
- 必须锁定客户、车辆或车辆占用意向、成交价格、优惠、付款责任、交付预期和责任人。
- 订单成立后进入交易履约。
- 订单取消、作废、变更必须保留原因和责任事实。

### 交易履约

- 记录订单成立后的履约视图。
- 聚合观察库存、收款、发票、交付和异常，但不替代这些模块的独立状态。
- 交易完成必须由订单、资金、票据、库存和交付结果共同支撑。

### 收款退款

- 记录订金、尾款、退款、退回、冲正和外部支付参考号。
- 资金流水不可被普通删除。
- 收款满足金额条件只是交易完成的必要条件之一。

### 发票

- 记录开票申请、开具、失败、作废、红冲和票据交付。
- 发票状态不等于收款状态，也不等于交易完成状态。
- 发票作废和红冲必须保留原票据事实。

### 库存

- 记录车辆商品或具体车辆的可售、占用、锁定、释放、出库和盘点异常。
- 库存占用应由订单成立或明确锁车动作触发。
- 库存数字变化必须能通过库存流水核对。

### 交付

- 记录车辆准备、资料准备、预约交付、客户签收、交付异常和交付后回访。
- 交付完成不直接覆盖收款和发票状态。
- 交付完成后车辆不应继续作为可售库存。

### 经营分析

- 读取业务事实形成指标和异常提醒。
- 指标必须能从明细反算。
- 经营分析不能反向修改业务状态。

## 禁止替代边界

- 线索不能替代客户。
- 客户不能替代商机。
- 商机阶段不能替代报价、订单、收款、发票、库存或交付状态。
- 报价不能替代订单。
- 订单不能替代资金流水、票据记录和交付记录。
- 交易履约不能吞并收款、发票、库存和交付的独立状态。
- 统计指标不能反向修改业务状态。

## 业务协同原则

- 每个业务对象必须有清晰的负责人、状态、关键时间和关闭条件。
- 上游对象转化为下游对象时必须保留关联关系和历史事实。
- 下游对象异常、取消或作废时不得删除上游历史。
- 同一业务事实只能由一个模块拥有状态，其他模块只能引用或观察。
- 跨模块动作必须产生审计记录，并能被经营分析追溯。
