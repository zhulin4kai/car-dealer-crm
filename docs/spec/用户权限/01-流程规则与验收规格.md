# 用户权限流程规则与验收规格

## 主流程

### 用户账号管理

- 创建账号时应明确姓名、登录账号、状态、角色和所属团队。
- 账号禁用后不得登录或执行业务操作。
- 账号锁定用于安全风险或管理要求，应有解锁流程。
- 离职账号应禁用，并触发客户、线索、商机和订单责任交接。

### 角色管理

- 角色用于组合权限，不应直接等同于某个员工。
- 修改角色权限会影响该角色下所有用户，必须谨慎并可追溯。
- 系统管理员角色应受严格保护，避免被普通管理员随意削弱或扩权。

### 数据范围

- 数据范围应支持个人、团队、门店或全局等业务边界。
- 销售人员默认只查看自己负责或协作的数据。
- 主管可以查看团队数据。
- 财务、库存和审计人员按职责查看相关范围。

### 关键动作授权

- 导出客户、确认收款、处理退款、开票、交付确认、审批价格和查看审计必须独立授权。
- 前端隐藏按钮只是体验控制，服务端必须做权限判断。
- 越权请求应被拒绝并可追溯。

## 关键业务规则

- 用户不能通过修改请求中的负责人或组织信息绕过数据范围。
- 权限变更不得影响历史业务事实的责任人记录。
- 禁用账号的历史业务记录仍应可查询。
- 系统至少保留一个可用系统管理员。
- 权限删除或角色停用不得破坏已有审计记录解释。
- 批量授权必须有明确范围和责任人。

## 权限矩阵要求

每个业务模块应明确：

- 谁可以查看。
- 谁可以新增。
- 谁可以编辑。
- 谁可以关闭或删除。
- 谁可以导入。
- 谁可以导出。
- 谁可以审批。
- 谁可以处理资金、票据或交付。

权限矩阵必须以业务动作定义，不以页面名称定义。

## 验收场景

- 禁用账号无法登录和执行业务操作。
- 销售人员不能查看其他团队客户，主管可以查看团队客户。
- 无导出权限用户看不到导出能力，直接请求也被拒绝。
- 财务角色可以确认收款，但不能随意修改客户归属。
- 库存角色可以处理车辆入库，但不能确认收款。
- 角色权限调整后，新权限立即影响后续操作。
- 权限变更和关键授权动作可被审计查询。
