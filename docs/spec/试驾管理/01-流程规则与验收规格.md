# 试驾管理流程规则与验收规格

## 主流程

### 试驾预约

- 试驾应基于客户或商机创建。
- 预约时必须确定试驾车型、预约时间、负责销售和客户联系方式。
- 如果指定具体车辆，必须判断车辆在该时间段是否可用。
- 预约成功后应生成试驾确认或到店提醒任务。

### 到店与安全确认

- 客户到店后应确认客户身份、试驾意愿和试驾安排。
- 需要驾驶证、试驾协议或风险提示的场景，应在试驾前完成确认。
- 安全确认未完成时，试驾状态不得进入试驾中或已完成。
- 销售不得用试驾完成状态代替客户到店状态。

### 试驾执行

- 试驾开始和结束应形成明确状态。
- 试驾结束后应记录客户反馈、意向变化和下一步动作。
- 客户试驾后要求报价时，应进入报价流程。
- 客户明确放弃时，应更新商机结果或后续跟进计划。

### 取消、爽约与改期

- 客户取消试驾必须记录原因。
- 客户未到店应标记为爽约，不得伪装为已完成。
- 改期应保留原预约时间和新预约时间。
- 多次爽约可以影响商机优先级，但不自动关闭客户。

## 关键业务规则

- 试驾记录必须关联客户，避免匿名试驾无法追溯。
- 试驾车辆不能在同一时间段被多个客户占用。
- 试驾完成不代表商机赢单。
- 试驾结果应回写客户和商机视图。
- 试驾涉及的证件、协议和联系方式属于敏感业务信息。
- 试驾异常应保留事实摘要，但不在 CRM 中处理完整事故理赔。

## 指标要求

试驾管理应支持观察：

- 预约试驾数量。
- 到店率。
- 完成率。
- 爽约率。
- 试驾后报价率。
- 试驾后成交率。
- 销售人员试驾转化表现。
- 车型试驾热度。

## 验收场景

- 销售为商机创建试驾预约后，客户和商机详情可看到该预约。
- 同一车辆同一时间段已有试驾安排时，不能再次确认占用。
- 客户未到店时，试驾记录标记为爽约，并可安排再次跟进。
- 试驾完成后，系统要求记录结果和下一步动作。
- 试驾完成后进入报价流程时，商机阶段发生合理推进。
- 无权限人员不能查看试驾中的敏感证件或协议信息。

## 状态与事件边界

- 拥有状态：待预约、已预约、待到店、待安全确认、试驾中、已完成、已取消、爽约和异常。
- 消费事件：商机试驾邀约、客户改期、车辆不可用和安全确认。
- 发出事件：试驾完成、试驾取消、试驾爽约、试驾异常和试驾后跟进。
- 终态包括已完成、已取消、爽约和关闭异常；已预约、待到店和待安全确认为可推进态。
- 不允许试驾状态覆盖商机赢单、报价状态、订单状态或库存最终状态。
