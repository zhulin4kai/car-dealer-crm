# 客户管理业务范围与边界

## 业务目标

客户管理用于沉淀可持续经营的客户资产，形成客户基础资料、购车意向、联系记录、商机、交易、交付和回访的统一视图。

客户是可以被长期经营的个人或组织，不等同于一次线索，也不等同于某一笔订单。

## 目标用户

- 销售人员：维护客户资料、跟进意向和推进商机。
- 销售主管：管理客户归属、客户质量和销售过程。
- 客服人员：查看客户历史、协助回访和满意度处理。
- 管理者：关注客户沉淀、复购、来源质量和归属风险。

## 功能范围

客户管理覆盖：

- 客户创建。
- 客户资料维护。
- 联系方式维护。
- 意向车型、预算和购车周期记录。
- 客户来源归因。
- 客户归属和协作人员。
- 客户标签。
- 客户跟进历史。
- 关联线索。
- 关联商机。
- 关联订单、收款、发票和交付。
- 客户状态维护。
- 客户合并和重复处理。
- 客户导出。

## 客户信息

客户至少应表达：

- 姓名或组织名称。
- 主要联系方式。
- 备用联系方式。
- 客户类型。
- 客户来源。
- 意向车型或需求。
- 购车预算。
- 预计购车时间。
- 负责人。
- 客户状态。
- 最近跟进时间。
- 客户标签。
- 历史线索、商机和交易关系。

敏感资料只保存业务必要部分，展示和导出应支持脱敏。

## 客户状态

客户状态应表达经营阶段，至少区分：

- 潜在客户。
- 意向客户。
- 到店客户。
- 试驾客户。
- 成交客户。
- 休眠客户。
- 流失客户。
- 无效客户。

客户状态不应替代商机阶段。一个成交客户未来仍可能产生新的商机。

## 非目标

客户管理不承担：

- 面向消费者的会员商城。
- 客户积分体系。
- 金融征信和贷款审批。
- 保险承保。
- 售后维修工单。
- 客服呼叫中心完整坐席系统。
- 精细化营销自动化平台。

## 成功标准

- 销售能够围绕客户看到资料、来源、意向、历史跟进、商机和成交记录。
- 客户不会因为多次线索进入而形成多个互相冲突的客户档案。
- 客户归属清晰，主管能够处理转移、共享和离职交接。
- 客户敏感信息在普通列表、导出和跨权限访问中受到控制。
- 管理者能够判断客户沉淀质量和客户经营结果。

## 业务对象关系

- 上游对象：线索、人工创建、客户合并和归属转移。
- 下游对象：商机、跟进任务、试驾、报价、订单、收款、发票、交付和经营分析。
- 本模块负责客户主档、联系方式、归属、生命周期、敏感信息边界、客户视图和客户合并。
- 本模块不负责商机推进、报价审批、订单履约、资金票据和车辆交付状态。
- 客户可以拥有多个商机和多段交易历史；客户存在不代表存在进行中商机或成交事实。
