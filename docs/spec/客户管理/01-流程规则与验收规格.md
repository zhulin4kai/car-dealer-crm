# 客户管理流程规则与验收规格

## 主流程

### 客户创建

- 客户可以由线索转化、人工创建、批量导入或历史交易沉淀产生。
- 创建客户前应进行重复检查。
- 客户来源应继承线索或活动来源；人工创建时必须选择明确来源或未知来源。
- 客户负责人应来自线索负责人、分配规则或主管指定。

### 客户维护

- 客户资料变更应保留最近编辑责任。
- 手机号、证件、地址等敏感资料只允许授权角色查看完整值。
- 关键资料变更应避免覆盖历史业务事实，例如订单签约信息不应因客户资料修改而失真。
- 客户标签用于辅助经营，不得替代正式状态和业务结论。

### 客户合并

- 重复客户应由授权人员确认合并。
- 合并前必须展示两边的线索、商机、订单和跟进关系。
- 合并后应保留原客户来源、历史跟进和业务关系。
- 合并不得导致订单、收款、发票或交付关系丢失。

### 客户归属

- 客户必须有明确负责人或责任团队。
- 归属转移必须记录原负责人、新负责人、原因和时间。
- 离职、调岗或长期未跟进客户应支持主管重新分配。
- 共享协作可以用于跨岗位协同，但不能模糊主责任人。

## 关键业务规则

- 客户与线索是不同业务对象，线索转客户后不应删除线索历史。
- 线索转客户时，客户、首个商机或首个报价的业务归属必须一致，不能由操作按钮的人改变真实负责人。
- 客户与商机是不同业务对象，客户存在不代表必然有进行中商机。
- 一个客户可以同时存在多个商机，但每个商机必须有独立阶段和结果。
- 客户分页、筛选和导出必须使用统一参数口径，翻页结果必须可解释。
- 客户导出必须受独立权限、范围和数量限制。
- 客户删除应谨慎：存在商机、订单、收款、发票或交付记录时，不应允许普通删除。
- 客户跟进记录是客户生命周期的一部分，成交、交付、回访和复购沟通都应能追加到客户时间线。
- 客户状态必须来自真实业务动作，不应由统计任务随意覆盖。

## 客户视图

客户详情应能展示：

- 基础资料。
- 联系方式和脱敏展示。
- 来源和归属。
- 标签和偏好。
- 跟进时间线。
- 关联线索。
- 关联商机。
- 关联报价、订单、收款、发票和交付。
- 风险或待办事项。

客户视图应帮助销售理解“下一步做什么”，而不是只展示静态资料。

## 验收场景

- 线索转客户后，客户档案保留线索来源和跟进历史。
- 同一手机号再次创建客户时，系统提示疑似重复。
- 客户归属从销售 A 转给销售 B 后，客户列表和详情体现新负责人，并保留转移记录。
- 客户合并后，商机、订单、跟进记录不丢失。
- 普通销售不能导出超出自己范围的客户资料。
- 无权限角色不能查看完整敏感联系方式。
- 成交客户再次产生购车需求时，可以创建新商机，而不是覆盖原成交记录。

## 状态与事件边界

- 拥有状态：潜在、意向、到店、试驾、成交、复购、休眠、流失、无效和已合并。
- 消费事件：线索转客户、客户归属转移、商机创建、成交完成、交付回访和客户合并。
- 发出事件：客户创建、客户归属变更、客户合并、客户关闭、客户敏感资料导出和客户跟进追加。
- 终态包括无效、流失和已合并；休眠为可恢复态，成交不是客户终态。
- 不允许客户状态自动覆盖商机阶段、订单状态、收款状态、发票状态或交付状态。
