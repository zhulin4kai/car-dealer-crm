# 操作记录落地方案

## 关联 Spec

- docs/spec/审计日志/00-业务范围与边界.md
- docs/spec/审计日志/02-操作记录功能规格.md
- docs/spec/审计日志/03-权限安全与数据治理规格.md

## 背景

操作记录需要追溯关键业务命令的责任事实。它不等于请求日志，也不应由控制器方法名、页面中文或临时日志拼接来解释业务含义。

## 目标

- 补齐操作记录查询、详情和导出能力。
- 操作动作使用稳定编码和业务名称。
- 操作摘要使用受控结构，不直接保存完整请求、响应、实体或异常。
- 成功操作记录与业务事务提交结果保持一致。
- 关键业务写操作覆盖 Spec 要求的第一阶段范围。

## 当前现状

- `dealer-server/src/main/java/com/autodealer/crm/audit/OperationAuditRecorder.java` 提供 `record` 和 `recordQuietly`。
- `dealer-server/src/main/java/com/autodealer/crm/audit/AuditActionEnum.java` 已定义部分动作。
- `dealer-server/src/main/java/com/autodealer/crm/model/TOperationLog.java` 当前字段包含用户、动作编码、模块、资源、详情、IP、创建时间。
- `dealer-server/src/main/java/com/autodealer/crm/mapper/TOperationLogMapper.java` 当前只提供按模块、按用户的基础查询。
- `dealer-server/src/main/resources/mapper/TOperationLogMapper.xml` 当前查询能力不足以支撑管理员组合筛选。
- 部分用户、线索、客户、交易、字典、商品操作已经显式调用操作审计记录器。
- 当前没有管理员可用的操作记录列表、详情和导出接口。

## 设计方案

### 动作模型

动作模型应包含：

- 稳定动作编码。
- 面向管理员展示的动作名称。
- 所属业务模块。
- 业务对象类型。
- 风险等级或审计级别。

动作编码不能依赖页面文案，页面文案可以从动作编码映射生成。

### 数据模型

操作记录应补齐以下业务表达能力：

- 操作结果：成功或失败。
- 业务对象类型。
- 业务对象标识或稳定业务编号。
- 请求标识。
- 受控结构化摘要。

直接在 `CarDealerCRM.sql`、`schema-test.sql` 和 `data.sql` 中维护 `t_operation_log` 的最终结构与数据。历史记录缺失可选字段时，详情页应显示明确占位，不能显示 `null`、`undefined` 或内部变量名。

### 写入策略

- 普通业务成功审计必须在事务成功提交后成为成功事实。
- 对需要保留失败记录的高风险动作，必须显式标记失败结果。
- 批量操作记录批次摘要，不为每条记录制造不可控日志量。
- 导入导出动作必须记录范围、数量和结果。
- 操作审计写入失败不能被静默吞掉；业务是否回滚由具体动作风险决定，但必须有明确策略。

### 查询与详情

- 列表支持模块、动作、操作人、结果、业务对象类型、对象标识、时间范围组合筛选。
- 默认查询最近时间范围内第一页数据，禁止空条件无上限返回全部历史。
- 排序使用 `create_time desc, id desc`。
- 列表展示简短摘要，详情展示完整受控摘要。

### 导出

- 导出使用独立权限。
- 导出使用与列表一致的筛选条件和排序。
- 导出限制时间范围和最大数量。
- 导出动作本身写入操作记录。
- 导出内容不得包含详情页禁止展示的敏感内容。

## 风险与约束

- 业务事务回滚后不能留下成功记录。
- 自由文本摘要可能泄露客户备注、手机号、支付信息或认证凭证。
- 导出范围过大可能造成性能和敏感数据扩散问题。
- 现有历史操作记录字段不足，页面必须兼容旧数据。

## 实施阶段

1. 梳理现有动作编码和已接入业务操作。
2. 补齐操作记录字段、Mapper 查询和历史兼容。
3. 新增操作记录分页查询、详情和导出接口。
4. 审查关键业务写操作，补齐动作覆盖和事务一致性。
5. 新增权限控制、测试数据和 API 文档。
6. 执行权限、脱敏、分页、排序、导出和事务回滚验证。

## 验收标准

- 管理员能按模块、动作、操作人、结果、对象和时间范围查询。
- 详情能展示受控摘要，不展示原始请求体、响应体或异常堆栈。
- 导出内容与筛选条件一致，并被独立授权。
- 导出操作本身产生操作记录。
- 业务事务回滚后不存在成功操作记录。
- 页面和接口不存在删除、批量删除或清空能力。

## 业务协同关系

- 依赖登录认证、权限变化、业务事件和敏感操作。
- 影响责任追溯、安全分析、异常排查和经营复盘。
- 权限控制覆盖审计查询、详情、导出和保留策略。
- 审计本身记录业务动作结果，不替业务模块做业务校验。
- 统计口径可读取审计异常，但不得用审计记录改写业务状态。

## 状态与事件方案

- 状态列表：记录成功、记录失败、待归档、已归档和保留期内。
- 触发事件：登录成功/失败、业务新增、编辑、审批、取消、作废、红冲、导出、删除和权限变更。
- 非法迁移：审计记录不得被业务接口物理删除。
- 异常策略：审计写入失败必须记录风险，不能悄悄吞掉关键业务操作。

## 数据与历史方案

- 必须保留操作者、业务对象、业务动作、结果、时间、IP、摘要和关联 ID。
- 审计日志在保留期内不可变更和删除。
- 审计查询和导出本身也应受权限和审计控制。
- 审计数据服务责任追溯和安全分析。
