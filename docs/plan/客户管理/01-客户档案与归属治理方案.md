# 客户档案与归属治理方案

## 关联 Spec

- docs/spec/客户管理/00-业务范围与边界.md
- docs/spec/客户管理/01-流程规则与验收规格.md

## 背景

客户是长期经营对象，不等同于线索、商机或订单。客户档案需要沉淀来源、意向、负责人、跟进历史和关联业务，同时避免重复客户、归属不清和敏感信息泄露。

## 目标

- 客户档案统一表达资料、来源、意向、标签、负责人和历史关系。
- 客户创建前进行重复检查。
- 客户归属转移保留原负责人、新负责人、原因和时间。
- 客户合并不丢失线索、商机、订单、跟进、收款、发票和交付关系。
- 客户列表、详情和导出遵守数据范围和敏感信息控制。

## 当前现状

- 后端已有 `CustomerController`、`CustomerServiceImpl`、`CustomerManager`、`TCustomer`、`TCustomerMapper`。
- 后端已有客户列表、详情、选项和导出相关 DTO：`CustomerListResponse`、`CustomerDetailResponse`、`CustomerOption`、`CustomerExcel`。
- 前端已有 `dealer-web/src/modules/customer/`、`dealer-web/src/pages/dashboard/customer.vue` 和客户详情页。
- 当前客户合并、归属转移、敏感字段脱敏和重复客户处理能力需要按 Spec 补齐。

## 设计方案

### 客户主档

客户主档保存当前有效资料和经营状态，历史线索、商机、交易等关系不能因主档编辑被覆盖。

客户状态应来自真实业务动作，包括潜在、意向、到店、试驾、成交、休眠、流失和无效。

### 后端方案

- 在 `CustomerServiceImpl` 中补齐客户创建、编辑、归属转移、合并、导出和删除限制规则。
- 在 `CustomerManager.convertCustomer` 中保证线索转客户的幂等、重复处理和来源继承。
- 客户导出继续由 `CustomerController.exportExcel` 承载，但必须独立权限、数量限制和审计。
- 客户敏感字段在 Response 和 Excel 中按权限脱敏，不让前端决定是否可看完整值。

### 前端方案

- 客户列表展示基础资料、负责人、状态、最近跟进和来源摘要。
- 客户详情组织基础资料、联系方式、来源归属、跟进时间线、关联线索、商机、报价、订单、收款、发票和交付。
- 客户合并和归属转移必须展示影响范围并要求原因。
- 无完整敏感信息权限时展示脱敏值。

### 数据方案

- 客户联系方式需要支持重复检查和脱敏展示。
- 归属转移、合并和关键资料变更需要保留历史或审计记录。
- 存在业务关系的客户不得普通物理删除。

## 风险与约束

- 不能把客户存在等同于存在进行中商机。
- 不能让客户资料修改覆盖历史订单签约事实。
- 客户合并必须保护所有关联业务对象。
- 导出客户资料属于敏感操作，必须独立授权和审计。

## 实施阶段

1. 梳理客户创建、线索转客户、详情、导出和删除现状。
2. 补齐客户重复检查、归属转移和敏感字段权限。
3. 设计并实现客户合并流程和关联迁移。
4. 调整前端列表、详情、转移和合并交互。
5. 补充客户数据范围、导出、合并和脱敏测试。
6. 更新 API、后端、前端和集成文档。

## 验收标准

- 同一手机号再次创建客户时提示疑似重复。
- 线索转客户后保留线索来源和历史沟通。
- 客户归属转移后列表和详情显示新负责人并保留转移记录。
- 客户合并后商机、订单、跟进记录不丢失。
- 普通销售不能导出超出自己范围的客户资料。
- 无权限角色不能查看完整敏感联系方式。

## 核心闭环补充

- 线索转客户时，客户和后续首个交易对象继承同一业务负责人。
- 管理员代转线索时，管理员是操作人，不应覆盖原线索业务归属。
- 客户列表分页统一使用 `page/size`，旧 `current` 只能作为兼容层。
- 客户跟进记录需要形成可新增、查询、编辑和删除或软删除的维护入口。

## 业务协同关系

- 依赖线索转化、人工创建、客户合并和权限数据范围。
- 影响商机、跟进任务、试驾、报价、订单、收款、发票、交付和客户 360 视图。
- 权限控制覆盖客户查看、编辑、归属转移、合并、导出和敏感信息查看。
- 审计记录覆盖归属变更、合并、敏感字段修改和导出。
- 统计口径依赖客户新增、转化、成交、复购、流失和沉淀质量。

## 状态与事件方案

- 状态列表：潜在、意向、到店、试驾、成交、复购、休眠、流失、无效和已合并。
- 触发事件：线索转客户、客户归属转移、商机创建、成交完成、交付回访、客户合并和客户流失。
- 非法迁移：客户成交不能关闭历史商机；客户合并不能改变历史订单责任事实。
- 异常策略：重复客户走合并，敏感资料按权限脱敏，休眠客户可重新激活。

## 数据与历史方案

- 必须保留线索来源、客户归属、合并关系、跟进时间线和敏感信息访问记录。
- 存在商机、订单、收款、发票或交付记录的客户不能普通删除。
- 客户合并必须迁移关联对象并保留原客户摘要。
- 归属转移、合并、导出和敏感字段修改必须审计。
- 客户状态、来源和成交情况进入经营分析口径。
