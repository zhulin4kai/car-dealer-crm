# 报价版本与订单成立方案

## 关联 Spec

- docs/spec/报价订单/00-业务范围与边界.md
- docs/spec/报价订单/01-流程规则与验收规格.md

## 背景

报价用于表达销售阶段的价格方案和客户协商过程，订单用于表达客户确认后的成交事实。报价版本、审批、客户确认和订单成立必须清楚区分。

## 目标

- 建立报价版本，不覆盖历史报价。
- 报价包含车辆、价格构成、优惠、促销、附加费用和有效期。
- 超权限价格、特殊优惠或超出促销规则时进入审批。
- 客户接受报价后才能创建订单。
- 订单成立后驱动收款、库存占用、发票和交付准备。

## 当前现状

- 当前交易能力集中在 `TranController`、`TranServiceImpl`、`TTran`、`TTranProduct`、`TranStage`。
- 当前已有交易审批、交易商品、收款、发票等能力，但缺少独立报价版本模型。
- 当前没有 `QuoteController`、`QuoteService`、`TQuote`、`TQuoteVersion` 和前端 `modules/quote`。

## 设计方案

### 报价模型

报价应关联客户、商机、车辆商品或库存车辆、版本、价格构成、优惠来源、有效期、审批状态、客户反馈和是否被订单采用。

每次价格方案变化生成新版本，不覆盖旧版本。

### 订单模型

订单基于客户接受的报价或主管确认的成交条件创建，必须确定客户、车辆、成交价、订金要求、预计交付信息和销售负责人。

订单不是交易完成，订单成立后进入交易履约。

### 后端方案

- 新增报价模型、Mapper、Service、Controller 和 DTO。
- 报价审批可以复用交易审批经验，但应独立表达报价审批事实。
- 订单成立时可复用或逐步迁移现有 `TTran` 作为交易履约主记录，但必须保留报价来源。
- 订单变更和取消必须保留变更前后事实和原因。

### 前端方案

- 新增报价列表、报价详情、创建报价、版本历史、审批和客户确认入口。
- 在商机详情中展示报价版本和订单结果。
- 在交易详情中展示订单来源报价和价格快照。

### 数据方案

- 新增报价主表和报价版本表。
- 订单保存成交价格、优惠、促销和车辆快照。
- 重大订单变更保存历史，不直接覆盖成交事实。

## 风险与约束

- 报价过期、库存不可用或促销失效时必须重新确认。
- 报价审批通过不等于客户接受。
- 客户接受报价不等于交易完成。
- 订单取消必须联动库存释放、收款处理和商机结果。

## 实施阶段

1. 梳理当前交易创建、审批、商品、收款和发票耦合点。
2. 新增报价和报价版本数据结构。
3. 实现报价创建、版本、审批、客户确认和失效规则。
4. 实现订单成立与现有交易履约记录的衔接。
5. 调整前端报价页面、商机详情和交易详情。
6. 补充报价版本、审批、客户确认、订单成立和取消测试。

## 验收标准

- 每次价格方案变化形成新报价版本。
- 低于授权底价的报价必须审批通过后才能作为成交条件。
- 过期报价不能直接创建订单。
- 订单创建后能驱动库存占用和收款计划。
- 订单取消保留原因，不破坏历史报价。
- 商机赢单以订单成立为依据。

## 核心闭环补充

- 创建报价或交易必须校验客户真实存在且在当前操作者数据范围内。
- 新报价只能选择当前可售商品。
- 报价创建不应永久扣减实际库存；库存占用发生在订单成立或明确锁车动作。
- 增量添加商品时，交易总金额必须按全部有效行项重算。
- 商品、促销和价格在报价或订单确认时保存快照。

## 业务协同关系

- 依赖客户、商机、商品、促销、库存可用性、价格审批和权限数据范围。
- 影响订单、交易履约、库存占用、收款计划、发票申请、交付准备和销售漏斗。
- 权限控制覆盖报价创建、价格修改、提交审批、审批、客户确认、订单创建和取消。
- 审计记录覆盖报价版本、价格变更、审批、客户确认、订单成立和取消。
- 统计口径依赖报价数量、审批通过率、报价成交率、让利金额和订单取消率。

## 状态与事件方案

- 状态列表：报价草稿、待审批、已驳回、待客户确认、已接受、已过期、已转订单、订单已成立、订单已取消和订单已关闭。
- 触发事件：报价提交、价格审批、客户确认、订单成立、库存占用、订单变更和订单取消。
- 非法迁移：报价不能直接完成交易，订单成立不能绕过库存、资金、票据和交付条件。
- 异常策略：过期报价不可转订单，驳回报价可生成新版本，订单取消联动释放和退款。

## 数据与历史方案

- 必须保留报价版本、商品快照、促销快照、价格审批、客户确认和订单成交快照。
- 已转订单报价不能覆盖旧版本。
- 订单取消、作废和变更必须保留原因。
- 报价提交、审批、客户确认和订单成立必须审计。
