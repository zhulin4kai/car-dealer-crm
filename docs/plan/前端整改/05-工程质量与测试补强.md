# 工程质量与测试补强

## FE-017 后端错误被统一文案吞掉

- 严重级别：P3
- 性质：体验改进
- 文件和准确行号：`dealer-web/src/pages/dashboard/product/promotion.vue:227-236,264-277`；`dealer-web/src/pages/dashboard/product/stock.vue:374-384`；`dealer-web/src/pages/dashboard/tran/invoice/[id].vue:369-389`
- 当前行为：catch 多数只显示“操作失败”，不区分 403、409、501、状态冲突或字段校验；有些地方直接把 `error.message` 拼到 UI，策略不一致。
- 正确行为：共享错误适配器按稳定 code 映射可理解提示；表单字段错误回填字段，状态冲突提示刷新，403 提示权限，未知错误使用通用文案。
- 触发方式：提交缺 productId 的促销、重复发票、无权限库存操作或后端状态冲突。
- 业务影响：用户无法修正输入，容易反复提交；开发者也难以从用户反馈定位真实问题。
- 修复建议：定义 `presentApiError(error, context)` 和字段错误契约；禁止页面自行匹配中文 msg。
- 可能受影响的后端接口或其他页面：全部命令接口和导入接口。

## FE-018 宽松迁移残留掩盖真实分支

- 严重级别：P3
- 性质：体验改进
- 文件和准确行号：`dealer-web/src/pages/dashboard/tran/index.vue:344-355,376-414`；`dealer-web/src/pages/dashboard/product/stock.vue:244-265`；`dealer-web/src/modules/activity/components/ActivityFormDialog.vue:1-9`；`dealer-web/src/pages/dashboard/tran/invoice/[id].vue:282-344,401-404`
- 当前行为：页面保留大量 `if (true)`、未类型化空数组/空对象、生产调试日志；页面直接调用通用 HTTP；`ActivityFormDialog` 是只渲染 slot 的空壳。
- 正确行为：Promise resolve 即代表成功，删除恒真分支；所有集合明确类型；页面只调用模块 API；无职责组件删除或承担真实表单职责；生产日志走统一策略。
- 触发方式：日常维护、契约变更或错误排查。
- 业务影响：死代码让错误路径不可测试，类型推断退化，重复 API 和组件职责增加修改成本。
- 修复建议：按模块渐进清理，优先本轮 P1 触达文件；不做无边界的全仓格式重写。
- 可能受影响的后端接口或其他页面：所有模块；先处理 user、customer、product、tran。

## FE-019 关键行为没有回归测试

- 严重级别：P2
- 性质：已确认缺陷
- 文件和准确行号：`dealer-web/tests/unit/router/routes.test.ts:5-32`；`dealer-web/tests/unit/shared/http-client.test.ts:10-53`；`dealer-web/tests/unit/stores/auth-store.test.ts:7-23`；`dealer-web/tests/unit/modules/api-endpoints.test.ts:15-52`
- 当前行为：路由测试只断言路径数组；HTTP 测试只验证解包和方法；Auth Store 只验证恢复 Token；API endpoint 测试主要检查函数存在/少量调用。没有挂载实际页面验证权限、DTO、状态和错误恢复。
- 正确行为：关键流程应覆盖权限守卫、组件交互、请求体、后端错误、状态刷新和跨页面一致性。
- 触发方式：任何契约或页面重构都可能让现有测试继续通过但真实业务失败；本轮 FE-001 至 FE-013 即为实例。
- 业务影响：测试提供错误安全感，阻断型缺陷无法在提交前发现。
- 修复建议：按下列优先级补回归测试；测试应断言业务结果而非“成功渲染”。
- 可能受影响的后端接口或其他页面：全部关键前端模块。

## 最需要补充的回归测试（本轮不编写）

1. 客户导出：断言 Token 位于 Header、URL 无 Token、Blob 文件名正确、401 会清理会话。
2. 用户新增/编辑：断言 JSON DTO 字段精确，编辑不带密码/状态，后端字段错误可回填。
3. 库存页：mock 非空 PageResult 后断言表格和分类选项渲染；筛选、重置和补货后刷新。
4. 促销表单：productId 必填，时间顺序和折扣范围校验，编辑完整回显。
5. 交易结算：促销预览来自后端，确认价与结算结果一致；并发状态冲突后刷新。
6. 发票：APPROVED→PENDING→ISSUED/VOID 全状态流，已有发票不可重复创建。
7. 权限守卫：无首页权限、有其他菜单、无菜单、直接 URL、401、403、权限加载失败。
8. 会话失效：多个并发 512 只触发一次清理和一次跳转；退出清理 Store 与两种 storage。
9. 分页：搜索回到第一页，删除最后一条回到合法页，旧请求不得覆盖新请求。
10. 时间与金额：GMT+8 日期不回退；BigDecimal 显示/提交保持两位精度；Long ID 不转 JS number。
