# 前后端契约与数据类型整改

## FE-001 客户导出认证方式错误并泄露 Token

- 严重级别：P1
- 性质：已确认缺陷
- 文件和准确行号：`dealer-web/src/pages/dashboard/customer.vue:149-157`；`dealer-server/src/main/java/com/autodealer/crm/config/filter/TokenVerifyFilter.java:43-50`；`dealer-server/src/main/java/com/autodealer/crm/web/CustomerController.java:75-78`
- 当前行为：前端创建隐藏 iframe，把 JWT 作为 `Authorization` 查询参数拼进 URL。后端过滤器只读取 `Authorization` Header，不读取查询参数。
- 正确行为：下载请求应通过共享请求层发送 Header，并以 Blob 处理文件名和内容；JWT 不应出现在 URL、浏览历史、代理日志或 Referer 中。
- 触发方式：登录后进入客户页，点击“全部导出”或“选择导出”。
- 业务影响：接口返回 Token 为空，导出不可用；同时 JWT 会暴露到浏览器和基础设施日志。
- 修复建议：在 customer 模块增加 typed blob API，复用 `axiosClient` 的 Token 拦截器，解析 `Content-Disposition` 后主动下载；删除 iframe 和查询串认证。
- 可能受影响的后端接口或其他页面：`GET /api/exportExcel`；其他未来文件下载页面也必须禁止查询串 Token。

## FE-002 用户新增和编辑的 Content-Type 与后端不一致

- 严重级别：P1
- 性质：已确认缺陷
- 文件和准确行号：`dealer-web/src/pages/dashboard/user.vue:386-404`；`dealer-web/src/modules/user/api/user-api.ts:35-40`；`dealer-server/src/main/java/com/autodealer/crm/web/UserController.java:61-71`
- 当前行为：页面绕过已经存在的 typed user API，把表单转换为 `FormData` 后调用通用 `doPost/doPut`。后端两个方法均使用 `@RequestBody` DTO，要求 JSON。
- 正确行为：页面应分别构造 `CreateUserRequest` 和 `UpdateUserRequest`，调用模块 API，以 `application/json` 提交；编辑请求不得携带密码和账号状态字段。
- 触发方式：用户管理页填写新增表单或编辑已有用户并提交。
- 业务影响：请求可能以 415/501 失败，用户维护主流程不可用；宽松表单还把后端不接受的字段一并提交。
- 修复建议：删除页面级 `doPost/doPut`，接入 `createUser/updateUser`；创建与编辑使用不同 Zod Schema 和请求映射。
- 可能受影响的后端接口或其他页面：`POST /api/user`、`PUT /api/user`；用户详情和列表刷新。

## FE-003 库存列表对统一响应执行了二次解包判断

- 严重级别：P1
- 性质：已确认缺陷
- 文件和准确行号：`dealer-web/src/shared/api/http-client.ts:70-79`；`dealer-web/src/modules/product/api/product-api.ts:33-42`；`dealer-web/src/pages/dashboard/product/stock.vue:268-289,293-323`
- 当前行为：`httpClient` 已返回 envelope 的 `data`，页面却要求 `res.data` 存在才赋值。`PageResult` 没有 `data` 字段，因此分类选项和库存预警列表都不会进入成功分支。
- 正确行为：直接使用 `res.list`、`res.total`；失败由 Promise reject 进入 catch。
- 触发方式：进入 `/dashboard/product/stock` 或点击刷新/筛选。
- 业务影响：页面一直显示空库存预警，掩盖真实缺货风险；分类筛选只有“全部”。
- 修复建议：移除 `res.data` 检查并使用明确 `PageResult<ProductCategory/StockAlert>`；补回归测试验证非空响应真正渲染。
- 可能受影响的后端接口或其他页面：`GET /api/products/stockalerts`、`GET /api/product-categories`、库存记录弹窗。

## FE-004 促销写请求缺少必填 productId

- 严重级别：P1
- 性质：已确认缺陷
- 文件和准确行号：`dealer-web/src/pages/dashboard/product/promotion.vue:73-126,183-190,240-270`；`dealer-server/src/main/java/com/autodealer/crm/dto/CreateProductPromotionRequest.java:16-20`；`dealer-server/src/main/java/com/autodealer/crm/dto/UpdateProductPromotionRequest.java:16-20`
- 当前行为：促销表单只有名称、类型、折扣、时间和状态，从未选择或提交产品；后端创建和更新 DTO 均对 `productId` 使用 `@NotNull`。
- 正确行为：表单必须选择有效商品 ID，并在编辑回显及提交时保持该稳定 ID；不能只使用商品展示名。
- 触发方式：新增任意促销，或编辑历史数据中没有被当前表单保留的促销。
- 业务影响：所有新增促销必然校验失败；编辑可能因丢失 productId 失败，促销维护不可用。
- 修复建议：新增商品选择器和专用 `PromotionForm`/请求类型；校验商品、起止时间、折扣范围和状态；编辑前按详情契约回显。
- 可能受影响的后端接口或其他页面：`POST/PUT /api/product-promotions[/{id}]`；交易详情的促销选择。

## FE-014 领域类型不能约束真实 DTO

- 严重级别：P2
- 性质：高风险疑点
- 文件和准确行号：`dealer-web/src/shared/types/common.ts:3-5`；`dealer-web/src/modules/activity/model/activity.types.ts:4-12`；`dealer-web/src/modules/product/model/product.types.ts:4-25`；`dealer-web/src/modules/tran/model/tran.types.ts:4-44`；`dealer-web/src/shared/types/id.ts:1-4`
- 当前行为：多个领域对象继承 `LooseRecord`，表单直接是 `LooseRecord`；ID 普遍为 `number | string`，金额为 JS `number`，枚举为任意 `string`。
- 正确行为：请求 DTO、响应 DTO、表单模型和展示模型应独立、精确建模；Long ID 从网络边界起使用字符串；金额明确使用十进制定点策略；状态使用稳定联合类型/常量。
- 触发方式：后端字段重命名、返回 null、Long 超出 `Number.MAX_SAFE_INTEGER`、新增枚举，或页面提交后端不接受字段时。
- 业务影响：TypeScript 无法发现当前已经出现的 `res.data`、缺 productId、错误字段名等契约漂移；Long ID 和金额存在静默损坏风险。
- 修复建议：逐模块替换 `LooseRecord`，优先交易、支付、发票、商品、库存；在 API 边界做日期/金额/ID 映射和 runtime validation。
- 可能受影响的后端接口或其他页面：全部模块 API；尤其 Long 商品 ID、BigDecimal 金额、LocalDateTime、布尔/状态字段。
- 缺少证据：当前数据库 ID 是否会达到 JS 不安全整数、线上金额精度案例无法从静态代码确认，因此 Long/精度损坏列为高风险而非已发生事故。
