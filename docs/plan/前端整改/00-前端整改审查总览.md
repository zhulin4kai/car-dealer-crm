# dealer-web 前端整改审查总览

## 审查边界

- 本轮仅做静态排查和整改规划，没有修改 `dealer-web` 或 `dealer-server` 业务代码。
- 已读取 `AGENTS.md`、规则总览、前端/API/联调文档、业务方向 Spec，以及前端、后端 Controller、DTO、权限常量和交易状态机实现。
- 已为当前 worktree 建立 codebase-memory-mcp 索引，并核对路由、页面、模块 API、Pinia Store、权限常量与后端 Controller 的 HTTP 调用关系。
- `docs/api.md` 和 `docs/integration.md` 含历史信息，本报告以当前代码为最终证据。
- 未启动服务、未安装依赖、未提交 Git。尝试执行现有 `npm run typecheck` 时，本地缺少 `vue-tsc`，按任务约束没有安装依赖，因此无法提供本轮编译结果。

## 结论

当前前端存在会直接阻断核心业务的 P1 缺陷，不能视为可稳定联调状态。最优先处理的是认证下载、用户写接口、库存页、促销维护、交易结算和发票状态流。未发现有代码证据的 P0 缺陷。

## 问题清单（按严重程度）

| 编号 | 严重级别 | 分类 | 性质 | 摘要 |
|---|---|---|---|---|
| FE-001 | P1 | 前后端契约/安全 | 已确认缺陷 | 客户导出把 JWT 放入 URL，但后端只从 Authorization Header 取 Token，导出必然认证失败并泄露 Token |
| FE-002 | P1 | 前后端契约/表单 | 已确认缺陷 | 用户新增、编辑发送 FormData，后端要求 JSON `@RequestBody`，写接口无法正常绑定 |
| FE-003 | P1 | 列表/请求层 | 已确认缺陷 | 库存预警页把已解包结果当 AxiosResponse，列表和分类选项永远不赋值 |
| FE-004 | P1 | 表单/契约 | 已确认缺陷 | 促销新增、编辑表单没有 `productId`，后端 DTO 强制必填，提交必然失败 |
| FE-005 | P1 | 交易/金额 | 已确认缺陷 | 前端展示并确认促销结算价，但结算请求不提交促销，后端仍按原价结算 |
| FE-006 | P1 | 发票状态流 | 已确认缺陷 | 发票创建后为 PENDING，但前端没有可达的“开具/作废”操作，并允许再次创建后得到 409 |
| FE-007 | P1 | 客户详情 | 已确认缺陷 | 客户姓名按钮绑定不存在的 `view` 方法，且没有客户详情路由，点击无法进入详情 |
| FE-008 | P2 | 时间契约 | 已确认缺陷 | 编辑交易用 `toISOString()` 截日期，在 GMT+8 可把交付日期回退一天 |
| FE-009 | P2 | 权限 | 已确认缺陷 | 系统管理路由只要求 `system:list`，页面挂载后却持续调用要求 `monitor:view` 的接口 |
| FE-010 | P2 | 状态流 | 已确认缺陷 | 审批拒绝后后端支持重新提交，前端没有 API 和操作入口，交易停在 LOST |
| FE-011 | P2 | 分页/筛选 | 已确认缺陷 | 字典搜索不重置页码、不发送分页参数且不更新 total，结果与分页器状态不一致 |
| FE-012 | P2 | 分页 | 已确认缺陷 | 交易页删除当前页最后一条后不校正页码，可能停留在越界空页 |
| FE-013 | P2 | 请求层 | 已确认缺陷 | 并发会话失效会为每个失败请求创建确认框/定时跳转，缺少单飞处理 |
| FE-014 | P2 | 类型/契约 | 高风险疑点 | 大部分领域契约退化为 `LooseRecord`，金额、Long ID、枚举和空值错误无法由 TypeScript 发现 |
| FE-015 | P2 | 系统状态 | 高风险疑点 | 前端使用 `true/false` 字符串，DTO 文档要求 `Y/N`，数据库又存在 `y` 默认值，状态编码不统一 |
| FE-016 | P2 | 异步状态 | 高风险疑点 | 多个列表没有请求序号或取消机制，快速筛选/翻页可能被旧响应覆盖 |
| FE-017 | P3 | 错误反馈 | 体验改进 | 多处 catch 丢弃后端稳定错误码和错误信息，只显示统一“操作失败” |
| FE-018 | P3 | 工程质量 | 体验改进 | 大量 `if (true)`、调试日志、直接页面 HTTP 调用和空壳组件削弱可维护性 |
| FE-019 | P2 | 测试 | 已确认缺陷 | 现有测试没有覆盖权限守卫、表单 DTO、核心状态迁移、分页删除和错误恢复 |

## 已核对但未发现代码证据的问题

- 未发现 `v-html` 或直接写 `innerHTML`，当前没有可确认的 DOM XSS 点。
- 未发现由用户输入驱动的外部重定向；现有 `window.location.href` 均为固定站内地址。
- TokenVerifyFilter 每次请求会重新检查 Redis 会话和数据库账号状态，账号禁用、锁定、过期时后端会 fail closed；问题集中在前端失效交互，而不是后端继续放行。
- 路由守卫对无统计首页权限但有其他菜单权限的用户，会尝试跳到第一条可访问菜单；没有发现固定条件下的 403 导航死循环。
