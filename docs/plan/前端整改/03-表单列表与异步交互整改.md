# 表单、列表与异步交互整改

## FE-007 客户详情入口绑定不存在的方法

- 严重级别：P1
- 性质：已确认缺陷
- 文件和准确行号：`dealer-web/src/pages/dashboard/customer.vue:46-49,74-179`；`dealer-web/src/router/routes.ts:53-58`；`dealer-server/src/main/java/com/autodealer/crm/web/CustomerController.java:53-58`
- 当前行为：客户姓名按钮执行 `view(row.id)`，但 script 中没有定义或导入 `view`；路由表也只有客户列表，没有客户详情路由。后端详情接口已经存在。
- 正确行为：定义客户详情路由和页面，校验路由 ID 后调用 `GET /api/customer/{id}`；或移除不可用入口。
- 触发方式：打开客户列表并点击任一客户姓名。
- 业务影响：点击时报组件属性/函数错误，无法查看客户全生命周期详情。
- 修复建议：补齐 customer detail page、模块 API 和精确响应类型；处理刷新直达、404、403、加载中和失败状态。
- 可能受影响的后端接口或其他页面：`GET /api/customer/{id}`；线索转客户后的跳转、交易客户选择。

## FE-008 编辑交易时交付日期可能回退一天

- 严重级别：P2
- 性质：已确认缺陷
- 文件和准确行号：`dealer-web/src/pages/dashboard/tran/index.vue:511-534`；`dealer-server/src/main/resources/application.yml:33-36`
- 当前行为：后端按 GMT+8 的 `yyyy-MM-dd HH:mm:ss` 返回时间，前端通过 `new Date(...).toISOString().split('T')[0]` 转成 UTC 日期。当地时间凌晨会变成前一天的 UTC 日期。
- 正确行为：日历日期字段应按契约直接截取本地日期部分或使用明确时区的日期库，不经过 UTC 转换。
- 触发方式：交易预计交付时间为 `2026-06-22 00:00:00`，在 Asia/Shanghai 打开编辑表单。
- 业务影响：回显为 `2026-06-21`，保存后会静默把交付日期提前一天。
- 修复建议：建立共享 local-date/local-datetime 解析器；为跨日、夏令时和空值增加回归测试。
- 可能受影响的后端接口或其他页面：`GET/PUT /api/tran/{id|update}`；促销 datetime-local、活动时间也应统一复核。

## FE-011 字典搜索与分页状态脱节

- 严重级别：P2
- 性质：已确认缺陷
- 文件和准确行号：`dealer-web/src/pages/dashboard/dict/type.vue:199-235,331-335`；`dealer-web/src/pages/dashboard/dict/value.vue:259-295,404-408`
- 当前行为：正常加载使用 `{page,size,...searchForm}`，点击搜索却只传 `searchForm`，不把 `currentPage` 置 1，也不更新 `total`。分页器仍显示上一次查询的页数。
- 正确行为：所有查询统一走一个 loader；搜索和重置先回到第一页，并同时更新 list、total、pageSize 和选择状态。
- 触发方式：先翻到后续页，再修改字典筛选条件并点击查询。
- 业务影响：列表内容、页码和总数互相矛盾，用户可能误判数据不存在或遗漏数据。
- 修复建议：删除重复 `handleSearch` 请求逻辑，统一构造 query；服务端响应返回并消费当前页。
- 可能受影响的后端接口或其他页面：`GET /api/dict/types`、`GET /api/dict/values`；其他复制了同类列表逻辑的页面。

## FE-012 交易删除后不校正越界页码

- 严重级别：P2
- 性质：已确认缺陷
- 文件和准确行号：`dealer-web/src/pages/dashboard/tran/index.vue:371-415,599-603`
- 当前行为：单删和批删后原页调用 `fetchData()`，没有在 `total` 减少后检查当前页是否超过最后一页；该页面没有使用会自动校正的 `DataTablePagination`。
- 正确行为：删除成功后，如果当前页已空且页码大于 1，应请求前一页或根据最新 total 归一化页码。
- 触发方式：进入最后一页并删除该页最后一条待报价交易。
- 业务影响：页面停在空白越界页，用户误以为没有其他交易。
- 修复建议：抽取统一分页状态机；服务端响应后计算合法页码，仅在需要时补一次请求。
- 可能受影响的后端接口或其他页面：`DELETE /api/tran/{id}`、`POST /api/tran/batch-delete`；用户页也应复核相同情况。

## FE-016 旧请求可覆盖新筛选结果

- 严重级别：P2
- 性质：高风险疑点
- 文件和准确行号：`dealer-web/src/pages/dashboard/tran/index.vue:334-363,365-369`；`dealer-web/src/pages/dashboard/dict/type.vue:199-235`；`dealer-web/src/pages/dashboard/product/stock.vue:293-323,339-354`
- 当前行为：列表 loader 没有 AbortController、请求序号或最后响应获胜判断；多个请求共享一个 loading 布尔值。
- 正确行为：筛选、翻页和刷新应取消前一个同类请求，或只接受最新请求结果；loading 与最新请求绑定。
- 触发方式：在慢网络下连续点击查询、重置或快速翻页，使后发请求先返回。
- 业务影响：旧条件结果覆盖新条件，页码和列表不一致。
- 修复建议：在共享列表 composable 中实现 requestId/AbortSignal；所有列表统一使用。
- 可能受影响的后端接口或其他页面：所有分页 GET 页面。
- 缺少证据：本轮未启动服务，无法给出特定网络时序的运行录像；竞态由异步赋值结构确定存在，但实际出现频率取决于网络时序。

## Agent 执行说明

### FE-007：补齐客户详情，而不是只补一个同名函数

#### 文件和稳定符号

- `router/routes.ts`：新增 `customer-detail`，建议路径 `customer/:id`，权限 `customer:view`，`activeMenu` 指回客户列表。
- `modules/customer/api/customer-api.ts`：新增 `fetchCustomerDetail(id: EntityId): Promise<CustomerDetail>`。
- `modules/customer/model/customer.types.ts`：区分 `CustomerListItem` 与 `CustomerDetail`，不要继续依赖深层 optional 对象。
- 新页面 `pages/dashboard/customer/[id].vue`：负责参数校验、详情加载和页面状态。
- `customer.vue::handleView(row)`：使用命名路由跳转，不拼字符串并调用不存在的 `view`。

#### 具体函数改法

1. `handleView(row)` 先验证 `row.id` 存在，再 `router.push({ name: 'customer-detail', params: { id: String(row.id) } })`。
2. 详情页用独立解析函数 `parseCustomerId(route.params.id)`。数组、多值、空字符串、非数字和越界值进入参数错误态，不向后端发请求。
3. `loadCustomer(id)` 维护 `loading/customer/errorKind`，分别处理 404/业务不存在、403、session invalid、网络错误。失败时不能渲染一份默认空客户对象。
4. 监听路由 ID 变化时重新加载，并使用 FE-016 的请求取消/序号规则，防止快速导航的旧详情覆盖。
5. 刷新直达必须工作；不能依赖列表页通过内存 state 传整行对象。

#### 隐藏问题

- 只定义 `const view = ...` 而没有详情路由，只是把运行时报错改成导航 404。
- 列表项的 `clueDO` 嵌套结构不等于 `CustomerDetailResponse`。详情页必须以详情接口为事实源。
- 客户列表当前初始化一条空对象，会造成加载前出现伪行和选择问题；本项触达时应改成有类型的空数组。
- 客户详情包含个人信息，错误日志和页面状态不得打印完整响应。

#### 回归断言

- 点击姓名进入命名路由；刷新详情 URL 可恢复数据。
- 非法 ID 不请求接口；不存在、403、网络失败显示不同状态和可行操作。
- 从客户 A 快速切到 B，A 的后返回响应不能覆盖 B。

### FE-008：把日期按业务语义转换，禁止经过 UTC

#### 建议共享函数

在 `shared/datetime/local-date.ts` 建立纯函数：

- `toLocalDateInput(value: LocalDateText | LocalDateTimeText | null): string`
- `fromLocalDateInput(value: string): LocalDateTimeText | null`

当前后端返回 `yyyy-MM-dd HH:mm:ss` 且提交预计交付时间为当天零点时，`toLocalDateInput` 应验证格式后取日期部分，`fromLocalDateInput` 应生成 `${date} 00:00:00`。不要构造 `Date`。

#### 具体函数改法

1. `tran/index.vue::fetchTranDetail(id)` 将 `new Date(...).toISOString().split('T')[0]` 替换为 `toLocalDateInput(data.expectedDate)`。
2. `onSubmit()` 使用 `fromLocalDateInput(values.expectedDeliveryDate)`，并让请求类型明确允许 `null` 还是禁止缺失。
3. 同一轮搜索 `toISOString`、`datetime-local` 和 `new Date(serverString)` 的调用方，逐个分类为日期、无时区本地时间或绝对时间；只修与本项同契约的调用方，不机械替换全部日期。
4. 格式非法时进入可见错误态并阻止提交，不能静默变成空字符串。

#### 隐藏问题

- `new Date('yyyy-MM-dd HH:mm:ss')` 的解析不是可靠跨浏览器协议，Safari 等环境行为可能不同。
- “夏令时测试”对 Asia/Shanghai 本身不产生切换，但共享函数若声称处理任意时区，必须验证 DST 地区；本项目如果只处理本地日历日期，应完全不进入时区模型。
- 后端字段名同时出现 `expectedDate` 和 `expectedDeliveryDate` 是契约漂移，应在 API 适配器统一，页面不应继续 `a || b` 猜字段。

#### 回归断言

- `2026-06-22 00:00:00` 和 `2026-06-22 23:59:59` 均回显 `2026-06-22`。
- null 保持空值，非法格式不提交，保存后仍是同一日。
- 测试固定时区运行，结果不依赖执行机器。

### FE-011：字典搜索只保留一个 loader

#### 目标状态机

```text
handleSearch -> currentPage = 1 -> loadData()
handleReset  -> reset criteria + currentPage = 1 -> loadData()
pageChanged  -> currentPage = page -> loadData()
loadData     -> buildQuery -> request -> commit list/total -> clear selection
```

#### 具体函数改法

1. 删除 `type.vue` 和 `value.vue` 中直接调用 API 的重复 `handleSearch`；它们只修改查询状态并调用 `loadData()`。
2. 新增纯函数 `buildDictTypeQuery()`/`buildDictValueQuery()`，显式返回 `page/size` 与去除空值后的筛选字段。
3. `loadData()` 一次性提交 `tableData/total`，成功后清除跨查询 `selectedIds`。不要原地 `res.list.sort()`，使用 `[...res.list].sort(...)`，避免修改 API 返回对象。
4. 服务端排序应优先于前端局部页排序。若需要 ID 升序，应把 sort 契约放到后端查询；仅对当前页排序会让跨页全局顺序不成立。
5. 搜索失败保留当前查询条件和页码，显示重试入口；不得只 `console.error`。

#### 隐藏问题

- 搜索回第一页后，旧页选择必须清理，否则批量删除可能操作当前页面不可见的数据。
- 字典值页面还会加载类型选项；类型选项失败不应阻止字典值列表加载，两者需要独立 loading/error。
- 如果服务端返回的页码小于请求页码，客户端应采用服务端事实或执行 FE-012 的归一化。

#### 回归断言

- 在第 3 页搜索时，请求 page=1，列表、total、分页器和选择态同步更新。
- 重置使用同一 loader；空字符串不会出现在 query。
- 搜索请求乱序时只提交最新结果。

### FE-012：删除后归一化分页，而不是盲目重载当前页

#### 建议函数

```ts
async function reloadAfterDelete(deletedCount: number): Promise<void>
```

执行规则：先依据已知 `total - deletedCount` 计算候选最后页，把 `currentPage` 限制到 `[1, lastPage]`，再请求一次；服务端结果若仍为空且 `currentPage > 1`（并发删除导致估算过时），向前归一页并最多补请求一次。

#### 具体函数改法

1. `handleDelete()` 成功后 `await reloadAfterDelete(1)`。
2. `handleBatchDelete()` 在清空选择前保存 `deletedCount`，成功后 `await reloadAfterDelete(deletedCount)`。
3. `handleCurrentChange()` 不应拒绝 `total=0` 时的第 1 页；使用共享 `normalizePage(page,total,pageSize)`。
4. 请求失败时保留“删除已成功”的事实，显示“列表刷新失败”，禁止重新弹删除成功/失败的混合文案。

#### 隐藏问题

- 仅在 `tableData.length === 1` 时 `currentPage--` 无法处理批删、并发删除和 pageSize 变化。
- 客户端估算 total 不是最终事实，因此允许一次服务端响应后的补偿请求，但必须设上限，不能递归重试。
- 批删后只有后端确认成功才能按选择数扣 total；部分成功契约必须返回实际删除数，当前后端看起来是整体成功/失败，不能由前端臆测部分成功。

#### 回归断言

- 删除最后页最后一条回到上一页；删除第一页最后一条仍停在第一页。
- 批删跨越页容量后页码合法；并发导致空页时最多补一次请求。
- 删除成功但刷新失败不会诱导重复删除。

### FE-016：实现最后请求获胜，并让 loading 归属于请求版本

#### 推荐 composable 契约

`useLatestRequest<T>()` 或领域列表 composable 至少返回：

- `data/loading/error`
- `run(factory)`：递增 requestId，只有当前 ID 可提交 data/error/loading。
- `cancel()`：使用 AbortController 时取消当前请求。

伪代码语义：

```text
id = ++latestId
loading = true
try result = await factory(signal)
  if id == latestId: commit result
catch error
  if id == latestId and not canceled: commit error
finally
  if id == latestId: loading = false
```

#### 具体函数改法

1. 先在交易、字典、库存三个已确认页面应用，不要立即全仓迁移。
2. 如果选择 AbortController，`httpClient.get` 的 config 已可透传 `signal`；模块 API 查询函数需要接受可选请求配置或专用 options，不能让页面导入 Axios 类型。
3. 搜索、重置、翻页、手动刷新属于同一列表请求通道；分类选项、详情弹窗等独立请求使用不同通道。
4. 组件卸载时取消；取消错误不展示“加载失败”。

#### 隐藏问题

- 只比较响应的筛选条件对象可能因 reactive 对象被后续修改而失效，应使用单调 requestId 或不可变快照。
- 只阻止旧数据赋值但所有请求都在 `finally` 写 `loading=false`，仍会让新请求尚未完成时提前消失 loading。
- Abort 只能减少资源消耗，不能单独保证正确性；响应可能已进入回调，因此仍建议 requestId 守卫。

#### 回归断言

- A 请求先发后回、B 后发先回时最终显示 B，loading 在 B 完成前保持 true。
- 卸载取消不弹错误；真实网络错误只由最新请求展示。
