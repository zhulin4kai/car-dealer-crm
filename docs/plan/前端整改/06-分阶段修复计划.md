# 前端分阶段修复计划

本文件只描述实施顺序和验收条件，不在本轮执行。

## 阶段一：阻断型契约和财务风险

范围：FE-001、FE-002、FE-003、FE-004、FE-005、FE-006、FE-007。

1. 修复客户 Blob 下载和 Header 认证，确认 URL、日志中无 Token。
2. 用户页面接入 typed JSON API，拆分创建/编辑 Schema。
3. 修复库存二次解包判断，并补真实非空列表回归。
4. 为促销补 productId、专用请求类型和基本校验。
5. 暂停或隐藏无后端支持的前端促销结算预览，完成后端权威计价设计后再开放。
6. 完成发票状态页面与重复创建保护。
7. 建立客户详情路由、页面和模块 API。

验收：上述核心入口可完成一次真实成功流程和一次可理解失败流程；金额和认证没有双事实源。

## 阶段二：权限、状态机和分页一致性

范围：FE-008、FE-009、FE-010、FE-011、FE-012、FE-013、FE-015。

1. 统一日期和系统状态编码。
2. 拆分系统配置/监控权限边界，停止无权限轮询和模拟数据冒充。
3. 接入交易重新提交状态流。
4. 统一列表查询、筛选重置、删除后页码归一化。
5. 实现会话失效 single-flight 和完整 Store 清理。

验收：权限矩阵中的每种角色都能进入且只能操作授权能力；交易、发票、支付状态按钮与后端状态机逐项一致；列表不存在越界页。

## 阶段三：类型和请求基础设施

范围：FE-014、FE-016、FE-017、FE-018。

1. 按交易→商品库存→用户→线索客户→字典系统顺序替换 `LooseRecord`。
2. 建立 ID、Money、LocalDate、LocalDateTime 和稳定枚举的边界转换。
3. 抽取 typed list composable，支持取消/最后响应获胜。
4. 统一 ApiError 展示，移除页面直接通用 HTTP、`if (true)` 和调试日志。

验收：业务代码不新增 any/LooseRecord/不安全断言；模块 API 请求与 DTO 一一对应；快速筛选不会被旧响应覆盖。

## 阶段四：回归测试和交付门禁

范围：FE-019 及前三阶段全部回归。

1. 补齐 `05-工程质量与测试补强.md` 中十组关键测试。
2. 执行 typecheck、lint、unit test、build；有条件时对核心跨端流程执行集成测试。
3. 建立路由权限表、前端按钮权限表、后端 `@PreAuthorize` 的一致性检查。
4. 对移动宽度、键盘操作、表单 Label、图标按钮可访问名称做专项验收。

验收：`npm run check` 全部通过；P1/P2 每项均有防回归断言；不存在只断言“组件能渲染”的关键流程测试。

## 实施约束

- 每阶段先固定后端契约，再改前端类型和页面，禁止继续以宽松对象兼容漂移。
- 交易金额、库存、审批、收款、退款不得乐观更新；成功后重新读取服务端事实。
- 每个问题单独提交或按同一业务闭环组成原子提交，避免全仓机械重写混入修复。
- 阶段完成后同步更新 `docs/api.md`、`docs/frontend.md`、`docs/integration.md` 中已经过时的契约说明。

## 阶段门与禁止并行项

### 可以并行

- FW-01 与 FW-03 没有文件重叠时可以并行。
- UI-01、UI-02、UI-03 在共享 ID/列表契约固定后可以并行。
- CT-01 与 SEC-01 可并行，但都依赖统一错误分类，不能各造一套错误工具。

### 不应并行

- FE-005 前端页面与后端计价契约不能分别按猜测实现；先评审同一 API 契约，再跨端联动。
- FE-006 与 FE-010 都修改交易状态入口和 `tran-api.ts`，应串行或由同一任务包协调，避免覆盖类型与导出。
- FE-015 前端 Switch 修复不能先于后端 code 和主 Schema 决策，否则会制造第三套编码。
- FE-014 不应作为一个先行全仓类型重写；类型只随已固定的领域契约逐模块收紧。

### FW-03 列表请求状态机

状态：完成
实现证据：
- 新增 `shared/composables/use-latest-request.ts`：`useLatestRequest<T>()` 返回 `data/loading/error` refs 和 `run(factory)/cancel()` 函数；`run` 递增 `latestId`，只有当前 ID 可提交 data/error/loading；`finally` 检查 `id === latestId` 才设 `loading = false`，防止旧请求提前关闭新请求的 loading；`cancel()` 使用 `AbortController.abort()` 取消当前请求；`onUnmounted` 自动取消；取消不设 error。
