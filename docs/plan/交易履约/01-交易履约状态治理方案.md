# 交易履约状态治理方案

## 关联 Spec

- docs/spec/交易履约/00-业务范围与边界.md
- docs/spec/交易履约/01-流程规则与验收规格.md

## 背景

交易履约用于表达订单成立后到完成之间的推进状态。履约状态可以观察收款、发票、库存和交付进度，但不能替代这些子领域的事实记录。

## 目标

- 交易履约状态由真实业务动作触发。
- 订金、尾款、开票、交付等子状态不直接等同交易完成。
- 取消、关闭和异常处理保留原因和责任人。
- 交易历史记录关键状态变化、责任人和时间。
- 成交统计只统计符合业务完成或确认条件的交易。

## 当前现状

- 后端已有 `TranController`、`TranServiceImpl`、`TTran`、`TTranProduct`、`TTranHistory`、`TranStage`。
- 后端已有交易创建、审批、结算、删除、重提、收款、退款和发票相关方法。
- 前端已有 `dealer-web/src/modules/tran/` 和交易列表、详情、审批、发票页面。
- 当前交易阶段与订单、收款、发票、交付状态仍需进一步拆分清楚。

## 设计方案

### 状态模型

交易履约状态拆为履约主状态和阻塞点。履约主状态覆盖已下单、履约准备中、履约中、异常、已完成、已取消和已关闭；阻塞点覆盖待订金、待锁车、待收款、待金融确认、待开票、待票据交付、待交车、待签收、待资料移交和待异常处理。

状态迁移必须由命名业务动作触发，禁止任意更新阶段。

### 后端方案

- 在 `TranServiceImpl` 中统一交易状态迁移入口。
- 状态更新 SQL 必须包含当前状态和数据权限条件。
- 交易完成必须同时满足订单未取消、车辆已交付或确认交付、应收满足完成条件、票据流程完成或明确不需要、关键资料已移交。
- 取消和关闭必须联动库存释放、退款待处理和商机结果。
- 交易历史通过 `TTranHistory` 或等价结构记录前后状态、操作者和原因。

### 前端方案

- 交易列表展示履约状态、阻塞点、负责人、收款、发票和交付摘要。
- 交易详情分区展示订单事实、商品车辆、收款退款、发票、交付、历史和备注。
- 状态操作必须展示允许动作，不允许前端自由选择任意状态。

### 数据方案

- 履约状态、付款状态、退款状态、发票状态和交付状态分字段或分表表达。
- 历史记录不可物理删除。
- 交易完成统计以履约完成条件为准，已取消交易不计入完成成交数。

## 风险与约束

- 订单成立不代表交易完成。
- 收款、发票或交付任一完成都不能单独把交易置为完成。
- 已完成交易原则上不得普通取消，应走冲正或售后纠错流程。
- 履约异常必须暴露给相关责任角色。

## 实施阶段

1. 梳理 `TranStage`、交易创建、审批、结算、收款、退款、发票和删除逻辑。
2. 定义目标履约状态、允许动作和迁移矩阵。
3. 调整后端状态校验、事务边界和历史记录。
4. 调整前端交易状态展示和操作入口。
5. 与库存、收款退款、发票、交付、商机和报价订单计划对齐。
6. 补充状态迁移、事务回滚、并发冲突和前端测试。

## 验收标准

- 只完成订金收款时，交易不会被标记为已完成。
- 发票完成但车辆未交付时，交易仍处于待交付或交付中。
- 交付完成且应收满足完成条件后，交易可进入已完成。
- 订单取消后库存释放和退款待处理状态可见。
- 已取消交易不计入完成成交数。
- 交易历史能看到状态变化、时间和责任人。

## 核心闭环补充

- 交易完成条件必须同时考虑收款、发票和交付，不由单一收款动作直接完成。
- 每笔订单必须有明确票款策略，不能用系统全局默认流程替代订单自己的业务约定。
- 票款策略决定收款、开票和交付准备的允许推进顺序；履约主状态不得替代票款策略。
- 交易阶段不能替代发票状态、收款状态和交付状态。
- 所有交易状态变化必须写交易历史。
- 交易删除优先改为取消或关闭；已产生历史、支付、发票、审批或商品行的交易不得普通物理删除。

## 业务协同关系

- 依赖订单、库存占用、收款、发票、交付和权限数据范围。
- 影响经营分析、异常提醒、客户历史、库存释放、退款处理和商机结果观察。
- 权限控制覆盖履约查看、取消、关闭、异常处理和完成确认。
- 审计记录覆盖状态推进、取消、关闭、重提、异常处理和完成。
- 统计口径依赖完成交易、取消交易、履约周期和阻塞点。

## 状态与事件方案

- 履约主状态：已下单、履约准备中、履约中、异常、已完成、已取消和已关闭。
- 履约阻塞点：待订金、待锁车、待收款、待金融确认、待开票、待票据交付、待交车、待签收、待资料移交和待异常处理。
- 票款策略：先款后票、先票后款、无需开票和特批并行。
- 触发事件：订单成立、库存占用、收款确认、发票开具、交付完成、退款、发票作废和订单取消。
- 非法迁移：收款、发票或交付任一单独完成都不能直接完成交易。
- 异常策略：暴露阻塞点，取消联动库存释放、退款和票据处理，已完成交易走纠错或售后流程。

## 数据与历史方案

- 必须保留状态历史、阻塞点、取消原因、关闭原因、操作者和时间。
- 已产生商品行、审批、支付、发票、库存流水或历史的交易不得普通物理删除。
- 状态推进、取消、关闭和完成必须审计。
- 完成金额、履约周期、取消原因和阻塞点进入经营分析口径。
