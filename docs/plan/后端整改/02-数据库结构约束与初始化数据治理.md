# 数据库结构约束与初始化数据治理

## 目标

统一生产与测试 Schema、字典和产品状态数据，并用数据库约束保护唯一性、引用完整性、金额和库存。

## 当前问题

位置：

- `dealer-server/src/main/resources/CarDealerCRM.sql`
- `dealer-server/src/main/resources/schema-test.sql`
- `dealer-server/src/main/resources/data.sql`

当前 Schema 基本没有外键；生产初始化产品使用中文状态 `上架`，业务查询使用 `on_sale`；生产与测试的字典 ID、表结构和约束不一致；`t_product.sku/price/status` 等关键字段缺少非空或唯一约束；`t_clue.phone` 没有并发安全的唯一约束；`t_tran_production` 存在于 Schema 但没有实际业务链路。

## 修改方案

### Schema 单一契约

1. 以生产 MariaDB/MySQL 语义为主契约，让 H2 测试 Schema 在字段、非空、唯一和关联关系上等价。
2. 为每张核心表明确主键、业务唯一键、父对象和删除策略。
3. 不直接覆盖已有生产数据；为现有数据库提供可重复执行或有版本号的迁移步骤。

### 外键与删除策略

在清理孤儿数据后，为以下关系补充外键或等价约束：

- 客户到线索
- 交易到客户
- 交易产品到交易和商品
- 审批、发票、支付、交易历史、交易备注到交易
- 库存流水到商品
- 活动备注到活动、线索备注到线索
- 用户角色、角色权限关联表

财务、库存、审批、历史和审计表使用限制删除；普通从属备注是否级联必须逐表明确，禁止默认大范围级联。

### 唯一性与字段约束

- `t_user.login_act/phone/email` 按业务可空规则建立唯一约束。
- `t_clue.phone` 建立唯一或经确认的组合唯一约束。
- `t_product.sku` 唯一，`sku/price/stock/status` 非空，价格和库存不得为负。
- 发票号、支付流水号、分类 code、字典类型 code 建立唯一约束。
- 字典值增加稳定业务 code，建立 `(type_code, value_code)` 唯一约束；数据库主键仍用于关系引用，但业务代码不得硬编码自增 ID。
- 金额、数量和库存字段补充合理默认值与非负约束；H2 不支持的检查约束用等价测试验证。

### 初始化数据

- 产品状态统一使用 `on_sale/off_sale`，中文只用于展示。
- 生产、测试初始化数据使用同一套字典 type code、value code 和状态 code。
- 修正字段注释，明确线索字典字段引用 `t_dic_value.id`，不再标注为 `0/1`。
- 权限初始化数据与当前 Controller 使用的权限码一致，不删除已使用权限。
- `t_tran_production` 若仍无代码 owner 和业务入口，从活动 Schema 移除；历史迁移必须说明已有表如何处理。

### 迁移安全

1. 提供孤儿记录、重复手机号、重复 SKU、非法状态和负数数据检查 SQL。
2. 数据不满足约束时先输出修复清单，不得直接删除历史业务数据。
3. 按“新增列/约束准备、回填、校验、启用约束、清理旧结构”实施。
4. 每一步写明失败后回滚或继续方法。

## 测试

- H2 Schema 可完整初始化，测试数据可插入。
- 重复登录名、手机号、SKU、发票号和支付流水插入失败。
- 不存在父记录的交易、交易产品、支付和库存流水插入失败。
- 负库存、负数量和非法必填空值插入失败。
- 产品种子数据能被 `status='on_sale'` 查询。
- 生产与测试 Schema 的核心表、字段和约束对比测试通过。

## 验收

- 生产与测试 Schema 不再维护相互矛盾的字段和状态数据。
- 核心业务唯一性和引用关系有数据库级保护。
- 初始化数据不再依赖不同环境下漂移的字典 ID。
- 空库初始化脚本必须可重复用于重建开发和测试环境。
