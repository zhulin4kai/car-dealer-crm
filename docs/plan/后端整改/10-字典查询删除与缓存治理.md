# 字典查询、删除与缓存治理

## 目标

统一字典分页、查询语义、稳定 code、删除策略和缓存 Key，禁止为了删除字典而删除业务历史。

## 当前问题

### 分页和查询

`DicQuery` 继承 `BaseQuery.current/pageSize`，自身又定义 `page/size`；Service 使用后者且没有可靠默认值。字典值同时传 typeCode 和 typeValue 时 Mapper 使用 OR，可能返回其他类型的同名值。

### 删除破坏业务数据

删除字典值和批量删除时会先删除交易备注；删除字典类型只检查部分备注引用，没有覆盖线索、客户、用户和交易字段。

### 缓存 Key 不一致

`clearCache(pattern)` 忽略入参，固定删除三组 pattern；调用方却使用 `types`、`values`、`type:code`、`values:type` 等多套 Key。字典修改后可能残留旧缓存或过度清理。

## 修改方案

### Query 和 DTO

1. DicQuery 只保留 `current/pageSize`，删除 `page/size`，分页默认值来自 BaseQuery。
2. 类型列表、值列表和写命令按需拆分 Query/Request，写接口不直接接收持久化 Model。
3. typeCode 与 typeValue 同时存在时使用 AND，表达“指定类型内搜索”；全局搜索如确有需求使用独立方法。
4. 显式声明 equals/hashCode 父类策略，字段类型与 Schema 的 value code 契约一致。

### 稳定 code

1. 字典类型使用稳定 typeCode，字典值使用 02 提供的 valueCode；业务代码禁止硬编码自增 ID。
2. 同类型 valueCode 唯一，展示 value 可修改但 code 变更必须受限并审计。
3. 业务字段仍引用字典主键时，Mapper/Service 通过 code 查询，不假设各环境 ID 相同。

### 删除策略

1. 删除前统一查询全部业务引用；存在任一引用时返回 `DIC_IN_USE`。
2. 禁止调用 `deleteRemarksByDicValueId(s)` 删除交易或其他业务历史。
3. 已使用字典值优先增加禁用状态；禁用后不可用于新数据，但历史数据仍可展示。
4. 批量删除先校验全部值和类型，任一被引用则全部不删除。
5. Mapper 写操作检查精确影响行数，禁止无条件或空集合删除。

### 缓存

1. 使用 03 在 `RedisKeys` 提供的字典 Key 构造方法，DicService 不手工拼接平行格式。
2. `clearCache(pattern)` 要么真实按受控 pattern 清理，要么改成职责明确的 `clearAllDictionaryCache`。
3. 更新类型或值后失效详情、code 查询、类型值列表和分页列表缓存。
4. 数据库事务提交后再失效缓存；缓存失败不重复数据库写入。
5. 移除对 `DealerCRMApplication.cacheMap` 的清理依赖，导入上下文由 07 管理。

### 权限与审计

- 字典列表、创建、编辑、禁用、删除和刷新分别确认权限码；普通业务用户不得访问维护命令。
- 审计类型和值的创建、编辑、禁用和删除，记录 code 和前后状态。

## 测试

- 未传分页参数使用 1/10，不再出现 page/size 两套字段。
- typeCode 与 typeValue 查询只返回指定类型内匹配值。
- 被线索、客户、用户、交易或备注引用的字典值不能删除，业务记录保持不变。
- 批量删除包含被引用值时全部回滚。
- 字典新增/更新/禁用后所有相关缓存正确失效，无残留 Key。
- 前端分页、搜索、禁用状态、权限和错误码测试。

## 验收

- 字典查询契约只有一套分页语义。
- 字典删除永远不会连带删除业务历史。
- 字典业务逻辑依赖稳定 code，不依赖环境自增 ID。
- 缓存 Key 和失效入口唯一且有测试。
