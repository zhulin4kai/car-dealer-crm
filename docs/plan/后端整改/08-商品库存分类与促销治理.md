# 商品、库存、分类与促销治理

## 目标

统一商品状态和类型契约，消除重复入库入口，保护商品引用和库存一致性，并完成商品模块 SQL、权限和性能审计。

## 当前问题

位置：

- `model/TProduct.java`
- `dto/ProductSimpleDTO.java`
- `web/ProductController.java`
- `web/ProductStockController.java`
- `service/impl/ProductServiceImpl.java`
- `mapper/TProductMapper.xml`

当前生产种子状态使用 `上架`，查询使用 `on_sale`；ProductSimpleDTO 把 Long ID 转 Integer、字符串状态转 0/1；产品分页同时使用 PageHelper 和无效 offset/limit 参数；删除不检查交易、线索、客户和库存流水引用；两个 Controller 暴露重复 restock 接口和重复内部 DTO。数量校验已补，但入口和契约仍未统一。

允许修改：

- 商品、库存、分类、促销的直接测试
- `dealer-web/src/modules/product/`、商品页面和对应测试

禁止修改 Schema、公共错误码、交易模块、线索/客户模块和审计基础文件。

## 修改方案

### 类型和状态

1. 商品 ID 在 Model、DTO、Mapper、Controller 和前端统一为同一类型，禁止 Long 到 Integer 截断。
2. 商品状态统一 `on_sale/off_sale`，DTO 和前端直接使用稳定 code，不转换成另一套 0/1。
3. TProduct 字段与 Schema 的 sku、price、stock、status 非空和唯一契约一致。
4. 模型类级和字段注释说明表、字段和非数据库派生字段；统一时间类型转换边界。

### API 与 DTO

1. 创建、更新商品使用独立 Request DTO，不直接接收 TProduct。
2. 只保留 `ProductStockController` 的一个入库命令；删除或兼容迁移 ProductController 重复入口。
3. 抽出 `RestockRequest`，校验 productId、quantity、remark；Controller 内部类全部移除。
4. 库存调整、入库和出库使用不同业务动作与记录类型，禁止负数伪装入库。
5. 分类和促销写接口同样使用 Request DTO 和 Bean Validation。

### 分页与 SQL

1. 产品列表保留 PageHelper 时，Mapper 方法移除 offset/limit 参数；所有列表使用稳定排序。
2. 审查 Product、Category、Promotion、Stock Mapper XML 的动态条件、批量、join、resultMap 和索引需求。
3. 在售商品查询只使用 `on_sale`，商品不存在和非在售使用稳定业务错误。
4. 库存更新使用原子 SQL 并检查影响行数；库存不得变为负数。

### 生命周期

1. 商品被交易产品、线索意向、客户选购或库存流水引用时禁止物理删除。
2. 对已使用商品执行下架，保留历史名称、价格快照和库存流水。
3. 分类被商品引用、促销被有效业务引用时禁止删除或先停用。
4. 批量操作保持全成功，先校验全部对象再写入。

### 权限与审计

- 列表、详情、创建、编辑、下架、入库、库存记录、分类和促销接口建立明确权限矩阵。
- 审计商品创建/编辑/下架、库存变化、分类和促销变化；库存审计记录前后数量和业务原因。

## 测试

- 生产/测试状态数据下，在售查询能返回 on_sale 商品。
- Long ID 全链路不截断，ProductSimpleDTO 不再产生 0/1 状态。
- 只剩一个入库入口；空 ID、零数、负数和不存在商品失败。
- 并发扣减不会出现负库存，库存更新与流水写入同事务回滚。
- 被交易、线索、客户或流水引用的商品不能物理删除。
- PageHelper 不与手写分页混用，列表排序稳定。
- 前端状态映射、表单校验、库存 loading 和重复提交测试。

## 验收

- 商品状态、ID 和价格类型在数据库、后端和前端一致。
- 入库命令和 DTO 只有一套。
- 商品删除不会破坏历史交易和客户/线索关联。
- 商品模块 Mapper、权限、事务和性能问题有完整测试闭环。
