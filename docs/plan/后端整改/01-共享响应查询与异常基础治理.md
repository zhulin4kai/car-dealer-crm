# 共享响应查询与异常基础治理

## 目标

建立唯一响应包装、稳定业务错误码、统一业务异常和可靠分页默认值，为所有后续模块整改提供公共契约。

## 当前问题

### 响应包装重复

位置：

- `dealer-server/src/main/java/com/autodealer/crm/result/R.java`
- `dealer-server/src/main/java/com/autodealer/crm/result/Result.java`

当前业务代码使用 `R`，`Result` 没有生产调用，但两套类型长期并存。新增接口可能选择不同包装，导致字段、默认文案和异常响应漂移。

### 业务异常缺失

位置：

- `dealer-server/src/main/java/com/autodealer/crm/config/handler/GlobalExceptionHandler.java`
- `dealer-server/src/main/java/com/autodealer/crm/result/CodeEnum.java`
- 各 Service 中现存的裸 `RuntimeException`

当前全局处理器把部分 `RuntimeException.message` 直接返回客户端，业务错误与系统异常无法稳定区分，也可能泄露内部信息。

### BaseQuery 默认值失效

位置：`dealer-server/src/main/java/com/autodealer/crm/query/BaseQuery.java`

`@Builder` 会忽略 `current = 1`、`pageSize = 10` 的字段初始化，`BaseQuery.builder().build()` 得到空分页值，编译已经产生 Lombok 警告。

## 文件所有权

允许修改：

- `dealer-server/src/main/java/com/autodealer/crm/result/R.java`
- `dealer-server/src/main/java/com/autodealer/crm/result/Result.java`
- `dealer-server/src/main/java/com/autodealer/crm/result/CodeEnum.java`
- `dealer-server/src/main/java/com/autodealer/crm/query/BaseQuery.java`
- `dealer-server/src/main/java/com/autodealer/crm/config/handler/GlobalExceptionHandler.java`
- 新增 `dealer-server/src/main/java/com/autodealer/crm/exception/`
- 上述类型的直接测试
- `dealer-web/src/shared/api/`
- 前端 shared API 的直接测试

禁止修改任何业务 Controller、Service、Mapper、业务 Query 和数据库 SQL。

## 修改方案

1. 保留 `R<T>` 为唯一响应包装，确认无生产调用后删除 `Result.java`。
2. 明确 `R` 的成功、失败和 data 缺省行为，禁止 HTTP 失败仍返回成功业务 code。
3. 新增 `BusinessException`，至少携带 `CodeEnum` 和可选安全展示文案，保留原始 cause。
4. 全局异常处理器分别处理：
   - `BusinessException`
   - Bean Validation 和绑定异常
   - 请求体解析异常
   - 数据库异常
   - 未预期异常
5. 未预期异常记录完整堆栈，对客户端返回统一系统错误，不返回原始 message。
6. 在 `CodeEnum` 预留后续模块所需稳定错误码，至少覆盖：
   - 资源不存在、资源被引用、重复资源、并发冲突、非法状态
   - 交易产品为空、交易金额不一致
   - 用户唯一性冲突、受保护账号、用户仍被业务引用
   - 线索手机号重复、导入校验失败
   - 商品被引用、库存冲突
   - 客户导出超限、字典被引用、系统配置冲突
7. `BaseQuery` 使用 `@Builder.Default` 或显式构造方式保证默认分页值；保留 `dataScopeUserId` 的服务端专用语义。
8. 前端 `ApiError`、错误码类型和 http-client 与后端 envelope 对齐；未知错误码统一兜底，不按中文 message 分支。

## 兼容要求

- 不改变现有成功响应字段名和登录接口 Token 所在位置。
- 已完成的 401/403 认证授权状态码不得退回 HTTP 200。
- 后续模块只使用 `BusinessException + CodeEnum`，不得重新添加另一套业务异常或响应类。

## 测试

- `R` 成功、失败、含 data、无 data 的序列化测试。
- `BusinessException` 到 HTTP 状态、code、msg、data 的映射测试。
- 参数校验、JSON 解析、数据库异常和未知异常的 MockMvc 测试。
- 未知异常响应不包含异常类名、SQL、堆栈和内部 message。
- `BaseQuery.builder().build()` 返回 `current=1`、`pageSize=10`。
- 前端 http-client 对成功、业务失败、401、403、未知 code 的测试。

## 验收

- 生产代码只剩一套响应包装。
- 全局异常处理不再直接返回裸 RuntimeException message。
- `CodeEnum` 能支持后续模块稳定分支，既有 code 语义未改变。
- Maven 编译不再出现 BaseQuery Builder 默认值警告。
- 定向后端测试和前端 shared API 测试全部通过。
