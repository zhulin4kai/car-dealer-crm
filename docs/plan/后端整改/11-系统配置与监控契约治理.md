# 系统配置与监控契约治理

## 目标

为系统配置建立明确读写 DTO、状态命令、权限和审计边界，清理未接入 Query，并限制系统监控敏感信息。

## 当前问题

位置：

- `query/SystemQuery.java`
- `web/SystemController.java`
- `service/impl/SystemServiceImpl.java`
- `model/TSystem.java`
- 系统监控 Controller/Service

`SystemQuery` 没有调用方，实际创建、更新和状态切换直接接收 TSystem，数据库字段会隐式成为 API。SystemService 中还有已禁用缓存清理残留。系统监控属于敏感读接口，需要明确权限、返回字段和调用成本。

## 文件所有权

允许修改：

- System、SystemMonitor 相关 Controller、Service、Model、DTO、Query、Mapper 和 XML
- 系统配置和监控的直接测试
- `dealer-web/src/modules/system/`、系统页面和对应测试

禁止修改 application 配置、SecurityConfig、Redis 基础类、Schema、公共错误码和审计基础文件。

## 修改方案

### 请求与响应契约

1. 删除未使用 `SystemQuery`，或将其替换为职责明确的只读 `SystemListQuery`；不得继续作为写命令候选。
2. 新增 `CreateSystemRequest`、`UpdateSystemRequest`、`ToggleSystemStatusRequest` 和 SystemResponse。
3. Request 只暴露允许管理员修改的名称、站点、联系方式和展示配置；ID、审计字段、版本等服务端字段不可写。
4. 状态开关使用独立命令，校验当前状态并检查影响行数。
5. Controller 使用 `@Valid`，不再直接接收 TSystem。

### 业务与事务

1. 明确系统配置是单记录还是多站点；按当前业务选择唯一约束和更新方式，不允许多个“当前配置”。
2. 创建、更新、状态切换使用事务并记录当前操作者。
3. 清理空的 clearCache 和注释旧代码；如当前无系统缓存，不保留伪缓存接口。
4. Mapper 更新包含 ID/版本或当前状态条件，`0` 行返回不存在或冲突错误。

### 系统监控

1. 系统监控接口必须具有独立敏感读权限，不因登录即可访问。
2. Response 使用字段白名单，不返回环境变量、文件路径、数据库凭据、线程堆栈和内部网络信息。
3. OSHI 等系统采集不得在请求中执行无界或长耗时操作；设置采集周期或短 TTL 缓存时使用 03 的稳定缓存能力。
4. 监控失败返回安全错误，不向客户端透出底层异常。

### 权限与审计

- 系统配置列表、详情、创建、更新、状态切换和监控分别建立权限结论。
- 审计配置创建、更新和状态切换，记录字段白名单摘要；系统监控读取只记录必要访问事件。

### 工程规范

- 统一 TSystem 和其他 Model 的 ID、时间、类级/字段注释风格，不进行跨模块批量格式化。
- SystemService public 方法补充前置条件、事务副作用和异常 JavaDoc。

## 测试

- 外部请求不能提交 createBy/editBy/version 等服务端字段。
- 状态切换非法旧状态和并发影响行数为 0 时返回冲突。
- 无权限访问系统配置和监控返回 403。
- 监控响应不包含敏感配置、绝对路径和内部异常。
- 创建/更新失败时配置和审计同时回滚。
- 前端配置表单、状态切换、监控 loading/失败和权限展示测试。

## 验收

- SystemQuery 不再是无调用的伪契约。
- 系统配置接口不直接接收或返回持久化 Model。
- 系统监控具有独立权限、字段白名单和性能边界。
- 系统配置变化可审计且没有无效缓存残留。
