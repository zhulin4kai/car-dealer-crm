# 后端整改任务总览

## 目标

将仍未修复的后端审查问题拆成可由多个子 Agent 执行的独立 Plan。每个生产文件只归属一个任务；跨任务只能读取其他任务文件，不得同时修改。

## 执行顺序

第一批必须先完成：

1. `01-共享响应查询与异常基础治理.md`
2. `02-数据库结构约束与初始化数据治理.md`
3. `03-认证配置Redis与依赖治理.md`
4. `04-操作审计基础链路.md`

第二批在第一批完成后并行执行：

5. `05-交易支付发票与统计治理.md`
6. `06-用户账号角色与权限治理.md`
7. `07-活动线索备注与Excel导入治理.md`
8. `08-商品库存分类与促销治理.md`
9. `09-客户转换查询与导出治理.md`
10. `10-字典查询删除与缓存治理.md`
11. `11-系统配置与监控契约治理.md`（已废止，系统管理/监控已下线）

## 共享文件规则

- 第二批 Agent 禁止修改 01 至 04 的独占文件。
- 业务错误码由 01 统一预留；模块 Agent 发现缺码时报告，不直接修改 `CodeEnum`。
- 数据库约束和初始化数据由 02 统一修改；模块 Agent 只修改自身 Mapper XML 和业务代码。
- RedisTemplate、RedisManager、JWT 和认证链由 03 统一修改；模块 Agent 只调用稳定接口。
- 审计基础类型由 04 提供；模块 Agent 在自己拥有的 Service 中调用 Recorder，不修改审计基础文件。
- 新测试文件按被测模块归属；共享测试基类和跨层一致性测试禁止并行 Agent 修改，由主 Agent 在全部计划合并后统一维护。

## 每个 Agent 的交付要求

1. 开始前读取 `AGENTS.md`、相关规则、本总览和自己的 Plan。
2. 检查工作区，不覆盖其他 Agent 修改。
3. 只修改所有权范围内文件；发现跨范围依赖时停止该部分并报告。
4. 不降低权限、校验、事务、断言或错误语义换取测试通过。
5. 完成 Plan 中全部定向测试，并报告命令、结果和未执行验证。
6. 在自己拥有的文件中同步修复模型注释、Query Lombok 策略、Service JavaDoc、Controller DTO 和明显格式问题。
7. 输出修改文件清单、行为变化、兼容影响和遗留事项。

## 总体验收

- 所有生产文件只出现在一个 Plan 的所有权范围内。
- 原审查中已完成问题未被重复实现或退化。
- 每个未完成问题均被某个 Plan 覆盖，或明确说明因何不再成立。
- 后端完整测试、前端完整检查和关键运行时流程在各模块完成后统一执行。
