# 商机阶段与机会管理落地方案

## 关联 Spec

- docs/spec/商机管理/00-业务范围与边界.md
- docs/spec/商机管理/01-流程规则与验收规格.md

## 背景

商机用于表达销售机会推进过程，不应被订单、收款、发票或交付状态替代。客户可以存在多个商机，商机赢单后进入报价订单和交易履约流程，但商机本身保留赢单事实。

## 目标

- 建立独立商机对象和商机阶段。
- 商机阶段只表达销售推进，不混入收款、发票、交付状态。
- 商机与客户、线索、报价、订单、试驾和跟进任务建立清晰关系。
- 赢单、输单、搁置和恢复都有原因、责任人和时间。
- 长期停滞商机可被主管识别。

## 当前现状

- 当前没有独立 `OpportunityController`、`OpportunityService`、`TOpportunity` 和前端 `modules/opportunity`。
- 当前交易相关能力集中在 `TranController`、`TranServiceImpl`、`TTran` 和 `TranStage`。
- 当前线索可转客户，但缺少转商机的正式落点。
- 前端当前没有商机列表、详情、阶段看板和表单页面。

## 设计方案

### 状态模型

商机阶段建议覆盖：

- 初步接触。
- 需求确认。
- 车型匹配。
- 试驾邀约。
- 报价协商。
- 客户确认。
- 赢单。
- 输单。
- 暂停或搁置。

阶段迁移必须校验当前阶段、负责人、客户关系、必要业务事实和原因。

### 后端方案

- 新增商机领域模型、Mapper、Service、Controller 和 DTO。
- 商机创建可来自线索转化、客户新增需求或人工创建。
- 商机推进必须由命名业务动作完成，禁止通用更新阶段接口任意赋值。
- 赢单必须关联被客户确认的报价或订单成立事实。
- 输单必须记录原因，不能直接删除商机。

### 前端方案

- 新增商机列表、详情、创建编辑表单和阶段推进入口。
- 列表支持负责人、客户、阶段、来源、预计成交时间和停滞状态筛选。
- 详情展示客户、线索来源、跟进任务、试驾、报价、订单和阶段历史。
- 阶段推进需要原因或下一步计划。

### 数据方案

- 新增商机表、阶段历史表和必要关联字段。
- 商机编号或业务编码不得复用自增主键语义。
- 阶段历史记录操作者、前后阶段、原因和时间。

## 风险与约束

- 不能把交易 `TranStage` 直接改名成商机阶段。
- 收款、发票、交付变化不能反向覆盖商机阶段。
- 赢单商机不能直接代表交易完成。
- 已有关联报价、订单或交易的商机不得普通删除。

## 实施阶段

1. 梳理当前 `TranStage` 与销售推进概念的耦合点。
2. 新增商机数据结构、状态枚举和阶段历史。
3. 实现商机创建、推进、输赢单、搁置和恢复。
4. 接上线索转商机、客户详情关联商机。
5. 新增前端商机列表、详情和表单。
6. 补充权限、审计、测试和 API 文档。

## 验收标准

- 线索转商机后不会直接产生订单、收款或发票。
- 商机赢单后可进入报价订单流程，但交易不会自动完成。
- 收款变化不会覆盖商机阶段。
- 长期停滞商机可被主管识别。
- 已关联订单的商机不能普通删除。

## 业务协同关系

- 依赖客户、线索转化、跟进结果、试驾结果和车辆商品。
- 影响报价、试驾、跟进任务、订单成立、销售漏斗和预测金额。
- 权限控制覆盖商机查看、创建、阶段推进、转派、赢单、输单和导出。
- 审计记录覆盖阶段推进、负责人变更、赢单、输单和关闭。
- 统计口径依赖阶段停留、转化率、赢单率、输单原因和预计金额。

## 状态与事件方案

- 状态列表：初步意向、需求确认、车型匹配、试驾邀约、报价中、协商中、待审批、赢单、输单、搁置和关闭。
- 触发事件：商机创建、跟进完成、试驾完成、报价提交、审批通过、客户确认订单、输单和搁置。
- 非法迁移：商机阶段不得被收款、发票或交付反向覆盖；赢单必须依据订单成立。
- 异常策略：长期无跟进进入停滞提醒，输单必须记录原因，搁置可恢复。

## 数据与历史方案

- 必须保留阶段历史、预计金额、负责人、意向车型、赢单/输单原因和关闭原因。
- 已有关联报价、试驾或订单的商机不能物理删除。
- 阶段推进、赢单、输单、搁置和关闭必须审计。
- 阶段停留、漏斗金额、赢单率和输单原因进入经营分析口径。
