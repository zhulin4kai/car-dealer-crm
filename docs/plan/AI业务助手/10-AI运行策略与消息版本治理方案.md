# AI 运行策略与消息版本治理方案

## 关联 Spec

- docs/spec/AI业务助手/00-业务范围与边界.md

## 背景

现有管理入口只维护模型供应商参数，无法真实约束工具、安全、联网、上下文和运行时限。Conversation 已能持久保存，但用户消息没有编辑和撤回能力；SSE 订阅同时承担 Run 启动，断线重连存在重复调用模型和工具的风险。

## 目标

- Provider 配置和全局 AI 运行策略分层管理。
- 管理员策略真实约束模型可见工具、低风险提议、安全等级、联网边界、上下文窗口和运行时限。
- 用户消息以不可变修订链支持编辑和撤回，活动上下文与审计历史分离。
- 同一 Run 只执行一次，SSE 支持事件持久化、序号去重和断线重放。
- 普通用户继续在自己的业务权限和数据范围内使用 AI。

## 运行策略

- `enabledTools`：工具总开关。
- `allowedToolNames`：ToolRegistry 白名单内允许下发的工具。
- `proposalsEnabled`：是否允许生成低风险 Proposal。
- `maxToolCallsPerRun`：单次 Run 最大工具调用数。
- `safetyMode`：`STRICT` 或 `STANDARD`；`STRICT` 只允许只读工具。
- `networkMode`：`DISABLED` 或 `PROVIDER_ONLY`；禁止任意 URL 和通用 HTTP。
- `contextMessageLimit`：1 到 8 条活动消息。
- `summaryMaxChars`：脱敏会话摘要长度上限。
- `maxRunSeconds`：单次 Run 运行时限。
- `version`：管理员并发编辑的乐观锁版本。

有效工具集合固定为：管理员允许集合、ToolRegistry 白名单和 Run owner 当前权限的交集。Spring Boot 下发 Schema 前过滤，内部 Tool API 执行时重新校验。

## 消息版本与活动分支

- Message 保存稳定消息编号、状态、修订号、被替代消息、是否进入上下文和并发版本。
- Run 保存当前上下文是否有效和失效原因。
- 编辑用户消息时，原轮次及后续活动轮次退出当前上下文，新 Run 的父节点指向被编辑轮次之前的活动 Run。
- 撤回消息时，相关轮次退出活动上下文，旧内容不再进入 `messageHistory` 和 Conversation 摘要。
- 已执行 Proposal、业务写入和审计不因上下文修改而回滚。
- Assistant 消息不允许人为覆盖；需要不同回答时创建重新生成 Run。

## SSE 单次执行与恢复

- Run 使用条件更新从 `CREATED` 原子进入 `RUNNING`，只有成功占有者启动 `dealer-ai`。
- AI 事件按 Run、事件编号和序号持久化；事件 payload 必须先脱敏。
- 新订阅者先重放 `afterSequence` 之后的持久化事件，再观察实时流。
- 反向代理关闭 SSE 缓冲，Spring Boot 和 `dealer-ai` 设置 `no-cache` 与 `X-Accel-Buffering: no`。
- Provider 失败、取消和超时必须以稳定终态事件驱动 Run 状态，不能用连接正常结束推断成功。

## 验收标准

- 管理员关闭工具、Proposal 或外部 Provider 访问后，运行时实际拒绝对应能力。
- 普通用户只向模型暴露自己有权执行的工具，工具结果继续遵守数据范围。
- 编辑或撤回消息后，旧分支可审计但不进入模型历史和会话摘要。
- 同一 Run 多次订阅只执行一次；断线续传不重复 ToolCall、Proposal 或助手消息。
- SSE 在 LF、CRLF、UTF-8 跨块和反向代理路径下逐增量展示。
