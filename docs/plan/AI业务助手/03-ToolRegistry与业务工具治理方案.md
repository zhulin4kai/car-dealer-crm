# ToolRegistry 与业务工具治理方案

## 关联 Spec

- docs/spec/AI业务助手/00-业务范围与边界.md

## 背景

AI 工具允许模型间接访问 CRM 数据，但业务权限、数据范围和工具白名单必须由 Spring Boot 控制。`dealer-ai` 的工具 Schema 只帮助模型选择工具，不是最终安全边界。

## 目标

- Spring Boot ToolRegistry 是最终工具白名单。
- 工具必须声明名称、描述、权限码、风险等级、确认要求、输入 Schema、输出 Schema、超时、最大返回量和审计动作。
- 工具执行必须恢复 run owner 的权限和数据范围。
- `dealer-ai` 只能调用内部 Tool API，不调用普通业务 API。

## 工具分类

- 只读工具：查询客户、跟进、库存、交易、商品、审批待办等摘要。
- 低风险提议工具：创建沟通记录 Proposal、创建跟进任务 Proposal。
- 禁止工具：交易审批、收款确认、退款执行、票据处理、库存出库、删除、合并、批量操作。

## 输入输出边界

- 输入不得包含 `userId`、角色、权限、数据范围、审计操作者。
- 输出不得返回数据库实体。
- 输出必须脱敏、限量、结构化。
- 工具结果必须能被前端结构化展示。

## 审计与追踪

- 每次工具调用写入 ToolCall trace。
- 低风险提议写入 Proposal trace。
- 工具失败写入稳定错误码和脱敏错误摘要。
- 需要业务写入的确认执行继续写现有操作审计。

## 验收标准

- 未授权工具调用被拒绝。
- 工具参数出现可信上下文字段时被拒绝。
- 危险工具不存在可执行入口。
- ToolCall trace 可恢复。
- 前端刷新后能展示工具结果。
