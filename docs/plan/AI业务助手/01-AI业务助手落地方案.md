## 背景

当前 CRM 已形成较完整的汽车经销商业务链路，包含线索、客户、商机、跟进、试驾、报价、交易、收款、退款、发票、库存、交付、用户权限、数据字典、审计日志和经营统计。

AI 能力应作为旁路增强入口接入现有系统，不改变普通业务页面到普通业务 API 的调用方式。Agent 只做工具选择和编排，业务系统仍负责权限、数据范围、事务、状态机、审计和数据库写入。

## 目标

- 新增受控 AI 入口，支持业务用户用自然语言查询当前 CRM 数据。
- 新增独立 Agent 服务边界，避免把模型调用、工具选择和业务 Controller 混在一起。
- 新增 AI Tool API，统一承载 Agent 对业务能力的受控调用。
- 首批只开放只读工具和低风险 Proposal。
- 高风险业务动作只能形成待确认 Proposal，不允许 Agent 直接执行。
- 所有 AI 工具调用均可追溯、可审计、可限流、可拒绝。

- 后端已有客户、线索、商机、跟进任务、沟通记录、商品、库存车辆、交易、发票、收款、退款、交付等 Service、Controller、Mapper 和数据库表。
- 前端已有 `shared/api/http-client.ts`、`stores/permission.store.ts`、`v-has-permission`、模块化 API 和受保护路由。
- `docs/api/openapi.yaml` 已记录普通业务 API 契约。

待确认现状：

- `dealer-ai` 服务目录和运行方式。
- AI 模型供应商、模型名称、流式协议和调用网关。
- Spring Boot 到 Agent 服务的网络边界、认证方式和部署拓扑。

## 目标方案

### 架构边界

```text
dealer-web
  普通页面 -> 普通业务 API
  AI 入口 -> /api/ai/*

dealer-server
  普通 Controller / Service / Mapper 保持
  新增 ai 模块
  /api/ai/* 面向前端 AI 入口
  /api/ai-tools/* 面向 Agent 服务

dealer-ai
  独立 Agent 服务
  模型调用、工具选择、对话状态、计划编排
  只能调用 /api/ai-tools/*
```

### 普通接口与 AI Tool 的关系

- 普通接口继续服务页面和模块 API。
- AI Tool API 不直接等同于普通接口转发。
- AI Tool API 应是围绕业务用例设计的受控工具入口，内部复用现有 Service。
- 工具输入只接收业务参数，不接收当前用户、角色、权限、数据范围或审计字段。
- 工具输出使用 AI 专用 DTO，默认脱敏和限量。

### 权限和审计

- 只读工具必须映射现有查看类权限码。
- 写工具必须映射现有创建、编辑或命令类权限码。
- 高风险写工具必须映射独立风险等级和审批确认流程。
- 工具调用记录写入 AI 可观测事件。
- 真正改变业务事实的写操作继续写入 `t_operation_log` 或等价操作审计。

## 阶段 0：项目现状对齐

### 工作内容

- 梳理现有业务模块和普通 API：客户、线索、商机、跟进、沟通记录、车辆商品、库存、交易、发票、收款、退款、审批、交付、审计和统计。
- 梳理现有权限码：以 `PermissionCodes`、`dealer-web/src/shared/constants/permissions.ts`、`t_permission` 初始化数据为准。
- 梳理现有审计能力：以 `AuditActionEnum`、`OperationAuditRecorder`、`t_operation_log`、`t_login_log` 为准。
- 梳理普通接口与 AI Tool 的对应关系：只确认内部 Service 复用关系，不把普通 API 直接暴露给 Agent。
- 确定 AI 文档目录和命名规范：使用 `docs/spec/AI业务助手`、`docs/plan/AI业务助手`、`docs/task/AI业务助手`。
- 确认 AI 数据结构是否进入 `CarDealerCRM.sql` 和 `schema-test.sql`。

### 验收标准

- 形成 AI 工具候选清单，逐项标注当前 Controller、Service、权限码、表结构和风险等级。
- 明确哪些候选工具可直接设计，哪些需要前置任务。
- 明确 `/api/ai/*` 和 `/api/ai-tools/*` 不在当前 OpenAPI 中，需要后续 API 契约任务补齐。
- 明确没有修改普通业务链路。

## 阶段 1：只读 AI Copilot

### 目标

- 实现 AI 聊天入口。
- 实现 Spring Boot 与 Agent 服务的调用边界。
- 实现只读工具注册和执行。
- 前端展示结构化结果、对象引用和后续操作入口。

### 首批只读工具

| 工具名 | 业务含义 | 当前项目依据 | 权限码 | 结果要求 | 状态 |
| --- | --- | --- | --- | --- | --- |
| `list_my_followups` | 查询当前用户今日、逾期或即将到期跟进任务 | `FollowTaskController`、`FollowTaskService`、`t_follow_task` | `follow-task:list` | 分页、限量、隐藏过长沟通内容 | 可设计 |
| `search_customers` | 按姓名、手机号摘要、关键词搜索客户 | `CustomerController.list`、`CustomerService`、`t_customer` | `customer:list` | 默认脱敏联系方式 | 可设计 |
| `get_customer_profile` | 获取客户摘要、负责人、状态、最近跟进和关联业务摘要 | `CustomerController.detail`、`CustomerDetailResponse`、`t_customer` | `customer:view` | 默认脱敏，敏感字段按权限控制 | 可设计 |
| `resolve_vehicle_product` | 解析车型、SKU、商品名或车架号关联的车辆商品 | `ProductController`、`ProductStockController`、`t_product`、`t_product_vehicle` | `product:view` | 返回商品和车辆实例摘要 | 可设计 |
| `get_inventory_alerts` | 查询库存预警和低库存商品 | `/api/products/stockalerts`、`t_product.stock`、`t_product.min_stock` | 待确认 | 返回分页预警列表 | 权限口径待确认 |
| `get_transaction_detail` | 查询交易摘要、阶段、产品、发票、收款退款摘要 | `TranController.detail`、`TranService`、`t_tran`、`t_tran_product` | `tran:view` | 财务和票据字段按权限脱敏 | 可设计 |
| `list_pending_transaction_approvals` | 查询待审批交易 | `t_tran.stage`、`TranController.list`、`tran:approve` | 待确认 | 返回可审批摘要，不执行审批 | 查询口径待确认 |
| `get_vehicle_sales_summary` | 查询车辆维度销售概况 | 当前只有统计概览、漏斗、来源接口；车辆维度销售汇总未确认 | 待确认 | 返回聚合指标和明细入口 | 需要前置任务 |

### 前端展示

- 聊天内容与工具结果分离展示。
- 工具结果用表格、摘要块、对象引用和状态徽标展示。
- 对象跳转使用现有路由，例如客户详情、交易详情、库存页面、跟进页面。
- 前端不展示内部工具 JSON 原文给业务用户。

### 验收标准

- 用户能在 AI 入口提问并获取只读结构化结果。
- 每个工具调用都校验用户登录态、权限和数据范围。
- 普通用户无法通过 AI 查询其他负责人不可见的客户、交易或跟进。
- 客户联系方式、票据、支付和沟通内容默认脱敏。
- Agent 不能执行写操作。

## 阶段 2：低风险写操作

### 目标

- 支持创建沟通记录。
- 支持创建跟进任务。
- 支持修改下次跟进时间。
- 支持创建交易草稿或交易创建 Proposal。
- 所有写操作必须经过 Proposal 和用户确认。

### 工具拆分

| 工具名 | 业务动作 | 当前依据 | 风险等级 | 状态 |
| --- | --- | --- | --- | --- |
| `create_communication_record_proposal` | 新增沟通记录 | `CommunicationRecordService.createCommunicationRecord`、`t_communication_record` | `R1_LOW_RISK_WRITE` | 可设计 |
| `create_follow_task_proposal` | 新建跟进任务 | `FollowTaskService.createFollowTask`、`t_follow_task` | `R1_LOW_RISK_WRITE` | 可设计 |
| `update_next_contact_time_proposal` | 更新线索、客户或商机下一步跟进时间 | `t_clue.next_contact_time`、`t_customer.next_contact_time`、`t_opportunity.next_action_time` | `R1_LOW_RISK_WRITE` | 专用接口待确认 |
| `create_transaction_draft_proposal` | 创建交易草稿或交易创建提议 | `CreateTranRequest`、`TranController.create`、`t_tran` | 待确认 | 草稿状态待确认 |

### Proposal 规则

- Agent 只生成候选动作。
- Spring Boot 校验并规范化参数后保存 Proposal。
- Proposal 必须包含参数哈希和过期时间。
- 前端展示确认卡片。
- 用户确认后，Spring Boot 执行已保存参数。
- 执行前再次校验权限、数据范围和业务状态。

### 验收标准

- 未确认 Proposal 不产生业务写入。
- 用户确认后执行的参数与 Proposal 保存参数一致。
- Proposal 过期、权限变化、数据范围变化或业务状态变化时拒绝执行。
- 写操作成功后可在普通业务页面看到结果。
- 写操作成功后有 AI 执行事件和必要操作审计。

## 阶段 3：可控 Agent 工作流

### 目标

- 支持多步骤计划。
- 支持状态持久化。
- 支持暂停与恢复。
- 支持人工确认。
- 支持执行校验。
- 支持错误处理。
- 支持幂等与重试。

### 工作流范围

优先选择低风险、可回滚或可拒绝的销售辅助流程：

- 客户跟进摘要 -> 生成沟通记录 Proposal -> 生成下一次跟进任务 Proposal。
- 今日待办查询 -> 批量识别逾期 -> 为单个客户生成后续行动 Proposal。
- 交易详情查询 -> 识别缺少发票、收款或交付节点 -> 只生成提醒或待办 Proposal。

高风险流程只允许计划和提醒，不允许直接执行：

- 交易审批。
- 交易结算。
- 收款确认。
- 退款审批或执行。
- 发票开具、作废、红冲、重开。
- 库存占用、释放、出库。
- 客户合并或删除。

### 验收标准

- Agent 每一步有状态记录和事件记录。
- 用户可看到当前计划、已执行步骤、待确认步骤和失败步骤。
- 人工确认前不执行写操作。
- 重试不会重复创建沟通记录、跟进任务或交易草稿。
- 业务执行仍由 Spring Boot Service 完成。

## 阶段 4：主动式 AI 能力

### 目标

- 跟进提醒。
- 库存预警。
- 异常交易提醒。
- 每日摘要。
- 周期性销售分析。

### 能力边界

- 主动式能力只能在用户订阅、角色权限、数据范围和频率控制范围内触发。
- 主动式能力只能生成提醒、摘要、待办或 Proposal。
- 主动式能力不得越权读取跨负责人、跨角色或跨数据范围的数据。
- 主动式能力不得直接审批、收款、退款、开票、删除、结算或出库。
- 周期性任务需要记录触发时间、用户、数据范围、结果数量和失败原因。

### 验收标准

- 用户可订阅和取消订阅主动提醒。
- 系统限制提醒频率和单次结果数量。
- 无权限或数据范围不足时不生成对应提醒。
- 主动提醒产生 AI 事件，可追溯触发原因和数据来源。
- 主动提醒不会修改业务状态。

## 风险与约束

- Prompt 注入可能来自客户备注、沟通记录、活动备注和导入内容，工具结果必须视为不可信文本。
- AI 工具返回过多数据会造成敏感信息扩散，必须分页、限量和脱敏。
- 委托令牌一旦泄漏会扩大工具调用风险，必须短期、限工具、限 Run、不可给浏览器。
- AI Proposal 过期后不能执行。
- 高风险写操作不能为了演示便利而降低确认和审计要求。
- 模型供应商响应不可作为业务真源。

## 文档和契约同步

后续实现阶段必须同步：

- `docs/api/openapi.yaml`：新增 `/api/ai/*` 和 `/api/ai-tools/*` 契约。
- `docs/api/api-conventions.md`：如新增流式事件、委托令牌或 AI 错误码统一规则。
- `docs/backend.md`：新增 AI 模块、Agent 边界、工具注册和可观测性说明。
- `docs/frontend.md`：新增 `modules/ai`、AI 页面/组件、结构化结果展示说明。
- `docs/integration.md`：新增 dealer-web、dealer-server、dealer-ai 的联调方式。
- `CarDealerCRM.sql` 和 `schema-test.sql`：如新增 AI Run、Message、Tool Call、Proposal、Approval、Event 表。

## 总体验收标准

- 普通业务链路不变。
- AI 链路只走 `/api/ai/*` 和 `/api/ai-tools/*`。
- Agent 不直连数据库。
- Agent 不直接调用 Mapper。
- Agent 不绕过权限、数据范围、事务、状态机和审计。
- 只读工具默认脱敏、分页和限量。
- 写操作全部通过 Proposal 和确认。
- 高风险动作没有 Agent 直接执行入口。
- AI 全链路可追溯到用户、Run、消息、工具、Proposal、确认和业务审计。
