# 模型供应商配置与密钥治理方案

## 关联 Spec

- docs/spec/AI业务助手/00-业务范围与边界.md

## 背景

当前 `dealer-ai` 通过本地 env 读取 Provider Base URL、API Key 和模型名。这个方式适合开发调试，但不满足系统后台可配置 AI 的产品要求，也无法支撑管理员切换模型、轮换密钥、测试连接和审计。

## 目标

- 管理员维护多个全局 Provider 配置。
- 同一时间只有一个启用配置。
- 支持 `OPENAI_COMPATIBLE` 和 `ANTHROPIC`。
- API Key 加密入库，响应只返回掩码。
- Spring Boot 每次调用 `dealer-ai` 时下发运行时配置。
- `dealer-ai` 不持久化密钥，不访问数据库。

## 配置模型

配置应覆盖：

- 配置编号。
- 配置名称。
- Provider 名称。
- 协议格式：`OPENAI_COMPATIBLE`、`ANTHROPIC`。
- Base URL。
- 模型名称。
- 模型显示名。
- API Key 密文。
- API Key 掩码。
- 超时时间。
- 最大输出 token。
- temperature。
- 启用状态：`DRAFT`、`ACTIVE`、`DISABLED`。
- 测试状态：`UNTESTED`、`SUCCESS`、`FAILED`。
- 最后测试时间和测试错误摘要。
- 创建人、更新人、创建时间、更新时间。

## 密钥方案

- API Key 明文只允许出现在新增、轮换和测试连接的请求体内。
- 后端接收后立即加密保存。
- 响应永远不返回明文 API Key。
- 编辑配置时不传 API Key 表示保留原密钥。
- 加密主密钥来自运行环境或本地未跟踪 env 文件，不写入数据库、Git、文档或前端。
- `prod` 等非本地环境必须显式配置 `AI_PROVIDER_KEY_ENCRYPTION_SECRET`，缺失时服务启动失败。
- `local`、`dev`、`test`、`smoke` 环境未配置 `AI_PROVIDER_KEY_ENCRYPTION_SECRET` 时，后端自动生成并复用本地文件 `~/.car-dealer-crm/ai-provider-key.secret`。
- 本地自动生成的主密钥只解决开发配置便利性，不作为生产密钥来源；删除或更换该文件后，旧 Provider API Key 密文无法解密，需要重新录入。
- 日志、trace、SSE、审计摘要、测试报告均不得包含明文 API Key。

## 运行方案

- Spring Boot 创建或启动 AI Run 时读取当前启用配置。
- 如果没有启用配置，AI Run 拒绝启动并返回稳定错误。
- Spring Boot 解密 API Key 后组装 `providerRuntimeConfig`。
- `providerRuntimeConfig` 只传给 `dealer-ai` 本次请求使用。
- `dealer-ai` 根据 `providerFormat` 选择 OpenAI-compatible 或 Anthropic Adapter。
- `dealer-ai` 不缓存、不持久化、不记录 `providerRuntimeConfig` 中的密钥。

## 管理操作

- 创建配置。
- 编辑配置。
- 测试连接。
- 启用配置。
- 停用配置。
- 轮换 API Key。
- 查看配置列表、测试状态和掩码密钥。

## 权限

- `ai:provider-config:view`：查看模型配置。
- `ai:provider-config:manage`：创建、编辑、启用、停用、测试配置。
- `ai:provider-config:rotate-key`：轮换 API Key。
- 普通 AI 用户不得查看 Provider 配置。

## 验收标准

- 同一时间只有一个 `ACTIVE` 配置。
- 响应和前端只出现 `maskedApiKey`，不出现明文 API Key。
- 测试连接受 token、超时和次数限制，不调用业务工具。
- 新 Run 使用当前启用配置。
- 切换启用配置后，新 Run 使用新配置，旧 Run trace 不泄露历史密钥。
