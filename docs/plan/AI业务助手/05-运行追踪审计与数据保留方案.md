# 运行追踪审计与数据保留方案

## 关联 Spec

- docs/spec/AI业务助手/00-业务范围与边界.md

## 背景

AI 结果必须能追溯到用户、问题、工具、数据摘要、Proposal、确认、Workflow 和执行结果。追踪数据需要帮助用户恢复上下文，但不能保存敏感原文或供应商原始响应。

## 目标

- 记录 AI Run、Message、ToolCall、Proposal、Approval、Workflow、主动事件和 ExecutionEvent。
- 支持断线、刷新和稍后回看恢复。
- 不保存完整 Token、API Key、Authorization Header、Cookie、完整模型供应商响应、完整手机号、完整银行账号和数据库错误堆栈。
- AI 追踪不替代业务操作审计。

## 数据保留边界

允许保存：

- 脱敏问题摘要。
- 可展示回答。
- 工具名、风险等级、结果状态、耗时、数量和对象引用。
- 脱敏输入摘要和输出摘要。
- Proposal 状态和执行结果。
- Workflow 状态、步骤状态和失败摘要。

禁止保存：

- 明文 API Key。
- Provider runtime config。
- 模型供应商原始完整响应。
- 用户 Bearer Token。
- 服务间 token。
- 完整敏感业务字段。

## 恢复规则

- Run trace 必须恢复消息、工具结果、Proposal、Approval、Workflow、主动事件和 ExecutionEvent。
- 前端不能只依赖当前 SSE 连接展示结果。
- 事件重复到达不得重复创建 Proposal 或重复执行业务写入。

## 验收标准

- 任一 AI 回答可追溯到 Run 和消息。
- 任一工具调用可追溯到工具名、输入输出摘要、结果和耗时。
- 任一 Proposal 可追溯到创建、确认、拒绝、过期、执行成功或执行失败。
- 密钥泄露扫描无结果。
