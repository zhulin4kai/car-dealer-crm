# AI 助手整体架构与边界方案

## 关联 Spec

- docs/spec/AI业务助手/00-业务范围与边界.md

## 背景

AI 助手需要从一次性对话组件升级为完整业务辅助系统。目标形态应同时具备模型配置、LangGraph 编排、业务工具、人工确认、主动提醒、运行追踪和前端工作台，而不是把这些能力拆成互相等待的独立路线。

当前文档和代码仍存在旧分期表达，导致 LangGraph、Proposal、主动提醒、Provider 配置和前端展示互相割裂。新方案以整体 AI 助手为唯一目标架构。

## 目标

- AI 助手作为一个完整能力交付。
- LangGraph 作为默认编排内核。
- Spring Boot 作为 AI 业务控制面和 Provider 配置真源。
- `dealer-ai` 作为 AI 编排面，不保存业务事实和密钥。
- 前端提供 AI 工作台和管理员模型配置入口。
- 普通业务页面继续走普通业务 API。

## 目标架构

```text
dealer-web AI 工作台
  -> Spring Boot /api/ai/**
  -> AI Run / Provider Config / ToolRegistry / Proposal / Workflow / Audit
  -> dealer-ai LangGraph
  -> Provider Adapter
  -> 模型供应商

dealer-ai LangGraph
  -> Spring Boot internal Tool API
  -> ToolRegistry
  -> 现有 Service
  -> DB
```

## 责任边界

- `dealer-web`：展示 AI 工作台、对话、工具结果、Proposal、Workflow、主动提醒和模型配置管理页面。
- `dealer-server`：管理 AI Run、Provider 配置、权限、数据范围、ToolRegistry、Proposal、Workflow、主动提醒、审计和 OpenAPI。
- `dealer-ai`：执行 LangGraph 编排、选择工具、调用模型、输出内部事件。
- 模型供应商：只提供语言模型能力，不参与 CRM 权限、状态、业务事实和审计。

## 核心不变量

- 浏览器永远不直连 `dealer-ai`。
- `dealer-ai` 永远不直连数据库、Redis 会话、Mapper 或普通业务 API。
- Provider 配置来自 Spring Boot 管理端。
- API Key 加密入库，前端、SSE、trace、日志和模型上下文不出现明文。
- LangGraph 类型不得泄露到 Spring Boot 对外 API、前端类型、数据库表和 OpenAPI。
- AI 不能直接执行高风险业务动作。

## 实施顺序

1. 完成现有 AI 实现审查，列出保留、删除、迁移、重写清单。
2. 补齐 Provider 配置和密钥治理。
3. 收敛 `dealer-ai` 为 LangGraph 默认编排。
4. 调整 Spring Boot AI 运行控制和服务间契约。
5. 整理 ToolRegistry、Proposal、Workflow、主动提醒和前端工作台。
6. 执行端到端验收与文档同步。

## 验收标准

- AI Run 创建时必须存在启用 Provider 配置。
- Spring Boot 调用 `dealer-ai` 时携带 `providerRuntimeConfig`。
- `dealer-ai` 默认使用 LangGraph 编排。
- OpenAI-compatible 和 Anthropic 都有适配入口和 mock 测试。
- 前端能完成对话、工具结果、Proposal、Workflow、主动提醒和 Provider 配置管理。
- 密钥泄露扫描无结果。
