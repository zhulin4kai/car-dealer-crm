1. 29. Excel 导入的字典/产品转换失败会写入 `-1`

## 问题详情

### 29. Excel 导入的字典/产品转换失败会写入 `-1`

类型：数据完整性 / 导入校验

位置：
- `dealer-server/src/main/java/com/autodealer/crm/config/converter/AppellationConverter.java:36`
- `dealer-server/src/main/java/com/autodealer/crm/config/converter/AppellationConverter.java:48`
- `dealer-server/src/main/java/com/autodealer/crm/config/converter/NeedLoanConverter.java:34`
- `dealer-server/src/main/java/com/autodealer/crm/config/converter/NeedLoanConverter.java:46`
- `dealer-server/src/main/java/com/autodealer/crm/config/converter/IntentionProductConverter.java:36`
- `dealer-server/src/main/java/com/autodealer/crm/config/converter/IntentionProductConverter.java:48`
- `dealer-server/src/main/java/com/autodealer/crm/config/listener/UploadDataListener.java:64`
- `dealer-server/src/main/java/com/autodealer/crm/config/listener/UploadDataListener.java:73`

问题：
多个 Excel converter 在缓存未命中或文本无法匹配时返回 `-1`，监听器不校验转换结果，直接加入批量入库列表。

影响：
- 线索表会出现不存在的字典 ID 或产品 ID。
- 后续列表展示、统计、客户转换都会基于脏数据运行。

建议：
- 导入应按行收集错误，返回“第几行哪个字段非法”。
- 字典/产品字段转换失败时拒绝入库，而不是使用哨兵值。


### 30. Excel 导入没有文件和空批次保护

类型：健壮性 / 导入校验

位置：
- `dealer-server/src/main/java/com/autodealer/crm/web/ClueController.java:35`
- `dealer-server/src/main/java/com/autodealer/crm/web/ClueController.java:38`
- `dealer-server/src/main/java/com/autodealer/crm/config/listener/UploadDataListener.java:92`
- `dealer-server/src/main/java/com/autodealer/crm/config/listener/UploadDataListener.java:101`
- `dealer-server/src/main/resources/mapper/TClueMapper.xml:191`
- `dealer-server/src/main/resources/mapper/TClueMapper.xml:202`

问题：
导入接口没有检查 `file` 是否为空、类型是否为 Excel、大小是否合理。监听器解析结束后无条件 `saveData()`，即使 `cachedDataList` 为空也调用批量 insert。

影响：
- 空文件或解析失败场景可能生成非法 SQL。
- 大文件、错误格式文件会直接进入解析流程，错误信息不可控。

建议：
- Controller 层先校验文件存在、后缀/content-type、大小。
- `saveData()` 在列表为空时直接返回。
- 导入前做手机号唯一性、必填字段、字典字段合法性校验。


### 31. 客户导出“最多 10000 条”的限制没有真正生效

类型：业务逻辑 / 性能风险

位置：
- `dealer-server/src/main/java/com/autodealer/crm/web/CustomerController.java:97`
- `dealer-server/src/main/java/com/autodealer/crm/web/CustomerController.java:99`
- `dealer-server/src/main/java/com/autodealer/crm/web/CustomerController.java:102`

问题：
导出接口注释写“如果没有指定 ID，限制最多导出 10000 条”，但实际把 `idList` 设为 `null`，交给 service/mapper 后会导出所有客户。

影响：
- 数据量大时可能拖垮接口或产生超大 Excel。
- 普通导出行为和代码注释不一致，后续维护者容易误判风险。

建议：
- 未传 ids 时在 SQL 中加 `LIMIT 10000` 或要求前端必须按筛选条件分页导出。
- 对导出任务增加后台任务、状态查询和文件过期清理。

## 缓存、序列化与一致性问题


### 32. 字典内存缓存只被读取和清空，没有看到可靠装载路径

类型：缓存一致性 / 导入功能

位置：
- `dealer-server/src/main/java/com/autodealer/crm/DealerCRMApplication.java:22`
- `dealer-server/src/main/java/com/autodealer/crm/config/converter/SourceConverter.java:36`
- `dealer-server/src/main/java/com/autodealer/crm/config/converter/StateConverter.java:34`
- `dealer-server/src/main/java/com/autodealer/crm/config/converter/IntentionProductConverter.java:36`
- `dealer-server/src/main/java/com/autodealer/crm/service/impl/DicServiceImpl.java:252`

问题：
`DealerCRMApplication.cacheMap` 是静态内存缓存，Excel converter 依赖它取字典和产品数据。但在当前 `crm` 目录内只看到读取和清空，没有看到启动或刷新时把字典/产品装入 `cacheMap` 的路径。

影响：
- Excel 导入时 converter 可能长期拿到 null，进而返回 `-1`。
- 多实例部署时静态本地缓存无法保证一致性。

建议：
- 去掉 converter 对静态缓存的依赖，改为导入前构造明确的字典映射上下文。
- 刷新字典时统一刷新 Redis 或本地缓存，避免多套缓存源。


### 33. 字典缓存清理方法忽略入参，且 key 规则不一致

类型：缓存一致性 / 可维护性

位置：
- `dealer-server/src/main/java/com/autodealer/crm/service/impl/DicServiceImpl.java:74`
- `dealer-server/src/main/java/com/autodealer/crm/service/impl/DicServiceImpl.java:90`
- `dealer-server/src/main/java/com/autodealer/crm/service/impl/DicServiceImpl.java:239`
- `dealer-server/src/main/java/com/autodealer/crm/service/impl/DicServiceImpl.java:241`
- `dealer-server/src/main/java/com/autodealer/crm/service/impl/DicServiceImpl.java:320`
- `dealer-server/src/main/java/com/autodealer/crm/service/impl/DicServiceImpl.java:334`

问题：
`clearCache(String pattern)` 接收 pattern，但方法内部完全忽略入参，只删除硬编码的 `dic:type:*`、`dic:value:*`、`dic:list:*`。而调用方使用了 `dic:types:*`、`dic:values:*`、`dic:type:code:*`、`dic:values:type:*` 等多种 key 格式。

影响：
- 有些缓存不会被清掉，有些缓存会被过度清理。
- 字典修改后，接口和导入转换可能看到不同版本的数据。

建议：
- 统一字典缓存 key 命名。
- `clearCache(pattern)` 必须按入参执行，或改名为 `clearAllDicCache()`。
- 增加缓存命中/失效的单元或集成测试。


### 34. Redis 模式删除使用 `KEYS`

类型：性能风险 / 生产稳定性

位置：
- `dealer-server/src/main/java/com/autodealer/crm/manager/RedisManager.java:42`
- `dealer-server/src/main/java/com/autodealer/crm/manager/RedisManager.java:43`
- `dealer-server/src/main/java/com/autodealer/crm/service/impl/TranServiceImpl.java:627`
- `dealer-server/src/main/java/com/autodealer/crm/service/impl/DicServiceImpl.java:248`

问题：
`deletePattern` 使用 `redisTemplate.keys(pattern)` 查找匹配 key。生产 Redis key 数量上来后，`KEYS` 会阻塞 Redis。

影响：
- 字典刷新、交易缓存清理可能造成 Redis 短时间不可用。
- 高峰期会放大接口延迟。

建议：
- 改用 `SCAN` 分批删除。
- 对列表缓存尽量使用版本号或命名空间切换，避免频繁模式删除。


### 35. Redis 序列化在应用启动后动态修改，并启用 default typing

类型：安全问题 / 配置规范

位置：
- `dealer-server/src/main/java/com/autodealer/crm/DealerCRMApplication.java:31`
- `dealer-server/src/main/java/com/autodealer/crm/DealerCRMApplication.java:41`
- `dealer-server/src/main/java/com/autodealer/crm/DealerCRMApplication.java:44`
- `dealer-server/src/main/java/com/autodealer/crm/DealerCRMApplication.java:46`

问题：
应用实现 `CommandLineRunner`，在 `run` 方法里修改 `RedisTemplate` 序列化器，并启用 Jackson `activateDefaultTyping`。

影响：
- default typing 会扩大反序列化攻击面。
- 在启动后修改 template 序列化器不如 Bean 配置清晰，可能和其它 Bean 初始化顺序产生隐性差异。

建议：
- 使用 `@Bean` 显式配置 RedisTemplate。
- 避免 default typing，按业务 DTO 或安全白名单序列化。

## 业务逻辑完整性问题


### 57. `RedisService` 和 `RedisManager` 两套 Redis 封装职责重叠

类型：重复基础设施 / 缓存一致性风险

位置：
- `dealer-server/src/main/java/com/autodealer/crm/service/RedisService.java:5`
- `dealer-server/src/main/java/com/autodealer/crm/service/impl/RedisServiceImpl.java:11`
- `dealer-server/src/main/java/com/autodealer/crm/manager/RedisManager.java:13`
- `dealer-server/src/main/java/com/autodealer/crm/manager/RedisManager.java:21`
- `dealer-server/src/main/java/com/autodealer/crm/manager/RedisManager.java:42`
- `dealer-server/src/main/java/com/autodealer/crm/manager/RedisManager.java:49`
- `dealer-server/src/main/java/com/autodealer/crm/config/handler/MyAuthenticationSuccessHandler.java:24`
- `dealer-server/src/main/java/com/autodealer/crm/config/filter/TokenVerifyFilter.java:31`

问题：
项目中有 `RedisService/RedisServiceImpl` 和 `RedisManager` 两套 Redis 操作封装。认证成功处理器使用 `RedisService` 写 token，token 校验过滤器和业务缓存使用 `RedisManager`。两套封装的方法语义不同，`RedisManager.getValue/setValue` 使用 list 操作，`RedisService.getValue/setValue` 使用 value 操作。

影响：
- 调用方很难判断一个 key 应该用 String 还是 List 存储。
- token 和缓存逻辑由不同封装管理，过期时间、序列化、删除模式不统一。
- 后续修复 Redis `KEYS`、序列化、命名规范时需要改两套入口。

建议：
- 合并为一套 Redis 基础设施，例如 `RedisCacheService`。
- 明确方法名：`getObject/setObject`、`getList/setList`、`deleteByScan`。
- 认证 token 存储和业务缓存可以有不同上层 service，但底层 Redis 访问应统一。


### 62. 缺少导入结果/行级错误 DTO，Excel 导入无法表达部分失败

类型：缺失业务契约 / 导入健壮性

位置：
- `dealer-server/src/main/java/com/autodealer/crm/web/ClueController.java:35`
- `dealer-server/src/main/java/com/autodealer/crm/web/ClueController.java:40`
- `dealer-server/src/main/java/com/autodealer/crm/config/listener/UploadDataListener.java:61`
- `dealer-server/src/main/java/com/autodealer/crm/config/listener/UploadDataListener.java:101`

问题：
导入接口当前只返回 `R.OK()` 或抛异常，没有专门的导入结果模型。监听器按行解析后直接入库，无法把“第几行哪个字段错误”结构化返回。

影响：
- 用户不知道哪些行失败、为什么失败。
- 系统只能选择全成功或异常中断，无法做可解释的导入校验。
- 配合前文第 29 条的 `-1` 哨兵值问题，会让错误数据更容易进入数据库。

建议：
- 补 `ImportResult`、`ImportErrorRow` 或类似 DTO。
- 导入流程分为解析、校验、确认入库三个阶段。
- 返回成功数量、失败数量、错误行号、字段名、错误原因。
