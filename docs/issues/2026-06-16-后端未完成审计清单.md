### 1. 接口级权限矩阵审计

类型：安全审计 / 权限审计 / API 契约

审计目标：
建立完整 API 权限矩阵，确认每个接口是否具备正确的认证、授权和数据权限约束。

待审范围：
- `dealer-server/src/main/java/com/autodealer/crm/web/*.java`
- `dealer-server/src/main/java/com/autodealer/crm/config/SecurityConfig.java`
- `dealer-server/src/main/java/com/autodealer/crm/config/filter/TokenVerifyFilter.java`
- `dealer-server/src/main/java/com/autodealer/crm/aspect/DataScopeAspect.java`
- 权限相关 model、mapper、SQL 初始化数据

具体检查点：
- 列出所有 API：
  - HTTP method
  - URL
  - Controller 方法
  - 所属业务模块
  - 是否需要登录
  - 是否有 `@PreAuthorize`
  - 当前权限码
  - 建议权限码
  - 是否涉及数据权限
  - 是否涉及敏感数据
  - 是否是写操作
- 检查 `SecurityConfig` 放行规则与 `TokenVerifyFilter` 跳过规则是否一致。
- 检查所有写接口是否都有明确权限：
  - 新增
  - 编辑
  - 删除
  - 批量删除
  - 导入
  - 导出
  - 审批
  - 退款
  - 入库
  - 系统配置修改
  - 字典刷新
- 检查敏感读接口是否有权限：
  - 用户列表
  - 客户详情
  - 交易详情
  - 系统监控
  - 字典维护
  - 导出接口
- 检查权限码是否和菜单/按钮权限初始化数据一致。
- 检查管理员权限和普通权限是否混用，例如 `hasAuthority('admin')` 与业务权限码混用。
- 检查前端隐藏按钮是否被误当成后端权限。
- 检查没有 `@PreAuthorize` 的接口是否确实只需要登录。
- 检查数据权限是否覆盖列表、详情、备注、导出等接口。

产出物：
- API 权限矩阵表。
- 未授权接口清单。
- 权限码缺失/不一致清单。
- 需要新增的权限码建议。
- 高风险越权接口列表。

验收标准：
- 每个接口都有明确权限结论。
- 每个写接口都有后端权限控制。
- 每个敏感读接口都有后端权限控制。
- 所有公开接口有明确理由。

优先级：P0

### 2. Mapper/XML 全量 SQL 审计

类型：SQL 审计 / 数据完整性 / 安全审计 / 性能审计

审计目标：
逐个审查所有 MyBatis mapper XML，确认 SQL 的安全性、准确性、性能和业务条件完整性。

待审范围：
- `dealer-server/src/main/resources/mapper/*.xml`
- `dealer-server/src/main/java/com/autodealer/crm/mapper/*.java`
- 相关 service 调用链

具体检查点：
- SQL 安全：
  - 是否使用 `${}` 拼接不可信输入。
  - 是否存在动态排序、动态列名、动态条件注入风险。
  - `filterSQL` 是否可能被外部注入。
- 查询准确性：
  - mapper 方法名是否与 SQL 语义一致。
  - count SQL 是否统计了正确对象。
  - 统计接口是否存在 distinct、join、where 条件口径错误。
  - 字典、状态、枚举字段是否按稳定 code 查询。
- 更新安全：
  - update 是否缺少 `WHERE id = ?`。
  - 状态流转 update 是否缺少当前状态条件。
  - 批量 update/delete 是否限制最大数量。
  - 是否存在误删、误更新风险。
- 删除策略：
  - 是否物理删除核心业务数据。
  - 删除前是否检查引用。
  - 删除是否破坏审计链。
  - 是否存在级联删除业务历史数据。
- 分页：
  - PageHelper 与手写 limit 是否混用。
  - 是否存在未分页大表查询。
  - 是否存在导出全量查询。
- join：
  - join 字段是否正确。
  - resultMap 字段别名是否冲突。
  - left join 是否可能产生重复行。
  - 是否存在 N+1 查询。
- 批量 SQL：
  - foreach 空列表是否会生成非法 SQL。
  - 批量 insert 是否有字段校验。
  - 批量 delete 是否有数量限制。
- 索引：
  - where/join/order by 字段是否有索引。
  - 常用查询是否可能全表扫描。

产出物：
- Mapper SQL 审计表。
- `${}` 风险清单。
- delete/update 高风险 SQL 清单。
- 统计口径问题清单。
- 缺失索引建议清单。
- 大查询和性能风险清单。

验收标准：
- 每个 XML mapper 均有审计结论。
- 所有 `${}` 均有安全来源说明或替代方案。
- 所有核心 delete/update 均有业务条件说明。

优先级：P0

### 3. 事务边界审计

类型：业务一致性 / 事务审计

审计目标：
确认每个业务动作的事务边界是否正确，避免部分成功、部分失败造成数据不一致。

待审范围：
- `dealer-server/src/main/java/com/autodealer/crm/service/`
- `dealer-server/src/main/java/com/autodealer/crm/service/impl/`
- `dealer-server/src/main/java/com/autodealer/crm/manager/`
- 涉及多表写入的 mapper

重点业务动作：
- 创建交易。
- 更新交易和产品明细。
- 审批交易。
- 重新提交交易。
- 创建发票。
- 更新发票状态。
- 记录收款。
- 退款。
- 批量删除交易。
- 商品入库。
- 线索导入。
- 线索转换客户。
- 删除线索。
- 删除客户。
- 新增/编辑/删除字典类型和值。
- 新增/编辑/删除用户。
- 系统配置修改。

具体检查点：
- 方法是否存在多表写入。
- 是否加 `@Transactional`。
- `@Transactional` 是否在 public service 方法上。
- 是否存在同类内部方法调用导致事务不生效。
- 是否设置 `rollbackFor = Exception.class`。
- 是否在事务中调用外部系统或长耗时 IO。
- 是否存在先写状态、后校验数据的顺序问题。
- 是否存在缓存清理与数据库提交顺序问题。
- 是否存在异常被 catch 后吞掉导致事务不回滚。

产出物：
- 业务动作事务矩阵。
- 缺失事务方法清单。
- 事务过大/过小方法清单。
- 缓存与事务一致性问题清单。

验收标准：
- 每个核心写业务动作都有明确事务边界。
- 多表写入必须有事务。
- 涉及库存、财务、审批、状态迁移的动作必须有事务和回滚策略。

优先级：P0

### 4. 并发与幂等审计

类型：业务安全 / 并发一致性 / 幂等设计

审计目标：
检查关键业务在重复点击、并发请求、网络重试、定时任务重复执行时是否会产生重复数据或错误状态。

待审范围：
- 交易模块
- 支付/退款模块
- 发票模块
- 库存模块
- 线索导入模块
- 字典维护模块
- 用户管理模块

重点场景：
- 重复创建交易。
- 同一交易重复审批。
- 已拒绝交易重复提交。
- 同一交易重复创建发票。
- 同一发票重复改状态。
- 同一交易重复收款。
- 同一付款重复退款。
- 并发入库或扣库存。
- 同一手机号线索并发导入。
- 批量删除与状态流转并发发生。
- 字典删除与业务创建并发发生。

具体检查点：
- 是否有唯一约束。
- 是否有业务幂等 key。
- 状态更新是否使用当前状态作为条件。
- 库存更新是否原子。
- 金额计算是否以后端为准。
- 是否存在先查询后插入的竞态。
- 批量操作是否验证每条数据的当前状态。
- 重复请求返回是否可预测。

产出物：
- 幂等风险清单。
- 并发风险清单。
- 需要唯一索引的字段清单。
- 需要 CAS 更新的 SQL 清单。
- 需要业务幂等 key 的接口清单。

验收标准：
- 库存、支付、退款、审批、发票相关接口必须具备幂等或状态保护。
- 线索手机号、交易编号、发票号、支付流水等关键字段必须具备唯一性策略。

优先级：P0

### 6. Maven 依赖安全与版本冲突审计

类型：供应链安全 / 依赖治理

审计目标：
检查项目依赖是否存在已知漏洞、版本冲突、重复依赖、过期依赖。

待审范围：
- `dealer-server/pom.xml`
- Maven dependency tree

具体检查点：
- 是否存在已知 CVE。
- Spring Boot 版本是否过旧。
- MyBatis、PageHelper、EasyExcel、JWT、Jackson、Redis、OSHI 等依赖版本是否安全。

- 目录重构迁移顺序建议。

验收标准：
- 明确哪些模块应拥有哪些表。
- 明确哪些跨模块调用应改为 facade/service。

优先级：P1

## P2：中优先级审计

### 11. 运行时接口验证

类型：功能验证 / 集成验证

审计目标：
通过实际启动后端并调用接口，确认静态审查发现的问题是否真实触发，并补充静态审查看不到的运行时问题。

待审范围：
- 登录认证。
- 权限校验。
- 用户管理。
- 活动管理。
- 线索管理。
- 客户管理。
- 交易流程。
- 商品和库存。
- 字典维护。
- 系统配置。
- 系统监控。
- 导入导出。

具体检查点：
- 正常路径是否可用。
- 参数缺失是否返回统一错误。
- 权限不足是否被拦截。
- token 为空/过期/篡改是否被拦截。
- CORS 预检是否正常。
- Excel 导入错误文件是否可控。
- Excel 导出大数据是否受限。
- 交易完整流程是否能走通。
- 退款、审批、开票是否可重复触发。
- 商品库存是否和交易流程一致。

产出物：
- 接口验证清单。
- 可复现 bug 清单。
- 请求样例。
- 响应样例。
- 运行时异常日志。

验收标准：
- 核心业务流程至少跑通一遍。
- 高风险接口有失败场景验证。

优先级：P2

类型：质量保障 / 测试治理

说明：
当前根据要求未审查 `dealer-server/src/test/`。如果后续允许，应补做测试覆盖审计。

审计目标：
确认关键业务是否有自动化测试覆盖，并建立缺失测试清单。

待审范围：
- `dealer-server/src/test/`
- 测试配置
- 测试数据库 schema
- 测试数据

具体检查点：
- 是否有 service 单元测试。

- 是否有认证授权测试。

### 13. 日志、审计、隐私和敏感信息专项审计

类型：安全合规 / 可观测性

审计目标：
确认日志不会泄露敏感信息，同时关键操作具备可追溯性。

待审范围：
- logback 配置
- controller/service 日志
- filter/handler 日志
- Excel 导入日志
- 操作日志 model/mapper

具体检查点：
- 是否记录 token。
- 是否记录密码或密码哈希。
- 是否记录手机号、邮箱、身份证等敏感信息。
- 是否记录完整 Excel 行数据。
- 登录失败是否记录账号枚举风险。
- 关键写操作是否有操作日志。
- 异常日志是否包含必要上下文。
- 生产日志级别是否合理。
- 是否需要脱敏工具。

产出物：
- 敏感日志清单。
- 缺失操作日志清单。
- 脱敏规则建议。
- 操作审计字段建议。

验收标准：
- token、密码哈希不得进入日志。
- 关键业务写操作可追溯。

优先级：P2

### 14. 数据库索引与约束专项审计

类型：数据库设计 / 数据完整性 / 性能

审计目标：
检查数据库 schema 是否具备必要的唯一约束、外键约束、索引和字段约束。

待审范围：
- `dealer-server/src/main/resources/*.sql`
- mapper where/join/order by 字段
- model 校验注解

具体检查点：
- 手机号唯一性。
- 登录账号唯一性。
- 商品 SKU 唯一性。
- 交易编号唯一性。
- 发票号唯一性。
- 支付流水唯一性。
- 字典类型 code 唯一性。
- 字典值在同类型下唯一性。
- 核心外键关系是否有约束或等效业务检查。
- 金额、数量、库存是否非负。
- 状态字段是否限制可选值。
- 常用查询字段是否有索引。

产出物：
- 缺失唯一约束清单。
- 缺失外键/业务约束清单。
- 缺失索引清单。
- model 校验与 SQL 约束不一致清单。

验收标准：
- 唯一业务键必须有数据库唯一约束。
- 高频查询必须有合理索引。

优先级：P2

### 15. 文件上传下载与 Excel 处理安全审计

类型：文件安全 / 导入导出 / 稳定性

审计目标：
确认文件相关功能不会造成资源耗尽、格式绕过、敏感数据泄露或不受控下载。

待审范围：
- Excel 导入。
- Excel 导出。
- EasyExcel converter/listener。
- 文件响应头。

具体检查点：
- 上传文件是否校验空文件。
- 是否校验大小。
- 是否校验后缀和 content-type。
- 是否限制 Excel 行数。
- 是否限制列数。
- 是否处理公式注入风险。
- 是否处理超大单元格。
- 是否返回行级错误。
- 导出是否限制最大数量。
- 导出文件名是否安全。
- 下载 token 是否通过 URL 泄露。
- 是否设置正确响应头。

产出物：
- 上传风险清单。
- 导入数据校验清单。
- 导出安全问题清单。
- Excel 公式注入防护建议。

验收标准：
- 导入不会把非法数据写入数据库。
- 导出不会无上限拉取全量数据。
- token 不通过 URL 长期暴露。

优先级：P2
