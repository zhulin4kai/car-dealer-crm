## 一、业务流程完整性问题

### ISSUE-001：线索转客户时未校验线索状态的并发问题
| 属性 | 内容 |
|------|------|
| 问题编号 | ISSUE-001 |
| 所属模块 | 线索管理/客户管理 |
| 问题类型 | 流程缺失 |
| 严重程度 | P1-严重 |
| 问题描述 | `CustomerManager.convertCustomer()` 方法中，检查线索状态 `state == -1` 和更新状态为 `-1` 之间没有原子性保证，存在并发重复转换风险 |
| 涉及文件 | 后端：`manager/CustomerManager.java:42-57` |
| 期望行为 | 同一线索只能被转换一次，应使用乐观锁或数据库唯一约束防止重复转换 |
| 当前行为 | 两个请求同时到达时，可能都通过 `state == -1` 检查，导致重复创建客户和交易 |
| 修复建议 | 使用数据库乐观锁：`UPDATE t_clue SET state=-1 WHERE id=? AND state != -1`，检查影响行数 |

## 二、数据一致性问题

### ISSUE-006：库存扣减无下限校验，可能变为负数
| 属性 | 内容 |
|------|------|
| 问题编号 | ISSUE-006 |
| 所属模块 | 商品管理/交易管理 |
| 问题类型 | 数据不一致 |
| 严重程度 | P0-致命 |
| 问题描述 | `ProductMapper.updateStock()` 直接执行 `stock = stock + #{quantity}`，quantity 可以是负数（扣减），没有校验库存是否会变为负数 |
| 涉及文件 | 后端：`mapper/TProductMapper.xml`（updateStock SQL），`service/impl/TranServiceImpl.java:83` |
| 期望行为 | 库存扣减时应校验 `stock >= 扣减数量`，不足时应拒绝扣减 |
| 当前行为 | 库存可以被扣减为负数，超卖无感知 |
| 修复建议 | 修改 SQL 为 `UPDATE t_product SET stock = stock + #{quantity} WHERE id = #{id} AND stock + #{quantity} >= 0`，检查影响行数 |

### ISSUE-007：交易更新时库存恢复和扣减非原子操作
| 属性 | 内容 |
|------|------|
| 问题编号 | ISSUE-007 |
| 所属模块 | 交易管理 |
| 问题类型 | 数据不一致 |
| 严重程度 | P1-严重 |
| 问题描述 | `updateTransaction()` 方法更新产品时，先删除旧产品关联（恢复库存）再插入新产品关联（扣减库存），如果中间步骤失败，库存数据不一致 |
| 涉及文件 | 后端：`service/impl/TranServiceImpl.java:93-107` |
| 期望行为 | 整个更新操作应在同一个事务中，且有回滚机制 |
| 当前行为 | `updateTransaction()` 方法没有 `@Transactional` 注解，如果新产品插入失败，旧库存已恢复但新产品未关联 |
| 修复建议 | 为 `updateTransaction()` 方法添加 `@Transactional(rollbackFor = Exception.class)` 注解 |
