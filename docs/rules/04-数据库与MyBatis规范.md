# 数据库与 MyBatis 规范

## 表与字段

- 表名、字段名、索引名使用 `snake_case`；同一概念在不同表中必须使用同一字段名和类型。
- 主键、外键及关联字段的类型、符号和长度必须完全一致。
- 主键策略必须显式确定；业务 code、流水号和外部编号不得复用自增主键语义。
- 金额使用满足精度要求的 `DECIMAL`，Java 对应 `BigDecimal`，禁止 `FLOAT`、`DOUBLE`。
- 时间字段必须明确“业务发生时间”或“记录创建时间”，禁止一个字段承担两种语义。
- 状态字段保存稳定 code，禁止保存前端文案、Java 枚举 ordinal 或依赖字典表自增 ID。
- 必填、唯一、非负、默认值和引用完整性应由数据库约束兜底，不能只依赖 Java 判断。
- 支付、退款、审批、库存流水、操作历史等审计数据禁止物理删除。

## 索引与约束

- 唯一业务事实必须使用唯一约束，如支付流水号、幂等键和不可重复关联。
- 列表查询新增筛选或排序字段时必须检查执行计划和现有复合索引前缀。
- 外键字段、常用状态条件和时间范围查询应评估索引，禁止为每个字段机械建单列索引。
- 复合索引字段顺序根据等值条件、范围条件和排序方式确定，并记录对应查询场景。
- 禁止用应用层“先查是否存在”代替唯一约束；应用层检查仅用于提供可理解错误。

## Mapper 接口与 XML

- Mapper 接口和 XML namespace 必须一一对应，statement id 必须与方法名一致。
- 多参数方法使用 `@Param`，XML 参数名必须与注解一致；复杂条件使用 Query 对象。
- 参数值使用 `#{}`；`${}` 仅允许受控的列名或排序片段，并必须经过白名单映射。
- `resultMap` 明确映射含义不同或名称冲突的列；join 查询的列别名必须唯一。
- 动态 SQL 必须处理空字符串、空集合和 `null`，禁止生成全表更新或全表删除。
- `<foreach>` 批量 SQL 必须在 Service 入口限制数量，空集合不得进入 Mapper。
- 公共 SQL 片段只抽取稳定列清单和条件，禁止过度复用导致查询含义不可读。
- Mapper 写方法返回影响行数，Service 必须检查预期行数。

## 查询与分页

- 列表查询必须有确定排序；按非唯一字段排序时追加主键，避免翻页重复和遗漏。
- 同一查询只能使用一种分页方式，禁止 PageHelper 与手工 `LIMIT/OFFSET` 混用。
- 详情查询必须区分“不存在”和“无数据权限”，不得先全表查询再由前端过滤。
- 禁止无上限返回业务大表；导出必须有数量限制、分批读取或流式方案。
- 避免循环调用 Mapper 形成 N+1；使用批量查询、join 或预加载后在内存建立索引。
- `select *` 仅允许结构稳定且确需全部字段的单表查询；跨表查询必须列出字段。

## 写入、事务与并发

- 状态更新 SQL 必须包含主键、当前状态和数据权限条件，影响行数为 `0` 时视为冲突或非法状态。
- 库存、余额和累计金额使用数据库原子更新、CAS 或行锁，禁止只做“先查再写”。
- 悲观锁查询必须处于有效事务内，并保持固定加锁顺序避免死锁。
- 批量写入必须明确全成功或部分成功语义；全成功业务必须由事务包裹。
- 删除必须带主键和业务限制条件；禁止 Mapper 暴露无条件 delete/update 方法。
- 数据库异常不得转换为成功或空结果，唯一冲突等已知异常应映射为稳定业务错误。

## Schema 变更

1. 说明变更原因、受影响表、数据量、锁表风险和兼容窗口。
2. 优先采用可向前兼容的“新增、回填、切换、清理”步骤，禁止直接破坏旧代码读取。
3. 提供历史数据回填和校验 SQL，明确失败后的回滚或继续策略。
4. 同步生产 Schema、测试 H2 Schema、初始化数据、Model、Mapper XML 和测试数据。
5. 删除字段、索引或旧 code 前必须确认所有代码和数据已完成迁移。

## 验证

- Mapper 变更至少运行对应 Mapper/Service 测试；方言相关 SQL 必须验证 MariaDB/MySQL 兼容性。
- 约束和并发变更必须覆盖正常写入、重复写入、非法状态和影响行数为 `0`。
- 迁移完成后必须核对总行数、空值、重复值、孤儿关联及关键金额汇总。
