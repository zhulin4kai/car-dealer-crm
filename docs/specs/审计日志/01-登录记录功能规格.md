# 登录记录功能规格

## 业务目标

登录记录用于识别账号访问情况、排查登录失败、发现异常访问迹象，并为账号安全争议提供可验证事实。

## 记录触发

系统必须记录：

- 账号和凭证校验成功的登录。
- 账号不存在、密码错误、账号禁用、账号锁定、账号过期或凭证过期导致的登录失败。
- 认证流程发生未预期异常而未完成登录的失败结果。

普通接口的 Token 过期、权限不足和业务请求失败不属于登录记录。

登出记录不属于第一阶段必需项；如后续加入，必须与登录记录使用不同事件类型，不能伪装成登录失败。

## 记录内容

每条登录记录必须能够表达：

- 唯一记录标识。
- 用户提交的登录账号。
- 能够识别时的用户标识和用户姓名。
- 登录结果：成功或失败。
- 稳定的结果原因类别。
- 面向管理员的简短结果说明。
- 客户端 IP。
- 浏览器名称及主要版本。
- 操作系统名称。
- 登录发生时间。
- 可用于跨日志关联的请求标识。

登录失败且无法识别用户时，用户标识可以为空，但登录账号、结果、原因、IP 和时间不得缺失。

## 失败原因

失败原因必须使用稳定类别，至少区分：

- 账号不存在或凭证不正确。
- 账号被禁用。
- 账号被锁定。
- 账号已过期。
- 凭证已过期。
- 请求参数不合法。
- 认证服务异常。

对前台登录用户可以合并提示以避免账号枚举；管理员审计记录仍应保留受控的真实类别。

## 查询要求

管理员必须能够按以下条件组合查询：

- 登录账号。
- 用户姓名。
- 登录结果。
- 客户端 IP。
- 登录时间范围。

查询必须分页，默认按登录时间倒序；登录时间相同时必须保持稳定顺序。

空条件不得一次返回全部历史数据。时间范围应有合理默认值和最大跨度。

## 列表要求

列表至少展示：

- 登录账号。
- 用户姓名。
- 登录结果。
- 结果说明。
- IP。
- 浏览器。
- 操作系统。
- 登录时间。

无法识别用户时应明确显示“未知用户”或等价语义，不得伪造用户姓名。

## 详情要求

详情可以展示列表未完全显示的请求标识、完整结果类别和客户端信息。

详情禁止展示：

- 密码或密码摘要。
- 验证码。
- Token、Cookie、Session 或 Authorization。
- 完整请求体。
- 内部异常堆栈。

## 导出要求

具有导出权限的管理员可以导出当前筛选范围内的登录记录。

导出必须：

- 使用与列表一致的筛选条件和排序。
- 限制时间范围和最大数量。
- 不包含认证凭证和内部异常信息。
- 将导出动作记录为操作审计。

## IP 和客户端信息边界

- 第一阶段只保存和展示 IP，不解析 IP 归属地。
- IP 不作为用户身份的唯一证明。
- 反向代理场景下只能接受受信任代理提供的客户端地址信息。
- 浏览器和操作系统根据客户端声明解析，只用于辅助排查。

## 异常与降级

- 登录记录写入失败不得把认证失败错误转换成登录成功。
- 登录成功记录写入失败时，系统必须采用明确的安全策略，不得静默假装审计完成。
- 客户端信息解析失败时仍应保留账号、结果、IP 和时间，浏览器或操作系统可以显示“未知”。

## 验收场景

- 正确账号密码登录后产生一条成功记录。
- 密码错误后产生一条失败记录，且前台提示不暴露账号是否存在。
- 禁用账号登录后产生一条失败记录，并保留受控原因。
- 未知账号登录时用户标识为空，但登录账号、IP、时间和结果存在。
- 管理员能按账号、状态和时间范围查询。
- 无导出权限的用户不能导出。
- 任何记录和导出中都不存在密码、Token、Cookie 或 Authorization。
