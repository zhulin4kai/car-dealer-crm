# 汽车经销商客户关系管理系统业务方向

## 项目愿景

建设一个面向汽车经销商的客户关系管理系统，覆盖从线索获取、客户培育、商品匹配、交易推进、收款交付到经营分析的完整业务闭环。

系统应帮助门店把分散的销售线索、客户资料、跟进记录、车辆商品、库存变动、交易状态和经营数据统一管理起来，让销售过程可追踪、业务责任可识别、经营结果可衡量。

项目追求的是稳定、清晰、可信的业务管理能力，而不是单纯堆叠页面和功能。每个核心业务动作都应能回答：

- 谁发起了动作。
- 动作发生在什么业务对象上。
- 动作改变了什么业务状态。
- 动作是否符合业务规则。
- 动作产生了哪些后续影响。

## 目标用户

主要用户包括：

- 汽车经销商门店销售人员。
- 销售主管和门店管理者。
- 客服或市场活动跟进人员。
- 库存、商品和促销管理人员。
- 财务或收款确认人员。
- 系统管理员。

销售人员关注线索、客户、跟进、报价和交易推进。

管理者关注团队业绩、销售漏斗、客户来源、成交效率、业务风险和异常数据。

商品和库存人员关注车辆商品、分类、库存数量、库存变化和库存预警。

财务人员关注交易金额、发票、收款、退款和应收情况。

系统管理员关注用户、权限、字典、登录安全、关键操作追溯和基础业务数据的可控性。

## 核心业务问题

汽车经销商的销售业务存在以下核心问题：

- 线索来源多，质量不一，缺少统一归集和持续跟进。
- 客户信息分散，客户状态、意向、历史沟通和交易记录难以形成完整视图。
- 销售过程依赖个人经验，报价、审批、收款、交付等环节容易缺少明确状态。
- 车辆商品、库存和交易之间联动不足，可能出现库存不准、重复占用或业务记录脱节。
- 权限、责任人和操作记录不清晰，业务归属、异常追溯和风险控制困难。
- 字典、状态、分类等基础数据不统一，导致统计口径和业务判断不一致。
- 管理者缺少可信的销售漏斗、来源分析、成交金额和业务进展数据。

## 业务范围

业务范围包括：

- 线索管理。
- 客户管理。
- 市场活动管理。
- 车辆商品管理。
- 商品分类管理。
- 商品库存管理。
- 商品促销管理。
- 交易管理。
- 交易审批。
- 发票管理。
- 收款与退款管理。
- 销售统计与经营分析。
- 用户管理。
- 角色与权限管理。
- 数据字典管理。
- 登录记录。
- 操作审计。

线索业务覆盖线索登记、导入、查重、分配、跟进、状态维护和转化客户。

客户业务覆盖客户资料维护、意向记录、历史跟进、关联交易和客户选择。

市场活动业务覆盖活动创建、活动维护、活动关联线索和活动效果观察。

商品业务覆盖车辆商品、分类、状态、价格、库存、促销和库存变动记录。

交易业务覆盖创建交易、选择商品、报价、提交审批、审批结果、发票、收款、退款、关闭和完成。

基础治理与审计业务覆盖用户、权限、字典、登录记录和关键业务操作追溯。

## 主要能力

### 线索到客户的转化能力

系统应支持从不同来源沉淀线索，并让线索持续流转为可管理的客户。

主要能力包括：

- 记录线索基础信息。
- 识别线索来源。
- 维护线索意向状态。
- 记录跟进内容。
- 防止重复线索造成业务混乱。
- 将有效线索转化为客户。
- 保留线索转化前后的业务关联。

### 客户全生命周期管理能力

系统应围绕客户形成完整业务视图，让客户资料、跟进记录、意向商品和交易历史相互关联。

主要能力包括：

- 维护客户基础资料。
- 查询客户历史行为。
- 关联客户交易。
- 识别客户负责人。
- 支持销售人员持续跟进。
- 支持管理者查看客户沉淀质量。

### 商品与库存管理能力

系统应让车辆商品成为交易和库存管理的基础对象。

主要能力包括：

- 维护车辆商品信息。
- 管理商品分类。
- 区分商品状态。
- 维护商品价格。
- 管理商品库存。
- 记录库存变动。
- 提供库存预警。
- 管理促销活动。

### 交易过程管理能力

系统应把交易从报价到完成的过程明确化，避免交易状态混乱。

主要能力包括：

- 创建交易。
- 关联客户和商品。
- 计算和维护交易金额。
- 提交交易审批。
- 记录审批结果。
- 创建和维护发票。
- 记录收款。
- 处理退款。
- 关闭或完成交易。
- 保留交易状态变化历史。

### 权限与责任归属能力

系统应明确不同用户在不同业务中的可见范围和操作边界。

主要能力包括：

- 管理用户账号。
- 管理角色。
- 管理权限。
- 区分查看、新增、编辑、删除、导入、导出、审批、收款等业务动作。
- 明确业务数据负责人。
- 支持按责任归属查看和管理数据。

### 经营分析能力

系统应为管理者提供可信的经营观察入口。

主要能力包括：

- 展示关键业务指标。
- 展示销售漏斗。
- 分析线索来源。
- 观察成交情况。
- 观察商品和库存状态。
- 识别业务异常和待处理事项。

### 基础数据治理与审计能力

系统应让状态、字典、分类、登录记录和关键操作追溯保持统一，避免不同模块各自定义业务口径或责任事实。

主要能力包括：

- 维护数据字典。
- 管理基础分类。
- 控制基础数据变更。
- 记录登录成功和失败。
- 记录关键业务操作。
- 保持业务展示值和业务判断值一致。
- 支持管理员追溯关键业务责任。

## 非目标范围

不覆盖以下范围：

- 面向消费者的线上购车商城。
- 公开营销官网。
- 金融贷款审批系统。
- 保险报价与承保系统。
- 车辆生产制造管理。
- 维修保养工单系统。
- 二手车评估和拍卖平台。
- 第三方支付清算平台。
- 企业财务总账系统。
- 多品牌集团级经营中台。
- 跨门店复杂组织绩效系统。
- 客户移动端应用。

系统不承担外部专业系统的完整职责。

## 成功标准

业务成功标准包括：

- 销售人员能够清楚知道自己需要跟进哪些线索和客户。
- 每条线索都有明确来源、状态、负责人和跟进记录。
- 有效线索能够转化为客户，并保留转化关系。
- 客户资料、意向、跟进和交易历史能够形成完整视图。
- 商品、库存和交易之间保持一致。
- 交易状态清晰，报价、审批、发票、收款、退款和完成状态能够被追踪。
- 关键业务动作有明确操作者和业务结果。
- 管理者能够查看可信的销售漏斗、来源分析和成交数据。
- 用户权限能够覆盖核心业务动作。
- 基础数据口径统一，状态、字典和分类不会在不同模块产生冲突。
- 业务异常能够被识别、追溯和处理。
- 系统能够支撑门店日常销售管理，而不是只完成单点记录。
