# 试驾管理业务范围与边界

## 业务目标

试驾管理用于管理客户从预约试驾、车辆安排、到店确认、试驾执行到试驾结果反馈的过程。它帮助销售把客户体验变成可跟进的业务事实，并避免试驾车辆冲突、客户信息缺失和安全责任不清。

试驾是商机推进的重要节点，但试驾本身不等于成交，也不应直接创建订单。

## 目标用户

- 销售人员：发起预约、确认客户到店、记录试驾结果。
- 销售主管：查看试驾转化、协调车辆和处理异常。
- 库存或展厅人员：确认可试驾车辆和车辆占用。
- 管理者：观察试驾率、试驾后报价率和成交转化。

## 功能范围

试驾管理覆盖：

- 试驾预约。
- 客户和商机关联。
- 试驾车型或车辆确认。
- 预约时间维护。
- 到店确认。
- 试驾前安全确认。
- 试驾执行状态。
- 试驾结果记录。
- 取消、爽约和改期。
- 试驾后跟进任务。
- 试驾转化分析。

## 试驾信息

试驾记录至少应表达：

- 客户。
- 关联商机。
- 预约车型或车辆。
- 预约时间。
- 负责销售。
- 当前状态。
- 客户到店情况。
- 试驾结果。
- 客户反馈。
- 后续动作。

如涉及驾驶证、同行人、试驾协议等信息，只保存业务必要事实并控制可见范围。

## 试驾状态

试驾状态应至少区分：

- 待确认。
- 已预约。
- 已到店。
- 试驾中。
- 已完成。
- 已取消。
- 已爽约。
- 已改期。

试驾完成后应推动商机下一步动作，例如报价、继续跟进或战败分析。

## 非目标

试驾管理不承担：

- 车辆远程控制和车联网定位。
- 驾驶证真伪核验平台。
- 保险理赔系统。
- 展车维修保养工单。
- 试驾路线导航系统。
- 事故处理的完整法务流程。

## 成功标准

- 试驾预约不会与同一车辆或同一销售的关键时间冲突。
- 销售能够看到即将到来的试驾安排。
- 客户到店、完成、取消和爽约均有明确状态。
- 试驾结果能关联回客户和商机。
- 管理者能观察试驾对报价和成交的影响。
