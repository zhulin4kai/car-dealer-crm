# 收款退款流程规则与验收规格

## 主流程

### 收款计划

- 订单成立时应形成订金、尾款或全款等收款要求。
- 收款计划应明确金额、预计时间和责任人。
- 收款计划可以调整，但必须保留原因。

### 收款登记

- 销售或财务可以登记客户付款事实。
- 收款登记应包含订单、金额、类型、方式、付款时间和凭证摘要。
- 登记不等于财务确认。
- 收款凭证应受权限控制，不得随意公开。

### 收款确认

- 财务确认后，收款才计入实收。
- 确认失败或退回时，应说明原因。
- 多笔收款可以共同满足订单应收。
- 实收达到要求后，可以推动履约进入下一步。

### 退款

- 退款应基于订单取消、多收、价格调整或业务纠错产生。
- 退款申请必须说明原因、金额和关联原收款。
- 退款审批通过后进入退款执行或结果确认。
- 退款完成后应更新订单资金状态，但保留原收款和退款两条事实。

## 关键业务规则

- 收款登记和财务确认必须区分。
- 退款不能直接删除原收款。
- 订单取消不代表自动退款完成。
- 未确认收款不得作为交易完成依据。
- 退款金额不得超过可退金额，除非有明确纠错流程。
- 收款和退款导出应受独立权限控制。
- 金额展示应保持统一币种和精度口径。

## 指标要求

收款退款应支持观察：

- 订单应收金额。
- 已确认收款金额。
- 未确认收款金额。
- 欠款金额。
- 逾期应收数量。
- 退款申请数量。
- 已完成退款金额。
- 异常资金记录。

## 验收场景

- 订单创建后，可看到订金或尾款应收要求。
- 销售登记收款后，资金状态为待确认而不是已收。
- 财务确认收款后，订单实收金额增加。
- 收款被退回时，销售能看到退回原因。
- 订单取消后，可以发起退款申请，但原收款记录仍保留。
- 退款完成后，订单资金视图同时展示原收款和退款事实。
- 未确认收款不能使交易进入已完成。
