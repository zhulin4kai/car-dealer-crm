# 规则总览与优先级

## 规则用语

- **必须**：不可省略的要求。
- **禁止**：不可采用的做法。
- **应当**：默认遵守，偏离时必须说明理由。
- **可以**：根据实际情况选择。

## 适用方式

- 开始任务时先读取本文件，再根据目标文件的 `globs` 和任务性质读取相关规则。
- `globs` 表示主要代码范围，不排除测试、文档和跨层调用方必须同步遵守相关契约。
- 跨领域任务必须同时读取业务一致性、API、测试和交付规则，禁止只读取代码风格。
- 规则描述长期默认行为；用户对当前任务明确规定的范围、操作和验收方式优先执行。
- 偏离“应当”规则时必须说明具体原因、影响和替代保障；“必须”和“禁止”不得静默偏离。

## 优先级

1. 单次任务明确规定的范围、操作方式和验收要求。
2. 业务 Spec、安全和数据完整性。
3. API、状态机和数据契约。
4. 测试与验收规则。
5. 架构和代码风格。

- 高优先级要求不得静默放宽低优先级约束。
- 出现实质冲突时必须指出冲突文件、具体条款和可选处理方式后等待确认。
- 规则与工具配置不一致时必须同步修复，不得长期保留两套标准。
