# AI 业务助手开发规范

## AI 模块职责边界

- `dealer-web` 只调用 Spring Boot 的 `/api/ai/**` 接口，禁止直接调用 `dealer-ai`。
- `dealer-server` 是权限、数据范围、事务、状态机、审计、Provider 配置和业务写入的最终边界。
- `dealer-ai` 只负责 LangGraph 编排、模型调用、工具选择和供应商协议适配。
- LangGraph 是目标编排内核，禁止继续维护 `simple/langgraph` 双路线作为目标架构。
- `dealer-ai` 不连接数据库、Redis 会话或 Mapper，不保存用户 Bearer Token，不接收浏览器直接请求。
- 禁止用户输入、模型输出、工具参数驱动的通用任意 HTTP 能力。
- 禁止注册 `http_request`、URL fetch、webhook 调用、任意外部 URL 请求工具。
- Provider 地址必须来自管理员保存并由 Spring Boot 下发的运行时配置，不得来自用户输入、模型输出或工具参数。
- `dealer-ai` 只能调用 Spring Boot 内部 AI Tool API 和管理员启用的模型 Provider 地址。

## Provider 配置规则

- Provider 配置由管理员在系统内维护，`dealer-ai` 本地 env 只能作为开发兜底，不是正式模型配置来源。
- 系统支持多个全局 Provider 配置，同一时间只能有一个启用配置。
- 支持的协议格式固定为 `OPENAI_COMPATIBLE` 和 `ANTHROPIC`。
- Spring Boot 调用 `dealer-ai` 时必须携带本次 Run 的 `providerRuntimeConfig`。
- `providerRuntimeConfig` 只在服务间请求中存在，禁止进入前端响应、SSE、Run trace、日志、Prompt 或模型上下文。
- API Key 必须加密入库，响应只允许返回 `hasApiKey` 和 `maskedApiKey`。
- 编辑配置时不传 API Key 表示保留原密钥。
- 测试连接必须限次数、限 token、限超时，禁止触发业务工具和业务写入。
- Provider 原始错误必须映射为稳定错误码和可展示摘要。

## 业务枚举和值来源

- 后端 enum、DTO、Service 校验、数据库约束是可执行真源。
- OpenAPI 必须与后端可执行真源一致；不一致时视为契约错误。
- 前端类型必须从 OpenAPI 或后端稳定枚举同步。
- `dealer-ai` 只能使用“后端已接受 + OpenAPI 已声明”的交集值。
- `dealer-ai` 不得在 Python 编排、Prompt、Pydantic 默认值或测试夹具中临时创造业务值。
- 如果 AI 能力需要新的业务类型，必须先进入业务 Spec、后端状态设计、数据库约束、OpenAPI 契约和前端类型。

## 服务间用户上下文

- 浏览器只调用 Spring Boot。
- Spring Boot 是 AI Conversation、Run、Message、ToolCall、Proposal、Workflow 和主动事件的唯一业务控制面。
- Conversation 是多轮业务对话容器，Run 是一次执行；禁止把单次 Run 当作会话。
- 前端发送用户问题必须携带当前 `conversationNo`，或让 Spring Boot 按当前用户和业务对象上下文解析默认 Conversation。
- 同一用户和同一业务对象上下文默认复用一个活跃 Conversation；没有业务对象时使用通用 Conversation。
- Spring Boot 创建 AI Run 时，必须记录 run owner：用户 ID、必要的用户名摘要、入口、上下文对象引用。
- Spring Boot 创建 AI Run 前必须解析 Conversation，并写入 `conversationId`、`parentRunId` 和 `turnNo`。
- Spring Boot 调用 `dealer-ai` 时传递 runNo 或 runId、conversationNo、安全会话摘要、最近用户可见消息、必要上下文对象引用、工具 Schema 和 Provider runtime config。
- `dealer-ai` 不持久化 Conversation，只接收 Spring Boot 下发的 `conversationSummary` 和 `messageHistory`。
- `dealer-ai` 调用 Spring Boot 内部 Tool API 时，只能提交服务间 token、runNo 或 runId、toolName、arguments。
- Spring Boot 内部 Tool API 必须根据 runNo 或 runId 查询 AI Run，恢复 run owner，再以该 owner 的权限和数据范围执行工具。
- Tool arguments 中出现 `userId`、`role`、`permissions`、`dataScope`、`auditUserId` 等可信上下文字段时必须拒绝。
- 禁止以服务账号、管理员账号或 `dealer-ai` token 自身权限执行业务工具。
- 模型上下文只允许包含脱敏会话摘要、最近 8 条用户可见消息、当前问题、当前业务对象引用和本轮工具摘要。
- 模型上下文禁止包含权限、数据范围、API Key、Provider runtime config、服务间 token、内部 JSON 和供应商原始响应。
- Run trace 恢复只恢复单次执行；Conversation 恢复必须恢复多轮消息、每轮业务结果、Proposal、Workflow、Approval 和 ExecutionEvent。
- Conversation 详情必须按 turn 返回可恢复结构，禁止只返回 `latestRunTrace` 冒充完整会话。

## AI 前端 UI 与交互边界

- AI 前端展示状态固定为 `closed`、`sidebar`、`page`。
- 顶部导航栏必须提供浅色胶囊形“AI 助手”按钮，包含 Sparkles 类图标和文字。
- 右下角必须提供 48px 圆形渐变悬浮按钮，只展示图标，不展示文字。
- 顶部 AI 按钮和右下角悬浮按钮必须调用同一个打开右侧栏动作。
- 独立 AI 页面不显示右下角悬浮按钮。
- 其他登录后的 dashboard 页面在当前用户拥有 AI 权限时显示右下角悬浮按钮。
- 桌面端右侧栏必须通过布局列压缩主内容，不得做成 Dialog、普通弹窗或遮罩覆盖。
- 同一套 AI 对话面板必须复用于右侧栏和独立 AI 页面。
- `ai-api.ts` 是 AI 前端 API 入口，`ai.types.ts` 是 AI 前端类型入口，除非单独重构并替换全部引用，否则不得新增职责重复入口。
- AI 对话主视图必须业务结果优先，默认展示回答摘要、业务结果卡片、当前动作和业务风险提示。
- 工具结果必须渲染为消息气泡、表格结果、指标卡、对象引用卡、状态徽标、错误块、加载状态或空状态，不能把调试信息当作用户主结果。
- 工具结果必须按 CRM 业务对象类型建立中文字段映射，禁止直接把接口字段 key 渲染给用户。
- 交易、客户、库存、跟进任务等对象必须展示中文业务字段；金额、时间、状态必须格式化。
- 工具结果业务卡片必须来自实时 SSE payload 或持久化展示 payload；刷新和切换会话后卡片不得消失。
- 执行细节只能放在“查看处理过程”折叠区，默认关闭，视觉层级低于业务结论和业务结果卡片。
- Workflow 不得作为普通问答结果主体，不得默认展示内部编号、步骤类型、工具 code 或内部事件名。
- 对话中的操作按钮必须绑定当前问题和当前结果，禁止固定展示与本次问题无关的工作流快捷菜单。
- 用户可见模板禁止出现 `workflowNo`、`stepType`、`tranNo`、`stageLabel`、工具 code、Provider runtime config 或原始 JSON 字段名。
- 禁止直接展示内部工具 JSON。
- 模型 Markdown 必须通过单独安全组件渲染；该组件必须禁用 HTML 并进行 DOM 清理。
- 禁止渲染模型返回的 HTML，`v-html` 只允许用于经过清理的 Markdown 输出组件。
- 管理员模型配置页面必须只显示掩码密钥和测试结果，禁止在前端持久化明文 API Key。

## 工具调用规则

- Spring Boot `ToolRegistry` 是最终工具白名单和权限边界。
- `dealer-ai` 的 `ToolSchemaRegistry` 只能作为模型侧工具视图，不是权限来源。
- 工具调用必须经过 Spring Boot 内部 Tool API，禁止 `dealer-ai` 直接调用普通业务 API、Mapper 或数据库。
- 工具参数不得包含 `userId`、角色、权限、数据范围、审计操作者、组织范围等可信上下文字段。
- 禁止注册或执行 `run_sql`、`http_request`、`file_write`、`shell_exec` 或任何通用危险工具。
- 工具结果必须脱敏、限量、结构化，不直接返回数据库实体或内部 JSON 给用户。
- 工具调用验收必须覆盖完整链路：`dealer-ai` 选择工具、调用 Spring Boot 内部 Tool API、Spring Boot ToolRegistry 执行、写入 ToolCall trace、Run trace 恢复 toolCalls、前端刷新后展示恢复结果。
- ToolCall trace 必须保存脱敏展示 payload；只保存 `outputSummary` 不满足前端业务卡片恢复要求。

## Proposal 规则

- 未确认 Proposal 不产生业务写入。
- 确认 Proposal 时只执行后端已保存参数，前端不得提交新业务参数覆盖。
- Proposal 执行快照字段 `normalizedParams` 是用户确认后业务执行的唯一参数来源。
- `normalizedParams` 不作为前端展示字段，不进入 SSE 可展示 payload，不进入工具摘要。
- `paramsHash` 必须基于实际保存的 `normalizedParams` 计算。
- Proposal 过期、权限变化、数据范围变化或业务状态变化时必须拒绝执行。
- Proposal 创建、确认、拒绝、过期、权限变化、哈希不一致、业务执行成功和业务执行失败必须可追踪。
- 并发确认必须使用条件更新或等效乐观锁，只允许一个请求成功。
- 业务写入失败时，Proposal 必须进入失败状态，并保存失败 ExecutionEvent。
- 成功写入沟通记录或跟进任务后，仍必须写现有操作审计。

## SSE 和恢复规则

- 前端只订阅 Spring Boot SSE。
- `dealer-ai` 内部事件必须由 Spring Boot 转换为外部稳定事件。
- SSE 不得返回模型供应商原始响应、Token、Cookie、Authorization Header、API Key、内部堆栈或数据库错误。
- 断线或刷新后必须恢复 AI Conversation、Run 状态、消息、工具调用结果、Proposal、Approval、Workflow、主动提醒和执行事件。

## AI 代码风格规则

- Java、TypeScript、Python 标识符使用英文。
- 文档、注释和用户可见文案使用中文。
- 汉字、英文、数字之间必须加空格，例如“AI Run 状态”“Python 3.13.14”“LangGraph 编排”。
- 注释只解释业务边界、风险原因和非显而易见的状态机规则，不写无意义注释。
- Python docstring 使用三引号，描述模块、类、函数职责和边界。
- Prompt 文本属于安全边界文档，必须明确禁止模型伪造身份、权限、数据范围和执行高风险动作。
- 所有 AI 错误码、事件名、工具名和 Proposal 类型必须使用稳定英文编码，不通过中文 `message` 做业务分支。

## AI 测试规则

- 必须覆盖 `dealer-ai` 编排实际调用 `ToolClient`。
- 必须覆盖 LangGraph 图编排、工具节点、等待确认节点、失败节点和恢复事件。
- 必须覆盖 OpenAI-compatible 和 Anthropic Adapter 的 mock 测试。
- 必须覆盖 Provider 配置创建、测试连接、启用互斥、API Key 加密和掩码响应。
- 必须覆盖 ToolCall 成功和失败写入 trace，并通过 Run trace 查询恢复。
- 必须覆盖 Conversation 切换和刷新后的 turn 恢复，包含历史消息、业务卡片、Proposal 和 Workflow。
- 必须覆盖 Markdown 安全渲染，包含列表、表格、代码块和 HTML 清理。
- 必须覆盖 Proposal 确认、拒绝、过期、权限变化、哈希不一致、并发确认、幂等返回和业务执行失败。
- 必须覆盖前端不直连 `dealer-ai`。
- 必须覆盖危险工具不存在可执行入口。
- 禁止只写扫描测试冒充业务闭环测试。
