# 测试编写、执行与验收规范

## 测试选择

- 纯业务类、转换器、工具函数使用单元测试，不启动 Spring Context。
- Service 使用 Mockito 单元测试覆盖业务分支；事务、Mapper SQL 和数据约束使用 H2 集成测试。
- SecurityConfig、Filter、Handler、Controller 状态码和 JSON 契约使用 MockMvc 集成测试。
- Mapper XML 至少使用真实 H2 Schema 验证参数、resultMap、动态 SQL 和影响行数。
- Vue 组件使用 Testing Library 验证用户可见行为；composable、Store、API 适配使用 Vitest。
- 跨层认证、核心交易、库存和支付流程使用少量端到端式后端集成测试保护契约。

## 命名与结构

- Java 测试类命名为 `XxxTest`，集成测试按现有约定使用 `XxxIntegrationTest` 或明确场景名。
- Java 测试方法使用 `method_condition_expectedResult`，复杂场景可增加中文 `@DisplayName`。
- 前端使用 `describe` 表达对象、`it` 表达用户行为，名称使用英文结果句。
- 一个测试只验证一个主要行为，但必须断言该行为的全部关键结果和副作用。
- 测试采用 Arrange、Act、Assert；公共准备仅提取稳定夹具，禁止隐藏场景关键输入。
- Bug 回归测试必须在修复前能够失败，并在名称或注释中表达原问题条件。

## 后端单元测试

- 被测类使用真实实例，Mapper、Manager、CurrentUserProvider 等外部依赖使用 Mockito。
- 禁止 mock 被测类的 private 逻辑或核心业务动作；需要大量 partial mock 说明设计边界有问题。
- Mockito 保持严格模式；每个 stub 必须被场景使用，禁止全局 lenient 掩盖无效准备。
- 写操作必须验证 Mapper 参数、调用次数、影响行数处理、缓存失效和未发生的副作用。
- 异常测试同时断言异常类型、稳定错误码和关键依赖未被调用，不只断言中文 message。
- 时间、当前用户和随机值通过可控依赖提供，禁止测试依赖当前机器时钟和执行顺序。

## 后端集成测试

- 集成测试使用 `test` Profile、H2 Schema 和独立测试数据，不连接开发或生产数据库、Redis。
- 每个测试必须可独立运行，禁止依赖其他测试先插入数据或固定执行顺序。
- 涉及事务回滚时同时查询所有受影响表，确认不存在部分写入。
- Security 测试至少覆盖未登录、Token 无效、账号不可用、无功能权限和无数据权限。
- API 测试同时断言 HTTP 状态、业务 code、data 结构和必要响应头。
- SQL 方言差异无法由 H2 证明时必须明确报告，并增加 MariaDB/MySQL 验证计划。

## 前端测试

- 页面和组件测试从用户可见文本、角色和交互查询元素，禁止依赖内部变量和脆弱 DOM 层级。
- API 模块 mock 必须返回解包后的真实业务类型；错误场景使用 `ApiError` 和稳定 code。
- Store 测试覆盖初始状态、成功状态、失败清理、持久化同步和登出清空。
- 表单测试覆盖初始值、Schema 校验、提交转换、重复提交保护和服务端失败保留输入。
- 路由守卫测试覆盖未认证跳转、认证恢复、权限加载失败和正常放行。
- 异步断言使用 `findBy`、`waitFor` 或 Promise，禁止任意 sleep 和依赖计时碰运气。

## 必测风险

- 正常路径、空值和边界值、资源不存在、无权限、非法状态、并发冲突。
- 重复请求、事务中断、影响行数为 `0`、唯一约束冲突和缓存失败。
- 金额精度、库存不足、重复退款、重复转换及删除受限。
- 前端 loading、空状态、错误状态、取消操作、快速重复点击和未知错误码。

## 禁止退化

- 禁止删除断言、放宽 expected、跳过测试或关闭安全过滤器换取通过。
- 禁止把正确的生产行为改成测试 mock 所期待的错误行为。
- 禁止只验证“没有抛异常”；必须验证结果、状态和副作用。
- 禁止把失败测试标记为 ignored 或仅在本机排除而不说明根因。
- 测试暴露旧缺陷时，修复缺陷或明确记录阻塞，不得偷偷改写测试目标。

## 执行层级

1. 单文件修改：运行直接测试类或 Vitest 文件。
2. 模块修改：运行模块相关单元与集成测试；前端同时运行 `npm run typecheck`。
3. 共享组件、http-client、Security、数据库或跨模块修改：运行完整对应端测试。
4. 发布前或大范围改造：后端 `./mvnw test`，前端 `npm run check`。
5. 用户明确限制范围时遵守限制，并列出未运行的验证及风险。

```bash
cd dealer-server && ./mvnw -Dtest=TestClass test
cd dealer-server && ./mvnw test
cd dealer-web && npm test -- path/to/test.ts
cd dealer-web && npm run typecheck
cd dealer-web && npm run check
```

## 结果与验收

- 报告实际命令、退出状态、通过/失败/跳过数量和关键警告。
- 测试失败必须区分实现缺陷、测试缺陷、环境缺陷和既有失败，并提供证据。
- 未执行的测试不得宣称通过；依赖服务未启动不等于代码验证成功。
- 测试命令结束后确认没有遗留服务、Watch 进程和后台任务。
