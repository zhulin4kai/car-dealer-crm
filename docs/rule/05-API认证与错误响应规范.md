# API、认证与错误响应规范

## 路径与 HTTP 方法

- API 路径统一以 `/api` 开头，资源使用小写复数名词，禁止在路径中混入中文或实现类名称。
- GET 只读；POST 创建资源或执行不可幂等命令；PUT/PATCH 修改；DELETE 删除。
- 状态迁移使用明确命令子资源，如 `/transactions/{id}/approve`，禁止通用 `updateStage`。
- 业务对象 ID 优先放路径；筛选、分页和排序放查询参数；复杂命令放 Request DTO。
- 导入、导出、批量操作必须明确文件格式、数量限制、部分成功语义和错误结果。

## 请求契约

- 写接口使用用途明确的 Request DTO 和 Bean Validation，禁止直接接收持久化 Model。
- 必填、可空、默认值、长度、金额精度、日期格式和枚举范围必须在契约中明确。
- 新增或重构接口的 JSON 时间字段统一使用 ISO-8601 带时区字符串；历史接口仍返回 `yyyy-MM-dd HH:mm:ss` 时必须在 `docs/api/openapi.yaml` 标注兼容格式，禁止依赖单个字段临时注解或前端私有格式。
- 未提供字段与显式 `null` 的语义必须区分；更新接口禁止把未提交字段覆盖为空。
- 客户端不得提交可信操作人、权限范围、金额汇总和服务端决定的业务状态。
- 前端必须使用模块 API 和对应 TypeScript 类型，不得在页面临时拼装另一套请求结构。

## 响应契约

- JSON API 使用统一 `R` envelope；`code`、`msg`、`data` 的类型和缺省行为必须稳定。
- HTTP 状态表达协议结果，业务 code 表达可识别业务原因，二者禁止相互矛盾。
- 成功详情返回稳定 Response DTO；列表返回统一分页结构，空列表返回 `[]` 而不是 `null`。
- 删除或命令成功必须返回明确结果，不得以 HTTP 200 包装实际失败。
- 文件下载使用正确 Content-Type、Content-Disposition 和可解析文件名，不套 JSON envelope。
- 响应不得暴露密码、Token、内部异常、SQL、堆栈、权限实现和无关个人信息。

## HTTP 状态

- `200`：成功查询或命令；`201`：确实创建新资源且能提供资源标识时使用。
- `400`：参数格式、Bean Validation 或无法解析的请求。
- `401`：缺少、无效、过期或已撤销的认证会话。
- `403`：身份有效但功能权限或数据权限不足。
- `404`：允许向调用方披露的资源不存在；需要隐藏资源存在性时可统一为 `403`。
- `409`：并发冲突、重复提交、唯一约束或非法状态迁移。
- `500`：未预期系统异常；Redis、数据库等故障不得伪装成业务参数错误。

## JWT 与会话

- Token 只通过 `Authorization: Bearer <token>` 传递，禁止放入 URL、日志或业务请求体。
- JWT 只保存最小身份声明，不保存密码、手机号、权限全集和可变业务状态。
- Redis 会话是 Token 是否仍有效的服务端依据；JWT 合法不代表会话仍有效。
- 每次受保护请求必须校验 JWT、Redis 会话、数据库账号状态和权限上下文。
- 登出、禁用账号和强制失效必须删除 Redis 会话；失败时不得继续保留已认证上下文。
- 当前用户统一从 `CurrentUserProvider` 获取，业务层禁止自行解析 JWT 或信任客户端 userId。

## 功能权限与数据权限

- 写接口和敏感读接口使用后端 `@PreAuthorize` 或等价授权入口。
- 数据权限必须覆盖列表、详情、备注、导出、更新和删除，禁止只限制列表。
- Mapper 查询条件必须包含数据范围；禁止查询全部数据后在 Java 或前端过滤。
- 管理员绕过、本人访问和负责人访问必须有明确规则，禁止散落硬编码角色名。
- 前端权限码仅用于展示和导航，不作为安全边界。

## 错误码

- 业务错误码统一定义在后端 `CodeEnum`，名称表达稳定原因，发布后不得改变既有语义。
- 同一原因在不同接口使用同一 code；不同处理方式的原因不得共用模糊 code。
- `msg` 用于用户展示，可以优化文案；前端业务分支只能依赖 HTTP 状态和 code。
- 登录失败对未认证调用方统一返回 `AUTH_LOGIN_FAILED`，不得暴露账号是否存在、锁定或禁用。
- 未识别 code 由前端统一兜底，不得默认为成功或根据中文 message 猜测。
- 新增或修改 code 必须同步后端测试、前端错误码映射、`docs/api/openapi.yaml` 和 `docs/api/api-conventions.md`。

## 兼容与验证

- 删除、重命名字段或改变类型属于破坏性变更，必须提供迁移窗口或同步全部调用方。
- API 修改必须检查 Controller、Service、前端模块 API、TypeScript 类型、页面和契约测试。
- 认证权限修改至少验证未登录、登录成功、Token 失效、无功能权限和无数据权限。
- 错误响应测试必须同时断言 HTTP 状态、业务 code 和必要 data 结构，禁止只断言文案。
