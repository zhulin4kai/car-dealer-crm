# 日志与审计规范

## 记录位置

- HTTP 请求 ID、路径、方法、状态和耗时由 Filter/Interceptor 统一记录，Controller 不重复记录访问日志。
- Service/Manager 记录关键业务动作、状态迁移和业务失败，不记录每次普通查询。
- Redis、文件、外部接口等基础设施故障由对应组件记录，业务层只记录必要业务影响。
- 未处理异常由全局异常处理器记录一次，禁止 Controller、Service、Manager 层层打印同一堆栈。
- 审计记录用于证明业务事实，应用日志用于诊断运行问题，二者禁止互相替代。

## 日志级别

- `ERROR`：未预期异常、数据一致性风险、不可恢复基础设施故障，必须携带异常对象。
- `WARN`：认证失败、权限拒绝、非法状态、并发冲突、可恢复故障或明确降级。
- `INFO`：登录登出、关键业务命令、状态迁移、批量任务结果和系统生命周期事件。
- `DEBUG`：缓存命中、查询条件、技术分支和开发诊断，生产环境默认关闭。
- `TRACE`：默认禁止业务代码使用，确有底层诊断需要时必须避免高频和敏感数据。
- 禁止使用 `System.out`、`System.err`、`printStackTrace()` 和仅为证明“执行到了”的日志。

## 结构与字段

- 使用 SLF4J 参数化日志，禁止字符串拼接、对象整体序列化和无稳定字段的自然语言长句。
- 事件名和字段名使用稳定英文，推荐格式为 `event=... result=... field={}`。
- 请求日志按需包含 `requestId`、method、path、status、durationMs；禁止记录完整 query/body。
- 业务日志按需包含 `operatorId`、业务对象 ID、动作、结果、前后状态和 durationMs。
- 基础设施日志记录 key 类型、业务 ID、操作和失败原因，禁止输出完整 Redis Key 中的敏感值。
- 异常日志必须同时提供业务上下文和异常对象，禁止只记录 `e.getMessage()`。

```java
log.info(
        "event=tran_stage_change result=success tranId={} operatorId={} from={} to={}",
        tranId, operatorId, oldStage, newStage
);

log.error(
        "event=redis_read result=failed keyType={} businessId={}",
        keyType, businessId, exception
);
```

## 敏感信息

- 禁止记录密码、JWT、Authorization Header、Cookie、Session、Redis 会话值、密钥和验证码。
- 手机号、身份证、邮箱、地址、客户备注和支付信息必须脱敏、摘要或省略。
- 禁止直接记录 User、Customer、Payment、Request DTO 和 Response DTO 整体内容。
- 用户输入写日志前必须清理换行符和控制字符，防止日志伪造。
- 生产日志不得包含 SQL 参数全集、堆栈返回给客户端或可用于枚举账号的信息。

## 异常与失败

- 预期业务异常由稳定错误码表达，通常记录 `WARN` 或由统一边界记录，不按系统故障重复打印。
- 未预期异常记录 `ERROR` 和完整堆栈，对客户端只返回统一安全信息。
- 捕获异常后必须选择重新抛出、转换、补偿或明确降级；禁止仅记录后继续返回成功。
- 重试只记录最终失败为 `ERROR`，中间重试使用 `WARN/DEBUG`，避免同一故障形成日志风暴。
- 日志组件失败不得改变业务结果，但审计记录失败必须按业务重要性决定回滚或可靠补偿。

## 业务审计

- 登录安全事件、权限变更、客户归属、线索转换、交易状态、审批、支付、退款、发票和库存变化必须审计。
- 审计包含操作者、动作、业务对象、发生时间、结果、来源及必要的前后值。
- 操作者来自 `CurrentUserProvider`，禁止使用客户端提交的 `createBy/editBy/approveBy`。
- 成功审计必须与事务最终提交一致；业务回滚时禁止留下成功记录。
- 支付、退款、库存等审计必须关联原业务流水，禁止只保存中文描述。
- 审计记录禁止物理删除，查询权限和保留期限必须符合敏感数据要求。

## 数量与性能

- 禁止在循环中逐条输出 `INFO/WARN/ERROR`；批量任务记录总数、成功数、失败数和任务 ID。
- 高频请求成功日志应由统一访问日志采样或降级到 `DEBUG`，避免业务类重复输出。
- 大对象、集合和二进制数据不得进入日志；必要时记录数量、哈希或业务标识。
- 日志语句不得触发额外数据库查询、远程调用或昂贵序列化。

## 验证

- 认证和异常测试应验证响应不包含内部原因、Token 和堆栈。
- 关键审计流程测试成功提交、事务回滚、重复请求和操作者来源。
- 日志变更通过代码审查检查级别、字段、异常对象和敏感信息，不以控制台出现文字作为唯一验收。
