# 库存占用释放前端联动任务

## 任务目标

在库存车辆实例后端能力基础上，补齐前端库存车辆列表、占用释放操作、库存状态展示，并为试驾、报价订单和交付模块提供清晰联动入口。

## 修改范围

允许修改：

- `dealer-web/src/modules/product/api/product-api.ts`
- `dealer-web/src/modules/product/model/product.types.ts`
- `dealer-web/src/pages/dashboard/product/stock.vue`
- 新增 `dealer-web/src/modules/inventory/`
- 新增库存车辆列表、详情、入库、占用、释放、调整相关页面或组件。
- `dealer-web/src/router/routes.ts`
- `dealer-web/src/shared/constants/permissions.ts`
- 前端库存相关测试和前端文档。

禁止修改：

- 后端库存状态迁移规则。
- 商品目录状态语义。
- 试驾、报价订单和交付页面的核心流程，除非只接入库存选择组件。

## 当前代码落点

- 当前库存前端入口为 `dealer-web/src/pages/dashboard/product/stock.vue`。
- 当前商品 API 和类型集中在 `dealer-web/src/modules/product/`。
- 当前没有独立 `dealer-web/src/modules/inventory/`。

## 执行步骤

1. 新增库存车辆 TypeScript 类型和 API 函数。
2. 新增库存车辆列表，支持商品、车架号、状态、位置、占用类型和时间范围筛选。
3. 新增入库表单，选择商品并填写车辆唯一识别、颜色、配置和位置。
4. 新增占用、释放、调整和盘点异常处理入口。
5. 商品列表展示库存车辆状态摘要。
6. 路由和菜单接入库存管理权限。
7. 补充前端 API、路由、页面状态和权限测试。

## 交互要求

- 状态必须用文本表达，不只用颜色。
- 占用、释放、出库和异常处理必须有二次确认或原因输入。
- 查询失败保留当前筛选条件和上一轮成功数据。
- 快速重复查询不得由旧响应覆盖新条件结果。
- 无权限按钮不展示，但后端仍必须拒绝越权请求。

## 完成条件

- 库存人员能查看具体车辆库存列表。
- 入库后车辆出现在可售库存。
- 占用车辆在列表中显示占用类型、关联对象和有效期。
- 释放车辆需要原因，释放后状态更新。
- 前端类型检查和库存相关测试通过。

## 交付说明

完成后说明：

- 新增前端模块、路由和权限。
- 库存列表支持哪些筛选条件。
- 占用释放如何展示关联对象。
- 哪些联动等待试驾、报价订单或交付模块接入。

## 业务场景

- 车辆商品入库后支持可售、占用、锁定、释放、出库和盘点异常。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 库存状态表达车辆或库存数量事实，订单成立或锁车事件触发占用。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得让报价创建永久扣减库存，不得让商品编辑覆盖库存。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证库存数字和库存流水逐笔一致。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
