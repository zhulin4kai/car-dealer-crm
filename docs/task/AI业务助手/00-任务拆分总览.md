## 权威依据

- Spec：docs/spec/AI业务助手/00-架构边界与安全规格.md
- Plan：docs/plan/AI业务助手/01-AI业务助手落地方案.md

- Rule：docs/rule/10-文档与Spec治理规范.md
- Rule：docs/rule/12-日志与审计规范.md

## 全局不变量

- 普通业务页面继续调用普通业务 API。
- AI 入口只调用 `/api/ai/*`。
- Agent 服务只调用 `/api/ai-tools/*`。
- Agent 不直连数据库、不调用 Mapper、不执行任意 SQL、不执行任意 HTTP、不访问文件系统、不执行 Shell。
- Spring Boot 是权限、数据范围、事务、业务规则、状态机和审计的最终边界。
- 写操作必须通过 Proposal 和用户确认。
- 用户确认后只能执行后端已保存的规范化参数。

## 全局不得修改范围

- 不得把现有普通业务 Controller 改造成 AI 网关。
- 不得改变客户、线索、商品、交易、活动、用户、审计等普通页面的主调用路径。
- 不得绕过 `SecurityConfig`、`TokenVerifyFilter`、`CurrentUserProvider`、`DataScopeAspect`、`PermissionCodes`、`OperationAuditRecorder`。
- 不得降低现有权限、数据范围、事务、状态机、脱敏和审计要求。
- 不得新增 Agent 直连 DB、Redis 会话、Mapper、任意 HTTP、文件系统或 Shell 的入口。

- `cd dealer-web && npm run typecheck`
- `cd dealer-web && npm run test`

- 不得修改 Java、Vue、SQL、配置或测试代码。

## AI-02 AI Chat API 设计任务

### 任务编号

AI-02

### 任务名称

AI Chat API 设计

### 任务目标

设计 `/api/ai/chat` 和 `/api/ai/runs/{runId}`，让前端 AI 入口通过 Spring Boot 创建和查询 AI Run。

### 涉及文件/目录

- `dealer-server/src/main/java/com/autodealer/crm/ai/`
- `dealer-server/src/main/java/com/autodealer/crm/web/`
- `dealer-server/src/main/java/com/autodealer/crm/dto/`
- `dealer-server/src/main/java/com/autodealer/crm/result/CodeEnum.java`
- `docs/api/openapi.yaml`
- `dealer-web/src/modules/ai/api/ai-api.ts`
- `dealer-web/src/modules/ai/model/ai.types.ts`

### 前置条件

- 完成 AI-01。
- 确认 AI Run 和 Message 持久化方案。

### 具体工作

1. 设计创建 AI Run、继续对话、查询 Run 状态的 Request/Response DTO。
2. 输入只包含用户消息、会话引用和可选业务对象引用。
3. 后端从认证上下文取得当前用户，不接收客户端提交的可信用户 ID。
4. 响应使用 `R` envelope。
5. 错误响应使用稳定 `CodeEnum` 和 HTTP 状态。
6. 同步 OpenAPI 和前端 TypeScript 类型。

### 验收标准

- 未登录访问 `/api/ai/chat` 返回 `401`。
- 已登录用户只能查询自己的 AI Run。
- API 不返回模型供应商原始响应体、Token、堆栈或内部配置。
- 普通业务 API 不受影响。

### 不得修改范围

- 不得把 `/api/ai/chat` 设计成所有普通业务请求入口。
- 不得在 Chat Controller 内直接访问 Mapper。
- 不得在请求体中信任 `userId`、权限列表或数据范围。

### 风险点

- 对话上下文泄露敏感业务字段。
- Run 查询越权。
- 错误响应暴露模型供应商或后端内部信息。

## AI-04 AI Tool Registry 设计任务

### 任务编号

AI-04

### 任务名称

AI Tool Registry 设计

### 任务目标

建立工具白名单、工具 Schema、权限码、风险等级、确认要求、超时和审计动作的统一注册机制。

### 涉及文件/目录

- `dealer-server/src/main/java/com/autodealer/crm/ai/`
- `dealer-server/src/main/java/com/autodealer/crm/constant/PermissionCodes.java`
- `dealer-server/src/main/java/com/autodealer/crm/audit/AuditActionEnum.java`
- `docs/api/openapi.yaml`

### 前置条件

- 完成 AI-02。
- 完成 AI-03。

### 具体工作

1. 定义工具注册模型：`toolName`、`description`、`inputSchema`、`outputSchema`、`permissionCode`、`riskLevel`、`requiresConfirmation`、`readOnly`、`timeout`、`maxResultSize`、`auditAction`。
2. 工具调用前校验工具存在、启用、风险等级和权限码。
3. 工具输入按 JSON Schema 或等价校验执行。
4. 工具结果统一包装为专用 Tool DTO。
5. 工具注册表禁止动态接受模型创建的新工具。

### 验收标准

- 未注册工具无法调用。
- 工具权限码缺失无法上线。
- `R3_FORBIDDEN` 工具无法注册为可执行工具。
- 工具超时、最大结果数和审计动作可检查。

### 不得修改范围

- 不得让模型动态注册工具。
- 不得以字符串反射方式调用任意 Service 方法。
- 不得用普通业务 URL 列表替代 Tool Registry。

### 风险点

- 工具描述与实际权限不一致。
- Schema 过宽导致模型提交可信上下文字段。
- 工具超时拖垮业务线程。

3. 用户确认后读取已保存参数执行。

- Proposal 过期后不可执行。
- 参数哈希不一致不可执行。

### 不得修改范围

- 不得让 Agent 直接执行写 Service。
- 不得让前端确认时提交新业务参数覆盖 Proposal。
- 不得把高风险交易、资金、票据、库存动作降级为低风险。

### 风险点

- Proposal 参数保存不规范导致确认内容与执行内容不一致。
- 重试重复创建业务记录。
- 高风险动作绕过人工确认。

- 追踪数据过量保存敏感内容。
