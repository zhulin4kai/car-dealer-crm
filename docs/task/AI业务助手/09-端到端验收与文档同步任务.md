## 任务目标

完成 AI 助手整体端到端验收，证明功能真实可用，并同步 OpenAPI、backend、frontend、integration 和 agent-ai 文档。

## 禁止修改范围

- 不得用文档声明替代功能验证。
- 不得只以编译通过作为完成。
- 不得把真实 API Key 写入被 Git 跟踪文件。
- 不得提交 Git，除非用户明确要求。

## 验收场景

1. 管理员创建 Provider 配置。
2. 管理员测试连接。
3. 管理员启用配置。
4. 用户创建或恢复 AI Conversation。
5. 用户在 Conversation 中创建 AI Run。
6. SSE 返回模型响应。
7. AI 调用只读工具并展示结构化结果。
8. 用户继续提问，模型能使用当前 Conversation 的上一轮上下文。
9. AI 生成低风险 Proposal，确认前不写业务。
10. 用户确认 Proposal 后写入业务并可追踪。
11. LangGraph Workflow 执行工具节点、等待确认节点和失败处理。
12. 主动提醒生成并在前端展示。
13. 前端刷新后恢复 Conversation、最近 Run 和 Run trace。
14. 归档会话后默认列表隐藏，审计链保留。
15. 密钥泄露扫描无结果。

## 安全验证命令

- 运行密钥泄露扫描，覆盖 OpenAI、Anthropic、DeepSeek 常见密钥格式和 API Key 配置字段；允许本地未跟踪 env 文件，禁止 Git diff、文档示例、日志、trace、前端 store 和测试快照出现明文密钥。
- `rg -n "dealer-ai|localhost:8091" dealer-web/src`
- `rg -n "run_sql|http_request|file_write|shell_exec" dealer-ai/app dealer-server/src/main/java/com/autodealer/crm/ai`

## 真实模型验证约束

- 只在 mock、单元、集成、前端和契约验证通过后执行。
- 最多 2 次真实模型请求。
- 单次超时不超过 20 秒。
- 单次最大输出 token 不超过 128。
- 不循环、不并发、不无限重试。
- 跑出一个有效结果就停止。
- 交付说明只写模型名、调用次数、是否成功和脱敏摘要。

## 完成条件

- AI 助手整体链路可用。
- Provider 配置、LangGraph、Tool、Proposal、Workflow、主动提醒和前端工作台均验收。
- 文档与实现同步。
- 没有密钥泄露。
- 没有已知未完成项，或明确列出阻断原因。
