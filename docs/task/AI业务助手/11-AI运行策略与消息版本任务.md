# AI 运行策略与消息版本任务

## 任务目标

落地全局 AI 运行策略、消息编辑撤回、活动上下文分支和 SSE 单次执行恢复，使管理员配置、普通用户权限、会话持久化和真实流式传输形成同一条可验证链路。

## 前置阅读

- docs/spec/AI业务助手/00-业务范围与边界.md
- docs/plan/AI业务助手/10-AI运行策略与消息版本治理方案.md
- docs/rule/13-AI业务助手开发规范.md

## 允许修改范围

- dealer-server AI Policy、Conversation、Run、Message、Event、ToolRegistry、Provider、Proposal 相关代码、SQL 和测试。
- dealer-ai 运行策略输入、LangGraph 节点、SSE 和测试。
- dealer-web AI API、类型、对话面板、业务展示、策略管理页面和测试。
- Docker Nginx SSE 代理配置。
- docs/api、backend、frontend、integration 和 agent-ai。

## 禁止修改范围

- 不得物理删除或覆盖消息、Run、Proposal 和业务审计。
- 不得开放任意 URL、通用 HTTP、通用 SQL、文件或 Shell 工具。
- 不得只在前端隐藏工具或选项，后端和 `dealer-ai` 必须执行同一策略。
- 不得让断线重连再次启动同一 Run。
- 不得让管理员策略放宽权限、数据范围、危险工具禁令或密钥保护。

## 执行步骤

1. 新增全局 AI 运行策略模型、权限、API、并发版本和管理员页面。
2. 下发工具前计算策略、ToolRegistry 和 Run owner 权限交集，内部执行时再次校验。
3. 新增消息修订和 Run 活动上下文字段，落地编辑与撤回 API。
4. 编辑或撤回后重建活动分支摘要，失效未确认 Proposal，保留全部审计。
5. 新增 Run 事件持久化和原子启动，SSE 支持序号重放和多订阅观察。
6. 修复 LF、CRLF、多行 data、UTF-8 跨块、尾帧和反向代理缓冲。
7. 重构前端消息操作、逐字符显示、权限降级和无内部字段业务展示。
8. 补齐后端、AI 服务、前端、Schema、OpenAPI 和端到端测试。

## 完成条件

- 管理员可以管理工具、安全、联网、上下文和运行时限，配置真实生效。
- 普通用户可以使用 AI，但只能访问自己有权限和数据范围内的业务事实。
- 用户消息可编辑和撤回，旧分支不再污染上下文，已执行业务动作不回滚。
- 会话刷新后恢复完整有效消息和业务结果。
- SSE 首个增量在 Run 完成前到达，断线重连不重复执行。
- 未知工具 payload、对象 ID、权限码、内部枚举和原始 JSON 不进入普通用户主视图。
