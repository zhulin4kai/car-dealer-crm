# AI 模型供应商配置管理任务

## 任务目标

落地管理员可配置模型供应商能力，让 Spring Boot 成为 Provider 配置真源，并向 `dealer-ai` 下发本次 Run 的 `providerRuntimeConfig`。

## 禁止修改范围

- 不得修改普通业务模块语义。
- 不得让前端保存明文 API Key。
- 不得让 `dealer-ai` 访问数据库读取 Provider 配置。
- 不得把 API Key 写入日志、trace、SSE、测试快照或文档示例。

## 执行步骤

1. 新增 Provider 配置表和测试表结构。
2. 新增 Provider 配置 Model、Mapper、DTO、Service、Controller。
3. 新增 API Key 加密和掩码服务。
   - 非本地环境缺少 `AI_PROVIDER_KEY_ENCRYPTION_SECRET` 时必须启动失败。
   - 本地、开发、测试和 smoke 环境缺少 `AI_PROVIDER_KEY_ENCRYPTION_SECRET` 时，自动生成并复用 `~/.car-dealer-crm/ai-provider-key.secret`。
   - 本地自动密钥文件不得进入 Git；删除后旧 Provider API Key 密文需要重新录入。
   - 加密主密钥缺失、文件不可用和密文不可解时必须返回可理解错误，禁止只让用户查看后端日志。
4. 新增 Provider 配置权限码。
5. 实现创建、编辑、列表、详情、测试连接、启用、停用、轮换 API Key。
6. 保证同一时间只有一个启用配置。
7. 生成 `providerRuntimeConfig` DTO，供 Run 启动时传给 `dealer-ai`。
8. 同步 OpenAPI 和前后端类型。
9. 补齐单元、集成和权限测试。

## 完成条件

- 管理员能维护多个全局 Provider 配置。
- API Key 加密保存，响应只返回掩码。
- local/dev/test/smoke 环境不需要手动配置加密主密钥即可新增 Provider 配置。
- prod 等非本地环境仍必须显式配置加密主密钥。
- `OPENAI_COMPATIBLE` 和 `ANTHROPIC` 都可配置。
- 没有启用配置时 AI Run 不能启动。
- 启用配置变化后新 Run 使用新配置。
