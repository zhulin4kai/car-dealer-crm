# 现有 AI 实现审查任务

## 任务目标

对当前 AI 代码进行文件级审查，输出删除、保留、迁移、重写清单，为后续整体化代码收敛提供依据。本任务只审查和记录，不改业务代码。

## 前置阅读

- docs/spec/AI业务助手/00-业务范围与边界.md
- docs/plan/AI业务助手/08-现有AI实现审查与收敛方案.md
- docs/rule/13-AI业务助手开发规范.md

## 审查范围

必须审查：

- dealer-ai/app/api/routes/runs.py
- dealer-ai/app/core/config.py
- dealer-ai/app/providers/base.py
- dealer-ai/app/providers/openai_compatible.py
- dealer-ai/app/orchestrator/simple.py
- dealer-ai/app/orchestrator/langgraph_adapter.py
- dealer-ai/app/schemas/chat.py
- dealer-server/src/main/java/com/autodealer/crm/ai/dto/DealerAiRunRequest.java
- dealer-server/src/main/java/com/autodealer/crm/ai/service/DealerAiClient.java
- dealer-server/src/main/java/com/autodealer/crm/ai/service/impl/AiConversationServiceImpl.java
- dealer-web/src/modules/ai/
- dealer-web/src/pages/dashboard/ai.vue

## 已知审查基线

- `runs.py` 必须固定使用 LangGraph 编排器。
- `config.py` 只能保留服务运行参数和 Tool API 配置，不能读取正式模型供应商密钥。
- `openai_compatible.py` 必须从请求级 Provider runtime config 读取模型供应商配置。
- `DealerAiRunRequest.java` 必须包含 Provider runtime config。
- `ChatRunRequest` 必须包含 Provider runtime config。
- `AiConversationServiceImpl` 启动 Run 时必须读取启用 Provider 配置。
- 前端 AI 模块必须提供受权限控制的 Provider 配置管理页面。

## 执行步骤

1. 列出 AI 相关文件和职责。
2. 标记目标架构下必须删除的旧路线。
3. 标记目标架构下可以保留复用的能力。
4. 标记需要迁移到新契约的文件。
5. 标记必须重写的文件。
6. 输出代码审查报告，报告必须包含文件路径、问题、目标处理方式和验收方式。

## 完成条件

- 审查报告覆盖指定文件。
- 每个文件都有“删除、保留、迁移、重写”之一的结论。
- Provider 缺口、LangGraph 编排缺口、Spring Boot 运行契约缺口、前端配置缺口均被列出。

## 验证命令

- 运行旧编排残留扫描，目标运行路径不得命中旧编排路线、旧模型环境配置来源和无契约 Provider 传递。
- `git diff --check`

## 交付说明

完成后说明：

- 哪些文件必须删除。
- 哪些文件必须保留。
- 哪些文件必须迁移。
- 哪些文件必须重写。
- 哪些缺口会阻断真实模型端到端验收。
