# AI 会话管理落地任务

## 任务目标

按 AI 会话上下文管理方案补齐真实 Conversation 能力，让 AI 助手支持多轮业务对话、按轮次恢复消息和卡片、会话列表、会话归档、安全历史上下文和安全 Markdown 展示。

## 允许修改范围

- dealer-server AI Conversation、Run、Message、DTO、Mapper、Service、Controller、SQL 和测试。
- dealer-ai `ChatRunRequest`、LangGraph messages 组装和测试。
- dealer-web AI API、类型、对话面板、侧栏、独立页面、会话列表组件和测试。
- dealer-web AI Markdown 渲染组件、业务卡片组件和必要依赖。
- docs/api、backend、frontend、integration、agent-ai。

## 禁止修改范围

- 不得让前端直连 `dealer-ai`。
- 不得把 API Key、Provider runtime config、权限、数据范围、服务间 token 放入 Conversation、messageHistory、SSE 或 trace。
- 不得物理删除归档会话关联的 Run、Message、ToolCall、Proposal、Workflow、Approval 和 ExecutionEvent。
- 不得用单次 Run trace 冒充多轮会话恢复。
- 不得只保存工具摘要冒充业务卡片恢复。
- 不得直接渲染模型 HTML，不得在 AI 组件中任意使用 `v-html`。
- 不得把 `Object.entries(item)` 一类原始字段直出当作业务卡片。
- 不得在本任务中顺手重构 LangGraph 节点图；本任务只验证会话摘要、历史消息和工具展示 payload 能稳定进入现有 LangGraph 路径。完整节点图收敛由 `03-dealer-ai LangGraph编排任务.md` 负责。

## 执行步骤

1. 新增 `t_ai_conversation`，并给 `t_ai_run`、`t_ai_message` 增加会话字段。
2. 新增 Conversation model、Mapper、DTO、Service 和 Controller。
3. 调整 `CreateAiRunRequest`、`AiRunResponse`、`DealerAiRunRequest`，加入 `conversationNo`、`turnNo`、`conversationSummary` 和 `messageHistory`。
4. 创建 Run 前解析 Conversation：传入 `conversationNo` 时校验归属；未传时按当前用户和业务对象上下文复用或创建默认会话。
5. 每个 Run 写入 `conversationId`、`parentRunId` 和递增 `turnNo`。
6. 用户消息和助手消息同时写入 Run 和 Conversation 维度。
7. 给 `t_ai_tool_call` 增加 `display_payload_json`，ToolRegistry 成功执行工具后保存脱敏展示 payload。
8. `AiRunTraceResponse.ToolCallTrace` 返回 `displayPayload`。
9. `AiConversationDetailResponse` 返回 `turns`，每个 turn 绑定 Run、用户消息、AI 回答、ToolCall、Proposal、Workflow、Approval 和 ExecutionEvent。
10. Run 结束、取消或失败时更新 Conversation 的最近 Run、最近消息时间和累计脱敏摘要，不能只用当前 prompt 或最后回答覆盖。
11. dealer-ai 接收会话摘要和最近消息，并按 system、会话摘要、历史消息、当前问题、工具摘要顺序组装模型 messages。
12. 前端增加 Conversation turn 类型，`AiAssistantPanel` 改为 turn 视图，发送消息时携带 `conversationNo`，刷新和切换时恢复完整 Conversation。
13. 新增安全 Markdown 渲染组件，只允许基础 Markdown，禁止模型 HTML。
14. `AiToolResultCard` 支持交易、客户、库存、跟进任务和商品业务卡片，禁止原始字段直出。
15. dealer-ai 测试必须覆盖会话摘要、历史消息和工具结果 data 结构，防止恢复卡片再次丢失；不以 LangGraph 节点图是否完全重构作为本任务完成条件。
16. 更新 OpenAPI、前后端说明和端到端验收文档。
17. 补齐后端、dealer-ai、前端组件级测试和契约测试。

## 完成条件

- 同一业务对象连续提问能使用上一轮上下文。
- 无上下文时可以创建和恢复通用会话。
- 用户可新建、重命名和归档会话。
- 归档会话默认不出现在列表，但审计和 trace 保留。
- `DealerAiRunRequest` 含会话摘要和最近 8 条用户可见消息。
- dealer-ai 模型 messages 包含会话摘要和历史消息。
- 前端刷新后恢复整个 Conversation，而不是只恢复单个 Run。
- 切换会话再切回后，历史回答、业务卡片、Proposal、Workflow 和处理过程仍可见。
- 工具结果卡片来自持久化 `displayPayload`，不是 SSE 临时内存。
- AI Markdown 列表、表格、代码块可读展示，模型 HTML 被清理。
- 前端测试必须包含组件级行为测试，禁止只靠源码扫描宣称完成。
- 所有新增字段同步到 OpenAPI 和前端类型。
