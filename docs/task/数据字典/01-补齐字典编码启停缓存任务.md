# 补齐字典编码启停缓存任务

## 任务目标

按数据字典 Spec 和治理方案，补齐字典编码唯一性、启停、引用删除限制、缓存一致性和变更审计。

## 当前代码落点

- `DicController` 提供字典类型和值的创建、更新、删除、批量删除、刷新和清理。
- `DicServiceImpl` 已有字典写操作和缓存清理逻辑。
- 前端字典页面为 `DictManagementTabs.vue`、`type.vue`、`value.vue`。

## 执行步骤

1. 确认字典类型 code 唯一、字典值同类型下 code 唯一。
2. 补齐字典类型和值的启用、停用和排序规则。
3. 删除前检查业务引用，存在引用时拒绝删除或仅允许停用。
4. 字典读取缓存使用统一 key，变更后失效相关缓存。
5. 历史数据读取已停用字典时仍可展示名称。
6. 字典变更写操作审计。
7. 调整前端字典页面，展示编码、状态、排序、适用模块和影响提示。
8. 补充唯一约束、启停、引用限制、缓存和前端测试。

## 代码逻辑要求

- Mapper 写操作必须检查影响行数。
- 缓存删除使用受控 key，不得生产使用 KEYS。
- 字典 code 修改必须评估历史引用；核心 code 原则上不允许普通修改。
- 删除和批量删除必须限制数量并逐项说明失败原因。

## 完成条件

- 同一字典类型下不能创建重复 code。
- 停用字典项不再用于新增业务。
- 历史记录仍可展示已停用字典名称。
- 被业务引用的字典项不能普通删除。
- 字典变更后缓存一致。

## 业务场景

- 治理稳定编码、展示名称、启停、引用检查和缓存。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 字典状态表达口径可用性，核心状态机编码必须固定。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得修改核心编码造成业务语义漂移，不得删除被引用历史。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证字典引用保护、启停和稳定 code。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
