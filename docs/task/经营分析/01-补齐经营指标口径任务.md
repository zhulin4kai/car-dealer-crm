# 补齐经营指标口径任务

## 任务目标

按经营分析 Spec 和指标方案，补齐指标口径、数据来源、数据范围、前端展示和只读统计边界。

## 修改范围

允许修改：

- `dealer-server/src/main/java/com/autodealer/crm/web/StatisticController.java`
- `dealer-server/src/main/java/com/autodealer/crm/service/StatisticService.java`
- `dealer-server/src/main/java/com/autodealer/crm/service/impl/StatisticServiceImpl.java`
- `dealer-server/src/main/java/com/autodealer/crm/manager/StatisticManager.java`
- `dealer-server/src/main/java/com/autodealer/crm/result/SummaryData.java`
- `dealer-web/src/modules/statistic/`
- `dealer-web/src/pages/dashboard/index.vue`
- 统计相关测试和文档。

禁止修改：

- 统计查询反向修改线索、客户、商机、交易或库存状态。
- 将活动成本当正式财务成本。
- 将已取消交易计入成交完成数。

## 当前代码落点

- `StatisticController` 是当前统计接口入口。
- `StatisticServiceImpl` 和 `StatisticManager` 组合统计数据。
- 前端统计 API 和类型在 `dealer-web/src/modules/statistic/`，后台首页展示在 `dashboard/index.vue`。

## 执行步骤

1. 列出当前统计指标、接口、前端展示和数据来源。
2. 定义核心指标口径：线索、客户、商机、试驾、报价、订单、收款、库存、活动 ROI。
3. 为每个指标标明来源表、时间字段、状态过滤和数据范围。
4. 统计查询只读，不写业务状态。
5. 补齐数据范围、时间范围、空数据和异常响应。
6. 前端按模块展示漏斗、趋势、待处理异常和关键摘要。
7. 对商机、试驾、报价、交付等未落地模块，先保留接口扩展位置或显示未接入状态，不伪造数据。
8. 补充统计口径、权限、空数据和前端测试。

## 代码逻辑要求

- 成交金额不包含已取消交易。
- 交易完成口径以交易履约完成条件为准。
- 活动 ROI 需要显示来源、成本和成交贡献，不替代财务核算。
- 指标缓存必须可重算，并说明延迟。
- 大表统计必须评估索引，禁止无上限扫表。

## 完成条件

- 管理者能查看线索到成交漏斗。
- 成交统计排除已取消交易。
- 活动 ROI 口径清楚。
- 库存指标区分可售、占用、待交付和积压。
- 指标查询遵守数据范围。
- 统计读取不会修改业务状态。

## 交付说明

完成后说明：

- 每个指标的业务口径和来源表。
- 哪些指标等待未落地模块接入。
- 数据范围和时间范围规则。
- 前端展示和空数据处理。

## 业务场景

- 读取线索、客户、商机、报价、订单、收款、发票、库存、交付和活动事实生成指标。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 统计状态只表达计算和展示状态，不反向修改业务状态。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得展示无法下钻解释的混合口径，不得绕过数据范围。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证指标能从明细反算，普通用户统计与明细范围一致。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
