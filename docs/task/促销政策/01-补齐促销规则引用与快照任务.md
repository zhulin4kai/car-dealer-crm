# 补齐促销规则引用与快照任务

按促销政策 Spec 和适用方案，补齐促销状态、适用范围、叠加规则、报价引用校验、历史快照和使用统计。

## 执行步骤

1. 定义促销状态 code：草稿、待生效、生效中、暂停、已结束、已作废。
2. 补齐促销创建、编辑、生效、暂停、结束和作废命令。
3. 补齐适用范围字段：车型、门店、客户类型、库存范围、活动来源等。
4. 补齐叠加规则和预算或名额限制。
5. 新增促销可用性校验方法，供报价模块按客户、商品、库存、时间调用。
6. 报价引用促销时保存促销 ID、名称、优惠摘要和成交时状态快照。
7. 新增促销使用记录或统计查询。
8. 调整前端促销管理、状态操作和报价可选列表。
9. 补充状态、适用范围、叠加、历史快照和统计测试。

## 代码逻辑要求

- 促销不能直接修改商品基础价格。
- 暂停、结束、作废后不能被新报价引用。
- 已确认报价和历史订单仍能展示成交时促销摘要。
- 多个促销能否叠加由后端判断。
- 预算或名额扣减必须使用事务和并发保护。

## 完成条件

- 草稿促销不会出现在报价可选列表中。
- 生效促销只能被符合范围和时间条件的报价使用。
- 不可叠加促销不能同时选择。
- 历史订单保留成交时促销摘要。
- 管理者能查看促销使用次数和成交贡献。

## 交付说明

完成后说明：

- 促销状态 code 和允许动作。
- 适用范围和叠加规则字段。
- 报价/订单快照保存方式。
- 预算或名额并发保护方式。

## 业务场景

- 维护优惠政策、适用商品、时间、预算、叠加规则和报价引用。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 促销状态表达政策可用性，促销引用必须生成成交时快照。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得让促销修改商品基础价格或覆盖历史订单。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证促销值域、预算、快照和结算语义一致。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
