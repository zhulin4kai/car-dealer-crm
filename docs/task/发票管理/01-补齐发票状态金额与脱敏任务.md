# 补齐发票状态金额与脱敏任务

## 任务目标

按发票管理 Spec 和状态校验方案，补齐发票状态机、金额校验、作废红冲、权限和税务信息脱敏。

## 当前代码落点

- `TranServiceImpl.createTranInvoice` 创建发票记录。
- `TranServiceImpl.updateTranInvoiceStatus` 更新发票状态。
- `TranController` 暴露 invoice 相关接口。
- 前端发票页位于 `dealer-web/src/pages/dashboard/tran/invoice/[id].vue`。

## 执行步骤

1. 定义发票状态 code：待申请、待财务处理、已开票、开票失败、已作废、已红冲、无需开票。
2. 新增或调整发票申请、财务处理、开票成功、开票失败、作废、红冲、无需开票命令。
3. 开票申请校验订单、客户、可开票金额、已开票金额和票据信息。
4. 作废和红冲保留原因，并关联原发票。
5. 发票详情和导出按权限脱敏税务敏感信息。
6. 调整前端发票状态操作和交易详情发票摘要。
7. 补充金额、状态、权限、脱敏和前端测试。

## 代码逻辑要求

- 发票金额不得超过可开票金额。
- 发票状态迁移必须校验当前状态和操作者权限。
- 税务识别、银行账号、地址等敏感字段不能在列表和导出中完整暴露。
- 发票完成不代表车辆已交付。
- 发票历史记录禁止物理删除。

## 完成条件

- 财务能按状态处理待开票申请。
- 开票失败、作废和红冲有明确原因。
- 发票金额不能超过可开票金额。
- 票据信息访问和导出受到权限控制。
- 交易详情中的发票摘要与发票记录一致。

## 交付说明

完成后说明：

- 发票状态和迁移矩阵。
- 可开票金额计算方式。
- 作废和红冲如何保留历史。
- 税务敏感信息脱敏规则。

## 业务场景

- 订单满足开票条件后申请、开具、失败处理、作废、红冲和票据交付。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 发票状态表达票据事实，不能替代收款、交付或交易完成。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得物理删除原发票，不得让开票成功单独完成交易。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证作废、红冲、开票金额和交易履约关系。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
