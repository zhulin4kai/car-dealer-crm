# 新增试驾预约执行任务

## 任务目标

按试驾管理 Spec 和落地方案，新增试驾预约、改期、取消、签到、完成、未到店和车辆时间段占用能力。

## 修改范围

允许修改：

- 新增 `TestDriveController`、`TestDriveService`、`TestDriveServiceImpl`
- 新增 `TTestDrive`、Mapper、XML、DTO、Query、枚举。
- 库存占用 Service 接口，仅用于试驾时间段占用和释放。
- 商机和跟进任务 Service，仅用于阶段联动或生成下一步待办。
- 新增 `dealer-web/src/modules/test-drive/`
- 新增 `dealer-web/src/pages/dashboard/test-drive/index.vue`
- 新增试驾详情或操作组件。
- `dealer-web/src/router/routes.ts`
- 试驾相关测试和文档。

禁止修改：

- 试驾完成后自动赢单或创建订单。
- 用试驾占用替代销售锁定或订单占用。
- 绕过库存后端冲突校验。

## 当前代码落点

- 当前没有试驾后端和前端模块。
- 车辆和库存相关能力当前集中在商品/库存模块。
- 商机和跟进任务模块完成后，试驾需要与其联动。

## 执行步骤

1. 新增试驾表和状态枚举。
2. 实现预约，校验客户、商机、车辆、时间和负责人。
3. 预约成功后调用库存占用接口创建试驾时间段占用。
4. 实现改期，释放原时间段并占用新时间段。
5. 实现取消、签到、完成、未到店和异常。
6. 完成试驾后记录结果、客户反馈，并生成下一步跟进任务或推进商机阶段。
7. 新增前端试驾列表、预约表单、详情和状态操作。
8. 补充冲突、状态迁移、权限和前端测试。

## 代码逻辑要求

- 同一车辆同一时间段不能重复预约。
- 改期、取消和未到店必须记录原因。
- 试驾完成不能自动创建订单、收款或交付。
- 试驾反馈涉及客户沟通，详情和导出必须受权限控制。
- 车辆时间冲突必须由后端保证。

## 完成条件

- 试驾预约成功后产生车辆时间段占用。
- 同车同时间重复预约返回冲突。
- 取消试驾释放时间段占用。
- 完成试驾后记录客户、商机、车辆、执行人和结果。
- 前端能完成预约、改期、取消和完成操作。

## 交付说明

完成后说明：

- 试驾状态和允许动作。
- 车辆时间段冲突如何保证。
- 与商机和跟进任务如何联动。
- 哪些场景仍需库存实例任务先完成。

## 业务场景

- 客户基于商机或意向车辆预约、到店、安全确认、试驾和反馈。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 试驾状态表达预约和执行结果，试驾完成只影响商机推进依据。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得让试驾完成自动生成报价、订单或成交。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证试驾结果进入商机和客户视图，异常和爽约可追溯。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
