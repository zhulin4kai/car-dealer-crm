# 新增交付准备签收任务

## 任务目标

按交付管理 Spec 和交付方案，新增交付记录、准备清单、预约、签收、完成、异常和交易履约联动。

## 修改范围

允许修改：

- 新增 `DeliveryController`、`DeliveryService`、`DeliveryServiceImpl`
- 新增 `TDelivery`、`TDeliveryChecklistItem`、Mapper、XML、DTO、Query、枚举。
- 交易履约 Service 接口，仅用于交付完成后判断交易完成条件。
- 库存 Service 接口，仅用于交付完成后车辆出库或状态变更。
- 新增 `dealer-web/src/modules/delivery/`
- 新增 `dealer-web/src/pages/dashboard/delivery/index.vue`
- 新增交付详情或操作页面。
- `dealer-web/src/router/routes.ts`
- 交付相关测试和文档。

禁止修改：

- 用交付完成直接绕过收款和发票必要条件。
- 用库存出库替代客户签收事实。
- 实现物流运输全流程或售后维修服务。

## 当前代码落点

- 当前没有交付后端和前端模块。
- 交易详情当前可观察收款和发票，但缺少交付清单和签收记录。
- 库存实例任务完成后，交付应调用库存出库或状态变更接口。

## 执行步骤

1. 新增交付表和交付检查项表。
2. 定义交付状态 code：待准备、准备中、待客户确认、待交付、交付中、已签收、已完成、交付异常、已取消。
3. 实现创建交付、准备、预约、签收、完成、异常和取消。
4. 交付完成前校验订单、资金条件、车辆准备状态和资料清单。
5. 客户签收记录签收时间、签收人、交付人、车辆和资料确认结果。
6. 交付完成后调用库存状态变更，并通知交易履约判断完成条件。
7. 新增前端交付列表、详情、准备清单和签收操作。
8. 补充状态迁移、条件校验、权限、异常和前端测试。

## 代码逻辑要求

- 资金未满足交付条件时不能完成交付。
- 交付资料不完整不能被前端绕过。
- 交付完成和库存出库必须保持事务或补偿一致性。
- 交付异常必须记录原因、责任人和处理结果。
- 交付完成记录禁止普通物理删除。

## 完成条件

- 订单进入待交付后可以创建交付记录。
- 条件不满足时交付完成被拒绝。
- 客户签收事实可追溯。
- 交付完成后车辆不再是可售库存。
- 交易履约能观察交付完成状态。

## 交付说明

完成后说明：

- 交付状态和检查项。
- 完成条件如何校验资金、车辆和资料。
- 与库存出库和交易履约如何衔接。
- 前端交付入口和权限如何设置。

## 业务场景

- 订单进入交付准备后完成资料、车辆、预约、签收、异常和回访。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 交付状态表达车辆和资料交付事实，是交易完成必要条件之一。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得用交付完成绕过资金和票据条件。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证签收、出库、回访和交易完成条件关系。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
