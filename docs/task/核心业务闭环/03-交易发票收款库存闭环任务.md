# 交易发票收款库存闭环任务

## 任务目标

统一交易阶段、发票状态、收款幂等、库存占用释放和库存流水，保证交易完成、库存数字和资金记录可以对账。

禁止修改：

- 不让报价创建永久扣减实际库存。
- 不让单笔收款动作绕过发票和交付条件直接完成交易。
- 不通过删除支付或库存流水来修正金额。
- 不让商品编辑路径直接覆盖库存。

## 当前代码落点

- `TranServiceImpl.createTransaction()` 当前创建交易时会处理交易商品和库存，需要调整库存占用阶段。
- `TranServiceImpl.addTransactionProducts()` 涉及交易商品、金额和库存变化。
- `TranServiceImpl.approveTran()` 拒绝时存在库存恢复路径，需要统一库存流水。
- `TranServiceImpl.createTranInvoice()` 当前创建发票并推进交易阶段，需要与发票正式开具状态对齐。
- `TranServiceImpl.updateTranInvoiceStatus()` 负责发票状态变化，需要决定何时允许交易进入收款阶段。
- `TranServiceImpl.recordPayment()` 负责收款登记、金额累计和交易完成，需要增加幂等检查和完成条件检查。
- `ProductServiceImpl.restock()` 和相关库存调整路径需要统一走库存变动入口。
- `ProductMapper.updateStock()` 不能被业务 Service 直接散落调用。

## 执行步骤

1. 定义库存数量口径：
   - 当前 `t_product.stock` 若继续表示可售库存，报价创建不扣减。
   - 订单成立或明确锁车动作才扣减可售库存。
   - 拒绝、取消、退款恢复库存时必须与占用动作对称。
2. 建立统一库存变动入口：
   - 在库存服务中新增 `changeStock(productId, delta, type, businessId, remark)`。
   - 方法内部完成商品库存行加锁、库存非负校验、`t_product.stock` 更新和 `t_product_stock_record` 写入。
   - `type` 至少区分手工入库、交易占用、交易释放、审批拒绝释放、退款恢复、人工调整。
   - 所有库存变化在同一事务内完成。
3. 替换直接库存更新：
   - `TranServiceImpl.createTransaction()` 不再报价阶段扣库存。
   - 订单成立或审批通过后的明确占用点调用 `changeStock()`。
   - `TranServiceImpl.approveTran()` 拒绝释放库存时调用 `changeStock()`。
   - 交易取消、删除、退款恢复库存时调用 `changeStock()`。
   - `ProductServiceImpl.restock()` 调用 `changeStock()`，不直接更新库存。
   - 保留 `ProductMapper.updateStock()` 作为库存服务内部私有入口，其他 Service 不再直接调用。
4. 交易阶段与发票状态：
   - 采用先开票后收款规则时，`createTranInvoice()` 只创建发票申请，不直接把交易推进到可收款完成阶段。
   - `updateTranInvoiceStatus()` 在发票变为已开具时推进交易到待收款阶段。
   - 发票失败、作废或红冲时按交易当前状态决定是否回退或进入异常状态。
   - 交易完成条件必须同时检查已确认收款、发票正式状态和交付条件。
5. 收款幂等：
   - `CreatePaymentRequest.transactionRef` 或 `TPayment.transactionRef` 非空时必须业务判重。
   - `TPaymentMapper` 增加按 `transactionRef` 查询方法。
   - 已存在相同参考号时返回已有结果或拒绝重复入账，策略必须稳定。
   - 每一笔成功收款都写审计；交易完成另写交易状态历史。
6. 交易金额和收款完成：
   - `recordPayment()` 计算累计已收时只使用有效收款。
   - 未满足发票和交付条件时，即使收款已满额，也不能把交易标为完成。
   - 交易完成使用 CAS 或加锁，防止并发收款重复推进。
7. 前端展示：
   - 交易详情同时展示发票状态、收款状态、交付状态和当前阻塞点。
   - 收款按钮在前端按状态隐藏，但后端仍做强校验。
   - 重复支付参考号错误展示为明确业务提示。
8. 补充测试：
   - 报价创建不扣减库存。
   - 明确锁车或订单成立后库存扣减并写流水。
   - 拒绝、取消、退款恢复库存时库存和流水对称。
   - 发票未正式开具时不能完成交易。
   - 同一 `transactionRef` 重复提交不会重复入账。
   - 部分收款也写支付审计。
   - 全额收款但未交付时交易不完成。

## 代码逻辑要求

- 库存数字更新和库存流水写入必须在同一事务。
- 所有交易状态变化写 `t_tran_history`。
- 所有资金事实保留流水，不物理删除。
- 发票状态、收款状态、交付状态不得互相覆盖。
- 幂等检查必须在数据库唯一约束或加锁查询支持下完成。

## 完成条件

- 报价不会永久扣减实际库存。
- 交易库存占用、释放、退款恢复都能通过流水核对。
- 发票未满足规则时不能错误完成交易。
- 重复支付参考号不能重复入账。
- 每笔成功收款都有审计记录。
