# 核心业务闭环任务拆分总览

## 任务目标

把权限、商品促销、交易资金库存、基础资料历史保护、DDL 一致性和统计验证拆成可分配任务，减少多个 agent 同时修改同一文件。

## 前置阅读

- docs/plan/核心业务闭环/01-核心业务不变量治理方案.md
- docs/rule/07-测试编写执行与验收规范.md
- docs/rule/08-Git分支与提交规范.md
- docs/rule/10-文档与Spec治理规范.md

## 执行顺序

1. 权限数据范围与交易审批闭环。
2. 商品促销与报价契约。
3. 交易发票收款库存闭环。
4. 线索客户活动历史保护。
5. 字典删除与 DDL 一致性。
6. 统计口径与闭环验证。

## 职责分层

- 跨模块任务只负责业务不变量、共享文件、共享状态事件和跨模块验收。
- 模块任务负责本模块内部页面、接口、服务、模型、测试和文档落地。
- 当跨模块任务与模块任务同时涉及同一文件时，以本总览的文件所有权为准。
- 模块任务不得重新定义跨模块状态机，只能实现已定义的业务事件和完成条件。
- 跨模块任务不得吞并模块内部细节，模块内字段、页面和局部校验由模块任务承接。

## 协作规则

- 同一时间一个文件只交给一个任务修改。
- `TranServiceImpl.java` 涉及多个任务时，按方法分段处理；同一提交内不得混合无关方法。
- `TTranMapper.xml` 涉及权限和统计时，先完成权限范围，再由统计任务调整指标查询。
- 测试文件跟随对应业务任务修改，不单独拆出长期测试 spec。
- 每个任务提交前必须说明已验证场景和未覆盖风险。

## 完成条件

- 六个任务都有明确文件范围、执行步骤、验收条件和验证命令。
- 子 agent 可以按单个任务独立接手。
- 跨任务共享文件有优先级和修改边界。

## 业务场景

- 跨模块修复权限、商品促销契约、交易资金库存、历史保护、DDL 和统计口径。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 核心任务负责共享不变量和跨模块状态事件，不替代模块内部状态实现。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得和模块任务抢同一文件；共享文件以任务拆分总览 owner 为准。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证端到端场景从线索到经营分析可追踪。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
