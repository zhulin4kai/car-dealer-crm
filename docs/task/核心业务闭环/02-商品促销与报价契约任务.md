## 当前代码落点

- `CreateProductRequest.status` 和 `UpdateProductRequest.status` 接收字符串，需要限制稳定编码。
- `UpdateProductRequest.stock` 当前允许商品编辑提交库存，需要与库存调整入口隔离。
- `dealer-web/src/pages/dashboard/product/index.vue` 的商品状态选择和 `toProductPayload()` 需要确认只提交稳定编码。
- `ProductServiceImpl.updateProduct()` 直接更新商品对象，不能让库存字段被基础资料编辑覆盖。
- `ProductPromotionServiceImpl.addPromotion()` 和 `updatePromotion()` 需要校验商品、类型、折扣和值域。
- `dealer-web/src/pages/dashboard/product/promotion.vue` 需要把 `AMOUNT` 展示为每件直减，把 `PERCENTAGE` 按业务折扣展示。
- `TranServiceImpl.createTransaction()` 必须验证客户存在且当前用户可访问，并继续校验商品可售。
- `dealer-web/src/pages/dashboard/tran/index.vue` 创建交易时应加载在售商品候选。
- `TranServiceImpl.addTransactionProducts()` 必须按全部有效交易商品重算金额。

## 执行步骤

1. 商品状态编码：
   - 定义后端商品状态常量或枚举，至少包含 `on_sale`、`off_sale`。
   - `CreateProductRequest.status` 和 `UpdateProductRequest.status` 增加白名单校验。
   - 前端状态 Select 的 value 使用 `on_sale/off_sale`，label 使用“上架/下架”。
   - `formatProductStatus()` 只负责展示，不参与提交值。
2. 商品库存隔离：
   - 从 `UpdateProductRequest` 移除库存字段，或在 `ProductController.updateProduct()` 显式忽略库存字段。
   - `ProductServiceImpl.updateProduct()` 更新基础信息、价格、分类、规格、状态和最低库存，不直接覆盖现有库存数量。
   - 库存变化只允许通过库存入库、调整、占用、释放入口处理。
3. 在售商品候选：
   - 在 `ProductService` 增加只查询可售商品的服务方法，或在现有列表查询中支持 `status=on_sale` 的后端过滤。
   - `dealer-web/src/pages/dashboard/tran/index.vue` 加载交易商品候选时只请求在售商品。
   - 保存交易时服务端仍保留 `on_sale` 校验，防止伪造请求。
4. 交易客户授权：
   - 在 `TranServiceImpl.createTransaction()` 插入交易前调用客户访问校验。
   - 校验内容包括客户存在、客户在当前操作者数据范围内、客户未处于不可交易状态。
   - 伪造其他销售的 `customerId` 必须被拒绝。
5. 促销类型和值域：
   - 后端只接受 `PERCENTAGE` 和 `AMOUNT`。
   - `PERCENTAGE` 必须满足 `0 < discount <= 1`。
   - `AMOUNT` 必须满足 `discount > 0`，并按每件直减语义计算。
   - 校验 `startTime < endTime`，商品必须存在且未删除。
   - 前端页面把 `AMOUNT` 文案调整为“每件直减”，不显示为“满减”。
   - 前端展示百分比折扣时，`0.8` 显示为“8折”，不显示为“0.8折”。
6. 交易金额重算：
   - 明确 `addTransactionProducts()` 是增量添加还是完整替换。
   - 如果保留增量语义，插入新行后从数据库查询该交易全部行项并重新汇总。
   - 如果改成完整替换语义，重命名或新增方法，并修改调用方，使业务含义清楚。
7. 促销结算预览：
   - `TranServiceImpl.getSettlementPreview()` 的促销计算结果与前端详情展示一致。
   - 促销快照保存成交时的类型、折扣、名称和适用商品。
8. 补充测试：
   - 前端商品状态提交 `on_sale/off_sale`。
   - 后端拒绝非法商品状态。
   - 商品编辑不改变库存数量。
   - 八折促销按 `0.8` 计算并展示“8折”。
   - 每件直减促销按数量计算优惠。
   - 下架商品不能进入新交易。
   - 伪造无权客户 ID 创建交易被拒绝。
   - 增量添加商品后交易总金额等于全部行项汇总。

## 代码逻辑要求

- 商品状态、促销类型和促销状态集中定义常量或枚举。
- 前端类型定义中状态和类型尽量收敛为联合类型。
- 服务端校验失败返回稳定业务错误，不返回笼统保存失败。
- 价格和折扣使用 `BigDecimal`，不得用浮点数参与后端金额计算。
- 商品候选过滤是体验优化，服务端校验是最终边界。

## 完成条件

- 页面新建“上架”商品后，接口保存 `on_sale`，该商品可进入交易候选。
- 编辑商品基础资料不会覆盖库存数量。
- 促销页面、促销接口和结算预览对 `PERCENTAGE/AMOUNT` 的理解一致。
- 交易创建不能绑定无权客户，不能选择下架商品。
- 交易金额重算覆盖全部有效商品行。

## 业务场景

- 跨模块修复权限、商品促销契约、交易资金库存、历史保护、DDL 和统计口径。

## 状态事件要求

- 核心任务负责共享不变量和跨模块状态事件，不替代模块内部状态实现。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得和模块任务抢同一文件；共享文件以任务拆分总览 owner 为准。
- 不得为了让测试通过而降低业务断言或删除历史事实。
