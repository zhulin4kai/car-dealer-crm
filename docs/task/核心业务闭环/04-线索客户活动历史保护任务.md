## 当前代码落点

- `dealer-web/src/pages/dashboard/clue/index.vue` 构造编辑请求时需要支持空字符串、空数组或 null 的明确提交。
- `ClueServiceImpl.saveClue()` 已有保存入口，需要区分字段未提交和字段提交为空。
- `ClueServiceImpl.delClueById()` 和 `batchDelClueByIds()` 需要检查线索是否已转客户或已被客户引用。
- `CustomerManager.convertCustomer()` 负责线索转客户和自动创建交易，客户和交易归属需要继承同一个业务负责人。
- `CustomerController.getCustomerList()` 新接口使用 `page/size`，但客户前端仍存在提交 `current` 的路径。
- `TCustomerRemarkMapper` 和 `TCustomerRemark` 已存在，需要补齐客户跟进记录的服务、接口和前端维护入口。
- `ActivityServiceImpl.deleteActivity()` 和 `batchDeleteActivities()` 当前删除活动前需要检查活动备注、关联线索、客户、商机、报价或订单。

## 执行步骤

1. 线索编辑空值提交：
   - 检查 `clue/index.vue` 的表单转请求函数。
   - 移除 truthy 过滤，确保用户清空地址、微信、备注、意向描述等可选字段时请求包含对应字段。
   - 后端 DTO 或 Query 对象明确区分未提交字段和提交为空。
   - Mapper 更新语句对允许清空的字段写入空值。
2. 线索手机号并发去重：
   - 保留服务层重复手机号检查，用于返回友好错误。
   - 在生产 DDL 中补齐手机号唯一约束，重复键异常转换为稳定业务错误。
   - 批量导入时同批次和数据库已有线索都必须检查。
3. 已转客户线索保护：
   - `delClueById()` 删除前查询线索状态和客户引用。
   - 线索状态为已转客户，或 `t_customer.clue_id` 引用该线索时拒绝物理删除。
   - 批量删除逐条检查，返回不可删除 ID 或整体拒绝，策略必须在 API 文档中明确。
4. 转客户归属继承：
   - `CustomerManager.convertCustomer()` 获取原线索负责人作为业务负责人。
   - 创建客户时使用该负责人。
   - 自动创建的首个交易、商机或报价也使用该业务负责人。
   - 当前操作人只作为 `editBy`、审计操作者或转换执行人记录。
   - 管理员代转销售线索后，销售仍能看到客户和后续交易对象。
5. 客户分页统一：
   - `dealer-web/src/pages/dashboard/customer.vue` 改为调用 `getCustomerList({ page, size, ...filters })`。
   - 删除仍使用 `{ current }` 的客户列表路径。
   - 后端保留旧接口时标记兼容，不作为新页面调用入口。
   - 翻页时第二页必须使用后端第二页数据，不得继续显示第一页。
6. 客户跟进入口：
   - 基于 `TCustomerRemarkMapper` 增加客户备注 Service 和 Controller。
   - 支持新增、分页查询、编辑和删除或软删除客户跟进记录。
   - 客户详情页展示客户跟进时间线。
   - 成交后回访、金融跟进、交付回访都能追加到客户时间线。
7. 活动删除保护：
   - `deleteActivity()` 删除前检查活动备注、关联线索、关联客户和后续成交归因。
   - `batchDeleteActivities()` 与单个删除使用同一检查函数。
   - 已产生线索、客户、成交归因或备注的活动只能关闭或停用，不能物理删除。
   - 前端删除失败时展示具体不可删除原因。
8. 补充测试：
   - 清空线索字段后数据库值为空。
   - 已转客户线索删除失败。
   - 管理员代转客户后客户和自动交易归属为原线索负责人。
   - 客户第二页请求参数为 `page/size` 且返回非第一页数据。
   - 客户跟进可以新增并在详情时间线展示。
   - 已产生线索或备注的活动删除失败。

## 代码逻辑要求

- 历史事实保留优先于删除便利。
- 业务负责人和操作人分开记录。
- 批量删除与单个删除使用同一业务校验。
- 分页参数统一为 `page/size`，旧 `current` 只能作为兼容层。
- 前端不通过过滤空值破坏用户主动清空语义。

## 完成条件

- 线索可选字段能被用户主动清空。
- 已转客户线索不能被物理删除。
- 转客户后客户和后续首个交易对象归属一致。
- 客户分页使用统一契约。
- 客户跟进记录可维护。
- 活动存在业务引用时不能物理删除。

## 状态事件要求

- 核心任务负责共享不变量和跨模块状态事件，不替代模块内部状态实现。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得和模块任务抢同一文件；共享文件以任务拆分总览 owner 为准。
- 不得为了让测试通过而降低业务断言或删除历史事实。
