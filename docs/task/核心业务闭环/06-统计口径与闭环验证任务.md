## 任务目标

重定义成交金额、交易金额、交易数、成交客户数和转化率口径，保证统计数据与当前用户数据范围一致，并补齐少量核心业务闭环集成验证。

## 当前代码落点

- `StatisticManager.loadSummaryData()` 当前汇总成交金额、客户数、线索数和总交易金额。
- `TTranMapper.selectBySuccessTranAmount()` 已按完成阶段统计成交金额。
- `TTranMapper.selectByTotalTranAmount()` 当前汇总所有阶段交易金额，需要重新命名或限定口径。
- `TTranMapper.selectByTotalTranCount()` 当前按去重客户统计，不适合命名为交易数。
- `TTranMapper.selectBySuccessTranCount()` 当前按完成交易去重客户统计，可用于成交客户数但不能当交易数。
- 统计查询需要接入与交易、客户、线索一致的数据范围。

## 指标口径

### 成交金额

- 分子：`stage = COMPLETED` 的交易金额。
- 时间口径：成交完成时间；若当前缺少完成时间，短期使用交易更新时间并在 plan 中标注后续补字段。
- 数据范围：当前用户可访问的交易。

### 在途交易金额

- 分子：非终态、非取消、非失败交易金额。
- 不包含已拒绝、已取消、已丢失、已完成交易。
- 页面名称不得写成成交金额。

### 交易数

- 分子：符合阶段和时间条件的 `t_tran.id` 数量。
- 不使用去重客户数替代。

### 成交客户数

- 分子：完成交易中的去重客户数量。
- 与交易数分开展示。

### 转化率

- 分子、分母必须明确：
  - 线索转客户率：转客户线索数 / 有效线索数。
  - 报价成交率：完成交易数 / 有效报价数。
  - 活动成交率：活动归因完成交易数 / 活动有效线索数。
- 分母为 0 时展示为空或 0，规则必须统一。

## 执行步骤

1. 重命名或拆分统计字段：
   - 后端 DTO 中区分 `successTranAmount`、`activeTranAmount`、`tranCount`、`successCustomerCount`。
   - 如果保留旧字段，必须在前端展示文案中使用准确含义。
2. 调整 `TTranMapper.xml`：
   - `selectByTotalTranAmount()` 改为明确口径，或新增 `selectActiveTranAmount()`。
   - `selectByTotalTranCount()` 改为 `COUNT(t_tran.id)`。
   - 新增成交客户数查询，使用 `COUNT(DISTINCT customer_id)` 且限定完成阶段。
   - 所有统计 SQL 支持数据范围参数。
3. 调整 `StatisticManager.loadSummaryData()`：
   - 使用新的 Mapper 方法。
   - 传入当前用户数据范围。
   - 不同指标使用不同字段名，避免前端误读。
4. 调整 `loadSaleFunnelData()`：
   - 漏斗每个阶段来自明确业务对象。
   - 交易阶段、商机阶段、成交客户数不要混在同一层级。
   - 每个漏斗值可以通过明细查询复核。
5. 调整前端仪表盘：
   - 页面标签与指标口径一致。
   - 普通用户看到的统计与其列表明细一致。
   - 指标卡片不展示无法解释的混合口径。
6. 核心闭环集成验证：
   - 使用真实 Controller、Service、Mapper 和测试数据库。
   - 覆盖销售创建交易、主管审批、财务开票、财务收款、交易完成。
   - 覆盖商品状态中文展示到稳定编码提交。
   - 覆盖促销八折提交 `0.8` 和结算金额。
   - 覆盖伪造其他销售客户 ID 创建交易失败。
   - 覆盖库存变动流水对账。
   - 覆盖字典引用删除失败且业务备注保留。
7. 前后端契约验证：
   - 使用前端真实 API 包装层生成请求参数。
   - 不只在后端测试中手工构造 `on_sale`、`PERCENTAGE` 等理想值。
   - 对客户分页、商品状态、促销折扣和交易创建请求做契约测试。
8. 文档同步：
   - `docs/api/openapi.yaml` 更新统计字段含义。
   - `docs/frontend.md` 更新仪表盘指标展示口径。
   - `docs/backend.md` 更新统计 Mapper 口径和数据范围要求。

## 代码逻辑要求

- 指标字段名必须表达业务含义，不能用含糊的 total。
- 统计 SQL 不得绕过数据范围。
- 统计口径必须能用明细反算。
- 集成测试优先覆盖真实链路，不用过量 Mock 掩盖契约问题。
- 测试数据库结构必须与生产核心约束一致。

## 完成条件

- 成交金额只统计完成交易。
- 交易数按交易记录统计。
- 成交客户数按完成交易去重客户统计。
- 普通用户统计可以下钻到同范围明细。
- 核心链路集成测试覆盖销售、主管、财务完整路径。
- 前端真实请求不会再次提交中文商品状态或错误分页参数。
