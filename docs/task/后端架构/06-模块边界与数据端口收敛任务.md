# 模块边界与数据端口收敛任务

## 目标

- 清除所有跨模块 `persistence.mapper`、`persistence.model`、`application.internal` 和 `domain` 依赖。
- 让大型用例实现只通过目标模块公开契约访问外部事实。
- 不按行数机械拆分事务流程，不复制锁、CAS、状态机或审计逻辑。

## 实现

- 在事实拥有模块建立 `application.api.port`，MyBatis Mapper 在模块内部实现对应端口。
- 将真实跨模块数据模型移动到 `application.api.model`，原 persistence 模型文件直接迁走。
- AI 对跟进关联对象的访问改为 `FollowRelatedObjectAccess`，实现仍由跟进模块内部持有。
- `shared` 与业务模块保持单向依赖；`bootstrap` 只负责应用和安全装配。
- 架构测试把 sales、commerce、fulfillment 的每个子域视为独立模块，禁止通过同组目录绕过边界。

## 验证

```bash
cd dealer-server
./mvnw -Dtest=BackendModuleBoundaryTest,MapperXmlCompletenessTest test
```

结果：7 项通过；跨模块内部依赖清单为空，77 个 Mapper 均显式标注并由 75 个 XML 递归引用。
