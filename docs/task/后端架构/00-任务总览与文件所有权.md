## 执行边界

- 本目录只承载内部架构重构任务，不改变业务 Spec。
- 所有批次默认保持 API、Schema、权限、状态、错误码和前端行为不变。
- 包迁移批次只处理目录、包声明、import、Mapper namespace、测试和技术文档。
- Service 职责拆分在目录迁移稳定后单独执行，不与机械迁移混合。
- 未经用户要求不提交 Git；每批差异必须能独立验证和回退。

## 文件所有权规则

- 同一生产类、测试类和 Mapper XML 只属于一个迁移批次。
- 共享类只有满足两个以上模块稳定复用且不包含具体业务语义时才可进入 `shared`。
- 多个模块需要同一业务能力时，由事实拥有模块提供 `application.api`，禁止复制实现。
- 批次发现旁支业务缺陷时记录到对应业务目录，不在架构任务中静默修复。
- 每个后续 Task 在开始前补齐精确文件清单、调用方和验证命令。

## 总体验证

```bash
cd dealer-server && ./mvnw -DskipTests compile
cd dealer-server && ./mvnw test
git diff --check
```

执行结果必须报告命令、退出状态、测试数量和未验证风险。
