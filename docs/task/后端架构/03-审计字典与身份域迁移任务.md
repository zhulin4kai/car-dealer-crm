# 审计、字典与身份域迁移任务

## 权威依据

- Plan：`docs/plan/后端架构/01-后端模块化目录重构方案.md`

- Rule：`docs/rule/01-开发流程与架构边界.md`
- Rule：`docs/rule/02-Java后端代码风格.md`
- Rule：`docs/rule/04-数据库与MyBatis规范.md`
- Rule：`docs/rule/07-测试编写执行与验收规范.md`

## 目标

- 建立 `modules.audit`、`modules.dictionary`、`modules.identity` 三个业务模块。
- 将稳定跨模块错误、响应、分页、安全和缓存契约迁入 `shared`。
- 同步迁移 Controller、应用接口/实现、领域规则、Mapper/Model、XML 和单元测试。
- 保持 API、SQL、Schema、权限码、错误码、事务和状态行为不变。

## 文件所有权

### shared

- `shared.error`：`CodeEnum`、`BusinessException`。
- `shared.web`：`Result`、`ResponseUtils`。
- `shared.pagination`：`BaseQuery`、`PaginationConstants`。
- `shared.security`：`PermissionCodes`、`AuthenticationConstants`、`JWTUtils`。
- `shared.infrastructure.cache`：`RedisKeys`、`RedisManager`、`CacheUtils`。
- `shared.infrastructure.json`：`JSONUtils`。

### audit

- Web：`AuditLogController`。
- Application API：`AuditLogService`、全部审计 Recorder、审计 Query。
- Domain：`AuditSensitiveDataSanitizer`。
- Application internal：`AuditLogServiceImpl`。
- Persistence：登录、操作日志的 Mapper、Model 和 XML。

### dictionary

- Web：`DicController`。
- Application API：`DicService`、`DicEnum`、字典 Query 和四个增改请求对象。
- Application internal：`DicServiceImpl`。
- Persistence：`DicMapper`、`TDicTypeMapper`、`TDicValueMapper`、对应 Model 和 XML。

### identity

- Web：用户、资料、凭证、会话、生命周期、历史、组织和授权 Controller。
- Application API：身份 Service、身份 DTO、身份枚举、当前用户/会话与访问门禁契约。
- Application internal：身份 Service 实现、凭证投递、组织责任、数据范围和账户安全协调器。
- Domain：手机号、会话摘要和身份资格规则。
- Persistence：用户、凭证、会话、组织、岗位、汇报、角色、权限及关联表的 Mapper、Model 和 XML。
- 授权变更历史归属 identity；审计模块只提供通用审计动作、脱敏和记录能力。
- Test：对应单元测试迁入同构包；跨模块集成测试保留在 `integration`。

## 禁止修改范围

- 不修改前后端 API 路径、请求体、响应体和错误码。
- 不修改 SQL、Schema、索引、种子数据和 MyBatis statement 语义。
- 不改变认证、授权、数据范围、会话、审计和凭证安全规则。
- 不在本任务拆分大型 Service；大型职责拆分由任务 06 负责。
- 不新增依赖、不启动服务、不提交 Git。

## 执行步骤

1. 迁移共享底座并补齐同包隐式依赖的显式 import。
2. 迁移审计模块及其 XML，执行审计和 Context 定向测试。
3. 迁移字典模块及其 XML，执行缓存、Mapper 和 Service 定向测试。
4. 迁移身份模块及其 XML，执行认证、授权、会话、组织、凭证和用户回归。
5. 清理旧 FQCN、旧源文件和跨模块非公开依赖。
6. 执行干净构建、后端全量测试和差异审计。

## 完成条件

- 三个模块的生产文件、测试和 XML 均位于目标目录。
- 旧审计、字典、身份业务路径清零，不存在副本、转发类或旧包入口。
- 模块间只依赖目标模块的 `application.api` 或 `shared`。
- Context、Mapper XML、认证授权和全量测试通过。
- 差异只包含目录、包、import、namespace、边界适配和对应技术文档变化。
