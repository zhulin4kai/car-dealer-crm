# 补齐客户档案归属合并任务

## 任务目标

按客户管理 Spec 和治理方案，补齐客户重复检查、归属转移、客户合并、敏感字段脱敏、导出权限和删除限制。

禁止修改：

- 通过前端控制代替后端敏感信息权限。
- 物理删除有交易、收款、发票、交付等业务关系的客户。

## 当前代码落点

- `CustomerController.list`、详情、选项和导出接口承载当前客户查询能力。
- `CustomerServiceImpl` 承载客户列表、详情和导出相关业务。
- `CustomerManager.convertCustomer` 承载线索转客户编排。
- 前端客户 API 和类型在 `dealer-web/src/modules/customer/`，列表和详情在 `dealer-web/src/pages/dashboard/customer*`。

## 执行步骤

1. 梳理客户主表字段、联系方式字段、负责人字段、来源字段和客户状态字段。
2. 补齐客户创建前重复检查，至少覆盖手机号、备用联系方式、姓名加联系方式和已转客户线索。
3. 新增客户归属转移命令，记录原负责人、新负责人、原因和时间。
4. 新增客户合并命令，合并前查询两边线索、商机、订单、跟进、收款、发票和交付关系。
5. 实现客户合并事务，迁移可迁移关系，保留被合并客户历史引用或合并记录。
6. 补齐客户敏感字段脱敏：列表、详情、选项、导出分别按权限输出。
7. 补齐客户删除限制，存在业务关系时只能禁用、合并或标记状态。
8. 调整前端客户列表、详情、归属转移、合并和导出交互。
9. 补充客户 Service、Mapper、Controller 和前端测试。

## 代码逻辑要求

- 客户合并必须在事务内完成，失败时不能留下半迁移。
- 合并不能丢失线索来源、跟进历史和订单事实。
- 客户资料编辑不能覆盖历史订单签约信息。
- 客户导出必须限制数量、受独立权限控制并写操作审计。
- 敏感字段脱敏在后端完成，前端只展示后端返回值。

## 完成条件

- 同一手机号再次创建客户时返回疑似重复。
- 客户归属转移后列表和详情显示新负责人，并能追溯原负责人。
- 客户合并后关联业务不丢失。
- 无权限用户看不到完整敏感联系方式。
- 普通销售不能导出超出自己范围的客户资料。

## 交付说明

完成后说明：

- 重复客户判断规则。
- 归属转移和合并如何保留历史。
- 敏感字段哪些场景脱敏。
- 有业务关系客户的删除策略。
- 已运行验证和剩余风险。

## 业务场景

- 客户沉淀、归属转移、合并、客户视图和客户生命周期维护。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 客户状态表达客户经营阶段，不能替代商机、订单或履约状态。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得通过客户合并或删除破坏商机、订单、跟进、资金、票据和交付历史。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证客户 360 视图、归属继承、多商机和历史保留。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
