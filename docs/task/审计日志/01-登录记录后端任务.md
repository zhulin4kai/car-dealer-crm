# 登录记录后端任务

## 任务目标

按登录记录 Spec 和落地方案，实现登录记录持久化、分页查询、详情和导出能力。登录结果必须来自服务端认证结果，不得由客户端声明。

## 当前代码落点

- `MyAuthenticationSuccessHandler.onAuthenticationSuccess` 当前在认证成功后生成 JWT、写入 Redis 并返回 `R.OK(jwt)`。
- `MyAuthenticationFailureHandler.onAuthenticationFailure` 当前返回统一认证失败响应，并对登录账号做日志脱敏。
- 当前没有 `TLoginRecord`、`TLoginRecordMapper`、`LoginAuditRecorder`、`LoginRecordController`。

## 执行步骤

1. 新增登录记录表结构。
2. 新增 `TLoginRecord` 模型，字段与表结构一一对应。
3. 新增 `LoginResultEnum`，只允许 `SUCCESS` 和 `FAILURE`。
4. 新增 `LoginFailureReasonEnum`，至少包含 `SUCCESS`、`BAD_CREDENTIALS`、`DISABLED`、`LOCKED`、`ACCOUNT_EXPIRED`、`CREDENTIALS_EXPIRED`、`INVALID_REQUEST`、`AUTH_SERVICE_ERROR`。

7. 修改 `MyAuthenticationSuccessHandler.onAuthenticationSuccess`，在返回 JWT 前写入成功登录记录。
8. 修改 `MyAuthenticationFailureHandler.onAuthenticationFailure`，在返回失败响应前写入失败登录记录。
9. 新增 `LoginRecordService` 和实现类，封装分页、详情、导出。
10. 新增 `LoginRecordController`，暴露列表、详情、导出接口。
11. 补充后端单元测试和集成测试。
12. 更新 API 和后端文档。

## 代码逻辑要求

### 登录记录表

建议表名为 `t_login_record`，字段至少包含：

- `id`
- `login_act`
- `user_id`
- `user_name`
- `result`
- `reason_code`
- `reason_message`
- `ip`
- `browser`
- `os`
- `request_id`
- `create_time`

索引至少覆盖：

- `create_time, id`
- `login_act`
- `user_id`
- `result`
- `ip`

### `LoginAuditRecorder`

必须提供：

- `recordSuccess(Authentication authentication, HttpServletRequest request)`
- `recordFailure(String loginAct, AuthenticationException exception, HttpServletRequest request)`

成功记录要求：

- 用户 ID 和用户姓名以后端认证主体为准。
- `result` 固定为 `SUCCESS`。
- `reason_code` 使用 `SUCCESS`。
- 写入失败时阻止继续签发 Token，返回系统异常。

失败记录要求：

- `loginAct` 取用户提交账号，必须复用现有脱敏和参数安全思路。
- 能识别用户时可记录用户 ID 和用户姓名，不能识别时保持为空。
- `reason_code` 根据认证异常映射，不把真实原因暴露给前台登录响应。
- 写入失败时仍返回认证失败响应，同时写应用错误日志。

客户端信息要求：

- IP 提取逻辑必须支持后续可信代理配置扩展。
- 不能直接信任任意客户端传入的 `X-Forwarded-For`。
- User-Agent 解析失败时浏览器和操作系统写入 `UNKNOWN`。

### `LoginRecordController`

建议接口：

- `GET /api/audit/login-records`：分页列表。
- `GET /api/audit/login-records/{id}`：详情。
- `GET /api/audit/login-records/export`：按当前筛选导出。

列表查询要求：

- 入参使用 `LoginRecordQuery`。
- 支持登录账号、用户姓名、结果、IP、开始时间、结束时间。
- 默认时间范围不能无限大。
- 最大时间跨度必须受控。
- 排序固定为 `create_time desc, id desc`。

详情要求：

- 找不到记录返回业务错误，不返回空成功。
- 不返回密码、Token、Cookie、Authorization、验证码、完整请求体或异常堆栈。

导出要求：

- 使用与列表一致的筛选条件和排序。
- 限制最大数量。
- 导出动作必须调用操作审计记录器记录“导出登录记录”。

## 完成条件

- 登录成功产生成功记录。
- 登录失败产生失败记录。
- 未知账号记录中用户 ID 为空，但账号、结果、原因、IP 和时间存在。
- 登录成功审计写入失败时不签发 Token。
- 登录失败审计写入失败时不改变认证失败结果。
- 列表、详情、导出均经过后端权限控制。
- 登录记录中不包含认证凭证和完整请求体。
