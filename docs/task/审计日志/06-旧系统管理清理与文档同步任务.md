# 旧系统管理清理与文档同步任务

## 任务目标

清理旧系统管理、系统配置和服务器监控残留能力，并同步 API、后端、前端和集成说明，确保产品边界与审计日志 Spec 一致。

## 前置阅读

- docs/spec/审计日志/00-业务范围与边界.md
- docs/plan/审计日志/04-旧系统管理清理方案.md
- docs/task/审计日志/00-任务拆分总览.md
- docs/rule/10-文档与Spec治理规范.md

## 修改范围

允许修改：

- 前端旧系统管理、系统配置、服务器监控相关路由、页面、菜单和权限常量。
- 后端旧系统配置、系统监控、运行时指标相关 Controller、Service、Mapper、模型、SQL。
- `docs/api.md`
- `docs/backend.md`
- `docs/frontend.md`
- `docs/integration.md`
- 与旧能力引用相关的测试。

禁止修改：

- 用户权限管理。
- 数据字典管理。
- 审计日志登录记录和操作记录业务实现。
- 应用日志基础设施。
- 与旧系统管理无关的页面和接口。

## 执行步骤

1. 检索前端是否存在系统配置、系统管理、服务器监控、JVM、CPU、内存、磁盘、网络监控相关页面或路由。
2. 检索后端是否存在系统配置、服务器监控、运行时指标相关 Controller、Service、Mapper、模型和 SQL。
3. 检索权限种子和权限常量是否存在旧系统管理权限。
4. 检索文档是否仍把旧系统管理能力描述为 CRM 范围。
5. 对确认无业务价值的残留能力进行删除或修正。
6. 对已经不存在的能力只记录验证结论，不制造空改动。
7. 更新 API、后端、前端和集成文档。
8. 执行编译、类型检查、测试和文档引用检查。

## 清理判断标准

应清理：

- 系统名称、站点、Logo、版本等系统配置维护页面或接口。
- 服务器 CPU、内存、磁盘、网络监控页面或接口。
- JVM、线程、进程、运行时指标页面或接口。
- 无业务审计价值的系统信息表。
- 面向业务管理员暴露的开发诊断页面。

不应清理：

- 用户管理。
- 角色权限管理。
- 数据字典。
- 审计日志。
- 后端应用日志记录代码。
- 与安全、权限、数据完整性相关的基础设施。

## 文档同步要求

`docs/api.md` 必须说明：

- 审计日志接口范围。
- 登录记录和操作记录列表、详情、导出接口。
- 权限错误和导出错误契约。

`docs/backend.md` 必须说明：

- 登录记录持久化链路。
- 操作记录持久化链路。
- 审计写入与事务边界。
- 审计敏感信息禁止项。

`docs/frontend.md` 必须说明：

- 审计日志菜单和页面组织。
- 审计日志 API 类型位置。
- 前端权限按钮和路由控制。

`docs/integration.md` 必须说明：

- 前后端权限编码一致性。
- 导出文件和错误处理。
- 认证失败、权限不足、查询失败的联调边界。

## 完成条件

- 前端不存在旧系统配置和服务器监控入口。
- 后端不存在旧系统配置和服务器监控业务接口。
- 权限种子中不存在旧系统管理菜单权限。
- 文档不再把旧系统管理描述为 CRM 产品范围。
- 审计日志相关 API、后端、前端和集成说明完整。
- 删除行为没有误伤用户权限、数据字典或审计日志能力。

完成后说明：

- 更新了哪些文档。

## 业务场景

- 记录登录、权限变化、业务事件、敏感导出和关键操作结果。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 审计状态表达记录可查询和保留状态，不替代业务状态。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得通过业务删除动作删除审计事实。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证业务事件审计、查询权限、脱敏和保留策略。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
