## 页面逻辑要求

### 路由

建议路径：

- `/dashboard/audit/login-records`
- `/dashboard/audit/operation-records`

路由要求：

- 两个页面独立加载。
- 进入登录记录页不得请求操作记录接口。
- 进入操作记录页不得请求登录记录接口。
- 无菜单权限时不在菜单中展示。

### 登录记录页面

筛选项：

- 登录账号。
- 用户姓名。
- 登录结果。
- IP。
- 时间范围。

列表列：

- 登录账号。
- 用户姓名。
- 登录结果。
- 原因说明。
- IP。
- 浏览器。
- 操作系统。
- 登录时间。

操作：

- 查询。
- 重置。
- 查看详情。
- 导出。

### 操作记录页面

筛选项：

- 模块。
- 动作。
- 操作人。
- 操作结果。
- 业务对象类型。
- 业务对象标识。
- 时间范围。

列表列：

- 模块。
- 动作。
- 操作人。
- 业务对象。
- 结果。
- 摘要。
- IP。
- 操作时间。

操作：

- 查询。
- 重置。
- 查看详情。
- 导出。

### 交互要求

- 首次进入页面加载默认时间范围内第一页。
- 点击查询后页码回到第一页。
- 点击重置后恢复默认筛选条件和默认时间范围。
- 分页切换保持当前筛选条件。
- 查询期间只显示局部加载状态。
- 查询失败保留上一轮成功数据和当前筛选条件。
- 空结果显示明确空状态。
- 快速重复查询时使用 `useLatestRequest` 或等价机制避免旧响应覆盖新结果。
- 状态必须有文本，不得只靠颜色表达。
- 长摘要在列表中截断，详情中展示完整受控摘要。
- 导出期间禁用导出按钮，防止重复提交。
- 导出失败时显示后端错误，不生成空文件。

## API 类型要求

`audit.types.ts` 至少定义：

- `LoginRecordQuery`
- `LoginRecordListItem`
- `LoginRecordDetail`
- `OperationRecordQuery`
- `OperationRecordListItem`
- `OperationRecordDetail`
- `AuditExportParams`

类型字段必须与 `docs/api.md` 和后端 DTO 保持一致，不允许使用 `any` 绕过类型检查。

## 权限要求

- 菜单显示依赖 `audit:menu`。
- 登录记录页面依赖 `audit:login:list`。
- 登录记录详情按钮依赖 `audit:login:detail`。
- 登录记录导出按钮依赖 `audit:login:export`。
- 操作记录页面依赖 `audit:operation:list`。
- 操作记录详情按钮依赖 `audit:operation:detail`。
- 操作记录导出按钮依赖 `audit:operation:export`。

## 完成条件

- 系统管理员能看到审计日志菜单和两个页面。
- 无权限用户看不到审计日志菜单。
- 两个页面分别完成筛选、分页、详情和导出交互。
- 查询失败不清空上一轮成功数据。
- 快速重复查询不会显示旧条件结果。
- 前端类型检查、Lint 和测试通过。
