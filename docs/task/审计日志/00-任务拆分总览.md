# 审计日志任务拆分总览

## 关联 Plan

- docs/plan/审计日志/00-审计日志落地总览.md
- docs/plan/审计日志/01-登录记录落地方案.md
- docs/plan/审计日志/02-操作记录落地方案.md
- docs/plan/审计日志/03-权限与前端页面方案.md
- docs/plan/审计日志/04-旧系统管理清理方案.md

## 任务目标

将审计日志落地拆成可执行任务，确保每个任务有清晰文件所有权、修改范围、验收边界和验证命令。

## 执行顺序

1. 执行 `01-登录记录后端任务.md`。
2. 执行 `02-操作记录后端任务.md`。
3. 执行 `03-操作审计覆盖与事务一致性任务.md`。
4. 执行 `04-审计权限与数据种子任务.md`。
5. 执行 `05-审计日志前端页面任务.md`。
6. 执行 `06-旧系统管理清理与文档同步任务.md`。

## 文件所有权

### 登录记录后端任务

主要拥有：

- `dealer-server/src/main/java/com/autodealer/crm/config/handler/MyAuthenticationSuccessHandler.java`
- `dealer-server/src/main/java/com/autodealer/crm/config/handler/MyAuthenticationFailureHandler.java`
- 登录记录相关 model、mapper、service、controller、dto、enum、SQL 和测试。

### 操作记录后端任务

主要拥有：

- `dealer-server/src/main/java/com/autodealer/crm/audit/OperationAuditRecorder.java`
- `dealer-server/src/main/java/com/autodealer/crm/audit/AuditActionEnum.java`
- `dealer-server/src/main/java/com/autodealer/crm/model/TOperationLog.java`
- `dealer-server/src/main/java/com/autodealer/crm/mapper/TOperationLogMapper.java`
- `dealer-server/src/main/resources/mapper/TOperationLogMapper.xml`
- 操作记录查询、详情、导出相关 service、controller、dto、SQL 和测试。

### 操作审计覆盖任务

主要拥有具体业务 Service 和 Controller 中的写操作接入点，不独立重写审计基础设施。

### 权限与数据种子任务

主要拥有：

- `dealer-server/src/main/java/com/autodealer/crm/constant/PermissionCodes.java`
- `dealer-server/src/main/resources/CarDealerCRM.sql`
- `dealer-server/src/main/resources/schema-test.sql`
- 权限一致性、权限边界和种子数据测试。

### 前端页面任务

主要拥有：

- `dealer-web/src/router/routes.ts`
- `dealer-web/src/shared/constants/permissions.ts`
- `dealer-web/src/layouts/DashboardLayout.vue`
- `dealer-web/src/modules/audit/`
- 前端审计日志测试。

### 旧系统管理清理任务

主要拥有旧系统管理、系统配置、服务器监控相关残留文件；如果残留文件已经被其他任务拥有，必须顺序执行，不并行修改。

## 并行约束

- `02-操作记录后端任务.md` 与 `03-操作审计覆盖与事务一致性任务.md` 不建议并行，因为都可能涉及 `AuditActionEnum` 和操作审计语义。
- `04-审计权限与数据种子任务.md` 与 `05-审计日志前端页面任务.md` 可以分工，但权限编码必须以 `04` 中定义为准。
- `06-旧系统管理清理与文档同步任务.md` 应最后执行，避免提前删除仍被迁移任务引用的入口。

## 总体验收

- `docs/spec/审计日志/` 中的业务要求都有对应 plan 和 task 落点。
- 后续实现不得从当前代码反推业务范围；代码只用于确认修改位置和兼容风险。
- 每个任务完成后必须说明实际修改文件、已验证场景和剩余风险。

## 业务场景

- 记录登录、权限变化、业务事件、敏感导出和关键操作结果。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 审计状态表达记录可查询和保留状态，不替代业务状态。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得通过业务删除动作删除审计事实。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证业务事件审计、查询权限、脱敏和保留策略。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
