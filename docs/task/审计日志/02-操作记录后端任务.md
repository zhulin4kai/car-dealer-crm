按操作记录 Spec 和落地方案，补强操作记录数据结构、查询、详情和导出能力，并为后续业务写操作审计覆盖提供稳定基础设施。

## 当前代码落点

- `OperationAuditRecorder.record` 当前负责插入 `t_operation_log`。
- `OperationAuditRecorder.recordQuietly` 当前用于部分导出场景的弱失败写入。
- `OperationAuditRecorder.buildLogEntry` 当前从当前用户上下文、动作枚举、资源 ID、摘要和 IP 构造记录。
- `TOperationLog` 当前缺少操作结果、业务对象类型、请求标识等字段。
- `TOperationLogMapper` 当前只有按模块和按用户分页查询，无法支撑管理员组合筛选。
- 当前没有 `OperationLogController` 和 `OperationLogService`。

## 代码逻辑要求

### `t_operation_log`

在现有字段基础上补齐：

- `action_name`
- `object_type`
- `result`
- `request_id`
- `summary`

保留历史字段 `detail` 时，需要明确其与 `summary` 的兼容关系。新代码不得继续把完整请求、响应、实体或异常对象塞进 `detail`。

索引至少覆盖：

- `create_time, id`
- `module_name`
- `action_code`
- `user_id`
- `result`
- `object_type, resource_id`

### `AuditActionEnum`

每个动作必须包含：

- 稳定动作编码。
- 面向管理员的动作名称。
- 所属模块。
- 默认业务对象类型。

动作编码新增后不能随页面文案变化而变化。

### `OperationAuditRecorder`

必须保留统一入口，建议形成以下方法语义：

- `record(AuditActionEnum action, String resourceId)`：记录成功动作，摘要为空。
- `record(AuditActionEnum action, String resourceId, String result, String summary)`：兼容现有调用。
- `recordSuccess(AuditActionEnum action, String objectId, String summary)`：推荐新成功入口。
- `recordFailure(AuditActionEnum action, String objectId, String summary)`：仅用于明确要求记录失败的高风险动作。
- `recordQuietly(...)`：仅用于导出失败不应影响主流程的场景，并必须写应用错误日志。

摘要要求：

- 摘要必须由调用方传入受控字段或由专门 DTO 构造。
- 禁止直接序列化请求对象、响应对象、Entity、异常对象。
- 手机号、邮箱、地址、客户备注、支付信息等必须先脱敏或只保留业务编号。

事务要求：

- 成功审计应与业务事务提交结果一致。
- 如果业务方法存在事务，记录成功事实时需要确保业务回滚不会留下成功日志。
- 如果无法保证同事务一致性，必须在任务交付中列出具体风险和后续修复方案。

### `OperationLogController`

建议接口：

- `GET /api/audit/operation-records`：分页列表。
- `GET /api/audit/operation-records/{id}`：详情。
- `GET /api/audit/operation-records/export`：按当前筛选导出。

列表查询要求：

- 入参使用 `OperationLogQuery`。
- 支持模块、动作、操作人、结果、对象类型、对象标识、开始时间、结束时间。
- 默认时间范围不能无限大。
- 最大时间跨度必须受控。
- 排序固定为 `create_time desc, id desc`。

详情要求：

- 详情展示受控摘要。
- 不展示原始请求体、原始响应体、异常堆栈、SQL 或内部类名。

导出要求：

- 使用与列表一致的筛选条件和排序。
- 限制最大数量。
- 导出操作本身写入操作记录，动作语义为“导出操作记录”。

## 完成条件

- 管理员可以按模块、动作、操作人、结果、对象和时间范围查询操作记录。
- 详情可以展示受控摘要。
- 导出内容与筛选条件一致。
- 导出操作本身产生操作记录。
- 操作记录没有删除、批量删除、清空和编辑接口。
- 历史记录缺失新字段时，接口返回稳定占位，不返回 `null`、`undefined` 或内部变量名给前端。

## 业务场景

- 记录登录、权限变化、业务事件、敏感导出和关键操作结果。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 审计状态表达记录可查询和保留状态，不替代业务状态。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得通过业务删除动作删除审计事实。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证业务事件审计、查询权限、脱敏和保留策略。
