# 操作审计覆盖与事务一致性任务

## 任务目标

按操作记录 Spec，审查关键业务写操作，补齐缺失操作审计，并修正成功记录与业务事务提交结果不一致的风险。

## 当前代码落点

当前已有部分操作审计调用，至少包括：

- `UserServiceImpl` 中用户创建、编辑、启禁用、锁定解锁、角色分配、密码修改。
- `ClueServiceImpl` 中线索导入、创建、删除。
- `CustomerManager.convertCustomer` 中线索转客户。
- `TranServiceImpl` 中交易创建、结算、审批、发票、删除、重提、收款、退款。
- `DicServiceImpl` 中字典类型和值的新增、编辑、删除。
- `ProductServiceImpl` 中商品新增和补库存。
- `CustomerController.exportExcel` 中客户导出。

这些现状只能作为覆盖检查起点，最终覆盖范围以 Spec 必须审计的动作列表为准。

## 执行步骤

1. 使用知识图谱查找 `OperationAuditRecorder.record` 和 `recordQuietly` 的所有调用点。
2. 对照 Spec 列出必须审计动作清单。
3. 对每个动作标记状态：已覆盖、覆盖不完整、缺失、当前业务不存在。
4. 对已覆盖但摘要不合规的调用点改为受控摘要。
5. 对缺失的现有业务写操作补充审计调用。
6. 对事务边界有风险的调用点调整记录时机。
7. 为每类关键动作补充测试。
8. 输出覆盖矩阵和剩余风险。

## 覆盖要求

### 用户

必须覆盖：

- 创建用户。
- 编辑用户。
- 启用、禁用用户。
- 锁定、解锁用户。
- 重置或修改密码。
- 角色或权限调整。

摘要应包含用户 ID、登录账号、变更类型，不包含密码或密码摘要。

### 线索

必须覆盖：

- 创建线索。
- 编辑线索。
- 导入线索。
- 删除线索。
- 转化客户。

摘要应包含线索 ID、批量导入数量、转化目标客户 ID 等受控信息，不包含完整客户备注和沟通内容。

### 客户

必须覆盖：

- 归属变更。
- 关键资料变更。
- 敏感数据导出。

摘要应包含客户 ID、原负责人、新负责人、导出范围等受控信息，手机号、邮箱、地址等必须脱敏或不记录完整值。

### 交易、收款、退款、发票

必须覆盖：

- 交易创建、编辑、提交审批、审批通过、审批驳回、重提、结算、关闭、删除。
- 收款创建、确认收款。
- 退款和退款结果。
- 发票创建、开具、作废和状态变化。

摘要应包含交易 ID、交易编号、金额摘要、状态变化和审批结果，不包含支付凭证全文或第三方敏感返回。

### 商品与库存

必须覆盖：

- 商品状态变化。
- 入库。
- 库存调整。
- 库存锁定或释放。

摘要应包含商品 ID、调整数量、库存变化方向和关联业务对象。

### 字典

必须覆盖：

- 字典类型和值的新增、编辑、启停、删除。

摘要应包含字典类型、字典值、状态变化，不包含无关请求体。

### 导入导出

必须覆盖：

- 涉及客户、交易、资金或批量业务数据的导入导出。

摘要应包含筛选条件摘要、总数、成功数、失败数、文件类型，不包含文件原始内容。

## 事务一致性要求

- 成功审计必须在业务校验通过、数据库写入成功后记录。
- 如果业务方法发生异常并回滚，不能留下成功审计。
- 对已有 `@Transactional` 的方法，优先保证审计写入参与同一事务或使用事务提交后回调记录成功事实。
- 对导出、失败登录等无业务事务的动作，必须明确失败策略和错误日志。
- 批量动作不能每条都无控制写审计；应写批次摘要。

## 完成条件

- Spec 中第一阶段必须审计的现有业务写操作均有覆盖结论。
- 已存在的关键业务写操作全部补齐审计或说明当前业务不存在。
- 审计摘要不包含禁用敏感字段。
- 事务回滚不会留下成功操作记录。
- 批量操作审计为批次摘要，不产生不可控日志量。

## 交付说明

完成后说明：

- 覆盖矩阵中每个动作的状态。
- 新增或调整了哪些审计调用点。
- 哪些动作因当前业务不存在而未实现。
- 哪些事务一致性风险已修复，哪些仍需后续任务。

## 业务场景

- 记录登录、权限变化、业务事件、敏感导出和关键操作结果。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 审计状态表达记录可查询和保留状态，不替代业务状态。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得通过业务删除动作删除审计事实。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证业务事件审计、查询权限、脱敏和保留策略。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
