## 当前代码落点

- 后端权限编码集中在 `PermissionCodes.java`。
- 权限种子位于 `CarDealerCRM.sql` 和测试 schema。
- 权限一致性测试会检查前后端权限编码一致性。
- 当前没有审计日志权限编码和种子数据。

## 权限编码

新增权限编码：

- `audit:menu`
- `audit:login:list`
- `audit:login:detail`
- `audit:login:export`
- `audit:operation:list`
- `audit:operation:detail`
- `audit:operation:export`

命名要求：

- 使用小写英文和冒号分层。
- 菜单权限只表达菜单可见性。
- 列表、详情、导出分别独立。
- 不使用中文、数字 ID 或页面路径作为权限语义。

## 执行步骤

1. 在 `PermissionCodes.java` 新增审计日志权限常量。
2. 在权限种子 SQL 中新增审计日志一级菜单权限。
3. 在权限种子 SQL 中新增登录记录和操作记录的按钮或操作权限。
4. 默认只给系统管理员角色分配审计权限。
5. 给登录记录列表、详情、导出接口添加后端权限控制。
6. 给操作记录列表、详情、导出接口添加后端权限控制。
7. 补充权限一致性测试。
8. 补充有权限、无权限、无导出权限的接口访问测试。
9. 更新 API 和后端文档中的权限说明。

## 代码逻辑要求

### Controller 权限

建议按接口粒度控制：

- 登录记录列表使用 `audit:login:list`。
- 登录记录详情使用 `audit:login:detail`。
- 登录记录导出使用 `audit:login:export`。
- 操作记录列表使用 `audit:operation:list`。
- 操作记录详情使用 `audit:operation:detail`。
- 操作记录导出使用 `audit:operation:export`。

不能只在菜单入口做权限控制。

### 种子数据

权限种子必须：

- 使用权限编码建立角色权限关系，不依赖容易漂移的数字 ID。
- 保持菜单树稳定排序。
- 保持禁用权限和禁用角色不会被加载。
- 不给普通业务角色默认授予审计权限。

### 测试要求

必须覆盖：

- 系统管理员可以访问审计列表、详情和导出。
- 普通业务用户不能访问审计列表、详情和导出。
- 只有列表权限但无导出权限时，导出被拒绝。
- 前端权限常量和后端权限常量一致。
- 种子 SQL 不依赖数字权限 ID。

## 完成条件

- 审计权限编码存在于后端常量、数据库种子和测试 schema。
- 系统管理员默认拥有全部审计权限。
- 普通角色默认没有审计权限。
- 列表、详情、导出接口分别独立鉴权。
- 权限一致性测试通过。
