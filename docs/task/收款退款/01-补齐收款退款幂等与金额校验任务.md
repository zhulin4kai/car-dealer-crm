# 补齐收款退款幂等与金额校验任务

按收款退款 Spec 和流水幂等方案，补齐收款、退款、金额计算、幂等键、并发控制和财务权限。

## 当前代码落点

- `TranController` 已有 payment/refund 相关路由。
- `TranServiceImpl.recordPayment` 和 `TranServiceImpl.refundPayment` 是当前资金写入逻辑。
- `TPayment` 是当前支付记录模型。

## 执行步骤

1. 梳理当前支付类型、支付状态、退款逻辑和金额字段。
2. 为收款和退款请求新增幂等键或唯一业务约束。
3. 创建收款时服务端计算交易应收、已收、已退和剩余应收。
4. 退款时服务端计算可退款金额，并使用事务和并发控制。
5. 支付和退款状态迁移必须校验当前状态。
6. 财务操作接口加独立权限。
7. 前端交易详情展示应收、已收、已退、待退和可退金额。
8. 补充金额精度、重复请求、并发退款、权限和前端测试。

## 代码逻辑要求

- 金额使用 `BigDecimal`，数据库使用 `DECIMAL`。
- 重复幂等键返回第一次确定结果，不重复写流水。
- 退款必须关联原收款或可追溯资金事实。
- 支付、退款记录禁止普通物理删除。
- 资金动作写操作审计。

## 完成条件

- 重复提交同一收款请求不会产生两条成功收款。
- 退款金额不能超过可退款金额。
- 应收、已收、已退、待退由服务端计算。
- 无财务权限用户不能确认收款或退款。
- 交易详情展示资金状态与后端一致。

## 交付说明

完成后说明：

- 幂等键或唯一约束设计。
- 退款额度计算方式。
- 并发冲突如何返回。
- 前端资金字段和权限如何调整。

## 业务场景

- 订单产生应收后登记、确认收款，并在取消或异常时处理退款和冲正。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 资金状态表达到账、退款和冲正事实，是交易完成必要条件之一。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得删除原收款，不得绕过幂等和可退金额。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证每笔资金流水、退款、冲正和交易履约阻塞点一致。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
