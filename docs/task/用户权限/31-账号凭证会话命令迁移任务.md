## 迁移范围

- `ManagedUserAccountServiceImpl` 的受管账号状态、资料、登录标识和安全到期命令。
- `ManagedUserInvitationServiceImpl` 的人员账号邀请和首次初始化命令。
- `ProfileServiceImpl` 的本人非授权资料命令。
- `CredentialServiceImpl` 的激活、改密、重置、联系方式验证、break-glass 和降级恢复凭证命令。
- `LoginSecurityServiceImpl` 的登录失败自动锁与成功清理命令。
- `UserSessionServiceImpl` 的创建、本人撤销、管理者撤销和安全变化撤销命令。

## 目标不变量

- 本人资料白名单、禁止本人授权修改、最后恢复渠道和管理员代改边界保持不变。
- INVITED/ACTIVE/DISABLED、人工/自动锁、凭证到期、首次改密和员工状态仍是独立事实。
- 邀请、重置、验证和 break-glass 凭证保持单次、限时、不可读取，外部投递继续由 Task 24 持久 Outbox 保证。
- HUMAN 只使用员工当前联系方式，固定 SYSTEM 恢复账号只使用独立专用联系方式。
- 密码、账号状态、登录标识、授权和安全变化后数据库会话事实与安全版本在事务内生效，Redis 在提交后清理。
- 最后管理员、四态门禁、自动锁保护、登录会话上限和并发 CAS 结果保持不变。

## 允许修改范围

- 上述命令处理器、现有 Service、显式状态/管理员/凭证策略调用、协调器与事件适配。
- 会话策略配置收敛到校验过的 `@ConfigurationProperties`。
- 对应 Controller 注入、单元、H2、MockMvc、Outbox 和故障注入测试。

## 禁止修改范围

- 不改变登录、个人中心、凭证、恢复和会话 API、HTTP 状态或稳定 code。
- 不把密码校验、凭证用途、四态门禁、最后管理员或恢复账号目标规则放入切面。
- 不用普通提交后事件替代持久 Outbox，不在事务内调用 Webhook。
- 不把 Redis 成功当作安全事实，不因缓存失败回滚已经提交的数据库安全版本。
- 不记录原始凭证、密码、nonce、完整联系方式或恢复密钥。

## 执行步骤

1. 先迁移本人资料与受管账号资料，复用管理员可用性策略保护最后恢复渠道。
2. 迁移账号状态、登录标识和安全到期命令，保持显式图锁计划、锁内重验与 Mapper CAS。
3. 迁移邀请和首次初始化，保持账号、员工、主任职、根负责人、角色、预交付承诺和审计原子性。
4. 迁移激活、改密、验证、break-glass 和降级恢复，协调器只处理事务内安全事实，Outbox 继续负责提交后外部投递。
5. 迁移登录失败自动锁，保留恢复账号与唯一普通管理员保护及匿名高危审计。
6. 迁移会话创建和撤销，把数据库会话事实与 Redis 清理边界分开；会话创建失败仍不得提前删除旧会话。
7. 删除旧 Service 内重复的安全清理、缓存清理和手工提交后回调。
8. 用代码图谱确认 Controller 和认证流程只进入新命令入口，旧写方法无生产调用。

## 特征与并发测试

- 本人资料、管理员代改、唯一已验证恢复渠道和并发资料版本。
- 邀请事务回滚、Outbox 提交前零投递、Worker 幂等重试和永久失败撤销。
- 激活、禁用、离职、安全到期与旧凭证并发，旧凭证不得复活账号。
- break-glass 默认关闭、错误密钥、固定目标、单次消费、密码历史和审计脱敏。
- 自动锁、最后管理员保护、第二管理员存在时正常锁定和旧 Token 永久失效。
- 并发会话上限、后续步骤失败不提前删除旧会话、Redis 故障 fail-close。

## 量化验收

- 本任务新增命令处理器每个不超过 250 行、直接依赖不超过 8 个、公开写方法不超过 60 行。
- `ManagedUserAccountServiceImpl`、`ManagedUserInvitationServiceImpl`、`ProfileServiceImpl`、`CredentialServiceImpl`、`LoginSecurityServiceImpl`、`UserSessionServiceImpl` 合计行数相对 Task 25 基线至少下降 30%。
- 上述旧写类对 `revokeAllForSecurityChange`、`invalidateAfterCommit` 和手工 `registerSynchronization` 的直接调用全部为 0。
- `UserSessionServiceImpl` 构造器的配置标量收敛到一个配置对象；迁移后的命令处理器均不超过 8 个直接协作者。
