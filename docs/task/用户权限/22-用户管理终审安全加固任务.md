## 目标不变量

- 首次邀请原子激活账号和待入职员工；已离职只能通过返聘恢复。
- 禁用、离职、登录账号变化、安全到期和密码变化后，全部旧临时凭证永久失效。
- 普通自动锁提升安全版本并撤销会话，且不能关闭恢复账号或唯一普通管理入口。
- 首个普通管理员完成激活、首次改密和至少一个当前员工联系方式验证前，日常业务 fail-close；恢复账号无论何时都不参与日常业务，普通管理员全部失效时进入独立 `DEGRADED` 恢复而不是重复 bootstrap。
- break-glass 默认关闭，只面向固定恢复账号，依赖外部密钥和一次性凭证。
- 手机、邮箱验证形成单次凭证、验证状态、资料变更撤销、找回密码投递和审计闭环。
- 普通在职员工始终具有合法直属管理者；登录标识归属和恢复账号身份在数据库层不可篡改。

- 前端具体落点：`credential-api.ts`、`credential.types.ts`、`user-profile.types.ts`、`profile.vue`、公开联系方式验证页、四类任职表单、角色页面、路由、稳定错误码和精确单元测试。

## 禁止修改范围

- 不实现 ERP、财务外接、完整人事、SSO、MFA 或普通用户恢复码。
- 不把 break-glass 合并进普通忘记密码、管理员重置或本人授权入口。
- 不依赖前端隐藏替代服务端状态、用途和数据完整性约束。

## 执行步骤

1. 统一凭证消费、禁用、离职和安全处置的账号及员工行锁顺序与 CAS。
2. 修复自动锁定的管理员保护、安全版本和会话撤销语义。
3. 增加初始化就绪与恢复账号用途门禁，并过滤恢复账号日常业务菜单和权限。
4. 实现 break-glass 申请、交付和消费命令，默认关闭且不记录秘密。
   - 数据库基线不得保留仓库已知恢复密码；固定恢复账号初始化为人工锁定、强制改密和不可登录占位摘要，首次使用必须先完成 break-glass。
5. 实现手机和邮箱验证申请、消费、重签、资料变更撤销及个人中心入口。
6. 建立唯一管理者选择策略，以目标主要组织为锚点，统一邀请、组织调整、调岗和返聘四条写路径；只有 `根公司.leader_employee_id` 指向的员工可为空，首次初始化使用显式原子引导命令建立该事实。
7. 增加登录标识不可变和固定恢复账号身份不可降级的数据库触发器。
8. 同步 OpenAPI、错误码、前端类型、页面和三个正式数据库基线文件。
9. 串行化联系方式验证签发、资料变化和验证消费，验证绑定签发资料版本；公开申请增加账号、联系方式摘要和来源地址限流及冷却。
10. 串行化同一用户会话创建，保证并发不突破上限；所有 Redis 会话清理延后到事务提交。
11. 角色属性、状态、适用组织和权限矩阵的所有变更统一校验全部受影响成员，拒绝间接改变范围外用户授权。
12. Task 22 完成后只运行定向验证确认缺陷关闭，再依次交给 Task 23、Task 24；模块最终完成状态必须等待 Task 21 全链路验收。

## 手工验收

1. 初始化前使用恢复账号访问典型客户接口，确认稳定返回 641；创建并激活首个根公司负责人和普通管理员后仍保持 PENDING，完成首次改密并验证至少一个当前员工联系方式后普通业务才开放，恢复账号访问日常业务仍返回 642。
2. 使用错误/正确外部密钥申请 break-glass，验证默认关闭、固定目标、一次消费、密码历史、会话撤销和审计脱敏。
3. 本人分别修改手机和邮箱、申请验证、并发再次修改、消费新旧凭证，确认只有当前版本可以变为已验证并用于找回密码。
4. 在邀请、组织调整、调岗和返聘页面验证普通人员不能选择空或跨目标组织管理者，根公司负责人例外且不能形成循环。
5. 并发登录超过会话上限，确认数据库与页面都不超过上限；模拟后续写入失败，旧会话仍保持有效。
6. 使用只具有角色列表权限的账号进入角色页；编辑、停用或调整包含范围外成员的角色均被服务端拒绝。
7. 在真实 MySQL 和 MariaDB 从空库执行基线后，尝试更新、删除永久登录标识及恢复账号身份，确认均被拒绝。
