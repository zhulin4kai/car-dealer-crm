## 目标不变量

- `@UserManagementCommand` 只表达稳定命令编码，不携带权限、锁、状态、审计或历史配置。
- 切面只识别可信根命令并输出一次脱敏完成观测，不创建事务、不查 Mapper、不改变业务返回或异常。
- 同一外部命令只记录一次；内部协作调用不得重复记作第二个用户动作。
- 未标注查询方法和其他业务模块完全不受影响。

## 建议代码落点

- `dealer-server/src/main/java/com/autodealer/crm/service/command/UserManagementCommand.java`
- `dealer-server/src/main/java/com/autodealer/crm/config/aop/UserManagementCommandAspect.java`
- 对应 `dealer-server/src/test/java/` 单元和 Spring AOP 集成测试。

以上均为本任务计划新增落点，实施时若调整包名，必须保持 Service/Manager/Config 分层并同步 Plan 与测试。

## 允许修改范围

- 新增命令注解、薄切面及测试；不保留没有生产消费者的注册表、空管线或观察器协议。
- 选择 1 个低风险用户管理命令作为试点，只验证代理和根观测，不迁移业务规则。
- 必要的 Spring AOP 装配和测试配置。

## 禁止修改范围

- 切面中禁止出现 `PermissionCodes`、角色名、锁名、账号/员工状态枚举、Mapper、`OperationAuditRecorder` 或权威历史 Mapper。
- 不在切面增加 `@Transactional` 或手工事务，不依赖切面顺序完成业务提交。
- 不捕获 `BusinessException` 后返回成功，不翻译既有稳定 code，不记录请求中的原始凭证或完整联系方式。
- 不依赖同类方法自调用触发代理。

## 执行步骤

1. 定义只包含稳定命令 code 的注解，首批仅标注本人资料更新试点。
2. 切面取得请求 ID、可信操作者 ID、开始时间和随机根调用标识；敏感输入不进入日志。
3. 成功或失败只输出一条完成观测；失败只记录异常类型，不记录异常消息或堆栈。
4. 切面检测已有根调用时直接执行原方法，避免嵌套重复事件。
5. 明确切面顺序并用 Spring 测试证明业务 `@Transactional` 方法内事务仍真实存在；切面本身不决定事务。
6. 增加架构测试，禁止切面依赖 Mapper、业务策略、审计和用户状态枚举。

## 测试

- 标注命令输出一次根完成观测，未标注方法不输出。
- 同一请求嵌套调用不重复输出根命令记录。
- 正常返回值、`BusinessException` 类型/code、运行时异常和事务回滚与无切面时一致。
- 未登录或无权限请求仍由原 Security/Controller 边界返回原状态。
- 日志与指标不包含密码、凭证、完整手机、完整邮箱和授权明细。
- 切面类源码和依赖图不包含禁止的领域依赖。

## 量化验收

- 切面直接构造依赖不超过 4 个，单文件不超过 150 行。
- 注解属性不超过 2 个，除命令 code 外不得增加业务开关。
- 试点命令特征测试 100% 保持原结果，每个根调用恰好一条完成观测。
