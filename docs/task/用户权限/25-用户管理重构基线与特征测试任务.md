## P2 前置门禁

- Task 21 必须已经完成，且能够提供完整后端、前端、真实 MySQL/MariaDB、启动和手工验收证据。
- 用户管理范围内不得存在未关闭的 P0/P1；若本任务发现新的正确性或安全缺陷，停止 P2 重构并回到对应功能 Task。
- 仅在独立、可回退的工作分支执行，开始前记录现有工作区和未跟踪文件，不覆盖其他修改。

## 目标

- 建立用户管理写命令目录、调用入口、事务、锁、CAS、历史、审计和提交后副作用清单。
- 固化重构前的 HTTP、稳定 code、数据库事实、历史、审计和副作用特征测试。
- 建立同一口径的代码量、构造依赖和重复调用检查，供 Task 33 复测。
- 使用代码图谱记录 Controller 到写命令、写命令到 Mapper/策略/副作用的影响面。

## 允许修改范围

- 用户管理相关后端测试、测试夹具和结构检查脚本。
- 建议新增 `scripts/quality/user-management-architecture-check.sh`，只读统计目标文件，不自动改源码。
- 必要时补充本 Plan 的基线数字，但必须在任何生产代码重构前完成并说明口径变化。

## 禁止修改范围

- 不修改生产业务实现、API、Schema、前端行为或权限种子。
- 不删除失败断言，不把精确错误码改成宽泛异常，不关闭 Spring Security 或事务。
- 不以代码行数代替行为证据，也不通过压缩 Java 格式降低统计数字。

## 执行步骤

1. 用代码图谱获取冻结的 12 个既有实现类的 Controller 调用入口、直接依赖、调用方和影响面。
2. 列出所有公开写命令，至少包含命令编码、入口类、事务边界、目标对象、锁序、CAS、状态策略、历史、审计、版本提升、会话/凭证处理和提交后副作用。
3. 统计 12 个既有实现文件行数、每个写服务构造协作者数量、字段注入数量及重复调用文本。
4. 使用只读脚本固化本轮开始 HEAD 的 12 文件、5,025 行冻结快照；该冻结值是 Task 33 的权威比较基线，后续当前工作区数字只反映阶段进度，不得倒算为新基线。
5. 为每个命令族补特征测试：角色授权、账号资料、凭证会话、组织汇报、任职生命周期。
6. 测试同时断言主要数据库事实、CAS 冲突、稳定错误码、权威历史、操作审计和不应发生的副作用。
7. 对提交后清理使用可控事件/事务测试，证明提交前不执行、回滚不执行、提交后恰好一次。
8. 输出 Task 30—32 的命令迁移矩阵和每批必须保持的测试集合。

## 量化基线脚本要求

- 输入文件集合固定为本轮开始 HEAD 已存在的 12 个用户域实现，并按路径排序；新增 command、AOP、policy、coordinator、event 生产文件另行发现，不能在 Task 33 临时删减。
- 行数同时报告 12 个既有实现、全部新增架构生产文件及二者总量；测试代码单独验收，不混入生产代码净减少口径。
- 构造依赖按真实注入协作者计算；字段注入也计入，配置标量单独列出。
- 重复调用用固定字符串或 AST/代码图谱口径统计，并在输出中写明是否包含帮助方法定义。
- 生产代码未严格净减少或 revoke/invalidate 越过允许边界时脚本返回非零；构造依赖、字段注入、锁文本、事务同步和长行密度只报告，不驱动隐藏业务规则。
