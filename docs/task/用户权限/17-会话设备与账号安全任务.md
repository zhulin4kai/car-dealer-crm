# 会话设备与账号安全任务

## 关联业务缺口

- UM-17：每个用户只有单个 Redis Token，无法查看和选择性撤销会话。
- UM-18：登录账号、密码和授权变化后的旧会话兼容与撤销不完整。

## 当前错误行为

- Redis 会话 Key 以用户为单位，新登录覆盖旧登录，不能区分设备和当前会话。
- JWT 没有会话标识和安全版本，修改登录账号后旧 Token 仍可能继续有效。

## 目标不变量

- 每个登录建立独立、不可猜测的会话，JWT、Redis、数据库会话与账号安全版本共同校验。
- 用户可查看和撤销自己的指定会话或其他会话；管理者只能撤销管理范围内下属会话。
- 账号、密码、角色、个人权限、数据范围、禁用、锁定和离职变化立即撤销受影响会话。
- Redis 写入或删除失败不得返回伪成功。
- 同一用户的会话创建必须串行执行有效会话计数、超限撤销和新会话写入，并发登录不能突破最大会话数。
- 超限撤销、新会话、revision 和审计属于同一数据库事务；Redis 清理只在提交后执行，后续失败不得提前使数据库仍有效的旧会话掉线。

## 禁止修改范围

- 不在 JWT 中保存权限全集、手机号或其他可变业务资料。
- 不通过 Redis `KEYS` 或生产全库扫描查找用户会话。
- 不因 Redis 故障继续保留已认证上下文或返回撤销成功。

## 兼容契约

- 新 JWT 保存最小用户标识、会话标识和安全版本。
- Redis 按会话标识保存有效性，持久会话记录保存客户端摘要、时间、撤销事实和 Token 摘要。
- 旧 JWT 和旧 Redis Key 在最长现有会话期限内兼容，所有安全变化同时撤销新旧会话。
- 普通会话和 `rememberMe` 会话分别配置绝对有效期与空闲有效期；达到最大并发会话数时采用确定的最旧会话撤销策略。
- 最近活动时间按配置间隔批量或节流更新，不在每个请求写数据库；过期和撤销记录按保留期限清理。
- 设备、IP 和客户端信息只保存脱敏摘要，不向无关管理者暴露完整网络信息。

## 执行步骤

1. 新增会话记录和账号安全版本，建立会话 ID、Token 摘要、设备、IP 摘要、时间和撤销字段。
2. 登录成功先可靠写入 Redis 与会话记录，再返回 JWT；任一步失败均不返回 Token。
3. Filter 校验会话 ID、Redis、账号安全版本、账号状态和实时权限，并更新受控的最近活动时间。
4. 实现本人会话列表、撤销指定、撤销其他和撤销当前会话命令。
5. 实现管理者查看及撤销下属会话，复用禁止自改以外的管理范围策略；本人通过 `/api/me` 操作。
6. 安全相关变更在数据库事务内增加安全版本并记录撤销事实；Redis 清理提交后执行并可靠重试，不伪造跨存储原子事务。
7. 为会话创建增加用户级行锁或会话图锁，在锁内确定最旧会话并写入新会话；将全部 Redis 变更注册为提交后动作。
8. 增加旧 Token 兼容窗口和结束条件，不永久保留两套语义。
9. 本人会话挂载在个人中心；管理员会话入口挂载在 Task 13 已建立的最小用户详情，不创建无宿主组件。
10. 同步 OpenAPI、前端会话组件、错误码、技术文档和测试。

## 测试

- 多设备会话同时存在且列表能识别当前会话。
- 撤销指定、其他、当前和全部会话的影响范围正确。
- 用户不能撤销他人会话，管理者不能撤销同级、上级或范围外用户会话。
- 登录账号、密码、角色、权限、状态变化后所有旧会话失效。
- Redis set/delete 返回 false、异常或超时时不返回伪成功。
- JWT、Redis 或数据库安全版本任一不一致均返回 401。
- 旧 JWT 只在兼容窗口内有效，安全变化仍能立即撤销。
- 普通与记住登录的绝对/空闲期限、最大并发数和最旧会话撤销策略正确。
- 使用并发屏障证明最终有效会话数不超过上限；在新会话写入、审计或缓存失败时，旧会话数据库与 Redis 状态保持一致。
- 最近活动节流更新、记录保留清理和设备/IP 脱敏符合配置。
