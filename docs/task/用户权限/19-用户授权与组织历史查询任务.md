# 用户授权与组织历史查询任务

## 关联业务缺口

- UM-21：角色、个人权限、组织、岗位、管理者和会话变化无法从用户视角完整追溯。
- UM-22：现有审计动作粒度过粗，批量禁用等操作缺少完整记录。

## 当前错误行为

- 角色和密码动作复用用户状态审计，缺少明确修改前后值和原因。
- 用户详情没有组织、任职、授权和安全历史查询。

## 目标不变量

- 用户管理关键变化均可按目标用户、动作和时间查询，历史使用稳定名称和 code 解释。
- 历史和审计不可被普通管理者修改或删除，停用对象仍能解释原事实。
- 敏感凭证、Token、密码哈希和完整联系方式不进入历史响应。
- Task 11 和各业务写任务负责生成组织、任职和授权历史事实；本任务只负责用户视角聚合投影、权限过滤和时间线，不重写历史事实。
- Task 20 的调岗、完成离职和返聘必须把任职与汇报关系前后快照写入同一 `t_authorization_history` 权威来源，组织历史查询和用户聚合时间线共同读取该事实，不以生命周期事件替代组织历史。

## 前置依赖

- 完成 Task 08 和 Task 10—18。

## 允许修改范围

- 用户域历史与审计查询 Service、Controller、DTO、Response、Mapper 和测试。
- 用户详情历史组件、API、类型和测试。
- 审计动作、批量摘要及必要的 OpenAPI、错误码和技术文档。

## 禁止修改范围

- 不提供历史或操作审计的修改、覆盖和物理删除接口。
- 不直接把操作日志实体或原始审计明细返回前端。
- 不在循环中逐条输出高频应用日志代替业务审计。

## 查询契约

- 普通用户历史至少覆盖账号状态、资料、组织、岗位、直属管理者、角色、角色矩阵、个人权限、数据范围、邀请签发与激活、联系方式验证、登录标识切换、密码重置、会话创建与撤销、自动锁及管理员保护阻断。限流主体摘要、初始化门禁和恢复账号 break-glass 保留在全局高危审计；没有安全 `target_user_id` 投影或目标本身禁止查询时，不得把动作加入普通用户历史白名单冒充已支持。
- 返回操作者摘要、动作、目标、前后稳定值、原因、有效期、结果和发生时间。
- 批量操作返回批次摘要及目标结果，查询受审计权限和目标管理范围共同限制。
- 三个来源必须在数据库内按发生时间倒序、来源键升序、来源主键倒序统一稳定排序，并在动作与时间过滤后执行总数统计和 `LIMIT/OFFSET`；禁止全量加载后在 JVM 内排序分页。`actionOptions` 仍取同一时间窗内实际存在的全部白名单动作，不受当前动作筛选影响。

## 执行步骤

1. 梳理现有用户管理动作并替换错误复用的审计枚举。
2. 补齐批量禁用、角色权限、个人授权、任职和会话撤销的事务内审计。
3. 实现按用户聚合的历史查询，以单一数据库 `UNION ALL` 投影读取 Task 11 等写任务产生的不可变历史、操作审计展示投影和生命周期事件，在数据库完成跨来源过滤、计数、稳定排序及分页，不再次定义历史当前态。
   `t_operation_log` 查询索引 `idx_operation_log_user_history(resource_id, action_code, create_time, id)` 必须直接写入生产和 H2 数据库基线。
4. 停用角色、权限、组织和岗位时保留稳定名称快照或可解释 code。
5. 实现审计查询权限、目标管理范围、真实动作组合注册表和敏感字段清理；后端必须拦截 digest、key、signature、salt、nonce 及任意长十六进制摘要，前端只作为第二道显示防御。
6. 在用户详情增加历史时间线、筛选、分页、空状态和失败状态。
7. 同步 OpenAPI、技术文档和测试。

## 测试

- 每类管理动作生成正确审计动作、目标、前后值、原因和操作者。
- 业务事务回滚时无成功审计，审计写入失败时业务事实回滚。
- 批量操作具有批次摘要和逐项结果，无循环日志风暴。
- 停用对象的历史仍能解释名称和 code。
- 无审计权限、跨组织和本人无权查看的敏感历史被拒绝或脱敏。
- 相同发生时间下，授权历史先于操作日志、操作日志先于生命周期事件；同一来源按主键倒序，跨页读取不得重排、重复或遗漏。
- 真实 MySQL/MariaDB 空库初始化必须验证用户历史索引的字段顺序和普通 BTREE 属性。
- 响应不包含密码、哈希、digest、Token、Credential、Key、Signature、Salt、Nonce、完整手机号和邮箱；原因、操作者、目标和批次字段也经过相同值清理。
