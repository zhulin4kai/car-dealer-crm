# 账号邀请激活与凭证生命周期任务

## 关联业务缺口

- UM-13：创建账号立即启用并由管理员填写初始明文密码。
- UM-14：没有邀请、激活、找回密码、首次改密、失败锁定和密码历史。

## 当前错误行为

- 管理员创建账号时直接提交初始密码，账号立即可登录，没有待激活和首次改密状态。
- 本人改密与管理员重置混用，缺少旧密码验证、一次性重置凭据和密码历史。
- 登录失败没有自动锁定，最后登录时间未可靠更新。

## 目标不变量

- 邀请、激活和重置凭证单次、限时；业务事务只保存不可逆预交付承诺，Worker 提交后才派生原始凭证并绑定实际摘要，重新签发后旧凭证失效。
- 本人改密验证当前密码；管理员重置下属密码禁止针对本人，并要求目标下次登录改密。
- 密码、密码哈希和原始临时凭证不进入响应、日志或审计。
- 连续失败自动锁定与人工管理锁定含义独立。

## 禁止修改范围

- 不建设外部邮件、短信、人事或统一身份平台；只提供安全交付适配边界。
- 不把原始凭证写入数据库、应用日志或操作审计。
- 不在未认证响应中泄露账号是否存在、禁用或锁定。

## 凭证与状态契约

- 账号管理状态使用待激活、启用、禁用；锁定、到期和首次改密为独立安全属性；待交接和已离职属于员工任职状态。
- `t_login_identifier` 永久保存登录标识归属；当前标识退休后不得转给其他员工，创建和改名共用 `LOGIN_IDENTIFIER_GUARD` 串行化锁。
- 账号到期时间与凭证到期时间分别持久化和判断；清除其中一个不得顺带清除另一个。
- 密码统一执行长度、复杂度和最近历史不可复用规则。
- 找回密码无论账号是否存在返回相同响应；一次性凭证成功使用后立即作废。
- 登录失败达到配置阈值后按配置时间自动锁定，人工锁定只能由授权管理者解除。
- 邀请激活在同一事务完成账号 `INVITED -> ACTIVE` 与员工 `PENDING -> ACTIVE`；密码重置保持账号启禁用和任职状态不变。
- 禁用、离职、登录账号变化、安全到期和密码成功变化撤销全部尚未消费凭证；凭证消费锁定账号与员工并使用状态及版本条件，禁止旧凭证后写复活账号。
- 联系方式验证使用独立单次凭证，联系方式变化清除验证状态并撤销旧验证凭证；找回密码只使用当前已验证联系方式。
- 普通管理员只有在至少一个当前员工联系方式已验证后才计入 `READY`；最后一个可恢复管理员的本人资料和受管资料命令都不能替换或清空唯一已验证渠道。
- 普通账号自动锁定原子提升安全版本并撤销全部会话；恢复账号和唯一普通管理员不使用会关闭最后管理入口的普通自动锁，必须记录高危阻断审计。
- 受保护恢复账号通过默认关闭、依赖部署环境外部密钥和一次性凭证的独立 break-glass 命令恢复，不得开放普通找回或受管重置入口。

## 执行步骤

1. 增加登录标识永久归属、密码历史、账号临时凭证、失败次数、锁定原因、账号/凭证到期时间和首次改密数据模型。
2. 实现邀请、重新邀请、激活、忘记密码和重置密码用例；业务签发路径只计算预交付承诺，不调用原始凭证派生，原始 Token 仅由提交后 Worker 生成并交给安全交付适配器。
3. 生产环境只向配置的通知渠道交付凭证；受理接口仅返回 HTTP 202/`QUEUED`。本地 `dev/test` Profile 的捕获适配器只能由提交后 Worker 调用，生产和测试业务接口都不得暴露原始 Token。
4. 分离本人改密和管理员重置下属密码，修正路径 ID 请求体重复校验。
5. 实现密码强度、最近历史、首次改密和凭证过期规则。
6. 登录失败原子累计并区分自动锁定与人工锁定；登录成功更新最后登录时间并清零允许清理的计数。
7. 登录账号修改在 `LOGIN_IDENTIFIER_GUARD` 内退休旧标识并激活或创建同一员工的新标识，在同一数据库事务内提升安全版本；任何员工都不能占用其他员工的当前或历史标识，Redis 清理失败不能恢复旧 Token。
8. 所有凭证和状态变化写明确审计动作，但不保存秘密值。
9. 在 Dashboard 之外增加 `/activate`、`/forgot-password`、`/reset-password` 和 `/first-password-change` 公共或受限路由，并放在兜底路由之前。
10. 当前用户需要首次改密时，路由守卫只能放行改密、登出和必要会话接口，不能进入其他业务页面。
11. 同步 OpenAPI、前端页面、类型、错误码、路由测试和守卫测试。
12. 实现联系方式验证申请、消费、重签失效、资料变更撤销和个人中心验证状态入口。
13. 实现受保护恢复账号的独立 break-glass 请求与消费命令，并验证默认关闭、外部密钥、一次性、审计和会话失效。
14. 生产交付通过 `CREDENTIAL_DELIVERY_WEBHOOK_URL`、至少 32 字节 `CREDENTIAL_DELIVERY_BEARER_TOKEN` 与独立 `CREDENTIAL_DERIVATION_KEY` 调用受信 HTTPS 通知服务；只在人工联调显式开启 `CREDENTIAL_DELIVERY_ALLOW_INSECURE_LOOPBACK` 时允许回环 HTTP。渠道或联系方式可在入库前本地拒绝；网络结果由提交后 Outbox 重试处理，不得再承诺同步 Webhook 失败使已提交业务回滚。
15. 使用 Redis 事务计数器实现账号/联系方式/凭证摘要与来源地址双层滑动窗口；Redis 不可用时 fail-close，忘记密码仍保持 `QUEUED` 同形响应，其他命令返回稳定 `628`/HTTP 429，并记录不含主体明文的限流审计。
16. 重发冷却必须在签发事务中锁定目标用户并查询用途族最近一次签发时间，覆盖已撤销和投递失败凭证；初始邀请可不受重发冷却，重邀、密码重置、联系方式验证、break-glass 和管理员降级恢复使用固定冷却窗口。
17. HUMAN 凭证签发和 Worker 只读取员工档案当前联系方式；`t_user` 联系方式仅是兼容投影，不得作为 HUMAN 投递回退，固定 SYSTEM 恢复账号使用独立账号联系方式。
18. Worker 使用与凭证消费端共用的 HMAC 摘要器，将预交付承诺 CAS 绑定为实际 `token_digest` 后才能投递；重试接受已绑定的同一摘要，承诺、已绑定摘要或凭证状态不一致时 fail-close。

## 测试

- 邀请、激活、重新邀请、过期、重复使用和首次改密。
- 本人改密旧密码错误、密码历史复用和成功后旧会话失效。
- 管理员不能重置自己密码，不能重置同级、上级和范围外用户。
- 管理员重置必须按 `ORGANIZATION_HIERARCHY -> REPORTING_GRAPH -> AVAILABLE_ADMIN_GUARD` 串行化，并在写入 `must_change_password` 前保护最后一个可用普通管理员入口。
- 忘记密码对存在和不存在账号返回相同结果。
- 达到失败阈值自动锁定，到期恢复；人工锁定不被时间自动解除。
- 登录成功更新最后登录时间且安全计数正确。
- 新建和改名并发争用同一登录标识时最多一个成功；改名后其他员工不能注册旧标识，同一员工恢复历史标识保留完整事实。
- 账号到期时间、凭证到期时间分别覆盖未来到期、立即到期和清除，并验证旧会话失效及最后普通管理员保护。
- 响应、日志和审计不包含原始 Token、密码或哈希。
- 首次邀请激活同时推进账号和员工状态；待交接、离职或已禁用状态不能被旧邀请及重置凭证复活。
- 恢复账号、唯一普通管理员、两个普通管理员并发第五次失败及普通账号自动锁定后的旧会话永久失效。
- 联系方式验证覆盖过期、重复消费、重新签发、联系方式变化和找回密码投递。
- 覆盖首管理员首次改密后仍因渠道未验证保持 `PENDING_FIRST_CHANGE`、验证后进入 `READY`，以及两个资料入口的最后恢复渠道并发保护。
- break-glass 覆盖默认关闭、错误外部密钥、一次性消费、受保护目标限制和秘密不落审计。
- 受信通知 Webhook 覆盖未配置、弱密钥、非 HTTPS、显式回环联调、非 2xx、缺少联系方式和成功投递；任何业务响应和应用日志均不出现原始凭证。
- 限流覆盖主体阈值、来源阈值、Redis 不可用、忘记密码同形响应、消费失败上限和脱敏审计。
- 并发双签发只产生一条凭证与一条 Outbox；上一凭证被撤销或投递失败后，冷却窗口内仍不得立即重发。
- 业务签发路径从不调用原始凭证派生；Worker 首次投递只绑定一次实际摘要，临时失败、租约恢复和重试使用相同 `messageId`、原始凭证和摘要，篡改预交付承诺时不得调用外部投递。
- 员工联系方式已变化而账号兼容投影仍为旧值时，Worker 必须拒绝投递并撤销凭证；固定 SYSTEM 恢复账号仍可使用专用联系方式。
