# 调岗离职返聘闭环任务

## 关联业务缺口

- UM-23：调岗、离职和返聘没有完整任职状态机。
- UM-24：现有交接只覆盖部分负责人对象，账号状态和任职事实未形成闭环。

## 当前错误行为

- 离职主要表现为账号禁用和部分活动、线索、客户转移，没有待交接、已离职和返聘任职事实。
- 调岗会改变当前信息，但没有完整原组织、岗位、管理者、生效时间和原因历史。

## 目标不变量

- 调岗、离职和返聘使用明确状态迁移，保留原任职、管理关系、授权和业务责任历史。
- 调岗、完成离职和返聘在生命周期事件之外，同事务写入 `ORGANIZATION_ASSIGNMENT` 与实际变化的 `REPORTING_RELATION` 前后快照，使组织历史接口可按员工查询完整事实。
- 离职先进入待交接，完成责任交接后才能终止任职和登录能力。
- 已离职人员不能登录、接受新授权或成为新业务负责人；返聘创建新的任职事实。

## 前置依赖

- 完成 Task 08、Task 11、Task 14、Task 15、Task 17 和 Task 19。

## 允许修改范围

- 用户域调岗、离职、返聘和交接编排 Service、DTO、Response、历史、审计和测试。
- 现有用户交接接口和用户管理前端调岗、离职、返聘流程。
- 为衔接责任交接必需的现有交接 Mapper 调用，不修改其他业务模块内部状态机。

## 禁止修改范围

- 不物理删除用户、员工、任职、授权或历史业务负责人。
- 不在未完成责任交接时直接把员工设为已离职并返回成功。
- 不把返聘实现为覆盖旧离职时间和旧任职记录。

## 状态与事务契约

- 任职状态按待入职、在职、待交接、已离职迁移，返聘作为从已离职重新建立任职的动作，非法跳转返回 409。
- 调岗和交接命令包含原因、目标组织、岗位、管理者、生效时间和预期版本。
- 离职闭环在数据库事务中写入交接结果、关闭任职/管理关系、撤销授权、提升安全版本、更新账号状态及审计；Redis 会话清理提交后重试。
- 六个直接责任域为 Activity、Clue、Customer、Opportunity、FollowTask、TestDrive；Quote、Tran 只通过 Customer 归属派生核验，待审批和 CommunicationRecord 禁止更新。
- 每个直接域必须使用同一组状态过滤生成逐项 ID、负责人、状态和版本快照，并以相同谓词逐项更新；接收人资格在预检、确认和完成离职前重新校验。
- 交接只改变当前 `owner_id` 及有版本对象的版本，不改写 `create_by`、`edit_by`、`approve_by`、`reviewed_by`、`completed_by`、`safety_confirmed_by`、`check_in_by` 或既有历史。
- TestDrive 在预检和确认时都校验接收人的目标排期冲突；任一冲突、资格漂移、计数不符、历史或审计失败均使整个数据库事务回滚。
- 预检 Token 使用随机不可猜测值，数据库只保存摘要；快照一次性、有限 TTL，并绑定用户、员工版本、原因和精确事实指纹，任何同数量事实替换也必须使快照失效。
- `transfers` 对每个数量大于零的直接责任域必须恰好一项；重复域、零责任域、Quote 或 Tran 均拒绝。
- 完成离职必须取消当前及未来的角色、个人允许、个人拒绝、任职和汇报事实；员工仍是启用组织负责人或仍有当前/未来直属下属时阻断。
- 返聘 `INVITE` 允许替换过期旧密码或凭证并签发新的单次邀请；`RECOVER` 要求现有凭证仍有效。两者都要求账号未到期、未人工锁定且自动锁定已结束，并且绝不恢复旧授权。
- 完成离职必须撤销全部尚未消费的邀请、本人重置、管理员重置和联系方式验证凭证；已离职员工不能通过通用启用、密码重置或授权命令绕过返聘。
- 凭证消费与完成离职使用一致的账号、员工加锁顺序和状态 CAS，并发时最多一个成功；离职成功后的最终账号不得被旧凭证重新启用。
- 生命周期事件为不可覆盖历史，生产初始化和版本化迁移必须同时建立拒绝 `UPDATE/DELETE` 的数据库触发器。

## 执行步骤

1. 实现调岗命令，关闭旧主要任职并创建新任职和管理关系历史。
2. 实现离职预检，按六个直接责任域保存精确责任快照，并统计 Quote/Tran 派生影响、有效授权、会话和待处理任职关系。
3. 进入待交接后限制新增长期责任；确认交接和完成离职均重新预检，逐域核对预期数量、实际数量及源用户剩余责任为零。
4. 交接成功后关闭有效任职、代理管理和个人授权，禁用账号并提升安全版本，使全部旧会话立即失效。
5. 实现返聘命令，创建新的任职事实并按邀请或恢复规则重新开通账号，不恢复过期旧授权。
6. 所有步骤写前后状态、原因、操作者和结果审计，失败不留下半完成状态。
7. 实现前端调岗、离职预检、交接确认和返聘流程。
8. 同步 OpenAPI、错误码、技术文档和测试。

## 测试

- 调岗保留原组织、岗位和管理者历史，版本冲突不覆盖新结果。
- 调岗、完成离职和返聘后，组织历史查询分别返回稳定组织、岗位、DIRECT/ACTING 管理者快照、原因、可信操作者和发生时间；历史写入失败时生命周期事务整体回滚。
- 未完成交接只能进入待交接，不能直接已离职。
- 交接任一部分失败时任职、账号、授权和会话均不发生部分关闭。
- 已离职不能登录、接受新角色/权限或进入负责人候选。
- 返聘创建新任职，旧历史和原业务责任不被覆盖，旧临时权限不自动恢复。
- `INVITE` 和 `RECOVER` 分别覆盖旧凭证过期、现有凭证有效、账号到期、人工锁定和自动锁定场景。
- 快照覆盖重复使用、过期、原因变化、同数量责任替换、授权/任职/汇报/组织负责人漂移和员工版本冲突。
- 生命周期事件在真实 MySQL/MariaDB 中均拒绝 `UPDATE` 和 `DELETE`。
- 禁用、授权撤销或安全版本提升失败时不返回离职成功；Redis 清理失败不恢复已经失效的旧会话。
- 完成离职撤销全部有效凭证；离职事务回滚时凭证撤销也回滚，返聘邀请只允许新签发凭证激活。

- 返聘该员工，确认产生新任职且旧历史可查询。
