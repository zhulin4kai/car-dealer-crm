## 当前错误行为

- `/api/login/free`、用户请求必填字段、路径 ID 请求体和 Token 续期等文档与实现不一致。
- 现有测试没有证明禁止自改、上下级边界、授权上限、临时权限、组织循环、多会话和个人中心闭环。

## 目标不变量

- OpenAPI、Java DTO/校验、前端 TypeScript 类型和实际请求响应完全一致。
- 用户管理全部 Spec 验收场景均有自动化或明确手工证据。
- 认证过滤层使用账号、凭证、锁定、强制改密、至少一个当前已验证员工联系方式、在职员工、真实主要任职、启用组织岗位和普通管理员角色的同一权威事实判断 `UNINITIALIZED/PENDING_FIRST_CHANGE/READY/DEGRADED`；任一条件失效时立即 fail-close。
- 初始化前仅开放登录信息、用户列表、引导选项读取和首个管理员创建；受保护恢复账号永久退出常规用户治理、组织、角色、权限、审计、普通会话以及客户、交易等日常业务，只保留登录信息、退出、本人非授权资料与独立专用联系方式，以及四态允许的独立引导或恢复入口。其专用联系方式不计入普通管理员就绪条件。
- 后端完整测试、前端完整检查和启动后的浏览器手工验收通过，无遗留后台进程和临时文件。

- 不宣称未执行、未覆盖或仅间接验证的场景已经完成。

## 契约检查

- 删除旧单数用户路径和重复目标 ID，只保留最终用户管理契约。
- 修正当前用户、邀请激活、组织岗位、角色矩阵、用户授权、会话、历史和生命周期全部接口。
- 补齐 `202`、`400`、`401`、`403`、`404`、`409`、`410`、`422`、`429`、`500`、`503` 的 HTTP 状态和稳定业务错误码；用户管理受保护接口的 `403` 必须同时覆盖普通授权拒绝 `520` 与四态门禁 `641/642`。
- 修正文档中的登录状态验证、JWT 声明、会话时长、滑动续期和个人信息字段说明。

## 自动化验证步骤

1. 执行用户管理定向后端单元、Mapper、H2、MockMvc 和认证集成测试。
2. 执行完整后端 `./mvnw test`，记录通过、失败、跳过和警告数量。
3. 执行前端用户领域测试、路由、Store、布局测试和完整 `npm run check`。
4. 执行权限 code 一致性、OpenAPI 契约、Schema 约束和数据库基线策略核验。
5. 在受支持的空 MySQL 和 MariaDB 数据库上分别完整执行 `CarDealerCRM.sql`；核对表、字段、约束、索引、触发器、种子、占位组织、账号状态和不可变规则。
6. 检查仓库不存在 migration 目录、增量 SQL、执行器、manifest、账本或迁移契约测试。
7. 执行 `git diff --check`、完整差异和未跟踪文件检查。

## 启动与手工验收步骤

1. 按 `docs/integration.md` 启动数据库、Redis、后端和前端，不修改本机永久配置。
2. 准备受保护管理员、安全管理员、主管、直属下属、同级、上级、跨组织和普通用户测试账号。
3. 验证组织树、岗位、主要任职、兼岗、代理管理、循环拒绝和版本冲突。
4. 验证角色矩阵影响预览、受保护角色、个人允许/拒绝、临时权限、数据范围和来源展示。
5. 验证任何用户不能自改授权，主管只能管理下属且不能越权下放。
6. 验证个人中心资料白名单、本人改密、左下角菜单和本人会话。
7. 验证多设备登录、选择性撤销及账号、密码、授权和状态变化后的会话失效。
8. 验证首次初始化由受保护恢复管理员引导创建首个真实任职的普通管理员；激活或首次改密任一完成都仍处于 `PENDING_FIRST_CHANGE`，只有首次改密和至少一个当前员工联系方式验证全部完成后才进入 `READY`。制造唯一管理员自然密码到期后进入 `DEGRADED`，窄恢复命令可恢复原账号且不能指定目标或变更角色。
9. 验证凭证业务事务提交前不生成原始凭证且 Webhook 为零，只保存预交付承诺；提交后 Worker 派生原始凭证并以 CAS 绑定实际摘要后才投递，崩溃可恢复、接收后超时以相同 messageId 与凭证幂等重试，篡改承诺时不投递，永久失败撤销凭证且所有终态清除派生秘密。
10. 验证邀请、激活、凭证单次使用、失败锁定、调岗、离职交接和返聘。
11. 验证手机、邮箱验证的重签、过期、重复消费和资料并发变化；已验证渠道可找回，未验证渠道响应同形且不投递。
12. 验证 break-glass 默认关闭、错误密钥、固定目标、单次消费、密码历史、会话撤销和高危审计脱敏。
13. 验证恢复账号和唯一普通管理员的自动锁保护；存在第二普通管理员时失败阈值仍触发锁定并使旧 Token 永久失效。
14. 验证固定恢复账号在四态中的个人中心例外：只能维护本人非授权资料和独立专用联系方式，不能改变普通管理员 `READY` 计数、本人授权、组织任职或常规治理与日常业务访问。
15. 验证邀请、组织调整、调岗、返聘使用同一目标组织管理者候选，普通人员不能提交空管理者；首次根公司负责人初始化只能成功一次且原子回滚。
16. 在 MySQL 与 MariaDB 从空库执行完整基线，并验证登录标识和恢复账号不可变触发器。
17. 并发创建超过上限的会话，验证上限、revision、数据库和 Redis 一致，后续失败不提前删除旧会话。
18. 验证无权限直接请求仍被后端拒绝，不能只依赖前端隐藏。
19. 验收结束后停止本任务启动的服务并确认无遗留进程。
