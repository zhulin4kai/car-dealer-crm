# 补齐权限数据范围与交接任务

按用户权限 Spec 和治理方案，补齐账号状态、权限粒度、数据范围、离职调岗交接、会话失效和权限审计。

- 给普通业务角色默认授予敏感导出、退款、开票、交付或审计权限。

## 当前代码落点

- `UserController` 提供用户列表、详情、创建、更新、启禁用、锁定解锁、角色分配等入口。
- `UserServiceImpl` 承载用户状态、角色和权限逻辑。
- `DataScopeAspect` 处理数据范围。
- `PermissionCodes` 与前端 `permissions.ts` 需要保持一致。

## 执行步骤

1. 梳理用户状态、角色权限、权限种子和前端权限常量。
2. 补齐导入、导出、审批、收款、退款、开票、交付和审计查看权限编码。
3. 所有敏感接口加后端权限控制。
4. 补齐数据范围规则，列表、详情、导出、更新和删除都必须覆盖。
5. 禁用、锁定用户时清理 Redis 会话。
6. 新增离职或调岗交接命令，支持线索、客户、商机、跟进任务等责任人迁移。
7. 权限和账号状态变化写操作审计。
8. 调整前端用户管理、角色分配和交接入口。
9. 补充权限一致性、数据范围、会话失效和交接测试。

## 代码逻辑要求

- 权限种子使用 code 建关系，不依赖数字 ID。
- Mapper 查询条件必须包含数据范围。
- 禁用最后一个系统管理员必须被拒绝。
- 角色权限变更后当前会话权限需要刷新或重新登录策略明确。
- 交接必须在事务内完成，失败不能留下部分迁移。

## 完成条件

- 禁用或锁定账号不能继续访问受保护接口。
- 普通业务人员只能看到职责范围内数据。
- 敏感动作权限独立控制。
- 人员调岗或离职时业务数据可以交接。
- 权限变化可审计。

## 交付说明

完成后说明：

- 新增权限编码和默认授权。
- 数据范围覆盖哪些接口。
- 会话失效策略。
- 离职交接支持哪些业务对象。

## 业务场景

- 管理账号、角色、权限、数据范围、关键动作授权和交接。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 账号和权限状态决定谁能触发业务事件，但不改变历史业务事实。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得用前端隐藏替代后端授权，不得移除最后管理员。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证角色数据范围、审批边界、负责人候选和权限审计。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
