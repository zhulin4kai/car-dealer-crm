# 角色权限目录与矩阵任务

## 关联业务缺口

- UM-07：角色和权限只有固定种子，没有应用层角色管理和权限矩阵。
- UM-08：受保护角色、权限敏感级别和影响用户范围不可见。

## 当前错误行为

- 应用只能读取固定角色和权限，不能新增自定义角色、停用角色或维护角色权限矩阵。
- 权限目录没有敏感级别、可委派性和业务说明，管理者无法判断开关影响。

## 目标不变量

- 权限目录只表达代码和初始化数据支持的真实资源，管理页面不能创造任意权限 code。
- 自定义角色可新增、编辑、复制和停用；角色 code 创建后不可修改，历史角色不物理删除。
- 角色权限矩阵保存原子化，受保护角色和敏感权限按安全规则限制。

## 禁止修改范围

- 不提供任意权限 code 的创建、删除或修改入口。
- 不允许普通管理员删除、停用或削弱受保护恢复角色。
- 不通过前端禁用开关替代后端敏感权限校验。

## API 与事务契约

- 提供角色分页/列表、详情、新增、修改、复制、启停、权限矩阵读取和原子替换。
- 提供只读权限目录树，返回模块、类型、敏感级别、可委派性、启停状态和说明。
- 矩阵保存请求包含原因、预期版本和权限集合；响应返回最终版本、影响用户数量和会话撤销结果。

## 执行步骤

1. 实现角色目录 Service 和受保护角色规则，创建后禁止修改角色 code；编辑角色属性、适用组织和启停前都校验全部当前/未来成员，不能通过矩阵之外的入口间接改变同级、上级或范围外人员权限。
2. 实现权限目录树和稳定模块分组，不暴露未启用或未知权限为可分配项。
3. 实现角色矩阵影响预览，突出新增、移除的敏感权限及受影响用户数量。
4. 角色矩阵保存时校验操作者上限、受保护角色、版本和全部权限 ID。
5. 校验角色适用组织和全部受影响用户；任一用户超出操作者管理范围时普通管理者不能保存。
6. 在同一事务内替换矩阵、写历史和审计；任一失败整体回滚。
7. 成功后在数据库事务内提升受影响用户安全版本，使旧会话立即失效；Redis 清理失败告警重试但不能恢复旧 Token。
8. 新增角色列表、表单、复制、状态操作和树形权限矩阵页面。
9. 新增只读权限目录页面；权限矩阵使用现有 Checkbox、Collapsible 和 ScrollArea 组合，不引用不存在的 Tree 或 Tabs。
10. 增加 `/dashboard/role`、`/dashboard/permission` 显式路由、菜单权限种子和路由测试。
11. 同步 OpenAPI、前端类型、错误码、后端/前端技术文档和测试。

## 测试

- 自定义角色新增、复制、修改、停用及 code 唯一、不可变。
- 有当前或未来成员占用的自定义角色不得停用；成员全部关闭后可停用且历史仍可解释。
- 受保护角色不能删除、停用或被普通管理员削弱。
- 全局共享角色只能由安全管理员维护；组织级角色维护者必须覆盖全部适用组织和受影响用户。
- 普通管理者不能修改已授予同级、上级或范围外人员的角色矩阵。
- 未知、停用或超过授权上限的权限不能写入矩阵。
- 角色矩阵影响预览数量和敏感权限差异准确。
- 版本冲突返回 409，审计或关系写入失败不留下部分矩阵。
- 矩阵成功后相关用户旧会话失效。
- 前端父子联动、变更摘要、原因校验、失败保留和重复提交保护。
