## 当前错误行为

- “销售经理”等角色名被当成管理能力，但系统不知道其具体下属和组织范围。
- 组织、岗位、直属管理者、兼岗和代理关系没有业务入口。

## 目标不变量

- 组织树、岗位、员工主要任职、兼岗、代理任职和直属管理关系均可维护和查询。
- 用户不能管理自己，汇报关系不能形成环，代理管理到期后自动失效。
- 组织负责人、岗位、直属管理者和权限角色含义独立。
- 只允许一个启用无上级根公司，父子类型固定为公司→门店/部门、门店→部门/团队、部门→团队；根公司不可移动、停用或降级。
- 最高级管理者唯一由根公司 `leader_employee_id` 识别；普通员工必须具有目标主要组织内合法直属管理者，邀请与所有后续任职写路径共用同一校验器。

## 禁止修改范围

- 不把组织负责人自动当作所有员工的直属管理者。
- 不根据权限角色自动生成管理关系。
- 不修改其他业务模块的数据范围和流程。

## API 与并发契约

- 提供组织树、组织新增修改启停、岗位列表新增修改启停、员工任职、管理者候选和历史查询。
- 更新请求携带目标版本，组织、任职和管理关系使用 CAS 或行锁防止丢失更新。
- 组织停用前检查有效下级组织和在职员工，冲突返回稳定 `409` 业务错误码。
- 组织停用同时检查当前/未来任职和待交接责任；岗位存在当前或未来任职时拒绝停用。普通员工空管理者、跨目标组织、账号禁用/锁定、任职或岗位无效均返回稳定冲突，根公司负责人是唯一例外。

## 测试

- 正常创建公司下的门店、部门、团队并稳定排序。
- 禁止组织父级环、本人管理和多级汇报环。
- 组织存在有效下级或在职员工时不能停用。
- 唯一根公司和合法父子类型矩阵不可破坏；岗位有当前或未来任职时不能停用。
- 邀请、组织调整、调岗和返聘对空管理者、跨兄弟组织、锁定/禁用管理者及环路给出同一结果。
- 一个员工只有一个主要任职，兼岗不改变主要组织。
- 代理任职和代理管理仅在有效期内生效。
- 两个管理者并发更新同一任职时后提交者得到版本冲突。
- 无权限和超出组织范围的接口请求返回 403。
