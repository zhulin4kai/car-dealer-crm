# 代理管理关系与主管并发闭环任务

## 关联业务缺口

- UM-34：ACTING 只有数据库枚举和文档概念，没有独立 API、页面和可执行命令；DIRECT 与 ACTING 未共用时间区间环校验，账号失效可与主管关系写入并发，形成候选校验后的资格失效窗口。
- UM-35：用户安全审计动作编码超过旧 `varchar(32)`，联系方式验证完成审计会写入失败。

## 前置依赖

- 完成 Task 03—20 和 Task 22；Task 23 必须复用 Task 22 已收口的四态门禁、管理员保护和账号失效锁序，不得建立第二套并发策略。
- 后续单向顺序为 Task 23 → Task 24 → Task 21；后续任务不得作为本任务的完成前置。

## 目标不变量

- DIRECT 是唯一单值直属管理者；ACTING 是独立多值集合，空集合只结束 ACTING。
- ACTING 立即生效、必须设置一年内的有限结束时间，同一命令中管理者不得重复。
- DIRECT 与 ACTING 共同参与按有效区间交集计算的汇报环；没有共同有效时间的路径不构成环。
- 关系写持有 `ORGANIZATION_HIERARCHY → REPORTING_GRAPH` 并在锁内重验管理者资格。
- 使候选立即失效的禁用、人工锁定、安全到期和自动锁使用 `REPORTING_GRAPH → AVAILABLE_ADMIN_GUARD → t_user`，不得反序。
- 代理关系变化使用员工版本 CAS，只提升一次版本，写历史、审计、认证安全版本并撤销旧会话。
- 操作审计动作编码至少支持 64 字符。

## 允许修改范围

- 组织汇报 DTO、Controller、Service、Mapper、前端组织页面、独立 ACTING 对话框和测试。
- `t_employee_reporting` 约束、`t_operation_log.action_code` 长度、后续迁移、Manifest、Fresh Schema、H2 Schema 和 OpenAPI。
- 账号状态、安全到期和登录自动锁的图锁顺序。

## 禁止修改范围

- 不让 ACTING 替代普通员工的 DIRECT 必填规则。
- 不把代理主管显示为直属主管。
- 不因组织关系绕过安全自动锁；锁定后组织事实保留，由后续治理重新分配。
- 不修改 ERP、财务、人事对接或其他业务模块流程。

## 执行步骤

1. 新增 ACTING 集合查询、基础候选查询和按员工版本替换接口。
2. 实现只关闭 ACTING 的差异更新，保留未变化事实并拒绝重复管理者、无限期和超一年关系。
3. 抽取 DIRECT/ACTING 共用的时间区间汇报图环校验，并保持 DIRECT 候选错误码为 `REPORTING_CYCLE`。
4. 统一候选资格丧失路径的图锁顺序，在关系写锁内重新查询候选。
5. 新增独立代理主管对话框、取消陈旧请求、稳定错误提示和 OpenAPI 契约。
6. 新增数据库有限期 CHECK，扩展审计动作列并登记 Task 23 迁移。
7. 补单元、H2、真实 MySQL/MariaDB、前端和手工验收证据。

## 测试

- 多条 ACTING 共存；空数组、差异更新和无变化保存均不影响 DIRECT。
- ACTING 缺少结束时间、超过一年、重复、自指、无效候选和混合环被拒绝。
- 时间不重叠路径不误判环；员工版本过期返回稳定冲突。
- 禁用先提交时后续关系写拒绝；关系先提交时禁用可继续且无死锁。
- 员工摘要始终显示 DIRECT，不被 ACTING 覆盖。
- 联系方式验证完成等长动作码可以成功写审计。
