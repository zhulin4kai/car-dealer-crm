# 新增商机前端任务

## 任务目标

在商机后端任务完成后，新增商机前端模块、路由、列表、详情、表单和阶段推进入口。

## 修改范围

允许修改：

- 新增 `dealer-web/src/modules/opportunity/api/opportunity-api.ts`
- 新增 `dealer-web/src/modules/opportunity/model/opportunity.types.ts`
- 新增 `dealer-web/src/modules/opportunity/model/opportunity-stage.ts`
- 新增 `dealer-web/src/pages/dashboard/opportunity/index.vue`
- 新增 `dealer-web/src/pages/dashboard/opportunity/[id].vue`
- `dealer-web/src/router/routes.ts`
- `dealer-web/src/shared/constants/permissions.ts`
- `dealer-web/src/layouts/DashboardLayout.vue`
- 商机相关前端测试和前端文档。

禁止修改：

- 交易页面的履约状态语义。
- 报价订单页面核心逻辑，除非只是建立跳转入口。
- 通过中文后端 message 判断业务分支。

## 当前代码落点

- 当前没有 `dealer-web/src/modules/opportunity/`。
- 当前侧边栏和路由集中在 `routes.ts` 与 `DashboardLayout.vue`。
- 当前交易阶段前端映射在 `dealer-web/src/modules/tran/model/tran-stage.ts`，不得直接复用为商机阶段。

## 执行步骤

1. 新增商机 TypeScript 类型和阶段映射。
2. 新增商机 API 函数：列表、详情、创建、更新、推进、赢单、输单、搁置、恢复。
3. 新增商机路由和菜单权限。
4. 实现商机列表筛选：客户、负责人、阶段、来源、预计成交时间、停滞状态。
5. 实现商机详情：客户、线索来源、跟进任务、试驾、报价、订单和阶段历史。
6. 实现创建编辑表单和阶段推进操作。
7. 阶段推进、赢单、输单、搁置和恢复需要原因输入或下一步计划。
8. 补充路由、API、页面状态和权限测试。

## 交互要求

- 状态必须文本展示，不只用颜色。
- 阶段推进失败保留当前页面数据和用户输入。
- 快速重复查询不能由旧响应覆盖新筛选结果。
- 无权限按钮不展示，后端仍必须拒绝越权请求。
- 赢单入口必须提示会进入报价订单流程，不直接完成交易。

## 完成条件

- 有权限用户能查看商机列表和详情。
- 销售能创建商机并推进阶段。
- 输单、搁置、恢复必须填写原因。
- 商机详情能看到阶段历史。
- 前端不把交易履约状态显示为商机阶段。

## 交付说明

完成后说明：

- 新增前端模块、路由和权限编码。
- 阶段映射与交易状态如何区分。
- 列表、详情、阶段推进、赢单和输单如何验证。

## 业务场景

- 客户产生购车需求后创建商机，推进试驾、报价、赢单、输单和停滞处理。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 商机阶段只表达销售推进，赢单以订单成立为依据。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得让商机阶段承载收款、发票、库存或交付状态。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证商机阶段、跟进、试驾、报价和订单关系清晰。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
