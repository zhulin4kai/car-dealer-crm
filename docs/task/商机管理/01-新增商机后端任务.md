# 新增商机后端任务

## 任务目标

按商机管理 Spec 和落地方案，新增独立商机后端模型、状态机、阶段历史、权限和审计，确保商机阶段不混入订单、收款、发票或交付状态。

## 修改范围

允许修改：

- 新增 `dealer-server/src/main/java/com/autodealer/crm/web/OpportunityController.java`
- 新增 `OpportunityService`、`OpportunityServiceImpl`
- 新增 `TOpportunity`、`TOpportunityStageHistory`
- 新增 `TOpportunityMapper`、`TOpportunityStageHistoryMapper` 和 XML。
- 新增 `OpportunityQuery`、创建/更新/推进/输赢单 DTO、Response DTO。
- `dealer-server/src/main/resources/CarDealerCRM.sql`
- `dealer-server/src/main/resources/schema-test.sql`
- `dealer-server/src/main/java/com/autodealer/crm/result/CodeEnum.java`
- `dealer-server/src/main/java/com/autodealer/crm/constant/PermissionCodes.java`
- 商机相关测试、API 文档和后端文档。

谨慎修改：

- `ClueServiceImpl` 和 `CustomerServiceImpl`，仅用于新增转商机入口或关联查询。
- `TranServiceImpl` 和 `TranStage`，仅用于解除商机阶段和交易履约阶段混用。

禁止修改：

- 把现有 `TranStage` 直接当商机阶段使用。
- 收款、发票、交付状态语义。
- 让赢单商机直接完成交易。

## 当前代码落点

- 当前没有 `Opportunity` 后端模块。
- 当前交易状态集中在 `TranStage` 和 `TranServiceImpl`。
- 线索转客户已有 `CustomerManager.convertCustomer`，但线索转商机没有正式落点。

## 执行步骤

1. 新增商机表和商机阶段历史表。
2. 定义商机阶段 code：初步接触、需求确认、车型匹配、试驾邀约、报价协商、客户确认、赢单、输单、暂停或搁置。
3. 新增创建商机、编辑商机、推进阶段、赢单、输单、搁置、恢复接口。
4. 商机创建支持来源线索、客户新增需求和人工创建。
5. 阶段推进校验当前阶段、负责人、客户关系、必要业务事实和原因。
6. 赢单必须关联被客户确认的报价或订单成立事实。
7. 输单必须记录原因，不删除商机。
8. 所有关键动作写阶段历史和操作审计。
9. 补充 Mapper、Service、Controller、权限和集成测试。

## 代码逻辑要求

- Service public 方法使用业务动作命名，如 `createOpportunity`、`advanceStage`、`markWon`、`markLost`。
- 状态更新 SQL 必须带当前阶段条件，影响行数为 `0` 时返回冲突或非法状态。
- 商机负责人来自后端认证和授权规则，不能信任客户端提交的操作者。
- 已关联报价、订单或交易的商机不能普通删除。
- 列表、详情、导出必须带数据范围。

## 完成条件

- 后端存在独立商机模型、状态机和阶段历史。
- 线索可创建或关联商机，但不会直接产生订单。
- 商机赢单后可进入报价订单流程，但不直接完成交易。
- 收款、发票、交付变化不会覆盖商机阶段。
- 普通销售不能越权推进不属于自己的商机。

## 交付说明

完成后说明：

- 新增商机表、阶段 code 和迁移矩阵。
- 线索、客户、报价、订单关系如何表达。
- 与 `TranStage` 的边界如何拆开。
- 权限、数据范围和审计如何验证。

## 业务场景

- 客户产生购车需求后创建商机，推进试驾、报价、赢单、输单和停滞处理。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 商机阶段只表达销售推进，赢单以订单成立为依据。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得让商机阶段承载收款、发票、库存或交付状态。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证商机阶段、跟进、试驾、报价和订单关系清晰。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
