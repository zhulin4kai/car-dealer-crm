# 新增报价版本后端任务

## 任务目标

按报价订单 Spec 和报价版本方案，新增报价和报价版本后端能力，支持价格构成、促销引用、审批、客户确认和历史版本保留。

## 修改范围

允许修改：

- 新增 `QuoteController`、`QuoteService`、`QuoteServiceImpl`
- 新增 `TQuote`、`TQuoteVersion`、`TQuoteApproval`、Mapper、XML、DTO、Query、枚举。
- 促销校验 Service 接口调用。
- 商品和库存查询接口调用。
- `dealer-server/src/main/resources/CarDealerCRM.sql`
- `dealer-server/src/main/resources/schema-test.sql`
- 报价相关测试、API 文档和后端文档。

禁止修改：

- 直接把 `TTran` 当报价版本使用。
- 报价审批通过后自动创建订单。
- 报价过期后仍允许直接成交。

## 当前代码落点

- 当前没有独立报价模块。
- 交易创建、审批和商品关联集中在 `TranServiceImpl`、`TTran`、`TTranProduct`。
- 促销能力在 `ProductPromotionServiceImpl`。

## 执行步骤

1. 新增报价主表和报价版本表。
2. 定义报价状态：草稿、待审批、审批通过、审批驳回、待客户确认、客户已接受、客户已拒绝、已过期、已转订单。
3. 实现创建报价、生成新版本、提交审批、审批通过、审批驳回、客户接受、客户拒绝和过期处理。
4. 报价价格构成包含指导价、销售优惠、促销、附加费用和建议成交价。
5. 报价引用促销时调用促销可用性校验，并保存促销摘要快照。
6. 低于授权底价、特殊优惠或超出促销规则时必须进入审批。
7. 客户接受报价后仅标记为可创建订单，不直接完成交易。
8. 补充 Mapper、Service、Controller、权限和测试。

## 代码逻辑要求

- 每次价格方案变化必须新增版本，不覆盖历史版本。
- 金额使用 BigDecimal，服务端计算汇总金额。
- 客户端不能提交可信审批状态、最终金额汇总和操作者。
- 报价有效期由服务端校验。
- 报价详情展示历史版本和审批意见。

## 完成条件

- 报价可创建多个版本。
- 低于授权底价报价必须审批。
- 过期报价不能被客户确认或转订单。
- 报价引用促销保存成交时摘要。
- 审批意见可在报价详情追溯。

## 交付说明

完成后说明：

- 报价状态和版本规则。
- 促销校验和快照字段。
- 审批触发条件。
- 与订单成立任务的衔接点。

## 业务场景

- 销售为商机创建报价，经过审批和客户确认后形成订单。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 报价版本、审批、客户确认和订单成立是不同事件。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得用报价审批或订单成立直接完成交易履约。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证报价快照、订单成交事实、库存占用入口和收款计划关系。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
