# 订单成立与前端页面任务

## 任务目标

在报价版本能力基础上，实现客户确认报价后的订单成立、现有交易履约衔接，以及报价订单前端页面。

## 当前代码落点

- `TranController.create` 和 `TranServiceImpl.createTransaction` 是当前交易创建入口。
- `TranServiceImpl.addTransactionProducts` 处理交易商品。
- 前端交易创建和详情在 `dealer-web/src/modules/tran/` 与 `dealer-web/src/pages/dashboard/tran/`。

## 执行步骤

1. 新增从已接受报价创建订单的后端命令。
2. 订单创建时校验报价状态、有效期、客户、商机、车辆、促销和库存可用性。
3. 订单保存成交价格、优惠、促销、车辆和报价版本快照。
4. 订单成立后创建或衔接 `TTran` 交易履约记录，初始状态不能是完成。
5. 订单成立后触发库存占用和收款计划。
6. 商机赢单以订单成立为依据。
7. 前端新增报价列表、详情、版本历史、审批、客户确认和转订单入口。
8. 交易详情展示来源报价和成交快照。
9. 补充订单成立、库存占用、前端路由和 API 测试。

## 代码逻辑要求

- 订单创建必须在事务内完成报价状态更新、交易记录、商品快照和库存占用。
- 报价已过期、已拒绝、已转订单或库存不可用时返回稳定业务错误。
- 订单取消必须保留原因，并为交易履约、库存释放和收款退款提供联动入口。
- 前端类型禁止 `any`，报价和交易类型要清楚区分。

## 完成条件

- 客户接受有效报价后可以创建订单。
- 订单创建后交易履约进入已下单或待订金，而不是已完成。
- 订单保存报价版本和促销摘要。
- 库存占用或占用失败结果明确。
- 前端能查看报价版本、审批意见和转订单结果。

## 交付说明

完成后说明：

- 报价转订单的事务边界。
- `TTran` 与订单成立事实如何衔接。
- 库存占用和收款计划如何触发。
- 前端新增页面和验证结果。

## 业务场景

- 销售为商机创建报价，经过审批和客户确认后形成订单。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 报价版本、审批、客户确认和订单成立是不同事件。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得用报价审批或订单成立直接完成交易履约。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证报价快照、订单成交事实、库存占用入口和收款计划关系。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
