# 新增跟进任务与记录任务

## 任务目标

按跟进任务 Spec 和落地方案，新增跟进任务、跟进记录、个人待办、团队督办和业务对象最近跟进同步。

## 修改范围

允许修改：

- 新增 `FollowTaskController`、`FollowTaskService`、`FollowTaskServiceImpl`
- 新增 `TFollowTask`、`TFollowRecord`、Mapper、XML、DTO、Query、枚举。
- `dealer-server/src/main/resources/CarDealerCRM.sql`
- `dealer-server/src/main/resources/schema-test.sql`
- `ClueServiceImpl`、`CustomerServiceImpl`、商机相关 Service，只用于同步最近跟进和生成待办。
- 新增 `dealer-web/src/modules/follow/`
- 新增 `dealer-web/src/pages/dashboard/follow/index.vue`
- `dealer-web/src/router/routes.ts`
- 跟进相关测试和文档。

禁止修改：

- 用备注替代任务状态。
- 让跟进任务直接修改交易、收款、发票或交付核心状态。
- 在前端自行判断逾期作为唯一事实。

## 当前代码落点

- 当前已有 `TClueRemark`、`TCustomerRemark`、`TTranRemark`、`TActivityRemark`，但没有统一跟进任务。
- 当前没有 `modules/follow` 和个人待办页面。

## 执行步骤

1. 新增跟进任务和跟进记录表。
2. 定义任务类型和状态 code。
3. 实现手工创建、业务触发创建、完成、延期、取消和逾期查询。
4. 完成任务时写跟进记录，并同步关联对象最近跟进时间和下一步时间。
5. 新增个人待办和团队督办接口。
6. 在线索、客户、商机详情中接入跟进记录查询。
7. 新增前端个人待办列表和任务操作。
8. 补充权限、逾期、延期、取消、完成和前端测试。

## 代码逻辑要求

- 关联对象类型必须是稳定枚举，不允许任意字符串。
- 完成、延期、取消必须校验负责人和数据范围。
- 任务内容和沟通记录可能包含敏感信息，列表和导出要受权限控制。
- 逾期识别以服务端时间为准。
- 任务完成和业务对象最近跟进同步必须在事务内完成。

## 完成条件

- 销售能看到按时间排序的个人待办。
- 主管能查看团队逾期任务。
- 完成跟进后，线索或客户最近跟进时间同步更新。
- 延期和取消必须记录原因。
- 无权限用户不能查看他人敏感跟进内容。

## 交付说明

完成后说明：

- 任务类型、状态和关联对象枚举。
- 哪些业务动作会自动生成待办。
- 最近跟进同步到哪些对象。
- 权限和敏感内容如何控制。

## 业务场景

- 围绕线索、客户、商机、订单和交付回访生成待办与沟通记录。
- 执行时先确认该任务在业务闭环中的上游对象、下游对象和责任边界。

## 状态事件要求

- 任务状态只表达待办处理结果，不代表主业务对象终态。
- 状态推进必须由真实业务事件触发，并保留必要原因、操作者和时间。

## 与其他任务的边界

- 跨模块共享不变量以 `docs/task/核心业务闭环/` 为准。
- 模块内部页面、接口、模型、测试和局部校验由本任务负责。
- 涉及共享文件时遵守 `docs/task/核心业务闭环/00-任务拆分总览.md` 的文件所有权。

## 不得破坏的业务事实

- 不得用任务完成覆盖线索转化、商机赢单、订单成立或交付完成。
- 不得为了让测试通过而降低业务断言或删除历史事实。

## 场景验收

- 完成后能验证任务与关联对象时间线一致，逾期和延期可追溯。
- 验收必须能映射到 `docs/task/文档链路治理/验收矩阵.md` 中至少一个端到端场景。
