# 补齐业务闭环 Spec 任务

## 任务目标

新增全局业务闭环 Spec，并让顶层项目方向文档引用它，避免顶层、模块和任务各自定义一套业务链路。

## 前置阅读

- docs/spec/项目业务方向规范.md
- docs/rule/10-文档与Spec治理规范.md

## 修改范围

允许修改：

- `docs/spec/业务闭环/00-业务对象关系与主流程.md`
- `docs/spec/业务闭环/01-状态事件与完成条件.md`
- `docs/spec/业务闭环/02-异常取消与历史保留.md`
- `docs/spec/项目业务方向规范.md`

禁止修改：

- 后端、前端和数据库代码。
- 模块 Plan 和模块 Task。
- 将当前代码实现当作业务规则来源。

## 执行步骤

1. 建立 `docs/spec/业务闭环/` 目录。
2. 编写业务对象关系和主流程，明确线索、客户、商机、报价、订单、履约、收款、发票、库存、交付和经营分析之间的职责边界。
3. 编写状态事件和完成条件，明确核心业务事件、触发条件、影响对象、允许角色、后续影响和失败处理。
4. 编写异常取消和历史保留规则，覆盖重复线索、客户合并、商机输单、报价过期、审批拒绝、库存不可交付、订单取消、退款、作废、红冲和交付异常。
5. 更新项目业务方向规范，让主业务闭环引用 `docs/spec/业务闭环/`，不重复展开细节。

## 完成条件

- 全局业务闭环有独立 Spec。
- 顶层项目方向文档只保留愿景、地图和引用，不重复定义完整状态规则。
- 模块级文档能以业务闭环 Spec 作为共同上游。
