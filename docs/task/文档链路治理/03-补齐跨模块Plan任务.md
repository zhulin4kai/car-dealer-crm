# 补齐跨模块 Plan 任务

## 任务目标

更新核心业务闭环 Plan 和各模块 Plan，使 Plan 层能够承接业务闭环 Spec，并给 Task 层提供明确的协同关系、状态事件方案和数据历史方案。

## 前置阅读

- docs/spec/业务闭环/00-业务对象关系与主流程.md
- docs/spec/业务闭环/01-状态事件与完成条件.md
- docs/spec/业务闭环/02-异常取消与历史保留.md
- docs/plan/核心业务闭环/01-核心业务不变量治理方案.md

## 修改范围

允许修改：

- `docs/plan/核心业务闭环/01-核心业务不变量治理方案.md`
- `docs/plan/*/*.md`

禁止修改：

- Spec 内容。
- Task 内容。
- 后端、前端和数据库代码。

## 执行步骤

1. 在核心业务闭环 Plan 中增加业务对象关系图。
2. 在核心业务闭环 Plan 中增加状态事件矩阵。
3. 在核心业务闭环 Plan 中增加跨模块依赖顺序。
4. 在核心业务闭环 Plan 中增加业务场景验收矩阵。
5. 为每个模块 Plan 增加 `业务协同关系`。
6. 为每个模块 Plan 增加 `状态与事件方案`。
7. 为每个模块 Plan 增加 `数据与历史方案`。
8. 确认 Plan 只写方案和边界，不写具体代码实现步骤。

## 完成条件

- 核心业务闭环 Plan 能解释跨模块不变量。
- 每个模块 Plan 能解释依赖哪些上游事实、影响哪些下游模块、如何处理状态事件和历史数据。
- Plan 层可以直接指导 Task 拆分。

## 验证命令

- `rg -n "业务对象关系图|状态事件矩阵|跨模块依赖顺序|业务场景验收矩阵" docs/plan/核心业务闭环/01-核心业务不变量治理方案.md`
- `rg -n "## 业务协同关系|## 状态与事件方案|## 数据与历史方案" docs/plan`
- `git diff --check`

## 交付说明

完成后说明：

- 核心 Plan 增加了哪些跨模块视图。
- 模块 Plan 增加了哪些统一章节。
- 哪些状态和历史边界被明确。
