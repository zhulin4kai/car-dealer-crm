# 补齐模块状态事件 Spec 任务

## 任务目标

为所有模块 Spec 增加业务对象关系和状态事件边界，让每个模块都能说明上游、下游、负责事实、禁止替代边界、拥有状态和业务事件。

## 前置阅读

- docs/spec/业务闭环/00-业务对象关系与主流程.md
- docs/spec/业务闭环/01-状态事件与完成条件.md
- docs/spec/业务闭环/02-异常取消与历史保留.md
- docs/rule/10-文档与Spec治理规范.md

## 修改范围

允许修改：

- `docs/spec/*/00-业务范围与边界.md`
- `docs/spec/*/01-流程规则与验收规格.md`
- 审计日志模块中与业务事件审计相关的功能规格。

禁止修改：

- Plan 和 Task。
- 后端、前端和数据库代码。
- 把模块状态写成可以替代其他模块状态的单一状态。

## 执行步骤

1. 为每个模块范围文档增加 `业务对象关系`。
2. 为每个模块流程规格增加 `状态与事件边界`。
3. 明确本模块上游对象、下游对象、负责事实和禁止替代事实。
4. 明确本模块拥有状态、消费事件、发出事件、终态、异常态、可恢复态。
5. 审查所有模块是否违背业务闭环 Spec。

## 完成条件

- 每个模块都能回答上游、下游、负责事实和禁止替代边界。
- 每个模块都能回答拥有状态、消费事件和发出事件。
- 线索、客户、商机、报价、订单、收款、发票、库存、交付和统计之间边界清晰。

## 验证命令

- `rg -n "## 业务对象关系" docs/spec`
- `rg -n "## 状态与事件边界" docs/spec`
- `git diff --check`

完成后说明：

- 哪些模块补了对象关系。
- 哪些模块补了状态事件。
- 哪些业务割裂被消除。
