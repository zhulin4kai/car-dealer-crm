# 重整执行 Task 任务

## 任务目标

更新既有执行任务，消除跨模块任务与模块任务职责重叠，把宽泛描述改为可执行的业务场景、状态事件、任务边界、不得破坏事实和场景验收。

## 前置阅读

- docs/spec/业务闭环/00-业务对象关系与主流程.md
- docs/spec/业务闭环/01-状态事件与完成条件.md
- docs/spec/业务闭环/02-异常取消与历史保留.md
- docs/plan/核心业务闭环/01-核心业务不变量治理方案.md
- docs/task/核心业务闭环/00-任务拆分总览.md

## 修改范围

允许修改：

- `docs/task/核心业务闭环/*.md`
- `docs/task/*/*.md`

禁止修改：

- Spec 和 Plan。
- 后端、前端和数据库代码。
- 删除现有任务文档。

## 执行步骤

1. 更新核心业务闭环任务拆分总览，明确跨模块 task 负责共享不变量和共享文件。
2. 明确模块 task 负责模块内部落地。
3. 为既有 task 增加 `业务场景`。
4. 为既有 task 增加 `状态事件要求`。
5. 为既有 task 增加 `与其他任务的边界`。
6. 为既有 task 增加 `不得破坏的业务事实`。
7. 为既有 task 增加 `场景验收`。
8. 检查共享文件所有权，避免多个任务同时修改同一文件。

## 完成条件

- 执行任务不再只是宽泛说明。
- 每个任务都有明确业务场景和状态事件要求。
- 跨模块任务和模块任务边界清楚。
- 子 agent 可以按单个 task 独立接手。

## 验证命令

- `rg -n "## 业务场景|## 状态事件要求|## 与其他任务的边界|## 不得破坏的业务事实|## 场景验收" docs/task`
- `git diff --check`

## 交付说明

完成后说明：

- 核心任务与模块任务职责如何划分。
- 哪些任务补了场景验收。
- 哪些共享文件有唯一 owner。
