# 补齐验收矩阵任务

## 任务目标

新增端到端业务验收矩阵，让每个关键业务场景都能从 Spec 找到 Plan，再落到 Task。

## 前置阅读

- docs/spec/业务闭环/00-业务对象关系与主流程.md
- docs/spec/业务闭环/01-状态事件与完成条件.md
- docs/spec/业务闭环/02-异常取消与历史保留.md
- docs/plan/核心业务闭环/01-核心业务不变量治理方案.md

## 修改范围

允许修改：

- `docs/task/文档链路治理/验收矩阵.md`
- `docs/task/文档链路治理/00-文档链路治理总览.md`

禁止修改：

- 后端、前端和数据库代码。
- 用测试命令替代业务验收标准。

## 执行步骤

1. 建立端到端业务验收矩阵。
2. 覆盖线索转客户、客户多商机、商机试驾、报价审批、订单成立、库存占用、收款、发票、交付、取消、退款、红冲、统计反算和权限范围。
3. 为每个场景标明关联 Spec、Plan、Task。
4. 标明通过标准和禁止行为。
5. 检查矩阵是否覆盖主要业务闭环。

## 完成条件

- 每个端到端场景都有 Spec、Plan、Task 落点。
- 每个场景都有明确通过标准。
- 验收矩阵能够指导后续代码改造和测试设计。

## 验证命令

- `rg -n "线索转客户|客户产生多个商机|报价审批|订单成立|库存占用|交易完成" docs/task/文档链路治理/验收矩阵.md`
- `git diff --check`

## 交付说明

完成后说明：

- 验收矩阵覆盖哪些端到端场景。
- 每个场景如何映射到 Spec、Plan 和 Task。
